# P3 Closure — Inventory & Native Game UI

Goal (from the slice doc): *the player can understand and change game state without diagnostics.* Remaining items per the doc's own list: **weapon equip (visual), visible player-mesh attachment, bars, notifications, objective text, selective transfer, pickup handling, theft/ownership rules, item-added/removed script events, open/close presentation** — plus the missing automated P3 smoke gate.

Decisions locked with user: **first-person player body with head hidden** (NPC-pipeline reuse, camera/controls untouched) · **minimal theft = stolen flag** (no crime/witness system) · **objectives = HUD line + toasts + Quests tab**.

Four stages, each landing green (`cargo test --workspace` + affected gates) before the next.

---

## Stage 1 — Container interaction completion (state layer + browser UI)

1. **Item events** — new `ItemEventBatch` marker in `crates/scripting/src/events.rs` (Pattern A: register in `event_cleanup_system` per `cleanup.rs` house rules, docstring declares the pattern). Rows: `ItemTransfer { wearer, item_form_id, count, stolen, added: bool }`. Emit sites: container loot (take-all + selective), pickup, `consume_item`.
2. **Refactor take-all** — extract `container_loot_system`'s body (`byroredux/src/inventory.rs:426-510`) into shared helpers `transfer_all_from_source` / `transfer_stack_from_source` keeping the existing validation (`is_loot_source`: locked / Dead / CONT-base / player-activator rules) so the Activate path and the new UI path share one validated implementation.
3. **Container browser** — new `GameMenuPage::Container` in `crates/debug-ui/src/panels.rs`: two panes (source rows ↔ player rows), per-row **Take**, **Take All**, and **Store** (player→container, containers only, not corpses). `PanelSnapshot.container: Option<ContainerSnapshot>` (reuse `InventoryItemView` shape), `PanelOutputs.container_actions: Vec<ContainerAction>` applied via `inventory::apply_container_action` in the existing `apply_debug_ui_outputs` site. Verb for Container/Corpse becomes **"Search"**; E opens the modal (via a `PendingContainerOpen { source }` resource consumed in `app_frame.rs`) instead of instant take-all. Input capture, Escape/Tab close, and world-input release come free from the existing game-menu chain (`app_events.rs:313-332`).
4. **Pickup** — `InteractionKind::Pickup` in `populate_candidates` (`byroredux/src/interaction.rs:1121+`) for REFR entities whose base is in `InventoryCatalog.entries` and that carry no `Inventory`. Activation adds the stack, hides visuals via a `PickedUp` marker consulted by the render passes (same pattern as `NpcAppearanceHidden`), and parks a `PersistentReferenceStates` tombstone so reload doesn't respawn it.
5. **Ownership** — stamp `Owned { owner_form_id, faction_rank }` at reference spawn (`cell_loader/references/attach.rs`, source: `PlacedRef.ownership`, already parsed). Transfer classification: stolen iff owner exists ∧ owner ≠ player ref 0x14 ∧ owner ∉ player `FactionRanks`. Stolen transfers notify "Stolen: N items" and set the flag on `ItemTransfer` rows. No bounty/witness — documented out of scope.
6. **Tests** — extend the `inventory.rs` suite (selective transfer preserves instance handles + equipment indices; store direction; stolen/faction-exempt classification; pickup validation) and extend `container_and_corpse_loot_survive_encoded_live_overlay` for selective transfer + pickup tombstone.

## Stage 2 — HUD presentation (vitals, bars, notifications, objectives)

1. **Player actor values** — in `spawn_player_body` (`byroredux/src/scene.rs:1635`) stamp `ActorValues` + `ActorVitals` from `derive_npc_actor_values(index.npcs[0x7], index)` (same derivation NPCs use via `stamp_actor_values`). ⚠️ Known consequence: the #3158 comment warns this flips `melee_damage_charal_bonus` off its 8-damage fallback onto derived SPECIAL — **re-run the P2 gate** and update its pinned expectations to the (more correct) derived value.
2. **Bars** — `HudVitals {health/magicka/stamina current+max}` in `PanelSnapshot`, populated on both snapshot paths in `app_frame.rs` (including the minimal no-surface path), keys per game (`EsmIndex::health_actor_value_key()` + magicka/stamina siblings; Skyrim 0x3E8–0x3EA already used by `hud.rs`). Draw three slim bottom-left bars in `draw_hud` (`panels.rs:94`). Game-agnostic native path — MenuXml/Scaleform stay compat frontends per the slice doc.
3. **Notifications** — `DebugUiState.player_message` becomes a small stack (up to ~4 visible, 4 s fade each); `PlayerNotifications` queue unchanged. Item/quest/objective producers from Stages 1–2 feed it.
4. **Objectives** — in `crates/scripting/src/quest_stages.rs`: add `HUD_QUEST_EVENT_SUBSCRIBER` (id 4 constant) and a batched `ObjectiveEventBatch { quest, objective, change: Displayed|Completed|Failed }` marker emitted from `set_displayed/set_completed/set_failed` (Pattern A). New `byroredux/src/quest_hud.rs` system (Stage::Late, before cleanup): joins `QuestObjectiveState` × `QuestDefinitionRegistry` → `QuestHudState { active_objective, recent_changes }`, pushes toasts ("New objective: …" / "Objective completed"), exposes data for the HUD line (top-center active objective) and a new **Quests tab** in the Tab modal (journal-lite: active quests, stage log entries, objective statuses — same data `quest.show` already formats). Tab modal gains an Items/Quests page switcher.
5. **Tests** — quest_hud join tests (synthetic registry + state), objective event emission tests, toast-stack tests.

## Stage 3 — Visible equipment (player body + weapon attach)

1. **Player body** — at character spawn, load the player race skeleton (RACE from base NPC_ 0x7, same resolution as the NPC path) via `load_nif_bytes_with_skeleton`, parent under the body entity, build `skel_map`. Spawn equipped armor from `PlayerInventoryTemplate` through `resolve_armor_meshes` + `external_skeleton` + `NpcEquipmentPart` stamping (actor = player) so it matches NPC semantics. **Strip `RigidBodyData`/`CollisionShape` from imported player-rig entities** — cosmetic rig only; the KCC capsule stays authoritative. **Head hidden**: don't spawn head-slot ARMO parts + hide skeleton head nodes via the appearance-hidden marker (`render/skinned.rs:83`, `render/static_meshes.rs:300` consult points).
2. **Weapon visuals** — `resolve_weapon_mesh(index, form_id)` in `crates/plugin/src/equip.rs` (WEAP `common.model_path`, already parsed). New `EquippedWeaponVisual { entity, inventory_index, mesh_path }` component on the player + `reconcile_player_weapon_visual(world)`: attach weapon NIF root under the hand bone (name candidates per lineage: "NPC R Hand [RHnd]" / "Bip01 R Hand", via `get_case_insensitive` — the `shared_hair_mount` precedent). Call sites: weapon equip/unequip in `apply_action`, loot that changes `EquippedWeapon`, post-load reconcile (next to `reconcile_player_equipped_weapon`), player spawn init. Never persists entity ids (NpcEquipmentPart precedent — rebuilt from persisted `EquippedWeapon` on load).
3. **Tests** — `resolve_weapon_mesh` tests; reconcile tests (equip → entity under bone, unequip → removed, load → rebuilt); live orientation check on the fixture (weapon models are authored in bone space; correct with a fixed offset transform if needed).

3. **Registration + docs** — add to `scripts/check-playable-smoke-contracts.sh` + smoke README; dated P3 closure note in the vertical-slice doc; `docs/engine/ui.md` native-HUD/container-browser sections; ROADMAP refresh at session close (repo convention).
4. **Regression re-runs** — `p2-melee-core.sh` (damage-fallback shift from item 1 of Stage 2), `p1-character-traversal.sh`, `p5-save-restart.sh`, `m48-4-oblivion-hud.sh`, full workspace tests.
