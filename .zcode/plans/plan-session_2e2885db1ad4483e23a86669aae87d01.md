# VATS, built mod-compatibility-first

**Principle:** VATS reads zero gameplay constants from code. Every number resolves as *load-order-merged ESM value → compiled-in vanilla-default fallback* (the established `with_gmst` overlay pattern). Every authored input decodes the vanilla wire format exactly so modded plugins parse, and every engine hook point (condition-function CTDA index, perk entry point, ObScript opcode) matches the original so mod scripts/perks/quests behave. A synthetic modded-load-order test proves it end to end.

Scope this session: **Phases 1–3** (data foundation → AP pool → mode machine with first live gate on FNV). Phases 4–5 (playback cinematics, per-limb damage routing, MenuXml skin, FO4 lane) are follow-up milestones. File the VATS milestone issue first; land each phase as its own conventional commit.

## Phase 1 — plugin-crate data foundation

**1a. GMST load-order hardening (the core mod-compat fix).** `EsmIndex::game_setting_float` (`crates/plugin/src/esm/records/index.rs:1153`) linear-scans a FormID-keyed HashMap — correct for proper FormID-collision overrides (already honored by `merge_from`'s last-write-wins fold, `index.rs:41-54`, driven sequentially by `load_order.rs:858-869`) but nondeterministic when a mod ships a *new* GMST record under a different FormID with the same EditorID. Fix: build `game_settings_by_edid` (lowercased EditorID → record) during the `merge_from` fold — the same special-case treatment `character_rules` gets — so last-loaded-wins holds per EditorID regardless of FormID; prune deleted-tombstones from it too. `game_setting_float` reads the table; callers unchanged. Tests: two synthetic plugins, same EditorID under different FormIDs → later plugin wins deterministically; remapped-FormID override still wins (pin existing behavior); tombstone pruning.

**1b. WEAP VATS completeness for FO3.** FO3 authors no `VATS` sub-record and its AP cost / Base VATS To-Hit Chance are read from nowhere (the FO3/FNV `DNAM` arm at `items.rs:362-384` discards the offset-20 f32). Follow the `probe_weap_vats.rs` (#3324) method: a corpus probe example correlates FO3 `DNAM` floats against known vanilla values to locate AP cost + base to-hit; decode both with width guards into `ItemKind::Weapon { ap_cost, vats_base_to_hit, .. }`. Census floors in `parse_real_esm.rs` (FO3 ~all weapons carry them). Wire real values through the runtime weapon constructors (`use_weapon_package.rs:129`, `projectiles.rs:428` currently hardcode `ap_cost: 0.0, vats: None`).

**1c. BPTD full decode + RACE→BPTD link.** Upgrade the count-only stub (`misc/equipment.rs:180`) per its own upgrade note (#1057): `BPTN`/`BPNN`/`BPNT` zstrings (name / part node / VATS-target node) + typed `BPND` payload (part type, flags, damage mult, health percent, hit chance, actor-value enum, severable/explode) — exact byte layout via corpus probe on vanilla FNV/FO3 BPTDs, cross-checked against the GECK wiki field list. Add the RACE→BPTD FormID reference (and NPC_/CREA override if the wire carries it — probe confirms) to `parse_race` with `remap_fid` (#3714). Keep census floors (≥40 BPTD, vanilla ~49) and add per-part floors. Standard upgrade pattern: dedicated struct, `CommonNamedFields`, width-guarded sub-record loop, in-file unit test.

## Phase 2 — VatsModel + AP pool runtime

**2a. `VatsModel`** (`crates/core/src/character/`, sibling of `LevelingModel`/`CrimeModel`): compiled-in vanilla defaults for the `fVATS*`/`iVATS*` family (~30 settings, defaults sourced from the GECK wiki *VATS Settings* page; gaps measured from the vanilla ESM corpus — the fallback only matters when a load order lacks the record) + `with_gmst(gmst)` overlay + the to-hit-chance function (weapon base × part hit chance × `fVATSDistanceFactor` falloff × `fVATSSkillFactor` × screen-percentage × `fVATSHitChanceMult`, clamped by `fVATSMaxChance`), all pure and unit-tested against wiki-documented examples. Installed once alongside `CharacterRuleset` (`npc_spawn.rs:302` / `references/mod.rs:343` idempotent resource insert).

**2b. AP regen + spend.** Extend `crates/core/src/character/regen.rs`'s fixed-60Hz-tick model with the FO3/FNV ActionPoints per-second rate (GMST name measured from corpus, e.g. the `fActionPoints*` family; default overlaid via `with_gmst`). Spend/restore via the existing `ActorValues::apply_damage`/`restore` on the ActionPoints AVIF — the HUD AP bar (`hud.rs:127`) already renders this pool live. Player AP derivation already matches the wiki.

## Phase 3 — mode machine, freeze, targeting, first live gate

**3a. State + input.** `VatsState` resource mirroring `GetVATSMode`'s five engine states (None/TargetSelect/MenuMode/ScanMode/Playback). `InputAction::Vats` + default binding (V, FO3/FNV PC vanilla) in `ActionBindings`; `Control::Vats` in `input_layers.rs` becomes that domain's first reader (enabled-gates honored).

**3b. Time freeze.** Generalize the loading-cover dt-pin (`app_events.rs:744-747`) into a `WorldTimeScale` resource (VATS publishes 0.0 for FO3/FNV) applied at the same dt-computation site, plus a `VatsClock` unscaled-dt resource for the overlay/camera (the `LoadingCoverClock` pattern, `render.rs:29-44`). `GameTimeRes` pauses alongside (`time.pause` precedent). Because world dt is 0, the fixed-tick AP regen pauses for free — matching vanilla.

**3c. Targeting scan.** New `byroredux/src/systems/vats.rs` (Update stage): for actors within `fVATSMaxEngageDistance`, resolve each BPTD part's VATS-target bone (bone world transforms + the NIF body-part data already decoded in `nif/blocks/skin.rs:399`), screen-project via the camera VP, occlusion-check with the existing physics ray casts, then compute per-part hit chance through `VatsModel`. Queue attacks as data (the `ActiveProjectiles` pattern — "systems cannot spawn"), confirm → AP spend → emit `HitEvent`s through the existing `combat_damage_system` funnel with `fVATSPlayerDamageMult` applied (per-limb routing deferred to Phase 4; `CombatState.last` traces the outcome for smoke asserts).

**3d. Mod-hook surfaces.** Console commands `vats.enter` / `vats.status` / `vats.exit` (+ `docs/engine/debug-cli.md` rows — the source-scan test enforces them); condition function `GetVATSMode` (new `ConditionFunction` variant + `ROWS` row with the FO3/FNV CTDA index from the GECK wiki function list + exhaustive `evaluate_function` arm reading `VatsState`); ObScript natives: real `GetVATSMode` getter, and `SetVATSTarget` (`cmd_11eb`) promoted from ledger-parking to an actual destructible-targeting flag read by the scan.

**3e. Overlay.** `GameMenuPage::Vats` in debug-ui (the Dialogue-page pattern): target/body-part list with percentages and AP cost, click-to-queue, world-frozen policy (`simulation_paused` inverse of dialogue). The authored MenuXml `vats_menu.xml` skin is Phase 4 presentation work.

**3f. Gates.** Unit tests in-crate per repo convention (scan math, freeze policy, state transitions, AP spend). Smoke test `docs/smoke-tests/vats-targeting.sh` on FNV: boot with debug server → `vats.enter` → assert world clock frozen, `vats.status` lists parts with percentages, AP cost matches the held weapon's `WEAP.VATS`, queue → AP spent → attack lands in `combat.status` → `vats.exit` resumes sim. SKIP≠PASS (exit 77) contract. **The mod-compat acceptance test:** a synthetic load order overriding `fVATSHitChanceMult` (+ adding a new-FormID GMST) changes the reported hit chances — proof the whole stack is load-order-driven, not code-driven.

Verification per repo convention: `cargo check`; `cargo test -p byroredux-core --features inspect`; `cargo test -p byroredux-plugin` census tests (env-gated); binary tests via the pinned 1.96 toolchain path; no wholesale `cargo fmt`.
