## Phase 2: Dimensions

### Dimension 1: Inventory & Equipment Model
**Paths**: `byroredux/src/inventory.rs`, `crates/core/src/ecs/components/inventory.rs`, `crates/core/src/ecs/resources/mod.rs` (`ItemInstancePool`), `crates/plugin/src/equip.rs`, `byroredux/src/player_body.rs`, `byroredux/src/npc_spawn/loot_appearance.rs` (`GearImportLoader`)
**First step**: `git log --since=<last> --format='%h %cs %s' -- byroredux/src/inventory.rs crates/core/src/ecs/components/inventory.rs`
**Guard**: `inventory::tests::{armor_toggles_never_touch_the_equipped_weapon, load_reconciler_*}`, core `no_armor_mask_can_reach_the_weapon_slot`.
- Canonical state is `Inventory` + `EquipmentSlots` + `EquippedWeapon` (core). `InventoryCatalog` and the two player templates are read-only, rebuilt by `install_catalog` per content load; a mutable inventory copy in the binary is a boundary violation.
- Rows are zeroed in place, never removed (equipment and `EquippedWeapon.inventory_index` point into `items`): check consume, `transfer_loot`, `pickup_loot`, `reference_state::restore`. Slot mutations re-derive `EquippedWeapon` (`reconcile_equipped_weapon`); armor toggles must not.
- `ItemInstance` has no fields (`_reserved`); production allocates only in `restore`. Reject claims that per-instance condition/mods/charge exist; `Some(instance)` paths must still be atomic.
- Player body + mid-life gear (P3): `attach_player_body` builds a strictly visual body via `NpcSpawnJob` (`player_body` flag: no identity/inventory/AI/collider stamps; the capsule stays the only physics body). An equip with no `NpcEquipmentPart` root queues `PendingGearImport` → `GearImportLoader` (retained `NpcSkeletonBones`/`ActorBodyClass`); `inv.equip` must go through `apply_action`. The body comes from the `NPC_ 0x7` record, read through its TPLT terminals like the player templates (#5047, c20dcdb04). Post-load, `reconcile_worn_gear` (`loot_appearance.rs`, #5034 20717d5b7) diffs live non-intrinsic roots against the restored `EquipmentSlots` (reveal / hide / queue `PendingGearImport`) from `reference_state::restore` (NPCs) and the post-`apply_deltas` player block — synthesized in memory, never an `EquipmentEventBatch`. Mid-life gear is released: a leaves-inventory transfer on a cellless wearer queues `PendingGearRelease` → `GearImportLoader` → `cell_loader::unload::release_entities` (#5028 f78e018ac; NPC gear stays cell-owned). `NpcEquipmentPart` has no `inventory_index` (#5049 dropped it; hide/reveal match on `form_id`).

### Dimension 2: Interaction, Locks, Containers & Loot Persistence
**Paths**: `byroredux/src/interaction.rs` (action half), `byroredux/src/systems/npc_dialogue.rs`, `byroredux/src/cell_loader/{reference_state,unload}.rs`, `cell_loader/references/{attach,synth_child}.rs`, `byroredux/src/npc_spawn/loot_appearance.rs`, `crates/core/src/ecs/components/lock.rs`, `crates/plugin/src/equip.rs`
**First step**: `cargo test -p byroredux -- reference_state scripted_lock_gate synth_child interaction::`
**Guard**: `reference_state::tests` (9), `synth_child_tests::actor_placement_stamp_restores_only_the_looted_instance_of_a_shared_base`, `scripted_lock_gate_tests`, `interaction::tests::key_gate_rejects_missing_zero_count_wrong_and_keyless_locks`, `loot_appearance::tests`.
- Pipeline: `interaction_system` (ahead of every OnActivate consumer) → `ActivateEvent` (read, not drained) → `container_loot_system` → `transfer_loot` (validates source/lock/both inventories *before* mutating; whole stacks; source equipment cleared, one unequip event each) or `pickup_loot`.
- Locks: key unlock happens on activation, not prompt, and is recorded in `ReferenceLockState` (saved). `carried_unlock_key` reads `PapyrusPlayerEntity`; loot/combat read `PlayerEntity` (both set in `scene.rs`; the fly-cam placeholder has no `Inventory`) — can they diverge? `lock_level` has no consumer.
- Persistence: `capture` runs before unload frees instances; `restore` at attach consumes the row; `without_parked_state` shields a save reload; parked rows own their payloads; identity is the REFR `FormIdPair`, not the base. Every new placement fact (lock override, `Dead`, `picked_up`, inventory, equipment, AVs) needs a row field or ledger, else eviction loses it. No serde defaults on `ReferenceState` (#4465): schema change ⇒ `FORMAT_MAJOR` bump (`/audit-save`).
- Leveled loot: containers and NPC CNTO carry lists (#4696) both use `expand_leveled_loot` (LVLO counts multiplied, Use-All `0x04`); only the worn outfit (DOFT/OTFT) keeps the flat `expand_leveled_form_id`. A new LVLI call site that takes the flat walk for a *carried* list is the regression.
- `NpcLootAppearance` hides originals only once the replacement is fully staged; never strips a living actor.
- NPC dialogue (P4, closed): Late `npc_dialogue_selection_system` reads `ActivateEvent` (before `event_cleanup_system`), walks running-quest `DialRecord::quest_refs` bound to the NPC, stamps `NpcDialogueTopic` into `DialogueRegistry`; `DialogueSurfaceState` keys the surface on its `npc` and `apply_selection` strips every other NPC's topic (#5038). Topic reachability follows the CK branch model (#5037, 7ab87c0fb; module doc is the spec): only `DialogueCategory::Topic` with an INFO passing for *this* NPC; a qualifying Blocking DLBR entry opens and its TCLT links replace the list; else Top-Level starting topics; FO3/FNV topics need the DIAL `DATA` Top-level bit 0x02 (#5224). Both entry points gate on `player_can_act`, and `npc_refuses_dialogue` (dead, `AiCombatState`, unconscious #5017) is shared by selection, topic click and the interaction Talk arm (#5043) — a fourth path without it is the regression. Spoken lines run their INFO VMAD TIF_ fragments (OnBegin at selection, OnEnd on change/close; #5152 via `DialogueInfoFragments`). Quest-less NPCs select nothing (no greeting fallback, by design); none of it is saved. INFO/CTDA semantics → `/audit-scripting`.

### Dimension 3: Consumables & Timed Effects
**Paths**: `byroredux/src/inventory.rs` (`consume_item`), `byroredux/src/systems/restoration.rs`, `crates/core/src/ecs/components/restoration.rs`, `crates/core/src/ecs/resources/hardcore.rs`, `crates/plugin/src/consumables.rs`
**First step**: `cargo test -p byroredux -- consum restoration timed_`; `cargo test -p byroredux-plugin consumables`
**Guard**: `unavailable_consumption_never_changes_health_or_count`, `consuming_invalid_instance_is_atomic`, `save_io/consumable_tests.rs`. The Hardcore/perk test `real_stimpaks_restore_scaled_health_and_limbs_but_hardcore_only_health` is `#[ignore]`d (FO3+NV data): it guards nothing unless run `--ignored`.
- Chain: ALCH EFID/EFIT/CTDA → `ConsumableEffect` (Skyrim, FO3/NV only) → `restoration_plan` → `InventoryCatalog.restorations` → `consume_item` → instant `restore` or `TimedRestorations` (constant rate, simulation seconds, no overheal banking) → `restoration_system` (clears on `Dead`/health ≤ 0).
- `restoration_plan` is all-or-nothing: any unsupported effect, condition, area, delivery, script or AV ⇒ `None`, never a partial potion. Conditions fail-CLOSED (`GetHasPerk` 448/449; `IsHardcore` 586 on the NV profile only); package CTDA is fail-OPEN (Dim 5). The asymmetry is deliberate; a flip is a finding.
- Hardcore is an effect CTDA, not a branch in `consume_item`; `HardcoreMode` is a saved flag only. Conditions and Medicine scaling are evaluated at use and the resolved rate stored, so later skill changes do not rewrite a dose.
- AV map in `restoration()` (Skyrim 24/25/26, FO3/NV 16/12) vs `docs/engine/charal-*-ruleset.md`; Oblivion/FO4+ Aid items are "effects unavailable" by design. `Unavailable` only reaches `log::warn!` (`main.rs`): #4458 (player lacked AVs) looked like a dead button.

### Dimension 4: Combat & Death Pipeline
**Paths**: `byroredux/src/combat.rs`, `byroredux/src/systems/{combat_ai,faction_hostility,combat_anim}.rs`, `crates/scripting/src/combat.rs`, death producers in `byroredux/src/systems/{water,character}.rs`
**First step**: `grep -rn 'Dead)' byroredux/src --include='*.rs' | grep -v test` — every production `Dead` insert must reach `reconcile_dead_actor` (in an exclusive, or `queue_dead_actor_reconciliation` → Late `reconcile_pending_dead_actors_system`). Today: `combat_damage_system`, NPC drowning (`water.rs`) and player drowning (`character.rs`), `reference_state::restore` + `apply_starts_dead` (#4814 ACHR 0x200, #5013 Oblivion base 0x80000, #5223 FO3/FNV dismember-trigger / kill-on-load scripts via `script_killed_corpse_forms`), the SDK AV batch (`extensions/commands.rs`, #4702).
**Guard**: `combat::tests::{consumer_applies_the_producers_damage_rather_than_recomputing_it, dead_state_reconciliation_removes_respawned_ai}`, `combat_ai::tests::{physics_world_is_taken_only_between_the_storage_passes, a_same_frame_hit_on_the_target_survives_and_the_strike_lands_next_frame}`.
- One damage path: `combat_input_system` and `npc_combat_ai_system` emit `HitEvent`; only `combat_damage_system` writes Health/`Dead`. `HitEvent` cleanup is Late `event_cleanup_system` — not a leak.
- `reconcile_dead_actor` teardown = `clear_ambient_behavior` set + `AmbientPackageRuntime` + `EvaluatePackageRequest` + `AiCombatState` + `AnimationPlayer`/`AnimationStack` (actor and skeleton root) + ragdoll; it must grow with each new per-actor runtime component (Dim 5) — check `AmbientEngagement`, `NpcDialogueTopic`, `PendingGearImport`.
- Combat start: `Effect::StartCombat` or `faction_hostility_system` (#4414; every `EVALUATION_PERIOD_SECS`, range from `DetectionConfig` GMSTs + line of sight, no `DetectionConfig` ⇒ no ambient hostility). Ambient combat carries `AmbientEngagement` and drops after `DISENGAGE_GRACE_SECS` out of contact (#4816); scripted combat never auto-drops — `Effect::StartCombat` removes the marker so a quest taking over an ambient fight owns it (#5046, fef67f3c3). Unconscious actors (#5017, `ActorControlState.unconscious`, mutually exclusive with `restrained`): combat AI drops an unconscious attacker's combat, hostility never arms an unconscious perceiver but may target it and arms it once awake, ambient AI suspends its procedure. `suspend_ambient_behavior_for_combat` must pause the package while fighting and let it resume (#4703).
- `attack_damage`: weapon + CHARAL melee bonus; `CreatureAttack` only when unarmed; else `UNARMED_DAMAGE` (formulas → `/audit-character`). `MeleeState` is per combatant; `PhysicsWorld` is taken only between storage passes (#4325). The swing resolves through `cast_ray_corridor` (`MELEE_SWING_CORRIDOR_RADIUS_BU` 12 BU ball, #5160) excluding only the aggressor's capsule body — its own bones can be hit, which `resolve_actor_root` turns into a miss; player rays originate at the eye (`player_camera_boom`, #5124). Combat take/sound feedback registers *outside* the locomotion kill switch (#4709).

**First step**: `cargo test -p byroredux -- ambient_locomotion npc_spawn::ai_package walk_anim locomotion::`
**Guard**: `boot/schedule/mod.rs::ambient_locomotion_default_on_tests::{locomotion_registers_behind_the_single_kill_switch, walk_animation_registers_after_all_six_movers}` (live source-shape) pin registration and order, not procedure semantics. `ai_package::tests::{same_winner_preserves_runtime_state, unknown_condition_function_remains_fail_open}`, `walk_anim::tests`.

### Dimension 7: Gameplay-State Coverage, Stage Order & Determinism
**Paths**: `byroredux/src/save_io.rs` (registrations), `byroredux/src/save_io/{registry_completeness,round_trip}_tests.rs`, `byroredux/src/boot/schedule/{update,post_update,late}.rs`
**First step**: `grep -nE 'Combat|Melee|Walk|Ambient|Seat|Loot|Picked|Notif|Interaction|Faction' byroredux/src/save_io/registry_completeness_tests.rs`
**Guard**: `registry_completeness_tests::every_component_or_resource_impl_is_saved_or_explicitly_allowlisted` and `round_trip_tests::npc_spawn_stamped_components_are_saved_or_intentionally_rederived` prove a *name* is classified, not that its stated rebuild path exists. `scheduler_access_tests::p2_gameplay_exclusives_declare_non_empty_access` covers three of the gameplay exclusives.
- Prove the claimed re-derivation for each gameplay allowlist row (`AmbientPackageRuntime` first tick, `WalkAnimation` from the spawn lookup, `PickedUp` re-stamped by `restore`). Genuinely unsaved: `AiCombatState` (session `EntityId` target) — ambient combat is re-derived by `faction_hostility_system` after load, a scripted `StartCombat` against a not-otherwise-hostile target is lost. Saved: `TimedRestorations`, `HardcoreMode`, `PersistentReferenceStates`, `ReferenceLockState`, `FactionRelations`; `Dead` and `ActorControlState` are *replacing* columns so a saved absence clears them on the process-lifetime player (#5027/#5052, 7aa1d7741).
- The load overlay is additive-only except replacing columns: a runtime *removal* that follows from a saved fact must be re-derived after load (models: `reconcile_dead_actor_runtime_state`, `reconcile_player_equipped_weapon`, `reconcile_worn_gear`, the player `FactionRanks` reset to the record (#5058), the pre-teardown cinematic purge (#5056)). Snapshot rows whose `FormIdPair` the reload cannot resolve (hysteresis band) are parked into `PersistentReferenceStates` (#5054) — a new per-reference fact must reach that park path as well as `capture`.
- Update order is mostly comment-enforced: `restoration_system` → `interaction_system` → `fragment_activation_flush_system` → `container_loot_system` → `combat_input_system` → `faction_hostility_system` → `npc_combat_ai_system` → `combat_damage_system` (only flush-before-consumers is pinned, by `activation_flush_is_scheduled_before_every_activate_event_consumer`); `ambient_ai_package_system` before `scene_package_system`; Late `water_damage_system` → `reconcile_pending_dead_actors_system` → `equipment_appearance_system` → `npc_dialogue_selection_system` → `event_cleanup_system`. Verify each consumer sees its producer the same frame; `inventory::apply_action` runs between frames with `&mut World`.
- Determinism: `grep -nE 'rand::|Instant::now|SystemTime'` over `combat.rs`, `inventory.rs`, `interaction.rs`, `ai_package.rs`, `faction_hostility.rs`, `npc_dialogue.rs` and the Dim 5 systems must be empty (`Instant` in `npc_spawn/resumable/mod.rs`/`unload.rs` is budget/telemetry timing).
- Written-never-read / tested-but-unwired is the repeated defect class: each gameplay resource needs a production reader (`FactionRelations`), each `pub(crate)` entry a non-test caller (#4464 closed: `transfer_loot` had none while six tests passed); justify each `#[allow(dead_code)]`.
