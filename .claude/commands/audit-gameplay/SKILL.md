### Dimension 1: Inventory & Equipment Model
**Paths**: `byroredux/src/inventory.rs`, `crates/core/src/ecs/components/inventory.rs`, `crates/core/src/ecs/resources/mod.rs` (`ItemInstancePool`), `crates/plugin/src/equip.rs`, `byroredux/src/player_body.rs`, `byroredux/src/npc_spawn/loot_appearance.rs` (`GearImportLoader`)
**First step**: `git log --since=<last> --format='%h %cs %s' -- byroredux/src/inventory.rs crates/core/src/ecs/components/inventory.rs`
**Guard**: `inventory::tests::{armor_toggles_never_touch_the_equipped_weapon, load_reconciler_*}`, core `no_armor_mask_can_reach_the_weapon_slot`.
- Canonical state is `Inventory` + `EquipmentSlots` + `EquippedWeapon` (core). `InventoryCatalog` and the two player templates are read-only, rebuilt by `install_catalog` per content load; a mutable inventory copy in the binary is a boundary violation.
- Rows are zeroed in place, never removed (equipment and `EquippedWeapon.inventory_index` point into `items`): check consume, `transfer_loot`, `pickup_loot`, `reference_state::restore`. `Inventory::add` folds a plain stack into the form's existing plain row (reusing a zeroed one in place) and appends only instanced stacks; scripted `AddItem`, barter, loot and pickup all go through it (#5871 f4269deb4) — a new add path that appends a plain row is the regression. Slot mutations re-derive `EquippedWeapon` (`reconcile_equipped_weapon`); armor toggles must not.
- `ItemInstance` has no fields (`_reserved`); production allocates only in `restore`. Reject claims that per-instance condition/mods/charge exist; `Some(instance)` paths must still be atomic.
- Player body + mid-life gear (P3): `attach_player_body` builds a strictly visual body via `NpcSpawnJob` (`player_body` flag: no identity/inventory/AI/collider stamps; the capsule stays the only physics body). An equip with no `NpcEquipmentPart` root queues `PendingGearImport` → `GearImportLoader` (retained `NpcSkeletonBones`/`ActorBodyClass`); `inv.equip` must go through `apply_action`. The body comes from the `NPC_ 0x7` record, read through its TPLT terminals like the player templates (#5047, c20dcdb04). Post-load, `reconcile_worn_gear` (`loot_appearance.rs`, #5034 20717d5b7) diffs live non-intrinsic roots against the restored `EquipmentSlots` (reveal / hide / queue `PendingGearImport`) from `reference_state::restore` (NPCs) and the post-`apply_deltas` player block — synthesized in memory, never an `EquipmentEventBatch`. Mid-life gear is released: a leaves-inventory transfer on a cellless wearer queues `PendingGearRelease` → `GearImportLoader` → `cell_loader::unload::release_entities` (#5028 f78e018ac; NPC gear stays cell-owned). `NpcEquipmentPart` has no `inventory_index` (#5049 dropped it; hide/reveal match on `form_id`). `reconcile_worn_gear` builds `equipped_forms` from biped slots only, in slot order (the weapon slot never has a mesh, so including it starved the reconcile and made `missing` nondeterministic, #5266 6e0594e68); a zero-mask item never reaches `occupants`, so a mis-decoded biped mask hides that gear on every restore (Skyrim's pre-BOD2 `BODT` decodes since #5358, 479414ffe); `queue_midlife_imports` resolves before the per-wearer pick so an unservable form cannot strand servable ones. A batch is folded as a transition LOG (an unequip cancels a queued equip of the same form), `GearImportLoader` re-checks the live slots (`equipped_forms`) before every path and drops an import whose item is no longer worn, and a file-level miss or failed import chains `reconcile_worn_gear_excluding` with the failed form held out so the forms behind it never stall (#5031 ec41e33e8; `an_unequip_in_the_batch_cancels_the_queued_equip`, `a_failed_import_does_not_stall_the_forms_behind_it`). The gear-release subtree walk uses core's guarded `collect_subtree` (#5513 9da80470d). The gear-release "still held" filter counts only `count > 0` rows (zeroed rows stay, #5268 fec2d14b2); the `added == false` release path is live: `remove_items` (barter sale, caps spend, `RemoveItem`, `DropObject`) emits it for the player and also drops an emptied `EquippedWeapon` with an unequip `EquipmentChange` (#5863 bae823643); `transfer_loot` emits it on the source side. The pre-baked FaceGen miss assembles a head (`PrebakedPhase::HeadParts`, `PrebakedHeadPart`; the Skyrim player has no facegeom so this is its normal path; #5095 8c925ec54) in `prebaked_head_fallback_paths`: the race's per-gender `RaceRecord::base_head_parts`, each part type the NPC's PNAM authors replacing the race's, then HDPT HNAM extras depth-first with a visited set (#5408 2a8663f39). The facegeom path, the facetint path, the PNAM list and the owning plugin all come from the Use-Traits terminal, not the placed shell (#6113 1dfac76f6). Reading them off the shell gave about 40% of Skyrim NPC bases a race-default head. Runtime-FaceGen gender also comes from that terminal (#6080 415c35cff); `npc_spawn::is_child_race` is the one shared FO3/FNV Child translation for spawn and player body (#5079).
