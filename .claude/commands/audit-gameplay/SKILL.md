**Guard**: `inventory::tests::{armor_toggles_never_touch_the_equipped_weapon, load_reconciler_*}`, core `no_armor_mask_can_reach_the_weapon_slot`, plugin `level_zero_terminal_takes_the_lvln_pick_entry_level`, `crafting::tests::{improving_raises_a_held_item_in_place_and_never_hands_out_a_copy, crafting_consumes_ingredients_yields_the_item_and_raises_craft_item}`.
- Canonical state is `Inventory` + `EquipmentSlots` + `EquippedWeapon` (core). `InventoryCatalog` and the two player templates are read-only, rebuilt by `install_catalog` per content load; a mutable inventory copy in the binary is a boundary violation.
- Rows are zeroed in place, never removed (equipment and `EquippedWeapon.inventory_index` point into `items`): check consume, `transfer_loot`, `pickup_loot`, `reference_state::restore`. `Inventory::add` folds a plain stack into the form's existing plain row (reusing a zeroed one in place) and appends only instanced stacks; scripted `AddItem`, barter, loot and pickup all go through it (#5871 f4269deb4) — a new add path that appends a plain row is the regression. Scripted `ResetInventory` returns the dropped stacks' `ItemInstancePool` entries (#6269 987affeb9); `pickup_loot` is `take_placed_item` for the player; an NPC taker (the Find package) takes the same path minus the notification and the player's theft report. Slot mutations re-derive `EquippedWeapon` (`reconcile_equipped_weapon`); armor toggles must not. A held count is `Inventory::count_of` (saturating, sums every row of the form; barter, guards' gold and bounty, jail, `GetGold`/`GetGoldAmount`, `DropObject` all use it, #6363 5b43fe347; `GetItemCount` over a form list is `Inventory::count_of_any`, saturating, #6470 457c5cd0d) — a hand-spelled `items.iter().filter(base_form_id).map(count).sum()` is the regression; the first non-empty row of a form is likewise the one `Inventory::first_row_of` (#6965 a7b3afd04; `inv.equip`/`inv.use`/`inv.drop` all queue through `queue_by_form_id`, #7232 c834ddb5e fixed the last hand-spelled first-row lookup, pinned in `inventory/tests.rs`). Take-all (`loot::transfer_loot`, `LootSelection::All`) reports and hands over only rows that hold items (a zeroed row still carrying an instance moves, so its pool entry stays owned), never a zero-count `ItemTransfer` (phantom OnAdd/OnDrop, zero-count theft row; #7231 2e535ba49). Weapon test fixtures go through `ItemKind::weapon_stub` (#6372 a65e11ef9; `workspace_hygiene_tests` rejects a field-by-field `ItemKind::Weapon` literal outside the parser).
- Arrows (player-archery BOW-AMM-001, e15645976): an `AMMO` stack's equip target is `EquipTarget::Ammo` only where the game has a `BowModel` row (`catalog.rs` filters it away elsewhere: a Fallout gun takes the first accepted ammunition it finds); `actions::toggle_equipped_ammo` sets the saved `EquippedAmmo` slot (a form id, never a count; choosing the equipped type puts it away, another replaces it, each with its `EquipmentChange` events) and never touches `EquipmentSlots` or `EquippedWeapon`. `bow::equipped_ammo` reads a form with no counted stack as unset; clear by writing `None`; the save column is *replacing* (#7228 c82e4f68f), so a save with no `EquippedAmmo` row (the slot is created lazily by the first arrow equip) clears the process-lifetime player's live choice too, pinned by a live-overlay test in `save_io/round_trip_tests.rs`.
- `ItemInstance` has exactly one field, `quality: u8` (Skyrim tempering, 0 = unimproved; M43 2c55546f4); production allocates in `restore` and `crafting::improve_item` (`armor.rs` only reads it). Reject claims that per-instance condition/mods/charge exist; `Some(instance)` paths must still be atomic. `ItemInstancePool` is created at boot (`boot/world.rs`; its absence made improving fail live, 542f3de7b).
- `EquipmentSlots` has `MAX_BIPED_SLOTS` = 64 slots and every slot mask is `u64` (`equip` / `unequip`, the catalog's equip targets, scene runtime and NPC equip state). Starfield's `BO64` (ARMO/ARMA carry no BOD2) puts the clothing layer in bits 0-31 and the spacesuit layer in bits 32-63, worn together, so SS BODY (35) and BODY (3) are different slots; `byroredux_plugin::equip::main_body_mask` is bit 3, or bit 35 on Starfield, and every other game's BMDT/BOD2/BODT widens losslessly. The NIF skin-partition masks stay `u32` (dismember parts are biped bits 0-31). A `u32` mask or `1u32 << bit` on an equip path, or folding the spacesuit bits onto the clothing ones, is the regression; the array serializes as exactly 64 entries, so a 32-slot save is refused (#6778 9405138e9, the `FORMAT_MAJOR` 129 bump; the SDK's inventory capture keeps all 64 slots too, #6918 8cfdea14a; `a_spacesuit_bit_and_a_clothing_bit_are_different_slots`, `the_64_slots_round_trip_and_a_32_slot_array_is_refused`). A script's `EquipItem` of a weapon (`PendingNonArmorEquips`, drained by `inventory::drain_script_weapon_equips`) toggles the player's carried row on through the menu's own `ToggleEquip` unless it is already wielded; another actor's request, a non-weapon and a weapon the player does not carry are logged and dropped (da95c875d). The Late dialogue selection runs before the gear reconcile (0d1c81b7b): a spoken line's result script equips (`player.equipitem VaultSuit21`), and its events must reach `equipment_appearance_system` before the end-of-Late cleanup drains them.
- M43 crafting (Skyrim `COBJ`; recipes and bench keywords installed per content load by `install_crafting` from `asset_provider/script.rs`): `craft` spends ingredients through `remove_items`, adds the product through `Inventory::add`, raises the Story Manager `CRFT` (bench `R1`, session location `L1`) and, at a forge only (`CraftingSmithingForge`/`Skyforge`; a smelter or tanning rack gives none), banks `smithing_xp` through `PendingSkillAdvances` — the `AdvanceSkill` path, not a direct AV write. `improve_item` (grindstone / armor table; UESP quality table in `smithing.rs`, 44 levels, gated by Smithing level, the material perk via `byroredux_scripting::tempering` and the enchanted-item recipe condition) splits ONE copy off its stack and gives it `ItemInstance { quality }`, so an improved item is never interchangeable with the rest. The instance-to-quality lookup is the one `smithing::stack_quality`, taking a COPIED stack: `improve_plan` copies its rows out before reading `ItemInstancePool`, since holding the `Inventory` guard across the pool read is the reverse of the save path's pool-then-Inventory order (#6561 3c9dca757). `armor::mitigate` (physical damage only) folds the quality bonus into the worn rating and reads the `ArmorModel` resource that `install_armor_book` installs from the profile's armor row (`CharacterRulesProfile`, `Some(ArmorModel::SKYRIM)` on Skyrim only; `fArmorScalingFactor`/`fMaxArmorRating`/… overlaid from the load order's GMSTs, cap 80 % by default — #6567 cb9faca7d; a `GameKind` test or armor const in the consumer is the regression), derives its skill coefficients from CHARAL's `LIGHT_ARMOR_RATING_COEFF` / `ARMOR_SKILL_RATING_COEFF_NPC` rather than restating UESP's numbers (#6568 a858df844), and is called from `combat_damage_system`; Fallout's DT/Resistance are CHARAL's. The numbers cite UESP in the module docs; only a doc-vs-code mismatch is a finding.
- Player body + mid-life gear (P3): `attach_player_body` builds a strictly visual body via `NpcSpawnJob` (`player_body` flag: no identity/inventory/AI/collider stamps; the capsule stays the only physics body).
