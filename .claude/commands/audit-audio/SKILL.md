# Audio Subsystem Audit (M44)

Read `.claude/commands/_audit-common.md` (delta-first scoping, dedup, finding format) and `_audit-severity.md` for shared protocol.

Audits `crates/audio/` (kira `0.12`, `default-features = false` with an explicit feature list in the workspace `Cargo.toml` — cpal, wav+pcm, ogg+vorbis, mp3, flac; 0.12 split container from codec features, so dropping a codec silently stops decoding (mp3 now carries Oblivion voice); `lib.rs` is now only the module docstring, the kira re-exports and glob re-exports of five modules (#6140 b2e542eee): `src/dsp.rs` (unit seam, reverb constants, underwater/reverb gates), `src/world.rs` (`AudioWorld`, `ActiveSound`/`SoundSource`, queue + music APIs), `src/components.rs` (`AudioListener`/`AudioEmitter`/`OneShotSound`/`Attenuation`), `src/system.rs` (`audio_system` and its per-frame steps, `build_spatial_track`), `src/cache.rs` (loaders, `SoundCache`, `VoiceSoundCache`, `with_start_delay`, `play_main_track`); plus `src/tests.rs` and `src/fuz.rs`, the `.fuz`/xWMA container reader and bounded ffmpeg bridge) and the engine systems that are the ONLY callers of its API. Orchestrator; one Task agent per dimension (max 3 concurrent). Verify the shipped surface against the `lib.rs` module docstring and `docs/feature-matrix.md` (Audio); if a module splits again, re-derive each dimension's paths first. The source-scan pins in `tests.rs` read `PRODUCTION_SOURCE`, a `concat!` of `lib.rs` and the five modules; `production_source_lists_every_module_file` fails when a new module file is not in it — otherwise every pin goes vacuous.

### Dim 1: Spatial Dispatch, Listener & the Unit Seam
**Paths**: `crates/audio/src/{system,world,dsp,components}.rs` (`dispatch_new_oneshots`, `drain_pending_oneshots`, `build_spatial_track`, `prune_stopped_sounds`, `sync_listener_pose`, `sync_emitter_positions` in `system.rs`; `ActiveSound`, `SoundSource`, `play_oneshot_following`, `stop_sounds_for` in `world.rs`; `bu_to_audio_space`, `linear_volume_to_db` in `dsp.rs`)
**First step**: `git log --since=D -- crates/audio/src/`
**Guards** (default lane): `tests.rs::{every_kira_position_site_goes_through_the_unit_seam, emitter_at_max_distance_in_bu_lands_on_max_distance_in_audio_space, drain_pending_oneshots_drains_in_place_instead_of_stranding_capacity, play_oneshot_queue_caps_at_max_pending_when_active, oneshot_marker_is_consumed_on_both_dispatch_failure_arms, with_start_delay_sets_the_start_time_and_shares_frames, play_oneshot_following_drops_on_inactive_audio, stop_sounds_for_is_a_no_op_on_a_headless_world}`; `#[ignore]`d device-gated `emitter_position_follows_the_source_entity_regression_3086` (#3086) and `anchored_voice_follows_survives_prune_and_stops` (#5410).
- Two dispatch paths stay observably equivalent: entity path (`OneShotSound`+`AudioEmitter` → per-emitter `SpatialTrackHandle`, `SoundSource::Emitter`, marker removed, `AudioEmitter` kept) and queue path (`PendingOneShot`, never loops: `play_oneshot` → `SoundSource::Detached`, or `play_oneshot_following` → `SoundSource::Anchored(entity)`, #5410 d1a7ee8c6). Both early-return without a listener id and build their sub-track through the one `build_spatial_track` (distance window, reverb send, underwater filter, kira sub-track; each loop keeps only its play tail and error policy, #5738 eac602644) — a loop that hand-builds the chain again is the regression. `stop_sounds_for(entity, fade_ms)` fades every playing `Emitter`/`Anchored` sound of the entity and drops its queued segments; its production caller is `dialogue_voice::stop_line_voice` (150 ms fade; `apply_selection`, `end_open_conversation`, `reconcile_dead_actor`, and ahead of each ObScript `Say` line in `scripted_line_voice_system`; #5432). The entity path has NO engine producer — `spawn_oneshot_at` is test/tooling-only, so its dispatch is exercised by `tests.rs` alone (#5612 81207d34d).
- `ActiveSound::track` is held for its Drop side effect AND carries the #3086 position pushes (renamed from `_track`; the track must still be kept alive): it must land in `active_sounds` before the helper returns. `Arc<StaticSoundData>` is shared, never deep-cloned; volume applies via `(*sound).clone().volume(db)`.
- `oneshots_requested` is a monotonic count of `play_oneshot` / `play_oneshot_following` calls **including headless discards** (incremented before the manager gate; read by `combat.status` in `commands/view.rs` for device-less smoke gates) — it proves a request, never audible playback.
- Producer queue caps at 256: both `play_oneshot*` entry points share one tail, `queue_oneshot` (#6160 3a50b3d5b), and through it one prologue, `oneshot_slot_ready` (#5738 eac602644). It bumps the request count, drops the request up front when the manager is `None`, and applies the `MAX_PENDING` FIFO cap with an O(1) `pop_front`; the manager-active gate precedes the drain; a drain of more than 32 warns once per tick (footstep tempo gone wrong). `linear_volume_to_db` is the single dB conversion (floor `SILENCE_DB` -60).
- Entity path reads post-propagation `GlobalTransform`, not `Transform`. World is Bethesda units (70/m), kira is metres: `bu_to_audio_space` is the only seam, applied to the listener pose and both dispatch paths; `Attenuation` is authored in metres (`min <= max`, `RangeInclusive`) and callers must never pre-scale by 70; `distance_range()` also guarantees `max > min` (a few ULPs), because kira's linear falloff is `(d - min) / (max - min)` and an equal pair (ObScript `PlayMusic`'s 1e9 sentinel, before it left the spatial path) gave a NaN gain that poisoned the whole mix and, through the reverb send's feedback, stayed alive after the track ended (#6207 b0586f285, `equal_attenuation_never_hands_kira_a_zero_span`). A missed site is silent (inaudible past ~43 cm, no log); `every_kira_position_site_goes_through_the_unit_seam` scans the listener sites, both dispatch paths and (since #5411, bb31c5fb3) the follow site, with a negative on raw `set_position`.
- Emitter follow (#3086, b4f08089b): `sync_emitter_positions` (pass 2, after the listener sync) pushes the sub-track of every `ActiveSound` whose `SoundSource::followed_entity()` is set (`Emitter` and `Anchored`) to its source's current `GlobalTransform` through the same `bu_to_audio_space`; change-gated on `ActiveSound::last_position` (seeded at dispatch on both paths) so a stationary emitter costs one compare and zero kira commands; `Detached` queue sounds and music are never touched; a despawned/transform-less entity is skipped (prune owns `Emitter` on emitter removal and `Anchored` on `GlobalTransform` loss — `orphaned_anchored_entity`, #5678 74d841165 — and `stop_sounds_for` owns the explicit `Anchored` stop). `AudioWorld::emitter_position_updates()` is the observable (kira has no position readback). The behaviour guards are `#[ignore]`d (device) — trace the code in the default lane.
- Listener: created lazily on the first frame an `AudioListener` has a resolved `GlobalTransform`; the handle is **sticky** (never cleared on despawn: kira listener capacity is 8, a clear/re-add loop exhausts it); a failed `add_listener` retries next frame; multi-listener warns once and uses the first. Pose uses `Tween::default()` (smooth follow); orientation is already renderer-space (no second Z-up conversion).
**Output**: `/tmp/audit/audio/dim_1.md`

### Dim 2: Send Graph: Reverb Send & Underwater Filter
**Paths**: `crates/audio/src/{dsp,world,system}.rs` (`AudioWorld::new`, `set_reverb_send_db`, `set_underwater` in `world.rs`; `apply_reverb_send`, `reverb_send_gate_open`, `apply_underwater_filter` in `dsp.rs`; `update_underwater_filters` in `system.rs`)
**First step**: `git log --since=D -- crates/audio/src/` (send/filter regions)
**Guards**: `tests.rs::{reverb_send_defaults_to_silent, reverb_send_gate_matches_silence_db_boundary, above_water_filter_state_is_a_dry_bypass, above_water_cutoff_never_reaches_the_kira_clamp_ceiling, both_dispatch_paths_build_the_filter_through_one_call_site}`.
- One global reverb send is created in `AudioWorld::new` from `REVERB_FEEDBACK`/`REVERB_DAMPING`/`REVERB_STEREO_WIDTH` (0.85/0.6/1.0). They have **no recorded provenance** and are not kira's defaults: flag the doc gap, never invent a rationale. `reverb_send: None` never cascades into an `unwrap()`.
- Send opt-in is build-time only (`with_send` at track construction, gated `is_finite() && > -60 dB`) and both paths use the shared helper. Default level `NEG_INFINITY` (dry). Playing sounds keep their construction-time level: the documented "next-dispatch knob" contract, not a bug — kira 0.12's `SpatialTrackHandle::set_send` could retarget an existing route, but the engine does not, and a track built while the send was muted has no route at all (doc corrected #5677 b0b9bc987; a live fader needs every track routed at `SILENCE_DB` from construction).
- Every spatial sub-track carries a low-pass built by ONE shared `apply_underwater_filter`; `update_underwater_filters` retargets live tracks when the listener's submersion changes. Above water is a genuine bypass via `Mix::DRY` (a default `FilterBuilder` is fully wet and colours the signal); the parked 20 kHz cutoff stays below kira's Nyquist clamp (beyond it the filter degenerates rather than turning transparent). `set_underwater` is written each frame by `water_audio_system` (Dim 5), before `audio_system`.
**Output**: `/tmp/audit/audio/dim_2.md`

### Dim 3: Streaming Music & SoundCache
**Paths**: `crates/audio/src/{world,cache}.rs` (`play_music`, `stop_music`, `is_music_active`, `play_script_music`, `stop_script_music` in `world.rs`; `load_streaming_sound_from_*`, `SoundCache`, `VoiceSoundCache`, `play_main_track` in `cache.rs`)
**First step**: `git log --since=D -- crates/audio/src/`
**Guards**: `tests.rs::{play_music_no_op_when_inactive, sound_cache_hits_are_case_insensitive_and_share_arc, sound_cache_get_or_load_invokes_loader_only_on_miss, sound_cache_clear_drops_entries_and_bytes_estimate_tracks_pcm_size, voice_cache_evicts_lru_under_byte_budget, voice_cache_negatives_are_capped_and_counted}`.
- Two music slots, one playback body (`play_main_track` / `stop_main_track`): the cell's `music` slot, `play_music(streaming_sound, volume, fade_in_secs, looping)` (4 parameters, `looping` since #3775; re-verify the arity before citing), crossfades any existing handle; and the scripted layer `script_music` (`play_script_music` / `stop_script_music` / `is_script_music_active`, #6226 567bfe593), a slot of its own because ObScript `PlayMusic` "will not stop the currently playing music of the cell". Music routes through the **main track**, never a spatial sub-track. `PlayMusic` used to decode the whole track to static PCM on the main thread (FNV stingers are 11-30 MB, uncached, even headless), play it as a Detached spatial one-shot at the listener's old spot (panning, reverb send, low-pass), never stop it on a cell change, and count it in `oneshots_requested`; the regression is any scripted music back on the one-shot queue. It uses `StreamingSoundData` (`from_cursor`/`from_file`), never `StaticSoundData` (full PCM decode = OOM on long tracks).
- `stop_music` fades for `fade_out_secs.max(0.0)` then drops the handle (an instant stop clicks); `is_music_active` goes false the moment `stop_music` returns (the slot is cleared while kira renders the fade tail): documented, so a caller must not read it as "audibly occupied".
- `SoundCache` keys lowercase once per entry point (`sound_archive_path` also drops a `Data\` game-root prefix that Skyrim.esm's pull-chain descriptors author); `clear()` never invalidates `Arc`s held by live `ActiveSound`s. **It is live since 2026-09-27**: inserted at boot (`boot/world.rs`), sampled by `ownership_sample.rs` (`len()` + `bytes_estimate()`), and its consumer is `combat_anim.rs::play_oneshot_cached` (three fixed combat paths; voice moved to `VoiceSoundCache`). M47.2's `scripted_sound_system` used to call it with script-chosen files — an open-ended key set on the unbounded cache; since #6281 (41b53ab41) every script sound (Papyrus `Sound.Play`, graph `SoundPlay.*`, ObScript `PlaySound`/`PlaySound3D`) goes through `play_oneshot_bounded`, which gates on `AudioWorld::is_active` before any archive work and decodes into `VoiceSoundCache`; a script path back on `play_oneshot_cached` is the regression. Footstep/splash loaders still bypass it into `FootstepConfig`/`WaterAudioConfig`. The map is `Option<Arc<_>>`: `None` is a **negative-cache** entry (loader returned no bytes, or decode failed) that `get_or_load` never re-probes and `len()`/`bytes_estimate()` exclude — so a sound missing at first use stays missing until `clear()`, which nothing in production calls (check whether the `--sounds-bsa` set can change at runtime). Still no eviction: a consumer keyed on open-ended paths (FOOT, REGN, per-NPC SFX) that lands on `SoundCache` is the finding.
- `VoiceSoundCache` (#5382, 8410ad1e5) is the open-ended-key cache, used only by dialogue voice: same `get_or_load` contract, LRU-evicted past `DEFAULT_BUDGET_BYTES` (64 MiB; the just-inserted entry is never its own victim), negatives capped at `VOICE_NEGATIVE_CAP` (4096; the set clears and re-probes past it) and counted (`negative_len`). Telemetry reports `voice_cache_{entries,bytes,negatives}` through `ownership_sample.rs`; the save registry allowlists it. A new open-ended consumer belongs here (or in its own bounded cache), not in `SoundCache`: dialogue voice and, since #6281, script sound plays (via `combat_anim.rs::play_oneshot_bounded`).
**Output**: `/tmp/audit/audio/dim_3.md`

Guards are `#[ignore]`d (Phase 1): trace the code.

A future CELL-level MUSC caller needs its own gate.
