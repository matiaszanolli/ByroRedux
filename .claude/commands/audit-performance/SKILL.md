# Performance Audit

Audit ByroRedux for CPU hot-path inefficiency, per-frame allocation churn,
draw-call/instancing waste, GPU memory pressure + eviction thrash, SSBO
sizing, and pipeline overhead.

**Architecture**: Orchestrator. Each dimension runs as a Task agent (max 3 concurrent).

See `.claude/commands/_audit-common.md` for project layout, methodology,
deduplication, context rules, path-reference convention, and finding format.
See `.claude/commands/_audit-severity.md` for the severity scale.
**Do not re-derive memory ceilings** — `docs/engine/memory-budget.md` is the
authoritative source for every SSBO size, LRU threshold, reserve floor,
deferred-destroy depth, and VRAM budget cited below. Cite it; don't transcribe.

Hardware target: **RTX 4070 Ti (12 GB) + Ryzen 7950X (16c/32t)**. RT VRAM
minimum is 6 GB. A CPU bottleneck on this machine is a **bug**, not a tuning
gap — the dimensions are ordered by per-frame impact accordingly.

## Parameters (from $ARGUMENTS)

- `--focus <dimensions>`: Comma-separated dimension numbers (e.g., `1,3,5`). Default: all 9.
- `--depth shallow|deep`: `shallow` = pattern scan only; `deep` = trace hot paths and quantify. Default: `deep`.

## Extra Per-Finding Fields

- **Dimension**: CPU Hot Paths | Draw & Instancing | GPU Memory Pressure | SSBO Sizing & Upload | GPU Pipeline | Skinning & BLAS | Streaming & Cells | NIF Parse | Telemetry & Origin Cost

## Bench-of-Record (do NOT hardcode numbers)

ROADMAP.md carries the **Bench-of-record** block (currently `R6a-stale-*`,
flagged in ROADMAP itself as ~100+ commits stale and not gating). **Never
copy FPS / frame-time / fence numbers into this skill** — they rot every
session and ROADMAP marks them stale. Instead: read the current ROADMAP
Bench-of-record + per-game compat table, run the bench described there, and
report **observed-vs-ROADMAP deltas**. A regression is a delta, not an
absolute. The canonical control benches named in ROADMAP are Prospector
(FNV, glass-heavy interior), WhiterunBanneredMare (Skyrim, steady-state),
and MedTekResearch01 (FO4, CSG-precombine-heavy).

  `geometry_rebuild_needs_idle` deciding when a chunk must serialize instead of

  reinstated single-frame rebuild is the regression.
- **Distant-LOD archive-presence probe is memoised** (#3385) — a per-placement
  archive probe was the cost.
- **Batched drains / batched `CellRoot` stamp / `touch_keys` allocation removal**
  (#3386 / #3388 / #3387), and the persistent-CELL stamp cursor (#3379) plus the
  skip of drain+rebuild when crossing identity is unchanged (#2369).
- **The `FxHash` conversion is finished** (#3051 closed the cluster; #3045 covered
  the skinning scratches) — the hot-path rule in `_audit-common.md` now has no
  known stragglers, so a `std::collections::HashMap` on a per-frame per-entity

- **`MorphSlot` eviction drains outside the `skin_compute` + `accel_manager`
  guard** (#3374).
- **`PackedStorage::clear_erased` releases capacity** and
  `SparseSetStorage::remove_entities_erased` early-outs (#2395/#2397) — both on
  the cell-unload path, so they pay per streaming cycle. `PackedStorage::
  remove_entities_erased` itself (a distinct function) got a further win under
  #3689: an in-place `swap`+`truncate` merge replaced the old two-fresh-Vec
  drain, avoiding a `2×live_rows` allocate-and-move per eviction call — same
  O(n) complexity, lower allocation cost. A finding that
re-proposes a landed fix is noise; a finding that the guard has eroded is real.
Each dimension lists its guards inline — confirm the cited symbol is present
before reporting anything in that area.

**dhat alloc-bound coverage is now wired** (#1381). `dhat` is a workspace dep
(`Cargo.toml`); the `byroredux` binary has a `dhat-heap` feature
(`byroredux/Cargo.toml`) installing the profiling allocator, and the NIF crate

`crates/nif/tests/heap_allocation_bounds_import.rs`. So allocation findings
on the NIF parse path are now *testable* — propose a bound, don't estimate.
The **gap** that remains: per-frame render/ECS hot paths have NO dhat coverage
(the profiler is a process singleton; the live engine loop is smoke-test

### Dimension 1: CPU Per-Frame Allocations & Hot Paths
The highest-impact surface: a 16-core Ryzen should never be the bottleneck.
**Entry points**: `byroredux/src/systems/animation.rs` (`animation_system`, `transform_propagation_system`), `byroredux/src/systems/bounds.rs` (world-bound propagation), `byroredux/src/systems/billboard.rs`, `byroredux/src/systems/particle.rs` (`apply_emitter_params`), `byroredux/src/render/particles.rs` (`emit_particles`, the per-frame hot loop), `byroredux/src/render/mod.rs` (`build_render_data`), `crates/core/src/ecs/packed.rs` (dirty-set drain), `crates/core/src/ecs/resources/skin_slot_pool.rs` (`SkinSlotPool` bone pool)
**Checklist**: Per-frame `Vec`/`HashMap`/`String` allocations that should reuse a persistent scratch; `collect()` into a fresh Vec where `clear()+extend` would do; capacity churn from `mem::take`; per-entity allocation inside a per-frame loop.
**Session 46 guards (verify intact, do NOT re-propose)**:
- `PackedStorage::drain_dirty_into(&mut self, out: &mut Vec<EntityId>)` (#1371, `crates/core/src/ecs/packed.rs`) drains into a caller-supplied buffer via `Vec::append`, preserving `self.dirty` capacity. `take_dirty` (the `mem::take` path) zero-capacities and forces 0→N regrowth every frame — its use in `transform_propagation_system` / world-bound propagation is the regression pattern. Guard test: `drain_dirty_into_preserves_storage_capacity`.
- `make_animation_system()` (#1372) captures two persistent scratch Vecs (`entities_scratch`, `playback_scratch`) reused via clear+extend; `make_billboard_system()` (#1374) captures `last_cam` and skips the whole `get_mut` loop when the camera hasn't moved (re-arming `GlobalTransform`'s `TRACK_CHANGES` dirty set every frame was defeating incremental bounds). Re-introducing per-frame `collect()` / unconditional billboard writes is the regression.
- `build_debug_ui_snapshot` deep-clone (2× BTreeMap + Vec<String>) is gated on `debug_ui … visible` (#1376) — boot-default hidden = ~0 cost. A path that clones unconditionally regresses normal play.
- Bone pool `next_slot` contracts after the idle-slot sweep (#1379, `SkinSlotPool` in `crates/core/src/ecs/resources/skin_slot_pool.rs`): `free_list` is sorted and tail-popped while the largest free slot == `next_slot-1`, so `max_used_slot()` (the bone_world copy size + skin dispatch count) shrinks when a high-NPC scene unloads to a low-NPC one. A sweep that never contracts the issued range regresses steady-state cost after cell unload.
- **`bone_world` steady-state reuse (#1794, `byroredux/src/render/mod.rs` + `render/skinned.rs`)**: `bone_world` is no longer `.clear()`'d per frame; the resize only identity-fills genuinely new tail slots and truncates on shrink. A reintroduced unconditional `.clear()` regresses to a full `MAX_BONES_PER_MESH`-stride identity-fill every frame regardless of dirty state.
- **Dead-probe removal (#1803)**: `emit_particles` no longer acquires a `GlobalTransform` query it never reads (particle positions come from `em.particles.positions`). Reintroducing an unused query+`get()` per emitter/frame is the regression.
**Output**: `/tmp/audit/performance/dim_1.md`

### Dimension 2: Draw-Call & Instancing Efficiency
**Entry points**: `byroredux/src/render/mod.rs` (`build_render_data` @827, `draw_sort_key` @547), `byroredux/src/render/static_meshes.rs` (draw enumeration), `crates/renderer/src/vulkan/context/draw.rs` (the per-instance `GpuInstance` build loop, split out into `crates/renderer/src/vulkan/context/build_and_upload_instances.rs`)
**Checklist**: Sort-key effectiveness — `draw_sort_key` returns a 12-tuple `(u8,u8,u8,u8,u32×8)` ordering by pipeline/material/texture before depth (the 4th `u8` is the #3797 `no_sorter` NiAlphaProperty flag); verify it actually minimizes pipeline + descriptor-set rebinds in the draw loop. Since #3663, the opaque branch's depth slot carries `opaque_depth_bucket(cmd.sort_depth)` (top bits only, via `OPAQUE_DEPTH_BUCKET_BITS`), not the raw depth — a reversion to raw depth reintroduces camera-driven sort-key churn every frame. Draw-call-count vs entity-count ratio (the compat table reports both per cell). Instanced batching — same mesh + multiple transforms should collapse, not emit N draws. Push-constant / per-draw state churn (`cmd_set_depth_bias` on every draw?). The parallel-sort gate: `sort_draw_commands` switches the raster prefix to `par_sort_unstable_by_key` only at `DRAW_SORT_PARALLEL_THRESHOLD` = 3000 commands (`render/mod.rs` ~742); verify the threshold against the `bench_draws_raster_cmds` column of `.claude/audit-baselines/runtime/*.tsv` (#3660), because `bench_draws_cmds` also includes RT-only occluders that never enter the sorter. A too-low gate pays rayon spin-up on small cells, too-high starves big exterior grids; the crossover table in `render/mod.rs` is the evidence, not cell-count folklore. **GT-presence hoist guard (#1377)**: the static-mesh loop does `if tq.get(entity).is_none() { continue; }` before the vis/wb sibling probes — dropping the hoist re-pays two SparseSet gets per GT-less entity. **Two-sided blend split gate (#1804 / #2165)**: `needs_two_sided_blend_split(&DrawBatch)` (`crates/renderer/src/vulkan/context/draw.rs`) is `is_blend && two_sided && order_dependent_glass`. It has had **no `z_write` limb since #2165** — that spelling was removed deliberately, because FO4 BGEM glass is commonly authored `z_write == false` and the proxy excluded the very population the split exists for. The regression to watch for is a split reappearing on **non-`order_dependent_glass`** batches (the #2165 particle case), NOT on non-depth-writing ones. Note also that the predicate is structurally dormant for engine-classified glass — `collect_static_mesh_draws` clears `two_sided` for `MATERIAL_KIND_GLASS` upstream — so split-related items here are unfalsifiable on real content and must not be used to attribute batch-count movement (#2691).
**Output**: `/tmp/audit/performance/dim_2.md`

### Dimension 3: GPU Memory Pressure & Eviction Thrash
**Entry points**: `crates/renderer/src/vulkan/acceleration/predicates.rs` (`compute_blas_budget` @707), `crates/renderer/src/vulkan/acceleration/blas_static.rs` (LRU eviction), `crates/renderer/src/texture_registry.rs`, `crates/renderer/src/mesh.rs` (vertex/index pool caps), `byroredux/src/asset_provider/material.rs` (BGSM/BGEM cache), `crates/renderer/src/deferred_destroy.rs`
**Checklist** (ceilings: `docs/engine/memory-budget.md`): BLAS budget is **dynamic** — `device_local_bytes / 3` floored at `MIN_BLAS_BUDGET_BYTES` (256 MB) via `blas_budget_bytes`; eviction runs pre-batch + mid-batch at 90% budget, check interval `BATCH_EVICTION_CHECK_INTERVAL` = 64 builds. **Do NOT cite a static "1 GB" figure — that's stale doc.** **Mid-batch eviction (regression guard, #1792)**: `evict_unused_blas`'s gate now routes through the `blas_over_budget` predicate (`predicates.rs`), which folds in the batch's own `pending_bytes` — the pre-fix gate compared `static_blas_bytes` alone, blind to `pending_bytes`, making mid-batch eviction structurally a no-op. Two further gaps are documented-not-fixed (#1793, cross-linked from `/audit-renderer` Dim 1): a permanently-missing rigid BLAS has no recovery path, and a synchronous multi-cell burst can false-evict a not-yet-drawn entry — both unreachable on the 12 GB dev card; don't re-discover as new. Verify LRU (smallest last-used tick = victim) evicts smoothly during streaming with no rebuild thrash. Scratch high-water: `shrink_blas_scratch_to_fit` / `shrink_tlas_to_fit` reclaim at cell-unload with `BLAS_REBUILD_SLACK_BYTES`/`TLAS_*_SLACK_BYTES` headroom — verify they don't shrink below the reserve floors (`MIN_TLAS_INSTANCE_RESERVE` / `WORKING_SET_FLOOR` = 8192). `MeshRegistry` soft/hard caps (`VERTEX_POOL_*`, `INDEX_POOL_*`) emit warn/error via `check_pool_growth()` per upload — confirm caps fire, not silent overrun. BGSM/BGEM cache uses **half-eviction** (#1430, drop oldest N/2 via insertion-order `VecDeque`), NOT full flush — a full-flush path reintroduces the cold-restart thundering herd. `NifImportRegistry` 2048-entry LRU (`BYRO_NIF_CACHE_MAX`) bounds scene count. Deferred-destroy countdown = `MAX_FRAMES_IN_FLIGHT` (2); freeing earlier writes in-flight GPU memory (CRITICAL).
**Output**: `/tmp/audit/performance/dim_3.md`

### Dimension 4: SSBO Sizing & Per-Frame Upload
**Entry points**: `crates/renderer/src/vulkan/scene_buffer/constants.rs` (all `MAX_*`), `crates/renderer/src/vulkan/scene_buffer/upload.rs` (`upload_instances` @680, lights/camera/bones/materials/indirect), `crates/renderer/src/vulkan/material.rs` (MaterialBuffer dedup), `byroredux/src/material_translate.rs` (`translate_material` @471), `crates/core/src/ecs/components/material.rs` (`resolve_pbr` @1275)
**Checklist** (sizes: `docs/engine/memory-budget.md`): Scene SSBOs are resident, double-buffered (~223–225 MB total per `memory-budget.md`'s own resident-buffer total and VRAM-budget table — cite the doc's current figure, don't hardcode this one either). `MAX_INSTANCES` = `0x40000` (262 144); `MAX_INDIRECT_DRAWS` is aliased to it; `MAX_MATERIALS` = 16 384. Per-frame upload size must be **O(live data)** not O(capacity) — a full-capacity memcpy of a near-empty buffer is the waste. Host-visible mapped writes: flush correctness + no redundant re-upload of unchanged data. Material dedup ratio — N placements of one material → 1 `GpuMaterial`; report dedup hit-rate per cell; `MaterialTable::intern` must be O(1) amortized; upload size O(unique materials) not O(draws).
**R1 + NIFAL guards (verify, do NOT re-propose)**:
- `GpuInstance` is 160 B (112 B at R1, down from ~400 B legacy; #2219 added an 8 B skinned-vertex-buffer GPU address + 8 B padding for 128 B, then #3231 added the morph-target delta/weight buffer addresses + target count for 160 B) carrying per-DRAW data only; per-material fields read through `materials[material_id]` in the shader. Guards: `gpu_instance_is_160_bytes_std430_compatible`, `gpu_instance_field_offsets_match_shader_contract`, `gpu_instance_does_not_re_expand_with_per_material_fields` in `crates/renderer/src/vulkan/scene_buffer/gpu_instance_layout_tests.rs`. A drift here is HIGH (shader-contract lockstep). As of #3661 the morph *delta* allocation itself is shared/deduped per-mesh via `Arc<MorphDelta>`/`VulkanContext`'s `morph_delta_cache` (first instance of a mesh uploads once, later instances `Weak::upgrade` the cached `Arc`) — only the small per-entity weight buffer remains truly per-instance; the `GpuInstance` fields and 160 B size are unaffected. `GpuLight` got the same lockstep treatment under #3763: it's 64 B (`gpu_light_is_64_bytes`) with a second Rust↔GLSL leg in `gpu_light_glsl_copies_stay_in_lockstep` (both in `crates/renderer/src/vulkan/scene_buffer/{gpu_instance_layout_tests,shader_contract_tests}.rs`) — a Rust-only field append/reorder now fails that test, not just a GLSL-mirror-vs-mirror drift.
- PBR resolved ONCE at import: `Material::metalness`/`roughness` are plain `f32` (not `Option` + per-draw classify), populated by `Material::resolve_pbr` after `translate_material`. The draw loop must NOT re-enter `classify_pbr_keyword` (`crates/core/src/ecs/components/material.rs` @1008) per draw. Regression pattern: per-draw keyword scan, or reading metalness/roughness as `Option`. See `/audit-nifal` for the single-boundary contract.
- **Dirty bone-slot upload (#3665)**: `upload_bone_worlds` (`upload.rs`) no longer memcpys/flushes/copies the whole bone-world range every frame — it takes a `dirty_slot_offsets` iterator sourced from `pose_dirty` (the same `FxHashSet<EntityId>` gating Dim 6's skin-dispatch dirty check) via a per-slot dirty/written byte state (`bone_world_slot_states`, `bone_world_slot_needs_copy`), and stages+records `vk::BufferCopy` regions only for those slots. Per-frame bone-world upload cost must be O(dirty slots), not O(all skinned bones); a reintroduced full-range copy is the regression.
**Output**: `/tmp/audit/performance/dim_4.md`

### Dimension 5: GPU Pipeline & Pass Efficiency
**Entry points**: `crates/renderer/src/vulkan/context/draw.rs` (`draw_frame`), `crates/renderer/shaders/triangle.frag`, `crates/renderer/src/vulkan/volumetrics.rs` (M55), `crates/renderer/src/vulkan/bloom.rs` (M58), `crates/renderer/src/vulkan/svgf.rs`, `crates/renderer/src/vulkan/taa.rs`, `crates/renderer/src/vulkan/composite.rs`, `crates/renderer/src/vulkan/ssao.rs`
**Checklist**: Per-pass dispatches must be O(pixels) / O(froxels), never O(meshes). Volumetrics froxel grid (`volumetrics.rs`: `froxel_extent` is resolution-derived — render extent / `froxel_xy_divisor` × `froxel_z_slices`, NOT a fixed grid; read the live defaults from `upscaling.rs::VolumetricsConfig::default`; inject+integrate, single-ray TLAS shadow per froxel) must not scale with mesh count. Bloom pyramid (`bloom.rs`: 5 down + 4 up mips, 4-tap bilinear box) pure O(pixels). TLAS rebuild-vs-refit frequency + AS barrier placement (missing build→read barrier is HIGH). G-buffer bandwidth (7 attachments × 2 FIF — normal, motion, mesh_id, raw_indirect, albedo, reactive, transparency; #1583/#1590 retired the ReSTIR reservoir attachment 7→6, then `f6d10838` added the FSR reactive + transparency masks 6→7). Disney BSDF lobe ALU now lives in `crates/renderer/shaders/include/pbr.glsl` (split out of `triangle.frag`) — verify lobes aren't evaluated for fragments that never reach them. **Legacy WRS compile-time gate (regression guard, #1799)**: the legacy 16-slot reservoir arrays (`resLight`/`resWSel`) only exist in `triangle.frag` when `ENABLE_LEGACY_WRS` is set (shipped default 0, gated in `shader_constants_data.rs`/`build.rs`) — previously declared unconditionally even though `useRestir` gated every read/write at runtime, so the compiler couldn't prove them dead and paid register/LDS cost on ~100% of frames taking ReSTIR. Verify the shipped `triangle.frag.spv` is built at the default; a build flipping it back to 1 taxes every production frame again. Streaming-RIS shadow reservoir loop count — verify `NUM_RESERVOIRS` in `crates/renderer/shaders/triangle.frag` (only compiled when `ENABLE_LEGACY_WRS=1`; NOT `lighting.glsl`, which only mentions it in a comment) against its `GpuLight` cost; a bumped count doubles divergence. `inv_vp` is computed once on the CPU and passed via UBO (cluster cull + SSAO read it) — a shader-side per-invocation `inverse()` (~100 ALU) is the regression. **Depth-history copy is gated, not unconditional (#3667)**: `scene_has_effect_soft_material` (`byroredux/src/render/mod.rs`) scans loaded `Material`/`ParticleEmitter` components for the `EFFECT_SOFT` flag; `draw_frame` only calls `copy_depth_to_history` (and pays its layout-transition barriers) when that's true, and the copy is now GPU-timed (`cmd_depth_history_copy_start/end`, see Dim 9). A copy running every frame regardless of scene content is the regression. **Speculative-Vulkan caveat**: render-pass / barrier / pipeline-state findings whose failure mode is invisible to `cargo test` need RenderDoc evidence or a revert plan, not speculation — flag confidence explicitly.
**Output**: `/tmp/audit/performance/dim_5.md`

### Dimension 6: Skinning & BLAS Cost (M29.x)
**Entry points**: `crates/renderer/src/vulkan/skin_compute.rs`, `crates/renderer/shaders/skin_palette.comp`, `crates/renderer/shaders/skin_vertices.comp`, `crates/renderer/src/vulkan/acceleration/blas_skinned.rs` (refit), `crates/core/src/ecs/resources/skin_slot_pool.rs` (`SkinSlotPool`: the `pose_dirty` `FxHashSet`, `try_mark_pose_dirty`, `clear_pose_dirty`), `byroredux/src/render/skinned.rs` (per-frame mark/clear call sites)
**Checklist + guards (verify, do NOT re-propose)**:
- Bone-palette multiply runs as a dedicated compute pass (`SkinPaletteComputePipeline`, M29.5), not inline per skinned-vertex. `bind_inverses` is a **persistent** SSBO with a per-entity slot pool (M29.6) — uploaded ONCE at first-sight; per-frame upload size must be O(first-sight entities), not O(all skinned).
- **Dispatch-dirty gate (#1195)**: skin dispatch is skipped when the bone-pose hash (FNV-1a over the bone-world slice) matches last frame. The dirty set is `pose_dirty: FxHashSet<EntityId>` on `SkinSlotPool` in `crates/core/src/ecs/resources/skin_slot_pool.rs` (NOT the renderer layer; std `HashSet` here was converted under #2923 and must stay Fx — see `_audit-common.md` → Hot-path hashing); marked/drained via `try_mark_pose_dirty`/`clear_pose_dirty`; call sites in `byroredux/src/render/skinned.rs` (`clear_pose_dirty` before the dispatch loop, `try_mark_pose_dirty` inside). Regression: a path that bumps `dispatches_total` without consulting `pose_dirty.contains(entity)`. First-sight invariant: `SkinSlot.has_populated_output` is false until the first dispatch flips it — the gate MUST NOT skip before that flip.
- **BLAS refit gate (#1196)**: `refit_skinned_blas` skips on `built_this_frame.contains(&entity_id) || (has_populated_output && !is_dirty && accel.has_skinned_blas(entity_id))` — the first disjunct covers an entity whose BLAS build ran earlier this same frame (#1812), the rest is first-sight/skip-safety as before. Refit must dominate; full rebuild only on bone-count change or after `SKINNED_BLAS_REFIT_THRESHOLD` (600) **plus a deterministic per-entity `SKINNED_BLAS_REFIT_JITTER` (60)** — `skinned_blas_refit_limit(entity_id)` (`predicates.rs`) computes `SKINNED_BLAS_REFIT_THRESHOLD + entity_id % SKINNED_BLAS_REFIT_JITTER`, staggering a moving cohort's rebuilds across a 600–659-frame window instead of a single flat cliff every entity hits on the same frame (#3669). A reversion to one flat threshold shared by every entity is the regression. `SKINNED_BLAS_FLAGS` is deliberately `FAST_BUILD` not `FAST_TRACE` (memory-budget.md: +15.8 FPS on Prospector) — flipping it back is a regression.
- **Descriptor-rewrite skip (#1197)**: `vkUpdateDescriptorSets` for the skin dispatch is skipped when the (input, palette) pair matches `SkinSlot.descriptor_bindings[frame]`; steady-state target is 0 writes after warm-up.
- **Instrumentation**: per-pass GPU timer + `dispatches_skipped` on `SkinCoverageFrame` (#1194) — reachable via `bench-stats --break-down skin` / `skin.coverage` (byro-dbg). A fourth timer bracket, "skin palette" (#3676, `cmd_skin_palette_start/end` in `gpu_timers.rs`, surfaced as `GpuTimerSnapshot.skin_palette_ms`), covers the bone-world/bind-inverse device-local transfer commands + `skin_palette.comp` dispatch specifically (opened at the first of bone-world copy / first-sight bind_inverses upload / the palette dispatch itself, closed after the dispatch) — distinct from the whole-pass "skin dispatch" bracket. Dispatch-count findings can be **quantified, not estimated**.
- **Early-return rollback (regression guard, #1791/#1796, extended by #3569)**: `ctx.skin_dispatch_ran` must be checked after every `draw_frame` return — `draw_frame`'s two early-return guards (empty framebuffers, `ERROR_OUT_OF_DATE_KHR`) used to leave `SkinSlotPool`'s CPU-side commits (pose-hash baseline, first-sight `bind_inverses` drain) irrevocably applied even though the GPU dispatch never ran, freezing RT skinned output/BLAS geometry for N+ frames and permanently corrupting a first-sight entity's skin palette on a resize. `byroredux/src/app_frame.rs` (`render_one_frame` — moved out of *main.rs* by the #2731 split) resets `skin_dispatch_ran` before both guards and sets it true only in `record_skinned_blas_refit`; a bailed frame must roll back the pose-hash commit and requeue drained first-sight `bind_inverses`. #3569 closed a gap in that same rollback: `record_skinned_blas_refit` used to set `skin_dispatch_ran = true` even when the first-sight `bind_inverses` upload itself failed (host-visible map/flush error), so the rollback never fired and the already-drained entries were lost for good. The gate is now `!ctx.skin_dispatch_ran || ctx.bind_inverse_upload_failed` — a new latch set only in `upload_pending_bind_inverses`'s error arm and reset alongside `skin_dispatch_ran` each frame. The scope guard is `skin_dispatch_ran_rollback_scope_tests` in `byroredux/src/app_frame.rs`, which asserts the rollback check comes *after* the dispatch call; `bind_inverse_upload_failed_rollback_tests`/`bind_inverse_upload_failure_latch_tests`/`bind_inverse_upload_failed_reset_tests` cover the #3569 latch specifically.
- **Known, documented-not-fixed throughput ceiling (#1797)**: every skinned BLAS build/refit in a frame shares one `blas_scratch_buffer`, so the required serialize barrier fully serializes N dirty entities — a real ceiling on moving-crowd frames, deliberately left unfixed pending measurement via `skin.coverage`/`gpu_skin_blas_refit_ms`. Quantify via those hooks before proposing a fix; do not re-report as an unaddressed finding.
**Output**: `/tmp/audit/performance/dim_6.md`

### Dimension 7: World Streaming & Cell Transitions (M40)
**Entry points**: `byroredux/src/streaming.rs` (+ `streaming_tests.rs`), `byroredux/src/streaming_helpers.rs` (`drain_streaming_state` + `consume_streaming_payload`), `byroredux/src/cell_loader/unload.rs` (`unload_cell`/`unload_cells`, `UnloadPhaseTimings`), `byroredux/src/cell_loader/transition.rs` (boundary cross), `byroredux/src/cell_loader/precombined.rs` (FO4 XCRI/XPRI), `byroredux/src/cell_loader/nif_import_registry.rs`, `byroredux/src/npc_spawn.rs`, `crates/sfmaterial/src/reader.rs` (Starfield CDB)
**Checklist + guards**: Cell-transition stall budget (frame-time spike at boundary cross). `pre_parse_cell` is a two-phase pipeline: serial header extract feeds a rayon-parallel body parse (#877) — collapsing the phases regresses cell-stream latency ~6–7× on FNV/SE exterior grids. Small-batch serial fast-path (#1262) skips rayon overhead below a batch-count threshold (`PRE_PARSE_RAYON_MIN` = 8 extracted NIFs) inside `pre_parse_cell` — verify intact. **Cross-request batch dedup (#3670)**: the pre-parse worker (`cell_pre_parse_worker`) now keeps a `batch_keys: HashSet<String>` memo across an already-queued run of `LoadCellRequest`s (drained via `recv_next_batch_request`, which uses `try_recv` to detect an empty backlog and clear the memo before the next blocking `recv`) — a NIF already produced for an earlier request in the same dispatch is skipped for a later one instead of being re-parsed, telemetered as `worker_batch_duplicate_skips`/`StreamingWorkerTimings::batch_duplicate_skips`. This closes the gap the frozen per-request cache snapshot left; a regression would show as duplicate parses of the same key within one dispatch burst. **NIF mesh import moved to the worker thread (#3672)**: `finish_partial_import` (`cell_loader/partial.rs`) no longer calls `import_nif_with_collision_and_resolver` on the main thread — the streaming worker now does the full mesh/collision import (via `PartialNifImport::meshes`/`collisions` plus a worker-local `StringPool`), and the main-thread drain only re-interns the already-imported meshes' string handles into the process-wide pool (`reintern_imported_meshes`). A regression is mesh import work reappearing on the main-thread drain path. NIF import cache hit-rate during streaming (cached across cells, not per-cell churn). BLAS LRU evicts smoothly under the dynamic budget (Dim 3) with no thrash. Shutdown drain joins the worker without leak. CDB parsed/indexed **once** per archive load (O(1) lookup), never per-cell or per-material. Multi-cell exterior grid is M40 follow-up; the single-cell baseline must not regress. **NPC-spawn cost now measured (#1798)**: interior-cell NPC spawning (`load_references`) had no throttle and no timing to show its cost — `npc_spawn_wall` is now surfaced in the end-of-cell summary log (`byroredux/src/cell_loader/references/mod.rs`); cite it rather than estimating the stall. The **exterior** path since gained a real sub-cell budget: `STREAMING_APPLY_BUDGET` (live value and rationale in `byroredux/src/app_step.rs`) seeds a `FrameTimeBudget` (`byroredux/src/cell_loader/work_budget.rs`) that `load_references_budgeted` yields against between placements and between an NPC's sub-NIFs. **The interior door-transition path now uses it too (#3671)**: `step_cell_transition` retains an App-owned `InteriorCellApplyJob` cursor (`byroredux/src/cell_loader/load.rs`) between frames — `begin()` does the atomic ESM-parse/precombined/water prefix, then `advance()` calls `references::load_references_budgeted` against the same `STREAMING_APPLY_BUDGET`-seeded `FrameTimeBudget` as the exterior path, yielding between placements and NPC sub-NIFs; a newer transition or shutdown cancels an unfinished job via `InteriorCellApplyJob::cancel` → `unload_cell`, reclaiming its partial cell. The one-shot entry points — `load_cell_with_masters`, still used by boot (`--cell`), save-load restore, and debug loads — remain unbudgeted (`FrameTimeBudget::unlimited()`); that's a one-time paid cost analogous to the exterior bootstrap path, not a live per-frame gap, so it is out of scope for this finding. **Batched exterior teardown (2026-08-05, `app_step.rs` `step_streaming` — verify intact)**: a boundary crossing now unloads its whole eviction ring (normally 3 cells) through `cell_loader::unload_cells`, which per-cell releases ownership/GPU/physics state as before but runs the global `world.shrink_storages()` + `shrink_blas_scratch_to_fit` compaction **once** after the last victim instead of once per cell — repeating those global passes per cell was the boundary-hitch multiplier this closed. The per-cell victim despawn itself routes through `World::despawn_batch`, which sorts+dedups the victim `Vec` once and hands it to `PackedStorage::remove_entities_erased` — a single sorted-merge pass over `entities`/`data` (O(n)), not a per-entity `Vec::remove` loop (which is the quadratic regression pattern at exterior-teardown scale, tens of thousands of rows; #3689 further replaced that pass's two-fresh-Vec drain with an in-place swap+truncate, cutting its allocation cost without changing the O(n) shape). `UnloadPhaseTimings` (ownership index / handle collection / GPU release / owned-state release / despawn / finalization) wraps each phase in a plain CPU `Instant::now()`/`elapsed()` pair, not a GPU timestamp query (contrast Dim 9) — negligible per-call cost, so no gating is needed or present; it only accumulates into `StreamingTelemetry` while a boundary sample is active, keeping the aggregate bounded like the pre-existing `StreamingLatencySummary` fields. This phase-timing plumbing is wired only on the `app_step.rs` exterior batch path today — the single-cell `unload_cell` call sites (`cell_loader/transition.rs` door/interior swaps via `unload_current_interior`, `cell_loader/exterior.rs` bootstrap) still discard their timings (`let _ = unload_cell_inner(...)` inside `unload_cell` itself); the `app_events.rs` shutdown sweep (moved out of *main.rs* by the #2731 split) now calls the *batched* `unload_cells` over every resident cell rather than the single-cell fn, and likewise discards its returned `UnloadPhaseTimings` by not binding it. That's not a bug by itself, but a finding proposing to *reuse* those timings for an interior-transition budget needs new wiring, not an assumption it already exists.
**Output**: `/tmp/audit/performance/dim_7.md`

### Dimension 8: NIF + ESM Parse Performance
**Entry points**: `crates/nif/src/stream.rs` (`allocate_vec`, `read_pod_vec`), `crates/nif/src/import/`, `crates/nif/src/blocks/`, `crates/nif/src/import/walk/mod.rs` (`extract_emitter_params`, `extract_emitter_rate`), `byroredux/src/streaming.rs` (`pre_parse_cell`), `crates/plugin/src/esm/records/mod.rs` (`parse_esm_with_load_order`)
**Checklist + guards (now dhat-testable — propose bounds)**:
- Bulk-array readers go through `read_pod_vec<T>` to collapse double-allocation (#833); direct allocate-then-loop-fill is the regression. The helper has a big-endian compile-error gate (bytemuck is NOT a workspace dep, despite some audits claiming it).
- `stream.allocate_vec::<T>(n)?` is `#[must_use]` (#831); bound-check call sites that discard the empty Vec are the no-op pattern it fixed.
- Per-block parse counters use `entry().get_mut()/insert` split, NOT `or_insert(name.to_string())` (#832) — the to_string path leaked ~150 KB/cell of throwaway short strings on Oblivion.
- Verify typed particle blocks (`NiPSysEmitter*`) parse during import only — `extract_emitter_params`/`extract_emitter_rate` are a one-time import-side walk, not re-walked per frame (the per-frame side lives in Dim 1). These feed the NIFAL canonical tier — see `/audit-nifal`.
- Allocation findings here CAN be bounded by a dhat test (see Regression-Guard Posture); the existing bounds cover the node + geometry + particle parse paths (`crates/nif/tests/heap_allocation_bounds.rs`, `heap_allocation_bounds_geometry.rs`) plus, since #3673, the import path (`heap_allocation_bounds_import.rs`). Propose extending them for new alloc sites rather than estimating.
- **Skinning parse buffers reserved up front (#3691)**: `crates/nif/src/blocks/skin.rs` + `crates/nif/src/import/mesh/sse_recon.rs` now `Vec::with_capacity`/`reserve` the skin-weight/bone-index scratch before filling it, instead of growing it via repeated pushes — covered by new bounds added to `heap_allocation_bounds.rs`. A reintroduced grow-by-push loop on these paths is the regression.
- **ESM parse cost (#3729)**: `parse_esm_with_load_order` is on the critical path of the first cell load, entirely single-threaded per plugin. 2026-08-30 measurements: `Oblivion.esm` 265 MB/1.41s, `Fallout3.esm` 275 MB/1.23s, `FalloutNV.esm` 234 MB/1.17s, `Skyrim.esm` 238 MB/1.27s, `Fallout4.esm` 315 MB/1.69s, `SeventySix.esm` 880 MB/3.41s — a vanilla FO4 load order (base + 7 DLC) is ~2.6s before the first cell can load. Each plugin's `FormIdRemap` is computed from its header alone, before the record walk, and `merge_from` is the only join point between plugins — parallel per-plugin parsing is architecturally possible but **not implemented**; a finding proposing it must design around `merge_from`'s ordering semantics (#3403, #3384) and add a byte-identical-`EsmIndex` regression test, not just parallelize and hope. Cite the measured table above rather than re-measuring from scratch.

### Dimension 9: Telemetry & Camera-Relative Origin Cost
**Entry points**: `crates/renderer/src/vulkan/gpu_timers.rs` (`GpuPerFrameTimers`, `GpuTimerSnapshot`), `crates/core/src/ecs/resources/mod.rs` (`ScratchTelemetry`), `byroredux/src/render/camera.rs` (`assemble_camera`, render-origin snap), `crates/renderer/src/vulkan/context/build_and_upload_instances.rs` (per-instance model rebase via `rebase_model_matrix`, shared with `origin_corrected_prev_view_proj` in `context/draw.rs`)
**Checklist**:
- **GPU-side timing**: `gpu_timers.rs` exposes per-pass `cmd_*_start/end` timestamp pairs (main render, skin dispatch, skin palette, BLAS refit, TLAS build, TAA, SVGF, SSAO, bloom, composite, cluster cull, caustic splat, volumetrics, upscale, presentation, depth-history copy) read back via `read_and_reset` into a `GpuTimerSnapshot`. Findings that claim a pass is "expensive" should cite these timers (reachable via `bench-stats`), not guess. Verify timers don't introduce a per-frame stall (timestamp query readback must use the prior frame's results, not block on the current).
- **CPU per-phase wall-clock breakdown (#ec81f233)**: `log_stats_system` (`byroredux/src/systems/debug.rs`) emits a once-a-second `cpu_ms:` line splitting the frame into `fence_wait` / `acquire` / `submit_present` / `ssbo_build` / `geom_rebuild` / `tlas_build` / `cmd_record` / `rof_*` / `atw_pre` / `atw_scheduler` / `atw_post` / `between_frames` (#3692). The buckets nest, not sum — `atw_post` ⊇ `atw_pre`/`atw_scheduler`'s sibling work, `rof_post_draw` ⊇ the remainder of `render_one_frame` after `rof_pre_draw`/`rof_draw_call` close — except `between_frames`, the one bucket NOT nested inside another printed field: it's the gap outside `render_one_frame` entirely (compositor throttling, Wayland frame-callback wait, event-loop sleep), captured at the frame's true start since #3674 so it no longer double-counts this frame's own `rof_*` work. This is the **measurement that classifies a multi-second frame** instead of guessing: large `fence_wait` ⇒ GPU hung on a prior submit; large `atw_scheduler` with `fence_wait≈0` ⇒ pure CPU stall; large `atw_post` ⇒ cell-load upload cost (`step_streaming` + uploads); large `between_frames` with everything else small ⇒ the frame isn't the engine's fault at all. Cite this split when attributing a CPU stall to a phase; the debug build is too slow to stream the dense cells that fault, so run release with the breakdown to localize.
- **CPU-side scratch telemetry**: `ScratchTelemetry` (refreshed per-frame, surfaced via `ctx.scratch`) tracks renderer-owned scratches (`gpu_instances` / `batches` / `indirect_draws` / `terrain_tile` / `tlas_instances`, plus — since #3693 filled four previously-missing rows — `tlas_addresses_scratch`/`tlas_missing_samples_scratch`/`blend_seen_scratch`/water's `param_scratch`) capacity-vs-used + wasted bytes, AND, since #3694, the engine binary's own seven `build_render_data` scratches (`draw_commands`, `water_commands`, `gpu_lights`, `gpu_fog_volumes`, `light_sort_scratch`, `bone_world`, `skin_offsets`) appended right after by the producer in `byroredux::app_events` — `ScratchTelemetry::renderer_row_count` marks the split so `ctx.scratch` can label the two groups without threading a per-row tag through every `ScratchRow` construction site. Diff against it for over-reserved scratch.
- **Camera-relative origin cost (#1492–#1496, #markarth-precision)**: the render origin is snapped to the 4096-unit cell grid (`RENDER_ORIGIN_SNAP`), so it only moves on a cell-boundary crossing. CPU cost: `assemble_camera` builds an extra relative view-proj (one `look_at_rh` per frame), and the per-instance build loop (now in `crates/renderer/src/vulkan/context/build_and_upload_instances.rs`, split out of `draw.rs` under #3282) calls the shared `rebase_model_matrix` helper to subtract the origin from each model translation column (`model[12..14] - render_origin`, 3 subtractions inside the already-O(visible-instances) loop). This is **negligible added CPU** — verify it stays inside the existing loop and is not refactored into a second full pass over instances. On a grid crossing, `origin_corrected_prev_view_proj` right-multiplies the previous VP by `translation(O₂−O₁)` so TAA/SVGF history is NOT reset (#1489) — a path that drops history on every crossing is a HIGH perf+quality regression (full-screen flash per cell edge).
**Output**: `/tmp/audit/performance/dim_9.md`
