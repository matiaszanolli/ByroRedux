**Not fixed — leaving open.** RenderDoc is not installed on this machine, so the capture this issue asks for is not something I can run. What I can contribute is a correction to the "what's ruled out" section, pinned as a test in 5e3d2d4c.

**The mask system should not be in the ruled-out column.** Point 2 says `shadow_mask_for_instance()` maps `RenderLayer::Actor` → `VISIBILITY_LAYER_DYNAMIC_ACTOR`. That mapping is **conditional**. The function tests, in order:

1. refractive glass → `GLASS`
2. `alpha_blend` **or** `MATERIAL_KIND_EFFECT_SHADER` **or** `MATERIAL_KIND_FIRE_REFRACTION` → `EFFECT`
3. only then `render_layer` → `ARCHITECTURE` / `STATIC_PROP` / `DYNAMIC_ACTOR` / `FOLIAGE`

`VISIBILITY_LAYER_EFFECT` is bit 5, and `ALL_OPAQUE` is bits 0-3 — so an actor draw carrying `alpha_blend` (or either effect kind) is **invisible to every shadow ray culling on `ALL_OPAQUE`, including the exterior sun's**. No ground-contact shadow. That is the reported symptom exactly, reached without any BLAS or refit-timing involvement.

To be clear about what this is and isn't:

* It does **not** prove causation. Whether a specific FO4 feral-hound draw actually carries `alpha_blend` needs the live scene. An actor built as an opaque body plus a blended fur sub-mesh would still cast a body shadow, so "whole dog has no shadow" needs *every* draw non-opaque — or something else entirely.
* The behaviour is **deliberate** and I changed nothing: #2224 / #2227 established that blended proxies must not become structural occluders. The test only pins the precedence so the interaction stays visible to the next reader.

**Also ruled out by reading, so you can skip it:** skinned and rigid instances get their mask through the same single `shadow_mask_for_instance` call in `build_tlas_instances` — there is no skinned-specific mask path, so the mask cannot be wrong *because* the actor is skinned. The first-sight refit-timing candidate from your "not yet checked" list is untouched and still the best remaining lead; that one genuinely needs the capture.

Suggested addition to the capture plan, since it is cheap once you are in there: read the failing instance's mask byte and check whether it is `0x20` (EFFECT) rather than `0x04` (DYNAMIC_ACTOR). That distinguishes this hypothesis from the BLAS ones in one look, before chasing hit/miss per pixel.
