Premise confirmed exactly, including the mechanism: the tail read makes `consumed == block_size` **by construction**, so this class of block contributes drift 0 no matter how much of it the parser failed to understand. That is now asserted in the regression test rather than just described, so the premise stays true.

`NifScene` gains a third histogram, `opaque_tail_histogram`, fed by a new `NiObject::opaque_tail_len` (default `None`).

**Trait method rather than the downcast you might expect.** `lib.rs` could have downcast to the four tail-carrying types after parse, which touches fewer files. I didn't, because a hardcoded type list in the accounting path goes stale the moment a fifth tail-capturing block lands — the same rot class as the stale source pins fixed in #4034/#4035 this week. With the trait, a new capturing block overrides one method and is counted automatically; without it, it silently reintroduces the blind spot for its own type.

`Some(0)` is deliberately distinct from `None`: "has a tail slot, consumed the whole declared size" is a different fact from "not instrumented", and collapsing them would make an instrumented-but-clean type indistinguishable from an uncovered one.

**SIBLING — the issue named one of four sites.** `read_starfield_tail` (shader.rs) covers `BSLightingShaderProperty` and `BSEffectShaderProperty`; `node.rs` captures tails inline for `BsWeakReferenceNode` and `BsFaceGenNiNode`. All four report. A test asserts every struct declaring a `starfield_tail` field has a matching override — verified by deleting one, which fails naming `BsWeakReferenceNode`.

`bump_drift` was generalised to `bump_hist<K>` rather than copied for the unsigned bucket key, so all three histograms share one implementation.

**On the requested end-to-end fixture:** the completeness check asks for a synthetic under-read asserting the histogram flags it. Building a valid synthetic Starfield NIF for `parse_nif` is more machinery than the guarantee needs, so the chain is pinned in three parts instead — the capture reports its length through the trait (using the existing 38-byte fixture), `parse_nif` calls it and buckets the result (source-pinned), and every capturing type overrides it (source-pinned). Worth saying plainly since it differs from what was asked.
