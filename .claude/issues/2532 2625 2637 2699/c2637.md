Fixed in 5b32f7e2.

The report now separates three things it previously merged:

1. **Known base forms outside `statics`** — attributed to their own record type. This is the bucket #2636 made possible and nothing consumed: it indexed `SECH`/`AOPF` precisely so they would stop being invisible, but sf_smoke's resolve check only ever consulted `statics`, so those REFRs still landed in the gap bucket. `nonstatic_base_type` probes the audio family (`SECH`, `AOPF`, `ASPC`, `ALOC`); each map is type-keyed, so the map that matches *is* the record type and no type tag needs storing.
2. **GRUPs skipped by design** — `skipped_unconsumed_groups` (PDCL) printed as its own section, so the largest single cause is visible instead of inferred.
3. **The residual**, now labelled *unattributed* rather than asserted to be a parser gap.

That third point is the actual fix. The tool could not tell a real gap from a skipped-GRUP member, and claiming otherwise is what let a regression hide behind two understood causes — the exact failure this report exists to catch. It now says what it knows.

Threading the full `EsmIndex` in was necessary: `EsmCellIndex` is the render-facing view and does not carry the audio maps, so `print_cell_report` needed the parent index.

**Not done, deliberately:** the suggested "thread the FourCC through the existing skip telemetry into a per-type unresolved counter". `skipped_unconsumed_groups` is GRUP-label-granular and carries no per-record FormIDs, so it cannot attribute an individual unresolved REFR to a type — only report that a whole GRUP was skipped, which is what the new section does. Per-FormID attribution for skipped GRUPs would need the walker to retain the FormIDs it skipped; worth a separate issue if the residual stays large enough to matter.

Three tests: attribution for each of the four types, a genuinely-unknown form staying unattributed (so the residual keeps catching real gaps), and a source pin that the retired "parser gap" assertion has not returned and both new sections are still printed.
