## #3042 — dead PACK selectors (FIXED)

15 `pub fn`s deleted from `crates/plugin/src/esm/records/misc/pack.rs`
(7 `active_package_is_*` + 8 `active_*_location`/`active_*_target`), plus the
two re-export lines. The issue counted 14; the actual set is 15 because Escort
carries both a `_target` and a `_location` accessor.

`byroredux/src/npc_spawn/ai_package.rs:106-146` actually calls.

they pin the selector's priority / schedule / CTDA-gating semantics and the
by-construction mutual exclusivity of the procedure classes, which are still
live properties of `active_package`. They now run against test-local shims
generated by an `active_package_is!` macro that composes
`active_package(...).is_some_and(PackRecord::is_*)`.

The two `#2031` equivalence tests compared a getter against a single resolve.
With the getters gone that comparison is tautological, so they were rewritten
to assert the resolved package carries the authored PLDT/PTDT payload
directly.

`_audit-common.md`'s Sandbox AI row (which pointed an auditor at the dead
path) and two stale comments in `actor/tests.rs` were corrected.

## #3039 — Skyrim-only playable-slice gates (FIXED)

`docs/smoke-tests/lib/fixture.sh` + `docs/smoke-tests/fixtures/<game>.env`.
The three gates take the title as `$1` (or `BYROREDUX_SMOKE_GAME`), default
`skyrim_se`, so every pre-existing invocation is unchanged.

Fixture values are derived, not guessed. `probe_slice_fixture` (new plugin
example) reports a cell's teleport doors, each door's resolved destination,
and a camera pose aimed at it — computed as
`door + normalize(centroid - door) * 0.75 * INTERACTION_REACH_BU`, aimed
horizontally at eye height, emitted in renderer Y-up because that is what
`--camera-pos` / `--camera-forward` consume. The NPC half is left to the
existing `probe_combat_fixture` rather than duplicated.

The derived FNV pose selected the intended door on the first live run
(`kind=Door distance=67.64  prompt=[E] Open`).

## #3005 — draw-batch merge regression on fnv and fo3 (FIXED)

Re-measured at `cc666a48`
(`--game <key> --cell <cell> --bench-frames 240`, xvfb):

| Scene | 2026-06-14/08-26 baseline | 2026-08-27 | verdict |
|---|---|---|---|
| fnv FreesideAtomicWrangler | 2110 / 109b / 26c | 2110 / 109b / 26c | inside ×1.1 on all three |
| fo3 MegatonPlayerHouse | 1839 / 96b / 9c | 1581 / 164b / 9c | cmds fell, gpu_calls recovered, batches still +71% |

Cause (the CAUSE-NOT-BASELINE box) was already root-caused in code and did not
need a bisect: `draw_sort_key`'s alpha-over branch in
`byroredux/src/render/mod.rs` (RT-1 / #2215) sorts true alpha-over draws
depth-primary, so draws that would otherwise share `group_state` stop being
contiguous whenever a different-state alpha-over draw sits at an intervening
depth — each interruption opens a new `DrawBatch`. That is the required cost
of the #1804/#2237 compositing fix, not a batching defect; the same comment
records the confirming experiment (state-primary order drops FNV Freeside
25 → 8 GPU calls).

fo3 was therefore re-baselined **with the justification written into the TSV
header**, and the FNV baseline's existing `#3005` caveat was closed out in
place. The fo3 refresh is explicitly marked PARTIAL: only the rows this run
measured (entities, fps, draws, skin pool) were updated; the `byro-dbg`-sourced
rows are carried forward and marked as not re-verified.

**SIBLING box not completed.** The oblivion / skyrim_se / fo4 baselines were
not re-measured in this session.
