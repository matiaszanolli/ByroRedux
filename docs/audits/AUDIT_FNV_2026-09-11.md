## Executive Summary

Fallout: New Vegas remains the healthiest title in the compatibility matrix and
the reference realization for NIFAL (material/collision translation) and PHYSAL
slice 1 (classic bhk ragdoll chain). This cycle ran all 9 dimensions of
`/audit-fnv` — 6 as fresh full passes (Dimensions 1, 2, 3, 5, 6, 8 were reused
from a partial prior run after being read in full and verified sound;
Dimensions 4, 7, 9 were run fresh this session) — against current source and,
for several dimensions, live against the real `FalloutNV.esm` / NIF corpus at
`/mnt/data/SteamLibrary/steamapps/common/Fallout New Vegas/Data/`.

**6 findings total, 0 CRITICAL, 0 HIGH, 1 MEDIUM, 5 LOW.** No regressions
against any ROADMAP-recorded baseline were found — every measured figure
(NIF parse rate, ESM record counts, ragdoll constraint-edge surfacing,
Prospector bench-of-record) matches or exceeds the last recorded value. The
one MEDIUM finding is a genuine, previously undocumented content-fidelity gap
(Dimension 4: `effective_actor_level` returns 0 for authored-level-0 `NPC_`
records, silently emptying every leveled-list-derived item those actors own);
the five LOW findings are two doc-rot items, one inert-on-FNV/live-on-FO4+
asymmetry, one incomplete regression-fix sibling, and one stale
self-documented invariant in a ragdoll-attach comment. Three dimensions
(1, 5, 8) and one dimension's schedule/procedure checklist (9) produced zero
findings — this is a mature, well-regression-tested slice of the engine.

Two dimensions ran live corpus sweeps that turned previously-open questions
into measured facts, which is this cycle's most durable contribution:
- **Dimension 5**: FNV NIF parse rate is 100.00% clean across all 20,746 NIFs
  in all 11 mesh-bearing archives (base + Update + 4 story DLC + 4 pre-order
  packs) — unchanged from the 2026-08-28 baseline.
- **Dimension 7**: over the entire FNV mesh corpus, **1,396 of 1,396 authored
  Havok ragdoll constraint edges surface as canonical PHYSAL joints (100%)**;
  the residual undecoded-constraint-kind occupancy (`bhkBallAndSocketConstraint`
  / `bhkStiffSpringConstraint`) is exactly 0 and 1 blocks respectively in the
  entire `Fallout - Meshes.bsa`, retiring an open question from the dimension
  brief with a number instead of an assumption.

### Dimension 2 — NIFAL Canonical Translation (FNV Slice)
**2 findings, both LOW.**

- **FNV-D2-01** [LOW] — The `material_translate.rs` module doc's Phase-2
  resolver table and prose ("**Both** Phase-2 resolvers…") undercounts a third
  Phase-2 resolver, `resolve_unresolved_gloss_neutral_roughness` (added by
  #3905), which also writes canonical `Material::roughness` post-handle-attach
  from the same two production call sites. Documentation-only; no runtime
  divergence (all three resolvers are correctly wired at both call sites).
  `crates/nif/src/material_translate.rs:28-45` vs the third resolver at
  `:1074-1093`.
- **FNV-D2-02** [LOW; inert on FNV, live on FO4+] — `translate_material`
  classifies glass from the caller's **overlay-resolved** (post-REFR-XATO/
  XTNM/XTXR) texture path, but PBR scalars arrive pre-computed at NIF-import
  time from the mesh's **own, un-overlaid** path — the two classifications key
  off different strings within one `translate_material` call. Currently
  unreachable on FNV because FNV's own `XATO` mis-decode (#1887, tracked,
  see Dimension 4) makes the overlay path inert; live and reachable on FO4+/
  Skyrim TXST-overlay placements, where an overlay swap can carry the
  original texture's metalness/roughness onto a materially different surface
  with no per-draw fallback to mask it. `byroredux/src/material_translate.rs:475-666`
  vs `crates/nif/src/import/material/mod.rs:1387-1411,1518-1519`.

5 regression guards confirmed intact (single-boundary invariant; plain-`f32`
resolve-once metalness/roughness with no render-time keyword scan;
`EmissiveSource` non-bleed across game lines; multi-sphere/convex-list
collision no-drop #9c6096aa; no-fabrication invariant #2707/#1873/#2573).

### Dimension 4 — ESM Record Parser (FNV Data)
**1 finding, MEDIUM.**

- **FNV-D4-2026-09-11-01** [MEDIUM] — `effective_actor_level`
  (`crates/plugin/src/esm/records/actor/mod.rs:96-102`) returns the raw
  authored `level` field verbatim for non-PC-level-mult `NPC_` records,
  deliberately never floored to 1. But every `LVLI` on `FalloutNV.esm` has a
  minimum entry level of 1, so an actor at `effective_actor_level == 0` finds
  **zero eligible entries in every leveled list it owns**, silently and
  simultaneously emptying armor, weapon, ammo, grenade, chem and money loot.
  Measured live: 30/3,816 `NPC_` records (0.8%) author `level == 0`; at least
  3 of a 5-NPC sample are confirmed spawn-reachable via an `LVLN` pick at
  entry-level 1 (e.g. `VHDNCRTrooper1aHeavy`, picked by
  `LVLN VarVHDNCRTrooper1Heavy`), and each resolves every owned leveled list to
  an empty `Vec` at its own authored level=0 but non-empty at any level ≥ 1 —
  isolating the defect to the level value itself, not list content or
  recursion logic. Distinct from, and additive to, the already-tracked CMNY
  leaf-kind silent-skip (`FNV-2026-08-26-D4-06`) and from the already-fixed
  #2955/#3081/#3171 level-derivation fixes, whose non-mult branch this sits
  entirely inside. `crates/plugin/src/esm/records/actor/mod.rs:96-102`;
  consumed at `crates/plugin/src/equip.rs:637-716`; called from
  `byroredux/src/npc_spawn.rs:82,157,208,858` and
  `byroredux/src/cell_loader/references/mod.rs:644`.
  **Suggested fix**: thread the `LVLN` pick's entry-level into gear resolution
  at the call sites that already know it, rather than re-deriving from the
  (possibly template-only, level-0) base `NPC_` record.

5 of 6 checklist items verified as regression guards, several via live test

**1 finding, LOW.**

- **FNV-D7-2026-09-11-01** [LOW] — The `RagdollTemplate` attach-site comment

  `Some(ImportedRagdoll)`, of which **150 have no `skeleton` in their path**

  debug-load / NPC-spawn paths, but the comment gives the next reader a wrong

  mis-attributing authored multi-prop fan-out to an upstream constraint drop)
  is noted as out-of-scope-for-this-dimension rather than lost.
  `byroredux/src/scene/nif_loader.rs:537-556`.
  **Suggested fix**: rewrite the comment to state the real structural gate
  (≥1 constraint block, ≥2 bone-hosted bodies, ≥1 decoded joint) and name the
  FNV non-skeleton content that legitimately satisfies it; gate explicitly at
  the call site if skeleton-only really is the intent.
