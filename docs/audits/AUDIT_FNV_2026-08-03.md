# Fallout: New Vegas Compatibility Audit — 2026-08-03

Reference-title audit, run as one leg of a `comprehensive` audit-suite
sweep against HEAD `1ae86f62`. FNV is the most-validated end-to-end path
in ByroRedux and the reference realization for NIFAL (material/collision
translation) and PHYSAL (ragdoll slice 1). All 9 dimensions were worked
directly (source re-verification, `cargo test` execution — including the
`--ignored` real-data parse-rate suite — and a live headless engine run
against on-disk FNV game data for the interior/exterior bench-of-record
and a `byro-dbg` attach exercising `stats`/`tex.missing`/`tex.loaded`/
`entities`) against real game data at
`/mnt/data/SteamLibrary/steamapps/common/Fallout New Vegas/Data/`.

## Executive Summary

**6 NEW findings: 2 HIGH, 0 CRITICAL, 2 MEDIUM, 2 LOW.** Six of nine
dimensions (Cell Loading, NIFAL Canonical Translation, RT Lighting, NIF
Parser, Animation/Skinning/Particles, AI Packages) came back completely
clean — every regression guard checked held. Dimension 7 (PHYSAL Ragdoll)
was initially reported clean from a static-code pass, but a deeper,
real-data-driven re-verification (probing the actual FNV/Oblivion/Skyrim
skeleton NIFs and the live Rapier multibody source) surfaced a HIGH-severity
transform bug plus two MEDIUM findings — that re-verification supersedes
the earlier "no new findings" read and is incorporated below. The findings
that surfaced through real on-disk data, live test runs, or direct
third-party (Rapier) source inspection rather than static code reading
alone:

- **FNV-D8-01 (HIGH, NEW)** — `--grid 0,0` worldspace auto-pick is
  non-deterministic (unstable `HashMap` iteration order breaks a
  multi-candidate tie) and can silently load the wrong FNV worldspace,
  including one with no usable terrain collision — the exact CLI example
  this project's own `CLAUDE.md` documents does not reliably load
  Wasteland. Found via three back-to-back real engine runs of the
  identical documented command, which returned three different results
  (one leaving the player in permanent freefall).
- **FNV-D7-01 (HIGH, NEW)** — `activate_ragdoll` composes the imported
  Havok body transform with the host bone's world transform a second time.
  The body transform is already in skeleton-root space (empirically
  identical to the host bone's rest-world transform across all 18 FNV
  ragdoll bodies, and confirmed on Oblivion and Skyrim SE skeletons too),
  not bone-relative as `ImportedRagdollBody` documents it. Every ragdoll
  the engine builds today is seeded in the wrong place; the #1616
  round-trip test cannot catch it because it round-trips the same wrong
  offset. PHYSAL-wide, not FNV-specific.
- **FNV-D7-02 (MEDIUM, NEW)** — Rapier's multibody forward-kinematics pass
  runs at the top of every physics step and recomputes every non-root
  link's pose from the authored joint frames (`coords = 0` at insertion),
  overwriting the 17 non-root per-bone seed poses `activate_ragdoll`
  computes. A ragdolled actor snaps from its animated pose to the rest
  configuration on the first physics tick.
- **FNV-D7-03 (MEDIUM, NEW)** — ragdoll colliders are inserted with no
  interaction-group exclusions, so directly-jointed and even non-adjacent
  body pairs self-collide; a probe against the corrected body poses found
  8 of 17 constrained pairs interpenetrating at rest (up to ~10 units).
  The authored Havok `HavokFilter` is parsed but discarded at the
  translate boundary.
- **NAVM-01 (LOW, NEW)** — a stale test comment in
  `crates/plugin/src/esm/records/tests.rs` still describes FNV's `NAVM`
  count as `0` (pre-#1272 state); a live run now shows 4771 navmeshes.
  No functional impact, but risks wasting a future auditor's time
  re-investigating already-fixed behavior.
- **FNV-D7-04 (LOW, NEW)** — four sibling drop sites in `extract_ragdoll`
  (unhosted body, failed shape resolve, unresolved constraint endpoint,
  non-finite guard) stay silent while the adjacent #1539/#1718 guards in
  the same function log loudly — telemetry-only, but undercuts the
  diagnostic story those guards exist for.

The one open, tracked issue that touches FNV — **PERF-REGRESSION-6c56e311**
(HIGH, `#2161`, ROADMAP Known Issues, DECIDED 2026-07-27 to accept the
cost) — was independently reproduced this session at native (`--upscaler
taa`) resolution: Prospector Saloon read 61.4 FPS / 16.28 ms wall against
the `8a668eff` baseline's 145.1 FPS, consistent with the already-documented
R6a-stale-17 re-measurement (65.3 FPS) within the ROADMAP's own ~6–12%
same-machine noise band. This is carried forward as a live
regression-status confirmation, not re-filed. With the engine's FSR 3.1
Quality default, the effective number a normal run sees is 114.1 FPS,
consistent with R6a-stale-17's own FSR-Quality figure (123.5 FPS) at the
same offset.

### Dimension 7 — PHYSAL Ragdoll — FNV Reference Slice

**Three new findings (1 HIGH, 1 MEDIUM, 1 LOW) surfaced on a deeper,
real-data re-pass; a second MEDIUM (FNV-D7-03) was found alongside them.**
An initial static-code pass reported this dimension clean; a follow-up
pass that built a throwaway probe against the real FNV/Oblivion/Skyrim
`skeleton.nif` ragdoll data, and cross-checked the live Rapier
`multibody_joint`/`narrow_phase` source, found the import→activation flow
does have a coordinate-space error, and that two further gaps exist in the
simulated result. This re-verification supersedes the initial "no
transform-composition error found" read.

**FNV-D7-01** (HIGH, NEW): `activate_ragdoll` seeds each Rapier body with
`world = bone_GlobalTransform ∘ body_local`
(`byroredux/src/ragdoll.rs:47-60,233-257`), on the documented assumption
that `ImportedRagdollBody.translation/rotation`
(`crates/nif/src/import/collision/ragdoll.rs:61-88`) is bone-relative. On
real content it is not: for all 18 bodies in the FNV `_male\skeleton.nif`
ragdoll, the imported body transform is numerically identical (within
~1 unit / 360° double-cover) to the host bone's own rest-world transform —
confirmed for Oblivion (18/18) and Skyrim SE (18/18) skeletons too, so
this is PHYSAL-wide, not FNV-specific. The composition therefore applies
the bone transform twice, seeding the multibody root
(`Bip01 NonAccum` on FNV) roughly 68 units from the real pelvis and
rotated into the pelvis's own frame. The #1616 round-trip test cannot
catch this: it round-trips the same wrong offset, so a body that hasn't
moved passes. Suggested fix: treat the imported body transform as
skeleton-root-space — either resolve `bone_rest_world⁻¹ ∘ havok_body_transform`
at the translate boundary (keeping the existing seed/writeback math), or
seed from the actor root instead of per-bone; add a real-data assertion
that a seeded body's world position lands within a few units of its host
bone.

**FNV-D7-02** (MEDIUM, NEW): even with FNV-D7-01 fixed, Rapier's
multibody forward-kinematics pass (`forward_kinematics` +
`update_rigid_bodies_internal`, run unconditionally at the top of every
`PhysicsPipeline::step`) recomputes every non-root link's pose from the
authored joint frames starting at `coords = 0`
(rapier3d `multibody_joint.rs:31-38`, `multibody.rs:965-1038`). Rapier's
own default therefore overwrites 17 of the 18 per-bone seed poses
`activate_ragdoll` computes on the very first step, snapping a ragdolled
actor from its animated pose to the rest configuration before it starts
falling. Suggested fix: after inserting the multibody joints, derive each
link's joint coordinates from the seeded relative poses
(`parent_seed⁻¹ ∘ child_seed`), or document that the sim intentionally
starts from rest pose and correct `activate_ragdoll`'s doc comment to
match.

**FNV-D7-03** (MEDIUM, NEW): ragdoll colliders are inserted with default
Rapier interaction groups (`crates/physics/src/ragdoll.rs:159-176`, no
`collision_groups`/`solver_groups` set anywhere in the crate), and
Rapier's multibody defaults enable both self-contacts and contacts
between directly jointed links. The authored Havok `HavokFilter` field is
parsed (`crates/nif/src/blocks/collision/rigid_body.rs:19,65`) but dropped
at the ragdoll translate boundary
(`crates/nif/src/import/collision/ragdoll.rs:78-88`) and has no consumer
anywhere in the tree. A probe against the (transform-corrected) FNV body
poses found 8 of 17 constrained pairs interpenetrating at rest, up to
~10 units deep (e.g. `Spine2 <-> Spine1` gap −10.3), which fights the
solver with separation impulses from the moment a ragdoll activates.
Suggested fix: give ragdoll colliders a per-actor `InteractionGroups`
excluding other members of the same ragdoll (or disable multibody
self-contacts / per-edge `contacts_enabled(false)`); surfacing the
authored `HavokFilter` group is the fidelity-correct version.

**FNV-D7-04** (LOW, NEW): four sibling drop sites in `extract_ragdoll`
(unhosted body, failed `resolve_shape`, an unresolved constraint endpoint,
and the non-finite guard) `continue` silently, while the adjacent
#1539/#1718 guards in the same function log loudly for the same class of
lost articulation edge. Telemetry-only — the downstream forest/emptiness
gates in `build_ragdoll` still fire — but undercuts the diagnostic story
those two guards exist for. Suggested fix: route all four through the
same "dropping … linking bones 'a' <-> 'b'" phrasing and add a test
driving a `BhkConstraintData::Other` edge through `extract_ragdoll`.

What still holds, re-confirmed on this pass:
- All four silent-drop regression guards remain present with real
  (non-stub) passing tests: #1718, #1539, #1540 (TriMesh→convex-hull
  substitution avoiding degenerate inertia), #1772 (keyframed
  bone-follower teardown on activation, pinned by
  `activation_tears_down_keyframed_bone_bodies` — its title's "collision
  groups" clause is FNV-D7-03, not yet implemented).
- Per-game seam confinement confirmed: zero `GameKind`/per-game branches
  found in `byroredux/src/ragdoll.rs` or `crates/physics/src/ragdoll.rs`
  — the only per-game seam is the upstream constraint CInfo decode, as
  PHYSAL design mandates.
- `bhkMalleableConstraint` wrapping Ragdoll: confirmed the decode
  genuinely unwraps the inner constraint type via a runtime dispatch on
  the wrapper's `type_name`. Real data confirms a properly jointed
  articulation, not an opaque blob: the FNV skeleton yields 18 bodies /
  17 joints, all decoded (9 Ragdoll + 8 LimitedHinge, zero `Other`).
- Writeback safety: `ragdoll_writeback_system` runs in `Stage::Late`,
  confirmed to execute after physics stepping and after transform
  propagation, so the GPU skin palette (built later, at render-data time)
  always samples the ragdoll-simulated pose — no stale-pose or race
  corruption. One known, separately-tracked exception: **#1981** — the
  WorldBound cull/RT bound is folded in PostUpdate, before the Late
  writeback, so a ragdoll leaving its origin doesn't move its bound.

### Dimension 8 — Real-Data Validation & Bench-of-Record

**One HIGH finding (FNV-D8-01).** Run on a real Vulkan device (RTX 4070
Ti) against real FNV game data.
- CWD gotcha: confirmed matches documentation exactly, with a loud
  self-diagnosing error message already in place — no surprise.
- Interior bench-of-record: entity count (3626) matches baseline exactly;
  FPS/fence gap fully attributed to the already-accepted
  `PERF-REGRESSION-6c56e311`/`#2161` (see Baseline Comparison above), not

- `byro-dbg` attach: `stats`/`tex.missing`/`tex.loaded`/`entities` all
  returned sane, non-garbage output across 5 round-trip commands.

**FNV-D8-01** (HIGH, NEW): `--grid 0,0` worldspace auto-pick
(`byroredux/src/cell_loader/exterior.rs:330-353`) is non-deterministic.
The selection order is `--wrld` override → "worldspace containing the
requested grid" → hardcoded preferred list → most-cells fallback. FNV
ships many small worldspaces (`ffencounterworld`, `freesidefortworld`,
`WastelandNVmini`) whose own local grid also spans the origin, so at
`--grid 0,0` every candidate satisfies the containment rule and the tie
breaks on unstable `HashMap` iteration order. Three back-to-back runs of
the byte-identical command — the exact invocation this project's
`CLAUDE.md` documents — returned three different results: `ffencounterworld`
(99 entities, no usable collider near spawn, player free-falls
permanently), `freesidefortworld` (7113 entities, wrong worldspace but
grounded), and only `WastelandNV` when `--wrld` was explicitly forced
(11867 entities, correctly grounded). Suggested fix: when the
containment rule matches multiple candidates, break the tie via the
preferred-list rule before falling back to most-cells, and log all
grid-containing candidates when ambiguous.
