## 2. Findings

### LOW

#### UI-D2-2026-09-09-01 — the response-handler re-entrancy invariant is load-bearing and unpinned

- **Dimension**: Host Bridge Transport · **Profile**: both
- **Location**: `crates/ui/src/host.rs` — `ScaleformHostBridge::record_call`,
  the `response_handler` clone immediately before `let mut state =
  self.state.borrow_mut()`
- **Status**: NEW — **FIXED this session**

**Fix.** `a_response_handler_may_re_enter_its_own_bridge`
(`crates/ui/src/host/tests.rs`). The handler captures a clone of the bridge it
is installed on (`set_response_handler` takes `&self`, so no
`Rc<RefCell<Option<_>>>` dance is needed) and re-enters through both borrow
kinds: `queued_call_count` (shared — catches a caller holding `borrow_mut`) and
`register_method` (mutable — catches a caller holding *any* borrow). One test
therefore covers both shapes of the refactor. It asserts the handler's
*mutation* landed, not merely that nothing panicked: the re-entrantly
registered method must subsequently dispatch as `Queued` rather than `Unknown`.
Verified by applying the refactor — it fails with `RefCell already borrowed`.

**Description.** `record_call` is careful in a way nothing records or enforces.
It clones the handler out of the map and lets the immutable borrow expire
*before* invoking it:

```rust
let response_handler = self.state.borrow()
    .response_handlers.get(&normalized.method).cloned();   // borrow ends here
let dynamic_response = response_handler.map(|h| h(&normalized.arguments));
let mut state = self.state.borrow_mut();                   // re-borrow after
```

That ordering is the only thing making a re-entrant handler safe. The obvious
"tidier" refactor — holding one borrow and calling through the map to avoid the
clone — compiles, passes all 70 tests, and turns any handler that touches the
bridge into a `RefCell` double-borrow panic.

**Evidence.** No test exercises a handler that re-enters. The one
`set_response_handler` test
(`skyrim_game_delegate_transport_is_normalized`) uses a closure that only
inspects its arguments. The `"reentry"` name in `run_fixture` is a *registered
method* for the SWF fixture, not a re-entering handler — it does not cover
this.

**Impact.** Nothing today: there are zero production `set_response_handler`
callers, because engine handlers are the Pending row. That is exactly why it is
worth pinning now — the invariant is unguarded during the window before the
first real handler lands, and the panic would surface as "the menu crashes the
engine" attributed to the new handler rather than to the borrow discipline it
tripped.

**Suggested fix.** One test: a handler that calls back into its own bridge
(`set_response`, or `drain_calls`) and asserts `record_call` returns normally.
It fails on the inlined-borrow refactor and passes today.

#### UI-D1-2026-09-09-02 — `ui.md` documents the pre-#3771 profile parameter on both resource-provider constructors, and following it re-introduces the redundant decode #3771 removed

- **Dimension**: Profile & VM Selection · **Profile**: both
- **Location**: `docs/engine/ui.md` — the `impl SwfPlayer` block
  (`from_resource_provider`) and the `impl UiManager` block
  (`load_swf_from_resource_provider`)
- **Status**: NEW — **FIXED this session**

**Fix.** Both signatures corrected, the `None`-is-normal contract written into
the prose, and — because this class rots silently — pinned by
`documented_profile_parameters_match_the_real_signatures`
(`crates/ui/src/lib.rs`), which compares the documented `profile` parameter
against the real one for all three profile-taking entries. `ui.md` had no test
coverage at all before this, despite `crates/scripting`, `crates/spt` and
`crates/renderer` all pinning their docs that way.

`load_swf_with_profile` is included as a **negative control**: it legitimately
takes a plain `ScaleformProfile`, so a well-meaning sweep that "fixes" every
occurrence to `Option` fails the test. Both directions were verified by
neutering. Checking that third occurrence before editing is what kept this fix
from introducing new rot — the finding named two constructors, and exactly two
were wrong.

**Description.** Both are documented as taking `profile: ScaleformProfile`.
Both take `Option<ScaleformProfile>` at HEAD, changed by #3771 (`884b5062`).

**Evidence.**

| | doc | code |
|---|---|---|
| `SwfPlayer::from_resource_provider` | `profile: ScaleformProfile` | `profile: Option<ScaleformProfile>` (`player.rs:226`) |
| `UiManager::load_swf_from_resource_provider` | `profile: ScaleformProfile` | `profile: Option<ScaleformProfile>` (`lib.rs:120`) |

**Impact.** Not cosmetic, and not merely a stale type. The `Option` *is*
#3771's contract: `None` means "trust `prepare_movie`'s own single detect".
A caller written against the documented non-`Option` signature has to obtain a
profile from somewhere, and the only available source is a pre-extract of the
archive entry plus an independent `ScaleformProfile::detect` — which is
precisely the second archive extraction and third whole-stream inflate that
#3771 deleted, and which this skill's own D2 checklist names as the regression
shape ("a caller re-adding a pre-extract-and-detect step to supply a profile
`prepare_movie` would have derived itself"). The doc currently instructs the
regression.

**Also verified while checking this** (no finding): every one of the 28
documented `pub fn` names exists in the crate — no phantom API — and the two
`render()` signatures that look contradictory (`Option<&[u8]>` at line 170,
`UiFrame<'_>` at line 262) are correct: they are `SwfPlayer::render` and
`UiManager::render` respectively, two different types.

**Suggested fix.** Correct both parameter types and add one clause saying
`None` is the normal production value.

## 5. Verified clean this cycle (checked, no finding)

- **AVM2 constant-pool indexing** — the signature failure mode. Every
  `Index::new(methods.len())` is captured *before* its matching `push`, so each
  index names the element that push lands. Spot-checked at the helper-method,
  ready-method, destroy-method, installer and init sites.
- **Injection idempotency** — guarded on `ADAPTER_NAME` (#2970) with an early
  return; a second injection cannot double-install.
- **Error policy (#3428)** — both hard `Err`s are inside
  `patch_root_constructor`, the one place a partial rewrite would hand Ruffle a
  corrupt SWF. The two degrade branches return `NotPresent`.
- **Destroy-hook conditionality** — registration is gated on the movie
  declaring the trait; `AdapterInjectedWithoutDestroyHook` is the honest state
  for movies that do not.
- **`BGSCodeObj.` normalisation** — one shared helper (`normalize_call`), 3
  occurrences in the rewriter, not 269.
- **Transport bound** — eviction is `pop_front` (O(1)), `dropped_calls`
  increments once per eviction, `overflow_warned` is set once and never reset,
  so the warn cannot re-arm into per-frame spam.
- **Drop-counter consumer (#2969/#3772)** — `host_call_gap_for_menu` keys the
  latch on menu name and `host_call_gap` treats a decrease as a reset, so
  neither a menu swap nor a repeated reading produces a false or wrapped gap.
- **`Unknown` vs `MissingResponse`** — a `Request`-kind method with no response
  resolves to `MissingResponse` and records into `unanswered_methods`; an
  uncatalogued name resolves to `Unknown`. The two remain distinct diagnoses.
- **Catalog lookup** — `find`'s `binary_search_by` prerequisite holds; both
  arrays verified strictly ascending, and pinned by
  `*_catalog_is_sorted_and_unique`.
- **Navigator trust boundary** — `archive_path_from_url` refuses any non-`file`
  scheme, any `ParentDir`, and any `Prefix` (absolute/drive) component, and
  refuses an empty result. `Url::join` resolves `../` before that check, so the
  load-bearing property is the one below.
- **Resolved paths never reach the filesystem** — `load_archive_resource` goes
  through `ScaleformResourceProvider::load(&str)`, and all three non-test impls
  (`Ba2Archive`, `BsaArchive`) are pure archive lookups. A `../`-escaped path
  is a key that misses, not an escape.
- **`resource_loads` is bounded** — `MAX_RECORDED_RESOURCE_LOADS` with a
  `resource_loads_capped` latch, alongside the already-bounded
  `import_asset_paths`.
- **`ui_instance_idx` clamp (#3601)** — captured immediately after the push and
  clamped there, not after `UiOverlayDraw` is built.
- **Presentation-pass composite (#3426)** — the UI pipeline is owned and
  rebuilt by `PresentationPipeline`; `pipeline_ui` is gone from the geometry
  path (source-pinned); both descriptor sets are rebound before the overlay
  draw, with the layout-incompatibility reason recorded at the site.
- **Input focus** — `release_world_input` clears `keys_held` *and*
  `mouse_buttons_held` and drops capture, so a menu opened mid-strafe cannot
  leave the camera latched. `is_debug_overlay_key` (F3) is checked before the
  UI swallow. `CursorEntered`/`CursorLeft` both drive `set_mouse_in_stage`.
- **Per-frame cost** — the whole UI block is behind `if let Some(ref mut ui) =
  self.ui_manager`, so a session with no menu ticks nothing.
- **Warn de-dup** — `ui_reported_host_methods` lives on `App`, constructed
  once, never cleared per menu load.
- **Thread discipline** — no `unsafe` in `lib.rs` or `host.rs`; `UiManager` is
  still not an ECS `Resource`.

## 6. Pending-Row readiness

Two mechanisms are correct *because* of a property the Pending work removes.
Neither is a finding today; both are cheap to get wrong later.

1. **Menu swap makes two dormant issues live.** Both `*ui_manager = Some(ui)`
   sites are in `scene.rs`'s one-shot `--menu` startup route — there is no
   runtime swap or reload. When the menu stack lands:
   - `host_call_gap_for_menu` keys its latch on the **menu name**. Reloading
     the *same* menu gives a fresh bridge counting from 0 while the latch holds
     the old total, so the new bridge's first drops are invisible until they
     exceed it. A bridge identity/generation counter is the durable key.
   - `SwfPlayer::new` creates a wgpu device per player. One swap per menu open
     becomes one device per menu open.
2. **The navigator's trust boundary rests on every provider being
   archive-backed.** `../` is neutralised only because the resolved string is a
   BSA/BA2 key. A filesystem-backed `ScaleformResourceProvider` — the natural
   way to support loose/modded menu files — makes the escape real and would
   need the traversal check moved to the resolved *string*, not just the URL
   components.
