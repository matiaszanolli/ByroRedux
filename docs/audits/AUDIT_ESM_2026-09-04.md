## Findings

### ESM-D5-01: No walker-level regression test for the XCLW no-water sentinel
- **Severity**: LOW
- **Dimension**: CELL / WRLD Walkers
- **Record/Sub-record**: `CELL.XCLW`
- **Location**: `crates/plugin/src/esm/cell/tests/cell.rs`,
  `crates/plugin/src/esm/cell/tests/wrld.rs`
- **Status**: NEW
- **Description**: `xclw_water_height` (`crates/plugin/src/esm/cell/
  helpers.rs:53-68`) is unit-tested for all four cases (normal height,
  `#INT_MIN#`, Skyrim `f32::MAX`, short/non-finite). The walker/integration
  level (`parse_cell_group` in `tests/cell.rs`) covers "XCLW present with a
  normal height" and "XCLW absent," but no test in `tests/cell.rs` or
  `tests/wrld.rs` drives a full walker call with an authored sentinel payload
  and asserts the resulting `CellData` carries `water_height_is_explicit ==
  true && water_height == None` together — the third tri-state value is
  exercised only at the helper's own unit-test boundary, not at the record
  walker that actually assembles `CellData`.
- **Evidence**: `grep -n -i "sentinel\|INT_MIN\|FLT_MAX" crates/plugin/src/esm/cell/tests/{cell,wrld}.rs` returns nothing. The composing code
  (`walkers.rs:262-274`, `wrld.rs:411-419`) is today provably correct by
  inspection — `water_height_is_explicit = true; water_height =
  xclw_water_height(&sub.data);` — but a future refactor that wraps the arm
  in a length guard matching the surrounding sub-record arms' style (e.g.
  `b"XCLW" if sub.data.len() >= 4 => { ... }`) would silently collapse
  "sentinel" back to "absent" for a too-short XCLW, and nothing at the walker
  level would catch it.
- **Impact**: None today. If it regresses: a cell whose author explicitly
  suppressed water (dry basement, drained reservoir) would grow a water plane
  back at whatever `WorldspaceRecord::default_water_height` resolves to for
  its worldspace — a silent, visual-only, per-cell regression.
- **Related**: #1305 / OBL-D6-NEW-02 (original tri-state fix); #3548 (a
  separate, already-fixed and well-tested consumer-side edge case — the
  Skyrim+/FO4 interior "authored `0.0` is the Creation Kit's inert default,
  not real water" heuristic in `byroredux/src/cell_loader/water.rs::
  interior_water_height` — deliberately out of the parser's tri-state and out
  of `crates/plugin` scope).
- **Suggested Fix**: Add one test per walker: encode an `XCLW` payload of
  `f32::MAX.to_le_bytes()` (or `#INT_MIN#`) through the full `parse_cell_group`
  / `parse_wrld_children` call and assert `water_height_is_explicit == true`
  and `water_height == None` on the resulting `CellData`.

### ESM-D5-02: WRLD whole-record merge can drop an inherited default water height on a sparse DLC override (restated pointer, not new)
- **Severity**: LOW
- **Dimension**: CELL / WRLD Walkers
- **Record/Sub-record**: `WRLD.DNAM` / `WRLD.NAM2`
- **Location**: `crates/plugin/src/esm/cell/mod.rs:1515`
  (`self.worldspaces.extend(other.worldspaces);`)
- **Status**: Existing (documented in-code, EX-09/17 item 6 / #2370)
- **Description**: `CELL` overrides get Bethesda's per-field partial-override
  treatment via `merge_cell_override` (verified correct for the water fields
  below). `WRLD` overrides do not: `EsmCellIndex::merge_from` replaces a
  worldspace's entire `WorldspaceRecord` on override
  (`self.worldspaces.extend(other.worldspaces)`), documented as deliberate at
  `mod.rs:1407-1420` because typical WRLD-override authoring re-declares
  every field it means to keep. The docstring itself flags the gap this
  creates: a DLC that patches an **existing** worldspace's `WRLD` record
  without re-authoring `DNAM` would silently lose the base game's
  `default_water_height` for every cell in that worldspace that relies on
  WRLD-default inheritance — the exact mechanism this run's `XCLW` tri-state
  feeds. A DLC that adds a **new** worldspace (Soul Cairn, Apocrypha,
  Solstheim) is unaffected — that's a new HashMap key, not an override.
- **Evidence**: `mod.rs:1407-1420` (docstring), `mod.rs:1515` (the whole-record
  `extend`).
- **Impact**: No live fixture demonstrates this today; the docstring itself
  calls it "low risk," and no shipped DLC across the seven supported games'
  masters has been observed to sparse-override an existing worldspace's WRLD
  record without re-authoring DNAM. Restated here only because it is squarely
  inside this run's "WRLD-level water default" scope, not because new
  evidence of live impact was found.
- **Related**: #2370 (EX-09/17 item 6 — where this was first identified and
  deliberately left unfixed pending a real fixture).
- **Suggested Fix**: No action recommended. The existing docstring's rationale
  for deferring a partial-merge implementation (no real content exercises it;
  a `WorldspaceRecord` partial-merge would need its own fixture to validate
  against) still holds. Do not re-file as a new issue — this entry exists so
  the water-deep preset's scope is fully accounted for, not to reopen #2370.

## Verified Clean (confirmed against current HEAD, not re-litigated as findings)

- `xclw_water_height` correctly implements the tri-state via a single
  finite+magnitude test (`h.is_finite() && h.abs() < 1.0e9`), covering
  `#INT_MIN#`, Skyrim `f32::MAX`, and short/non-finite payloads — 4/4 unit
  tests pass.
- Both the interior walker (`parse_cell_group_inner`, `walkers.rs`) and the
  exterior walker (`parse_wrld_children_inner`, `wrld.rs`) compose the helper
  identically: `water_height_is_explicit` is set unconditionally on seeing
  `XCLW`, decoupled from what the helper decodes it to.
- `merge_cell_override` preserves the tri-state under Bethesda's partial-CELL-
  override contract identically for interior cells, exterior cells (per-
  worldspace, per-`(x,y)`), and worldspace-persistent cells — no separate,
  weaker exterior-only path.
- WRLD-level capture of `NAM2` (water form), `DNAM` (default water height,
  second `f32`), and the independent `NAM3`/`NAM4` LOD-water pair is
  byte-verified and regression-tested.
- The downstream consumer (`resolved_exterior_water_height` +
  `default_water_for_worldspace`, both in `byroredux/`, read only for this
  run's cross-boundary check) correctly implements the documented
  Oblivion-vs-FO3+ default-water resolution and the cycle-guarded
  `WNAM`/`PNAM` selective-inheritance chain, with a child's own authored value
  always winning over an inherited one.
- GRUP nesting-depth bound (#3237/#3503) intact in both walkers and in the
  shared `parse_refr_group_inner`. **New since the 2026-08-30 audit**: Fix
  #3721 (`2ec58c43`, 2026-09-02) added a `parent_end` clamp to
  `bounded_group_content_end` so a nested GRUP's declared `total_size` can no
  longer overrun its parent's own bound — confirmed threaded into
  `cell/walkers.rs` and `cell/wrld.rs` alongside the other 11 call sites, with
  a dedicated regression test.
