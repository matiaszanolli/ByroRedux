## Findings

### FO4-SD-01: Pre-baked FaceGen path is built from the load-order-global FormID; DLC facegeom files are named by the plugin-local id

- **Severity**: MEDIUM
- **Dimension**: FO4 NPC spawn / head parts (npc_spawn)
- **Location**: `byroredux/src/npc_spawn.rs:1640-1649` (`prebaked_facegen_nif_path`), `:1655-1664` (`prebaked_facegen_tint_path`); callers `byroredux/src/npc_spawn/resumable/prebaked.rs:146-147` and `byroredux/src/cell_loader/references/mod.rs:726-729` (`plugin_for_form_id(child_form_id, load_order)` supplies the plugin, `npc.form_id` supplies the number); test `byroredux/src/npc_spawn/tests.rs:455-475`
- **Status**: NEW. Searched open + closed: "facegeom", "FaceGen DLC load-order" (nothing; #5095/#5408 are the head-part fallback, #2095 the tint DDS).
- **Description**: The path is `meshes\actors\character\facegendata\facegeom\<plugin>\<formid:08x>.nif`. `<plugin>` is correctly the owner of the NPC's slot (`plugin_for_form_id`), but `<formid>` is `npc.form_id`, which the ESM reader has already remapped to the load-order-global space (`reader.rs:857` `read_record_header` -> `remap_form_id`), so its top byte is the plugin's load-order slot. The shipped DLC archives name the file by the plugin-local id with a zero top byte. For any NPC whose owner is not slot 0 the probe asks for e.g. `...\dlccoast.esm\03002162.nif` while the archive holds `...\DLCCoast.esm\00002162.NIF`, so `extract_mesh` always misses. The path docblock says "load-order-global FormID rendered as 8 lowercase hex digits"; it was verified only against slot-0 masters (`Skyrim.esm`, `Fallout4.esm`). The unit test pins `Dawnguard.esm` with `0x0001684C`, a top-byte-zero value that no global Dawnguard FormID has.
- **Evidence** (static, FO4 install):
  - `Fallout4 - Meshes.ba2`: 1,094 facegeom NIFs under `FaceGeom\Fallout4.esm\`.
  - `DLCCoast - Main.ba2` 153, `DLCNukaWorld - Main.ba2` 224, `DLCRobot - Main.ba2` 12, `DLCworkshop02` 2, `DLCworkshop03` 5, all `FaceGeom\<plugin>\00xxxxxx.NIF` (a walk of the name tables: 0 names with a non-zero top byte in any archive; example `DLCCoast.esm\00002162.NIF`). 396 files in total.
  - The matching textures are named the same way (`FaceCustomization\DLCCoast.esm\00002162_d.DDS`).
  - Load order: DLCRobot, DLCworkshop01, DLCCoast, ... are slots 1.., so the global id is never `00xxxxxx` for them.
  - ESL plugins (FO4 Creation Club) hit the same shape (`FE` slot + sub-index in the top 12 bits).
- **Impact**: Every DLC-owned authored NPC (Far Harbor, Nuka-World, Automatron, workshop named NPCs) misses its baked head. Since `2a8663f39` (#5408) they fall into the race-base-parts fallback (a generic Human head), where before that commit they were headless. Either way the authored face is lost, 396 faces in total. The same code serves Skyrim/FO76/Starfield (`uses_prebaked_facegen`); the Skyrim DLC `.bsa` files are not installed here, so only FO4 was measured. The pre-baked texture path is unaffected only because FO4 never used it (FO4-SD-03).
- **Suggested Fix**: Format the file name from the plugin-local part of the id: `global_slot_of(form_id)` already classifies Regular / Medium / Light (the helper `scol_derived_cm_path` in `refr.rs` does exactly this for `cm<local>`: `0x00FF_FFFF` / `0x0000_FFFF` / `0x0000_0FFF`). Move that masking into a shared helper and use it in both facegen path builders. Fix the test to use a real DLC global id (`0x0200_xxxx`) and add a DLC-shaped case, plus an FO4 ignored real-data gate that every `FaceGeom\<plugin>\*.NIF` name round-trips through the path builder from a synthetic global id. File under `/audit-skyrim` as well for the Skyrim DLC half.

### FO4-SD-02: The exterior worker pre-parses the model of every placed STAT/SCOL, including the precombine-absorbed refs the main thread skips

- **Severity**: MEDIUM
- **Dimension**: M49 precombines, exterior streaming
- **Location**: `byroredux/src/streaming/pre_parse.rs:671` (`pre_parse_cell`; the `for refr in &cell.references` preflight loop starts at `:722`); the consuming gate `byroredux/src/cell_loader/references/mod.rs:521-534` (`absorbed_refs.contains(...)` then `continue`); the finishing cost `byroredux/src/streaming_helpers.rs:726-760` (`finish_streaming_import` -> `finish_partial_import`); the registry cap `byroredux/src/cell_loader/nif_import_registry.rs:549-601` (2048 entries)
- **Status**: NEW. Searched `pre_parse`, `absorbed`: PERF-SD-05 is the per-slice `effective_absorbed_refs` rebuild, PERF-SD-03 the created-reference stepper, neither is this; #5755 is MSWP. Not in any sibling list.
- **Description**: `pre_parse_cell` collects the model path of **every** `cell.references` entry whose base has a `MODL` and parses each unique, uncached one on the stream pool. It never consults `cell.absorbed_ref_bakes`. On FO4 the CK bakes nearly all static architecture into the cell's `_oc.nif` (XCRI), and the reference pass drops those refs (`absorbed_refs.contains(&placed_ref.form_id)` and `precombine_can_replace_record(STAT|SCOL)`) before any model lookup. The worker therefore extracts, inflates, parses and imports models the cell never spawns, and the drain then runs `finish_partial_import` (BGSM merge, material resolve, registry insert) for each on the main thread's frame budget.
- **Evidence** (raw GRUP walk of `Fallout4.esm`, all WRLD groups; script `/tmp/audit/streaming-deep/fo4/py/absorb_census*.py`, scratch):
  - 629,264 exterior STAT/SCOL placements, **599,618 (95.3 %) in an XCRI pair**; every XCRI ref is STAT/SCOL.
  - Per cell, unique model paths a worker request would parse: 251,012 summed over 4,834 cells with models, versus 12,907 for refs not in the cell's XCRI set: **94.9 % are never spawned**. For the 2,716 cells with at least 20 unique models: median 56 models parsed per cell, median **0** needed.
  - Globally 9,104 of 11,928 distinct placed exterior bases (76 %) have every exterior placement absorbed.
- **Impact**: This is the dominant per-cell worker and main-thread cost of an FO4 grid-cross: a 7x7 window (or the `FinishImports` phase of each cell) parses and finishes tens of models per cell that are never drawn. The never-used entries also fill the 2048-entry `NifImportRegistry` (LRU), so they evict genuinely reused statics and the cell's own heavy `_oc.nif` entries sooner, turning later cell loads into main-thread re-parses. It is the same cost on every FO4 DLC exterior. Not measured on a running engine (no launch allowed); the census is of the ESM data the worker sees. The failure mode the ungated parse "protects" (a bake that fails to decode, so the absorbed refs must render per-REFR) is real but rare and already has the main-thread fallback (a parse inside the frame budget).
- **Suggested Fix**: In `pre_parse_cell`, build the cell's absorbed ref set from `cell.absorbed_ref_bakes` restricted to hashes whose `_oc.nif` is present in the archives (`precombine_oc_nif_paths` plus an existence/declared-size probe; no parse needed), and skip the model of a STAT/SCOL REFR that is in that set. Keep parsing the model when the bake's `_oc.nif` is missing, matching `effective_absorbed_refs`' un-skip rule. If bake decode failure must also un-skip, parse the precombines first (they already go first in `inputs`) and defer the absorbed-ref models to a second pass only for hashes whose result came back `None`. Add a worker test that an all-absorbed cell requests only its precombine keys.

### FO4-SD-03: `prebaked_facegen_tint_path` encodes the Skyrim layout; FO4 ships no `facegendata\facetint` files

- **Severity**: LOW
- **Dimension**: FO4 NPC spawn
- **Location**: `byroredux/src/npc_spawn.rs:1655-1664`, probe at `byroredux/src/npc_spawn/resumable/prebaked.rs:148,296-299`
- **Status**: NEW (doc rot plus a dead probe; related to FO4-SD-01 but independent).
- **Description**: The tint DDS probe is `textures\actors\character\facegendata\facetint\<plugin>\<id>.dds`. FO4's facegeom NIFs reference their own textures inline: probing the shipped `FaceGeom\Fallout4.esm\0001A00C.NIF` yields `Data\Textures\Actors\Character\FaceCustomization\Fallout4.esm\0001A00C_d.dds` / `_msn.dds` / `_s.dds` on the head shape, and no `facetint` name exists in any FO4 texture archive (name-table walk of `Fallout4 - Textures1..3.ba2` and `DLCCoast - Textures.ba2` returns only `FaceCustomization\...`). So on FO4 `tint_path` is always `None` after one wasted archive miss per NPC, and the function's "Skyrim / FO4 / FO76 / Starfield" docblock is wrong for the texture half. No rendering effect (the inline texture path wins, and `select_facegen_diffuse` only fires for Skyrim skin-tint shapes).
- **Suggested Fix**: Gate the tint probe on `GameKind::Skyrim` (or make the path a per-game helper) and correct the docblock; no behaviour change expected.
