## Findings

### C-1: Regression of #5535 — `common_shape_rotation` holds a `MeshHandle` read guard across `collect_subtree`'s `Children` acquisition
- **Severity**: MEDIUM (REGRESSION of #5535; closed issue, fix undone by #5713's refactor `cfabdfd6a`, 2026-10-15)
- **Dimension**: ECS Lock Ordering (CPU half; out of volumetrics scope, found by the lock-order lane)
- **Location**: `byroredux/src/npc_spawn/resumable/runtime.rs:1320-1342` (`common_shape_rotation`)
- **Status**: Regression of #5535 (open-issue snapshot has no tracker; #5713 is the closed refactor that caused it)
- **Description**: #5535 reordered this function so the subtree's shapes were gathered first and every hierarchy guard dropped before composing bind transforms. #5713 then routed the walk through the shared `collect_subtree`, but wrote:
  ```rust
  let meshes = world.query::<MeshHandle>()?;          // read guard alive for the whole block
  collect_subtree(world, part_root)                   // acquires Children inside
      .into_iter().filter(|e| meshes.get(*e).is_some()).collect::<Vec<_>>()
  ```
  That records `MeshHandle -> Children`, the reverse of `tag_descendants_as_actor`'s `Children -> MeshHandle` — exactly the edge #5535's comment says this function must never record. The detector reports `Children -> MeshHandle -> Children`; with the full test list the victims were `female_hair_with_cancelling_root_and_shape_rotations_keeps_actor_axes`, `an_intentional_shape_tilt_survives_the_head_mount`, `male_hair_with_identity_root_and_shape_keeps_actor_axes` (a subset rerun hit `parent_part_only_tags_the_newly_attached_subtree` instead).
- **Trigger Conditions**: `BYRO_LOCK_ORDER_CHECK=1` (CI `lock-order-check`) over the whole bin test set. Not a live deadlock: the caller `align_part_root_to_actor_axes` takes `&mut World`, so no other thread can hold these locks (the skill's "graph cannot tell `&mut World` from `&World`" case). It does turn the hard-gate lane red, which is why it is not LOW.
- **Fix shape**: call `collect_subtree` first (it drops its `Children` guard on return), then take `world.query::<MeshHandle>()` and filter. Pin with the existing lock-order tests; no new test needed.
- **Related**: #5535, #5713, #5032.

### C-2: `projectile_flight_system` resolves actor ownership (storage reads) while holding the `PhysicsWorld` read guard
- **Severity**: MEDIUM (NEW, introduced by `99997e0e4` "perf(gameplay): cache projectile launcher bodies", 2026-10-16)
- **Dimension**: RwLock Patterns (Resource <-> Storage) / ECS Lock Ordering (out of volumetrics scope)
- **Location**: `byroredux/src/systems/projectiles.rs:228-262` (`is_actor_body` closure -> `resolve_actor` -> `world.get::<ActorColliderOwner>` / `world.get::<ActorVitals>`, called from the `cast_ray_corridor_where` filter while `let physics = world.try_resource::<PhysicsWorld>()` is alive)
- **Status**: NEW
- **Description**: Before `99997e0e4` the system built `actor_bodies` for every owner "before the physics world is taken" (the comment above `owners` still says the lock order is resolve ownership first). The perf change made actor resolution lazy and moved it into the ray-cast body filter, i.e. under the `PhysicsWorld` guard. `PhysicsWorld` is a sink in `docs/engine/ecs.md`'s canonical order (acquired last, nothing beneath it; #5371, #5556). Detector output: `ActorVitals -> ActorValues -> GlobalTransform -> PhysicsWorld -> ActorVitals`, failing `a_same_frame_melee_hit_survives_a_projectile_hit`, `flight_into_an_actor_queues_a_hit_and_into_a_wall_only_ends`, `flight_ignores_the_launchers_cached_body`.
- **Trigger Conditions**: lane only. The system is registered with `add_exclusive(Stage::Update, ...)` (`boot/schedule/update.rs:569`), which runs serially after the parallel batch, so there is no live second thread to complete the cycle today. It still makes the sink rule false and would become a real ABBA the moment it is demoted into the parallel batch or any physics-guarded caller is added.
- **Fix shape**: snapshot-then-acquire. Keep the lazy cost saving but resolve outside the guard: take the `PhysicsWorld` guard only for the cast, collect candidate bodies from the cast, or precompute the actor-body set once per frame from `owners` before the guard (the pre-`99997e0e4` shape, which was O(owners) once per frame, not per projectile). Do not hold the guard and "be careful".
- **Related**: #5371, #5556, #5535.

### C-3: The volumetrics and caustic skip-clear latches are committed at record time and never rolled back by the three tail `Err` sites
- **Severity**: LOW (NEW; same class as #3991, which fixed the skin chain only)
- **Dimension**: Compute -> AS -> Fragment Chains (volumetrics skip path) / Resource Lifecycle
- **Location**: `crates/renderer/src/vulkan/context/post_passes.rs:904-909` (`skip_clear_decision` + `self.volumetrics_cleared_on_skip[frame] = next_latch`; the caustic twin at `:536-537`); not reset by `rollback_skin_frame_state` (`context/skinned_blas_refit.rs:54`) nor in any `draw.rs` `Err` arm (`reset_fences`, `queue_submit`, `end_command_buffer`)
- **Status**: NEW (open-issue snapshot and `gh` searches for `cleared_on_skip`, "skip-clear latch submit failure" return nothing relevant; #3991's body lists volumetrics as a #917-compliant submit-time consumer, which holds for `history_valid` / `transport_fields` / `dispatched_this_frame` (promoted by `mark_frame_completed` after `queue_submit`) but not for this latch)
- **Description**: On a skipped frame (no TLAS yet, e.g. every frame at scene load) the first skip of a streak records `record_neutral_frame` (a `vkCmdClearColorImage` of `integrated_volumes[frame]`) and sets `volumetrics_cleared_on_skip[frame] = true` immediately. If that frame then fails at `end_command_buffer` / `reset_fences` / `queue_submit`, `draw_frame` returns `Err` before `current_frame` advances (`draw.rs:736`), the command buffer is discarded, the clear never runs, and the latch stays `true`. The retry on the same slot is again a skip, `skip_clear_decision(false, true)` returns `(false, true)`, so no clear is recorded. Composite keeps sampling the slot's last real integrated volume (the previous cell's fog), while the other slot shows the neutral volume: a visible flicker that persists until a real dispatch lands on that slot.
- **Trigger Conditions**: a skip-clear frame, followed by a tail submit failure on exactly that frame (host/device OOM, `ERROR_SURFACE_LOST`-style churn, i.e. the cases `draw.rs`'s #3837/#910 comments call reachable). Rare. Self-heals on the first real dispatch for the slot.
- **Verification Path**: pure CPU. A unit test that drives the decision + a simulated `Err` return is enough once the latch is promoted at submit. No RenderDoc/validation evidence needed because no barrier is involved.
- **Fix shape**: mirror #3991/#917 — record the latch into a "pending" value during recording and promote it where `mark_frame_completed` runs (after the successful `queue_submit`), or reset both latches in the failure arms that already call `rollback_skin_frame_state`.

### GPU sync half (Dim 2 / Dim 1, volumetrics)
- **Per-FIF indexing of every host-visible volumetrics buffer.** `param_buffers`, `fog_volume_buffers`, `fog_cluster_buffers`, `fog_cluster_index_buffers`, `combustion_light_moment_buffers`, `combustion_occupancy_buffers`, `integration_param_buffers` are all `Vec`s of `MAX_FRAMES_IN_FLIGHT` entries (`volumetrics.rs:585-660`, built in `init.rs` loops at `:400`, `:719`). Each descriptor set `f` binds slot `f` for writes and slot `previous = (f+N-1)%N` for the history samplers and occupancy-in (`init.rs:586-698`). Host writes in `dispatch` all target `[frame]` and all follow the all-slots fence wait (`sync_and_acquire_frame.rs`, `wait_for_fences(&in_flight, true, u64::MAX)`). No single shared buffer is written while a prior frame reads it.
- **The one cross-slot host-write hazard is the occupancy mask and it is a documented rider.** Frame N host-zeroes and seed-marks `occupancy[f]` while frame N-1 (slot `f^1`) reads that same buffer through binding 25. The all-slots wait retires N-1 first; `sync.rs` rider 15 names it and `frames_in_flight_contract_names_every_dependent_resource` greps `volumetrics.rs` for the name (passes). Every other volumetrics host buffer is read only by its own slot's set, so it does not depend on the all-slots wait. If #5365 narrows the wait, riders for this one mask are the only volumetrics items to migrate.
- **Device-side RAW/WAR on that mask** rests on the global COMPUTE `SHADER_WRITE -> SHADER_READ` `memory_barrier` at `post_passes.rs:740`, recorded before `write_lights_and_clusters` and `dispatch` in the same branch (it also supplies the execution dependency for the WAR against N-1's read). Its source scope reaches the previous submission. Stage B in `dispatch` carries the #5215 comment saying any narrowing of that barrier is a needs-syncval change. Unchanged.
- **History images (lighting / emission-history / combustion state, dynamics, optical).** Stage B (`dispatch`) emits `read_to_write(slot[frame])` and `write_to_read(slot[previous])` for all five fields in one COMPUTE->COMPUTE barrier before inject. Write-after-read on the recycled slot is covered (src `SHADER_READ`, which includes frame N-1's sampled history read of the slot), RAW of the previous slot is covered (src `SHADER_WRITE`). WAW against N-2's inject write is ordered by the Stage D `inj_to_int` barrier (write made available) plus the execution chain through the integrate read; whether sync-validation models that chain the same way is the only open question and is a HYPOTHESIS, not a finding: nothing in this area has produced a hazard in the CI lanes, and the default CI scene does not dispatch volumetrics.
- **inject -> integrate -> composite.** Stage D (`inj_to_int` write->read on `lighting[f]` plus `pre_int_write` on `integrated[f]` with source scope `SHADER_READ | TRANSFER_WRITE` at COMPUTE|FRAGMENT|TRANSFER, #3647) and Stage F (`integrated[f]` COMPUTE write -> FRAGMENT read) are present and ordered. `integrated_volumes` is sampled only by `composite.frag` (grep of every `.frag`/`.comp`/include for `sampler3D`/volumetrics confirms `water.frag`/`triangle.frag` do not read it).
- **Neutral/skip path.** `record_neutral_frame` uses `clear_general_accumulator` with `COMPUTE|FRAGMENT` consumer stages (the TRANSFER half is structural, #3844), so clear-to-clear and clear-to-inject edges are in the source scope. `record_skipped_frame` runs on every not-dispatched frame including the dispatch `Err` arm (#4780 guard passes). The `Err` arm only fires before any command is recorded (all fallible calls are the `write_mapped*` host writes above the first `cmd_*`).
- **Latch symmetry.** `tlas_written`, `lights_written`, `boundary_geometry_written` are set by the three `write_*` calls and cleared at the top of `dispatch`; both sides are inside the one `if let (Some(tlas), Some(..), Some(..))` branch of `record_volumetrics_pass`, so a gated-off frame touches neither. `VOLUMETRIC_OUTPUT_CONSUMED` gates the whole block.
- **TLAS -> compute.** The frame's single AS_WRITE -> AS_READ barrier (`dispatch_skin_and_cluster.rs:~410`) has `FRAGMENT_SHADER | COMPUTE_SHADER` in its destination and runs on both build arms; `ray_query_tlas(frame)` withholds the stale handle on a failed build (#4779, source-scan guard passes).
- **Moment-buffer readback.** `dispatch` ends with COMPUTE `SHADER_WRITE -> HOST HOST_READ`; `append_combustion_surface_lights` runs after the fence wait, calls `invalidate_if_needed` before the read and `flush_if_needed` after the zeroing fill, and consumes the dirty latch only on success (`latched_drain`, #4535). The HOST->COMPUTE barrier in Stage A has `SHADER_WRITE` in its destination so the host zero precedes the shader's `atomicAdd`s. Both moment and occupancy buffers are now zero-initialised at creation under the partial-cleanup owner (`67476a5d7`, #5772).
- **Light identities (`c705c310d`).** `LightHistory` is `[Vec<Identity>; MAX_FRAMES_IN_FLIGHT]`, remap reads `ids[previous]`, commit writes `ids[frame]`, and the CPU-side identity vec rides `collect_lights` -> `FrameInputs.light_ids` -> `frame_light_ids.resize(...)` (#5204) in lockstep. A tail submit failure re-uses the same slot (`current_frame` advances only after success), so the committed-but-never-rendered ids are overwritten, not consumed. `LightHeader` size is pinned to a multiple of 16 (`light_history.rs:187`).
- **Boundary-geometry bindings 19-21** are rewritten each dispatch from `instance_buffers()[frame]` and the registry's current global vertex/index buffers (so an instance-SSBO grow or geometry rebuild cannot leave a stale descriptor on the dispatched slot). `build_and_upload_instances` (incl. the final instance grow) runs before `record_geometry_pass` and before `record_post_passes`, so the buffer is final when volumetrics records. Inject reads only TLAS-instance indices (`rayQueryGetIntersectionInstanceCustomIndexEXT`), i.e. never the ground-cover model tier's tail written by compute (whose EMIT barrier does not target COMPUTE). That absence of a COMPUTE edge from the ground-cover tail write to the inject's whole-range descriptor read is a possible sync-validation report with no real data race (the tail is never indexed); HYPOTHESIS only, needs a `BYRO_VALIDATION=1` run on a ground-cover scene to decide, not filed.
- **Resize / teardown (Dim 6).** `recreate_bloom_and_volumetrics` runs after `device_wait_idle`, destroys the old pipeline, builds and `initialize_layouts` the new one (one-time submit, fence-waited), and `volumetrics_cleared_on_skip` is reset (`resize.rs:1349`). A failed rebuild returns `Err` and the callers (`app_events.rs:530`, `app_frame.rs:767`) call `event_loop.exit()`, so the dangling composite descriptor is never drawn. `destroy()` frees all eight image groups and all seven buffer vectors; teardown order is unconstrained apart from the three load-bearing ones, none involving volumetrics.
- **One-time submit in `initialize_layouts`** goes through `texture::with_one_time_commands` (queue Mutex held across submit, wait after unlock, #1713). It is the only blocking submit in the area and runs at creation/resize, not per frame.

### CPU half (Dim 3)
- **No ECS guard crosses `draw_frame`.** `build_render_data` returns an owned `RenderFrameView` plus caller-owned `Vec`s (`gpu_lights`, `light_ids`, `gpu_fog_volumes`). `app_frame.rs:615` passes borrows of `App` fields and values; every `try_resource` on the way (`LightTuning`, `ExposureTuning`, `DeltaTime`, `WindField`, `CinematicPresentationState`, `compute_underwater_params`) is dropped at the end of its statement or block. `compute_underwater_params` holds one read guard at a time (`systems/water.rs:575`).
- **`build_render_data`'s nested `rayon::join` is read-only.** The four joined branches (`collect_static_mesh_draws`, `collect_lights`, `collect_fog_volumes`, `fog_height_reference`) acquire only read guards (grep of every `query_mut` / `resource_mut` / `get_mut` in `byroredux/src/render/*.rs` leaves only test bodies and the pre-join / post-join statements `SceneEffectSoftCache`, `SkyParamsRes`, `WaterDrawIndexScratch`). No `Resource -> Storage` inversion against `PhysicsWorld` in the render path.
