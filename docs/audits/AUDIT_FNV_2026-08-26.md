## Executive Summary

**43 findings: 1 CRITICAL · 6 HIGH · 14 MEDIUM · 22 LOW.**

This is a sharp break from the 2026-08-24 sweep, which found 3 LOW and nothing
above. The difference is not that the engine got worse in 94 commits — it is
that this run pushed censuses down to the *wire* level (RTTI names rather than
parsed struct names; per-shape Havok CInfo bytes rather than block presence;
`spirv-dis` member counts rather than test-suite green) on a title whose
ordinary test gates are all passing. **Every one of the six HIGH-or-above
findings is invisible to `cargo test` at HEAD**, and four of them are invisible
*by construction*:

- **The reference path is the tested path.** `bhkRigidBodyT` ragdoll bodies
  (D7-02) are read one way in `template_from_imported` and another way in
  `extract_from_classic` from the identical bytes — but the non-T humanoid
  chain is correct to 0.12 BU, so `_male.nif` passes and 351 creature bodies
  across 160 files (dog, deathclaw, protectron, sentry bot) are seeded up to
  379 BU off their bone. The same shape of blind spot produces D7-01.
- **Presence assertions instead of value assertions.** The real-archive
  particle test (D6-04) asserts an emitter *exists*, so it stays green while
  62% of FNV birth rates fall back to a name heuristic (D6-03).
- **A baseline that cannot see the drift it exists to catch.** The per-block
  histogram keys on the parsed struct's name (D5-01), so 21.5% of FNV blocks
  are counted under a name they do not have, and a re-route between two
  structs sharing a `block_type_name` is structurally invisible to the gate.
- **A CI gate that is red and therefore silent.** The CRITICAL (RT-01) is
  caught by `scripts/check-shader-artifacts.sh` and by nothing else — and that
  script reports DRIFT at HEAD.

**The CRITICAL is a shader-struct lockstep break.** `ceb69d24`/`d9d4a6d7` grew
the shared `GpuMaterial` in `bindings.glsl` but recompiled only
`triangle.frag.spv`. Verified independently by the orchestrator:
`water.frag.spv` carries **91** `GpuMaterial` members, `triangle.frag.spv`
carries **108**, and the host pins 432 B (`gpu_material_size_is_432_bytes`).
Every FNV exterior water RT reflection/refraction/alpha-skip hit decodes a
misaligned material, including `parallaxMapIndex`/`glowMapIndex` fed straight
into `textures[nonuniformEXT(...)]` — an out-of-range bindless index, i.e.
undefined behaviour, not merely a wrong colour. It fixes with a plain `-V`
recompile; no source or pipeline change.

**Two findings falsify a premise the project has been acting on.** D1-03: FNV
ships 295 systematic object-LOD quads plus a shared atlas under
`meshes\landscape\lod\wastelandnv\blocks\` that no code path consumes — the
"FO3/FNV ship neither LOD scheme" claim in `exal.md:364` and
`placement_lod.rs` is falsified by the archive, and #2086 was closed on that
guess. D4-01: the in-code comment calling the FNV weapon AP cost an
"unconfirmed DNAM offset" is wrong — FNV authors a dedicated 20-byte `VATS`
sub-record on 245/261 weapons, and it has no dispatch arm at all.

**What is genuinely healthy.** The parse baselines are honest: 662 102 disk
blocks reconcile *exactly* with the checked-in baseline, the three re-baseline
commits in the delta window masked nothing, `parse_rate_fnv_esm` is exact at
`total=77828`, dispatch covers 106 of 107 record types, and all 183 distinct
Prospector meshes plus all 281 authored texture paths extract and resolve from
the real archives. The bench artifact re-processes to every ROADMAP figure
exactly. Roughly 60 named regression guards were verified still live
(catalogued below), several of them provably load-bearing rather than
vacuous — the SCHR-u16 fix protects 2 575 of 2 576 FNV scripts, the decal
slot `-8` applies to all 3 018 FNV blocks, and the pre-#1652 `havok_motion_type`
collapse would today mis-type 4 124 real FNV bodies.

**File**: `crates/nif/src/import/collision/shape.rs:154-164` (sibling cylinder arm `:167-176`),
consumed at `crates/physics/src/convert.rs:253-264`

**Premise verified**: current code at HEAD, reached by *both* the ragdoll path
(`extract_ragdoll` → `resolve_shape`) and the architecture path (`extract_from_classic` →
`resolve_shape`):

```rust

let p2 = finite_vec(havok_to_engine(s.point2[0], s.point2[1], s.point2[2]) * scale)?;

origin and always along +Y**. Both the midpoint `(p1+p2)/2` and the axis direction `p2-p1` are

(`nif.xml:3079-3086`, `bhkCapsuleShape`): `First Point` / `Second Point` = "First/Second point on
the capsule's axis" — they define placement *and* orientation in the shape's own (host-node) space.

Corpus-wide over all 20 746 FNV NIFs: **1363 `bhkCapsuleShape` blocks; 1321 (96.9 %) have a

regression-guarded.

`ragdoll::tests::imported_root_space_body_pose_converts_to_bone_local_once` accordingly, and add a
real-data pin asserting no FNV ragdoll body's local offset exceeds e.g. 40 BU.

**Evidence** — census of `PSDT.time >= 0 && PSDT.duration == 0` in

procedure):

```
The complementary cases are all handled correctly and are worth recording
as guards: 2813 packages use `time = -1` (`start_hour = None` → always

`duration.max(0)` clamp at `pack.rs:901` never fires on this corpus.

**Impact**: 5 FNV Travel packages are unreachable by the engine's package
selector — `HVPaladinPatrolGoToLocker` and `RCSecurityUnlockHangar6x0Alt`
are Hidden Valley / REPCONN scripted-movement packages whose actors will
simply never travel. Small absolute count, and the *correct* semantic for
duration 0 is not documented anywhere I could reach (the GECK exposes it
as a plain integer; nothing in this repo or in `docs/legacy/` states what
the original engine does with a zero-length window), so I am **not**
proposing a specific value — per the no-guessing policy.

**Fix sketch**: do not guess a replacement semantic. Either (a) confirm the
original behavior from xEdit / GECK docs before changing `active_at`, or
(b) at minimum surface it — `parse_pack` should `log::debug!` when it
decodes a `start_hour.is_some() && duration_hours == 0` PSDT, so the
unsatisfiable window is visible rather than silent.

### [LOW] FNV-2026-08-26-D9-07: `ambient_ai_package_system` heap-clones every actor's PKID candidate `Vec` on every frame, before the once-per-game-minute guard that exists to avoid the work

*Dimension 9 — AI Packages & Procedures*

**File**: `byroredux/src/npc_spawn/ai_package.rs:515-529`

**Premise verified**:
```rust
let runtimes: Vec<(EntityId, AmbientPackageRuntime)> = world
    .query::<AmbientPackageRuntime>()
    .map(|query| query.iter().map(|(actor, runtime)| (actor, runtime.clone())).collect())
    .unwrap_or_default();
…
for (actor, runtime) in runtimes {
    …
    if !explicitly_requested && runtime.last_evaluated_game_minute == Some(minute) { continue; }
```
`AmbientPackageRuntime::package_candidates` is a `Vec<u32>`, so `.clone()`
is a heap allocation per actor. The minute-gate — the entire point of
which is *"Schedule-only checks are bounded to one evaluation per in-game
minute per actor"* (module doc, `ai_package.rs:508-512`) — is checked
**after** the clone, so the allocation happens 60×/second regardless. The
loop also takes a fresh per-entity read lock via `world.get::<Dead>` and
`world.has::<EvaluatePackageRequest>` before the same gate.

**Evidence**: the system is registered unconditionally
(`boot.rs:900`, `Stage::Update`, exclusive) — unlike the seven locomotion
systems it is **not** behind an env gate, so this cost is paid in the
default configuration. FNV corpus: 3073 of 3816 NPC_ records carry PKID,
mean 2.4 entries (max 14), so each clone is a small `Vec<u32>` — the finding
is the churn shape (N allocations + 2N lock acquisitions × every frame),
the same class as #3269 but a different site and a different component.
At the default `time_scale = 30.0` (`components/game_time.rs:7`) an in-game
minute is 2 real seconds, so ~119 of every 120 frames' worth of that work
is thrown away.

**Fix sketch**: read `last_evaluated_game_minute` (a `Copy` field) under the
query without cloning, collect only the entities that actually need
re-evaluation, then clone `package_candidates` for that (usually empty) subset
— or keep a persistent scratch `Vec` in a `make_ambient_ai_package_system()`
factory, the same `#2033`/PERF-D1 pattern the six locomotion systems already use.

### [LOW] FNV-2026-08-26-D9-08: `sandbox_seat_system` rebuilds the whole world-space seat table and its `HashMap` every frame, forever, including after every actor is already seated

*Dimension 9 — AI Packages & Procedures*

**File**: `byroredux/src/systems/sandbox.rs:170-196`

**Premise verified**: the early-outs are `SandboxSitClip` missing,
`SandboxBehavior` storage missing, `GlobalTransform`/`Furniture` storage
missing, and `seats.is_empty()`. None of them is "every sandboxing actor is
already `Seated`". The seat build runs unconditionally before the actor
loop:
```rust
scratch.seats.clear();
scratch.seat_meta.clear();
for (furn_e, furn) in furn_q.iter() {
    let Some(furn_g) = gq.get(furn_e) else { continue };
    for (idx, marker) in furn.markers.iter().enumerate() {
        if !is_sit_marker(marker) { continue; }
        scratch.seats.push((seat_id, seat_world_transform(furn_g, marker)));
        scratch.seat_meta.insert(seat_id, (marker.local_offset, furn_g.translation));
    }
}
if scratch.seats.is_empty() { return; }
```
`SandboxBehavior` is never removed on seating (only `Seated` is added, and
the actor loop skips on it), so `sandbox_q` stays non-empty and this runs
every frame for the life of the cell. `seat_meta` exists only to feed the
one-shot `log::info!` diagnostic emitted per assignment, yet it is
re-hashed in full every frame.

**Impact**: opt-in (`BYRO_SANDBOX_SIT`), and per-frame cost is
O(furniture entities × markers) plus one `HashMap` insert per sit marker —
a `GlobalTransform::compose` and a hash per seat per frame in a
furniture-dense FNV interior. Not a default-configuration regression, but
it is unbounded work with a trivially available early-out. Distinct site
from #3269 and from D9-07 above.

**Fix sketch**: skip the whole Pass-1 body when every `SandboxBehavior`
actor already carries `Seated` (a cheap `sandbox_q`/`seated_q` count
compare); and build `seat_meta` lazily inside the assignment branch, since
it is only ever read for the entries that produce a log line.
