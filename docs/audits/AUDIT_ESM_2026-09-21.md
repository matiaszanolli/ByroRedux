# ESM / Plugin Parser Audit — 2026-09-21

**Scope**: `crates/plugin/src/` as a parser — header detection and GRUP walk, sub-record byte
accounting, per-record schema dispatch, FormID load-order remap, CELL/WRLD walkers, localized
strings, the `EsmIndex` → ECS handoff, and the Redux-native tier. No arguments were passed, so the
defaults applied: all dimensions, all games, depth `deep`. This was one leg of
`/audit-suite --preset comprehensive`, with no sub-agents. Each dimension was analysed in turn and
its notes were written to `/tmp/audit/esm/dim_<N>.md` before the next dimension started.

**Test baseline**: `cargo test -p byroredux-plugin -j 4` gives **1,027 passed** (1,024 lib + 1
integration + 2 doc), **0 failed** and **57 ignored**. Every ignored test needs game data on disk.
The baseline figures were 964 passed and 55 ignored. No named guard is `#[ignore]`d. The
`--ignored` suite was not run (*plugin_ignored_tests_oom*).

**Reference layouts**: xEdit `dev-4.1.6`, specifically *Core/wbDefinitions{TES4,FNV,TES5,FO4,FO76,SF1,Common}.pas*,
`wbInterface.pas` and `wbImplementation.pas`. These files are not in the repo. For this run they were
fetched to `/tmp/audit/esm/xedit/`. Every width claim below cites them.

**Real data**: all seven installed vanilla masters were parsed, one process at a time, under
`ulimit -v`. Each master went through both the raw-walk coverage probe and the production
`parse_esm` bench. Header-only Python scans read the TES4 header of every installed
.esm/.esp/.esl file (178 files across 8 installs), and targeted sub-record censuses ran on
specific (record, sub-record) pairs. The run used no engine instance, no `--ignored` tests and no
release build. The examples were built with the dev profile (opt-level 1 plus overflow checks), so
parse *times* cannot be compared with the release baseline; peak RSS can.

**What the delta was.** The baseline's findings were largely closed in the interval: its seven
Localized-Strings findings, the `group_type` bug, XEZN, `from_subs`, TRDA, lstring 0, the
zero-table warning and the `categories()` guard. Each of those fixes was re-verified against
current source, and all of them hold (see *Verified-Fixed*). The interval also added new decode
surface: LSCR, APPA, CLOT, carryable LIGH, SCRL, CCRD/CMNY, FNV IMOD, ALCH/MGEF consumption fields,
FO76 split `LVLO`, LTEX `GNAM`, the Skyrim LE `GameKind` arm and Starfield LIGH `DAT2+56`. Every new
width was re-derived from xEdit, and every new decode is correct as written. **The findings below
come from what the new code and the prior fixes did not reach.**

**The five MEDIUMs:**
1. **Oblivion leveled lists (ESM-2026-09-21-D2-01).** Two legacy TES4 encodings are not normalized.
   Eight-byte `LVLO` rows (count omitted) are dropped, and `LVLD`'s `0x80` bit (the legacy "all
   levels" flag) is read as chance-none 128. As a result **18 Oblivion LVLIs expand to nothing**,
   among them Arena gear, Fighters Guild quest gear, Oblivion-gate loot and Dark Brotherhood
   rewards. This decode has been wrong since M24.
2. **Starfield master flags (ESM-2026-09-21-D3-01).** The reader tests TES4 bit `0x200` as "light
   master" on every game. On Starfield, `0x200` is *Update*, and the small-master bit is `0x100`,
   which 16 official `.esm` files carry. Those 16 therefore take regular slots, and a plugin
   carrying `0x200` would be truncated into 12-bit ESL space.
3. **Compressed-record ceiling (ESM-2026-09-21-D1-03).** The ceiling's calibration census covered
   three masters, and its doc says Oblivion "compresses nothing", but Oblivion has 41,789 compressed
   records. **82 vanilla Starfield `SFTR` records (724–786:1) fail the ceiling** as "corrupt or
   hostile". Today they sit in an unrouted group. The Starfield audit lists SFTR as a next decode
   target, and the first SFTR arm would fail the whole Starfield.esm parse.
4. **FO4 terminals (ESM-2026-09-21-D2-02).** The #4171 fix does not read FO4's `UNAM` "Display Text".
   1,804 of 1,818 terminal entries in `Fallout4.esm` keep their bodies there, and `WNAM`/`NAM0` and
   multi-`BTXT` bodies are also dropped.
5. **LTEX grasses (ESM-2026-09-21-D2-03).** `LTEX.GNAM` is an array of grasses, but the map keeps one
   per LTEX. In real data, 151 of 184 grass-bearing LTEX records author 2–4 grasses.

**The LOWs** are:
- FO76 HEDR drift. The game patch of 2026-09-20 moved it from 266.0 to 279.0. Classification is
  unaffected, but code, docs and the skill still pin 266.
- The skip-arm half of #3721's GRUP clamp.
- The #4068 fix's false premise that `TRDA` has no cited layout; xEdit has one.
- Two sibling "Oblivion-only ACRE" comments that #3755 did not reach.
- Two leftover references to the deleted *legacy/* module.

**Coverage posture**:
- Routing is unchanged on Oblivion, FO3, FNV and FO4, apart from the probe-methodology notes in the
  matrix.
- Skyrim gained the 74 SCRL records.
- Sub-record unknown share fell on every master, from 13.16% to 11.93% on FO4, mostly because the
  ~75k `TRDA` occurrences are now matched.
- Peak RSS rose by a uniform 2–3%.
- All seven masters walk to EOF and parse `Ok` with overflow checks on.

## Findings

### MEDIUM

#### ESM-2026-09-21-D2-01: Oblivion's legacy leveled-list encodings are not normalized — 8-byte `LVLO` rows are dropped and `LVLD`'s 0x80 flag bit is read as chance-none 128, so 18 LVLIs expand to nothing
- **Severity**: MEDIUM
- **Dimension**: Sub-Record Byte Accounting
- **Record / Sub-record**: `LVLI` / `LVLC` / `LVSP` — `LVLO`, `LVLD`, `LVLF`
- **Location**: `crates/plugin/src/esm/records/container.rs:203` (`LVLD` → `chance_none = sub.data[0]`), `crates/plugin/src/esm/records/container.rs:235-246` (`b"LVLO" if sub.data.len() >= 12`); consumer `crates/plugin/src/equip.rs:788`
- **Status**: NEW (both defects date from the original M24 parser, 470ddd2f1, and neither has been reported before)
- **Description**: `parse_leveled_list_for_game` has two problems with legacy TES4 encodings.
  (a) xEdit's shared `wbLeveledListEntry` makes `Count` optional (`SetOptionalFrom(3)`, default 1).
  A TES4 `LVLO` can therefore be 8 bytes (Level, pad, Reference), and the decoder's `>= 12` guard
  drops such rows entirely.
  (b) xEdit's TES4 `wbLVLAfterLoad` treats the high bit of `LVLD` as the legacy "Calculate from all
  levels" flag: it masks the bit off chance-none and ORs `0x01` into `LVLF`. Redux stores the raw
  byte instead.
- **Evidence**:
  - xEdit sources: `wbDefinitionsCommon.pas:9062-9076` and `wbDefinitionsTES4.pas:755-775`
    (`if (Chance and $80) <> 0 then Chance := Chance and not $80; LVLF := LVLF or $01`).
  - Real data, `Oblivion.esm` (`/tmp/audit/esm/lvlo8.py`, `lvld.py`):
    - (a) 94 LVLO rows are 8 bytes long, spread over 14 lists. In every one of those 14 lists
      *all* rows are 8 bytes, so each decodes to `entries = []`. The lists are
      TesKvatchCreature (LVLC), OblivionContainerArmor01/02, OblivionContainerWeapon01,
      FGC03ThiefWeapons (25 rows), FGC03ThiefArmor (17), Dark02RewardRing, Dark03RewardDagger,
      Dark05RewardHeart, Dark06RewardBow, ArenaYellowArmor, ArenaBlueArmor, ArenaRandomShields and
      ArenaRandomHelmets.
    - (b) 11 lists have `LVLD = 128`: 6 LVLC (MQ14ClanfearMedium, KvatchCastleCreature,
      KvatchCountsChamberCreature, OblivionGateHard/Medium, ArenaMonsters1) and 5 LVLI
      (ArenaLeveledGoldGrandRecur/BeatGrand/Champ/Reward, Dark07RewardFinery).
  - Other masters: FO3, FNV, SSE and FO4 use only 12-byte `LVLO`, and their `LVLD` values never
    exceed 100.
- **Impact**:
  - (a) The 13 affected LVLIs are empty in both live resolvers. NPC inventory and outfits go through
    `expand_leveled_form_id` (`npc_spawn.rs:1161/1190`, `inventory.rs:395/417`); container loot goes
    through `expand_leveled_loot` (`byroredux/src/cell_loader/references/attach.rs:234`).
  - (b) The 5 affected LVLIs are empty in container loot, because `equip.rs:788` treats
    `chance_none >= 100` as always-empty.
  - Players see Arena combatants and Fighters Guild thieves without their authored gear, empty
    Oblivion-gate containers and empty Dark Brotherhood reward lists.
  - The 7 affected LVLCs lose data but have no current consumer.
- **Related**: #4248 (OPEN, FO4 container LVLI expansion; a different defect), ESM-2026-09-21-D4-* coverage notes
- **Suggested Fix**:
  - Accept `LVLO` rows of 8 bytes or more; read `Count` only when the row is at least 10 bytes and
    default it to 1 otherwise.
  - Mask `LVLD & 0x7F` and OR `0x01` into the flags when bit 7 is set, mirroring `wbLVLAfterLoad`.
  - Pin both behaviours with fixtures.

#### ESM-2026-09-21-D3-01: Starfield's TES4 master flags are decoded with the Skyrim/FO4 bit layout — the real small-master bit (0x100) is ignored and 0x200 ("Update") is treated as ESL
- **Severity**: MEDIUM
- **Dimension**: FormID Remap, Load Order & ESL Space
- **Record / Sub-record**: `TES4` record-header flags
- **Location**: `crates/plugin/src/esm/reader.rs:1043` (`light_master = header.flags & 0x0200 != 0`, every game); doc `crates/plugin/src/esm/reader.rs:588-602`; consumer `byroredux/src/cell_loader/load_order.rs:604`, `:644-675`
- **Status**: NEW. The ESH/`0xFD` "Medium" half has been a known gap since #4384 closed with "fold ESH 0xFD into `GlobalSlot` when needed", and no open tracker covers it.
- **Description**: `read_file_header` derives `light_master` from bit `0x200` on every game. According
  to xEdit:
  - Starfield's small-master bit is `0x100`; `0x200` is *Update* and `0x400` is *Medium*.
  - Oblivion, FO3/FNV, Skyrim LE and FO76 do not support light masters at all.
- **Evidence**:
  - `wbInterface.pas:20575-20592`: `IsLight` tests `$100` when `wbIsStarfield`, else `$200`, and
    `IsUpdate` is `$200` on Starfield.
  - `wbInterface.pas:5358-5361`: `wbIsLightSupported` = SSE / EnderalSE / FO4 / SF1 only.
  - `wbDefinitionsSF1.pas:9045-9053` lists the SF1 TES4 flags.
  - Installed Starfield plugins (`/tmp/audit/esm/tes4_headers.py`):
    - **16 official masters carry `0x100`**: Constellation.esm (0x181), OldMars.esm (0x181),
      SFBGS004/007/008, the sfbgs00a_* files, SFBGS00c/019/021/023/047, and others.
    - About 20 installed mods carry `0x101`.
    - SFBGS003, SFBGS006, kgcdoom and neonvertigo carry `0x400` (Medium).
    - None carries `0x200` today.
  - The doc comment's claim that no vanilla "Starfield master (.esm) is ESL-flagged" is true only
    because the wrong bit is tested.
- **Impact**:
  - Every Starfield small master takes one of the 254 regular slots, and `allocate_global_slot`
    hard-errors once `0xFD` is passed. A Creations-heavy Starfield load order that the game accepts
    is therefore refused.
  - Redux's global FormIDs for these plugins also differ from the game's FE-space ids.
  - A Starfield "Update" plugin, or any `0x200`-flagged plugin on a title without ESL support, is
    packed into `0xFE` space with its object ids truncated to 12 bits (`GlobalSlot::compose`), so
    distinct forms collide in `EsmIndex`.
- **Related**: #1554, #3546, #4384 (all CLOSED)
- **Suggested Fix**:
  - Decode the flag per game. `read_file_header` already has the variant and HEDR inputs `GameKind`
    is computed from.
  - Starfield: `0x100` is small and `0x400` is medium (a new `GlobalSlot::Medium` = `0xFD` + 8-bit
    index + 16-bit id); ignore `0x200`.
  - SSE and FO4: `0x200`.
  - Every other game: no light masters.

#### ESM-2026-09-21-D1-03: the compressed-record inflation ceiling was calibrated on three masters — 82 vanilla Starfield `SFTR` records (724–786:1) are rejected as "corrupt or hostile"
- **Severity**: MEDIUM
- **Dimension**: Header & GRUP Walk (the real-data evidence comes from Dim 8)
- **Record / Sub-record**: `SFTR` (Starfield); every record with `FLAG_COMPRESSED` set
- **Location**: `crates/plugin/src/esm/reader.rs:34-67` (`MAX_RECORD_INFLATION_RATIO = 512` plus its census doc), `crates/plugin/src/esm/reader.rs:784-790` (rejection), `crates/plugin/src/esm/reader.rs:2085-2105` (`inflation_ceiling_clears_every_observed_vanilla_shape`)
- **Status**: NEW. The calibration comes from #3399/#3410 (CLOSED) and was never measured beyond FNV, SSE and FO4.
- **Description**: The ceiling's doc and its test cite "Census over every compressed record in four
  shipped masters — 33 179 in `FalloutNV.esm`, 44 153 in `Skyrim.esm`, 56 399 in `Fallout4.esm`, 0
  in `Oblivion.esm`, which compresses nothing", with a worst real ratio of 102.1:1. The census
  missed four masters, and one of them exceeds the bound.
- **Evidence**:
  - A header-only scan (`/tmp/audit/esm/ratio.py`) reproduces the three cited counts exactly.
  - The same scan finds:
    - `Oblivion.esm`: 41,789 compressed records (worst 101:1).
    - `Fallout3.esm`: 41,903 (worst 75:1).
    - `SeventySix.esm`: 74,834 (worst 19:1).
    - `Starfield.esm`: 91,149, of which **82 exceed the ceiling**. All 82 are `SFTR` records in the
      top-level SFTR group. Examples: `0x00167A07`, 834 bytes inflating to 655,482 (786:1);
      `0x000478BB`, 846 bytes inflating to 655,493 against a ceiling of 433,152.
  - `esm_dim8_coverage` hits the error "Compressed record 000478BB declares 655493 uncompressed bytes
    … over the 433152 ceiling; plugin is corrupt or hostile", and its SFTR census stops there.
- **Impact**:
  - This is latent today. SFTR is not dispatched, so the top-level loop `skip_group()`s it without
    inflating, and every master still parses `Ok`.
  - The rejection is a hard `Err` that `?`-propagates out of `parse_esm_with_load_order`.
    `load_order.rs` then merges `EsmIndex::default()` for the plugin. The first SFTR decoder
    (AUDIT_STARFIELD_2026-09-16 lists SFTR as a next target), or any walker that reads the
    sub-records of every record, would therefore silently drop **all** of `Starfield.esm`.
  - The doc, the test and the skill all assert a calibration that real data falsifies.
- **Related**: #3399, #3410 (CLOSED); `byroredux_bsa::safety::inflate_bounded`, whose parity the skill requires
- **Suggested Fix**:
  - Re-run the census over all seven masters and re-derive the bound so that 786:1 clears it with
    margin. The 64 MiB absolute cap and the `take(declared + 1)` decode limit remain the real bomb
    guards.
  - Correct the doc and test numbers, and pin the SFTR shape (834 → 655,482).
  - Consider making an over-ceiling record a per-record skip plus warning rather than a whole-parse
    `Err`.

#### ESM-2026-09-21-D2-02: #4171's TERM fix still drops most Fallout 4 terminal text — `UNAM` display text, `WNAM`/`NAM0`, and conditional `BTXT` bodies
- **Severity**: MEDIUM
- **Dimension**: Sub-Record Byte Accounting (with Localized-Strings consequences)
- **Record / Sub-record**: `TERM` — `UNAM`, `WNAM`, `NAM0`, `BTXT` (+ CTDA), `BSIZ`
- **Location**: `crates/plugin/src/esm/records/misc/world.rs:1544-1619` (`parse_term`), `crates/plugin/src/esm/records/misc/world.rs:1517-1542` (`TermRecord`)
- **Status**: NEW. This is a residual of CLOSED #4171 (ESM-2026-09-11-D6-04), whose suggested fix named only ITXT, BTXT and RNAM.
- **Description**: The FO4 `TERM` layout is:
  - `NAM0` (Header Text) and `WNAM` (Welcome Text), both lstrings.
  - A `BSIZ`-counted array of `{BTXT, Conditions}` body texts.
  - Menu items of `{ITXT, RNAM, ANAM Type, ITID, UNAM 'Display Text', VNAM, TNAM, Conditions}`. For
    `ANAM = 8` ("Display Text") items, the text shown is `UNAM`.

  `parse_term` has no arm for `NAM0`, `WNAM` or `UNAM`. It keeps a single `body_text`, where the
  last `BTXT` wins and its conditions are discarded.
- **Evidence**:
  - xEdit: `wbDefinitionsFO4.pas` `wbRecord(TERM …)` (the `BSIZ` RArray and the menu-item struct).
  - `Fallout4.esm` census (`/tmp/audit/esm/termcensus.py`, 778 TERM records):
    - 1,818 menu items have ANAM = 8, and **1,804 of them carry their text in `UNAM`**.
    - 467 TERMs author `WNAM` and 291 author `NAM0`.
    - 82 TERMs author 2–7 conditional `BTXT` bodies.
  - The FNV layout (DESC, ITXT/RNAM/ANAM) is decoded correctly.
- **Impact**: This is latent, because nothing consumes `TermRecord` text yet. The parser is the
  only place the content can be recovered, and it currently keeps the entry titles and none of their
  bodies for nearly every FO4 terminal log entry. A terminal UI built on this decode would render
  FO4 entries empty.
- **Related**: #4171 (CLOSED)
- **Suggested Fix**:
  - Add `UNAM` as a per-item `display_text` read through `read_lstring_or_zstring`.
  - Add record-level `NAM0` and `WNAM`.
  - Model the body as a `Vec<(text, conditions)>`, mirroring the menu-item shape.

#### ESM-2026-09-21-D1-02: the #3721 parent-end clamp covers only the *recurse* arm — every *skip* arm still seeks by the child's raw declared size
- **Severity**: LOW
- **Dimension**: Header & GRUP Walk
- **Record / Sub-record**: GRUP headers
- **Location**: `crates/plugin/src/esm/reader.rs:947-949` (`skip_group`), `crates/plugin/src/esm/reader.rs:1011-1017` (depth-cap arm of `bounded_group_content_end`); skip arms at `crates/plugin/src/esm/cell/walkers.rs:196,200`, `crates/plugin/src/esm/cell/wrld.rs:57,61,347,351` and `crates/plugin/src/esm/records/grup_walker.rs:249`
- **Status**: NEW. This is a sibling residual of CLOSED #3721 (ESM-2026-08-30-D1-01) and #4076, which clamp only the `sub_end` handed to a recursive call.
- **Description**: `parse_cell_group_inner`, `parse_wrld_group` and `parse_wrld_children_inner`

  depth-cap arm inside `bounded_group_content_end` also calls the unclamped skip.
- **Evidence**: The depth-cap guard (`grup_walker.rs:524`) builds only well-formed nesting, so it

- **Related**: #3721, #4076 (CLOSED)
- **Suggested Fix**: Skip to the already-computed clamped `sub_end` (for example with a `seek_to`
  helper), clamp the depth-cap skip to `parent_end`, and add a fixture with an overrunning child in a
  skip arm.

## Disproved / not reportable

- **CELL-level `XWCU` removed (052c0a393).** 20 of the 21 Skyrim CELL payloads are all-zero, and the
  remaining one looks like position/direction data. The removal is defensible, and WATAL owns the
  semantics.
- **Skyrim WATR's three identical `NNAM`s collapse last-wins.** The values are identical on all 31
  vanilla records, so nothing is lost.
- **`StringTableSet::resolve` searches all three tables for any id.** SSE has 0 cross-table id
  collisions. FO4 has 2 (Creation Club paint-job ids whose DLSTRINGS copies are Japanese leftovers),
  which is negligible.
- **`VTXT` silently ignores a trailing partial row.** Measured `len % 8 == 0` on 524k payloads across
  three masters, so the case never occurs.
- **Identity-remap guard.** Its enclosing-fn scan skips `pub(super)` and `pub(crate)` fns, but no such
  site exists today.
- **`decode_entry`'s cp1252 fallback is whole-entry**, although its doc says per-run. This is harmless
  on the measured tables.
- **LSCR on FO76** decodes only EDID, DESC and CTDA. That is coverage, not a width bug.
- **The FO76 split-LVLO citation "3918–3923"** has drifted on the moving `dev-4.1.6` branch (the
  definitions are now at :4117-4125 and :12318-12366). The decode is correct.
- **Skyrim.esm CELL 0x25** has a 64-byte all-zero `XCLL`. This is one dev cell and one warning.
