### REN-D2-01: RLT-IBL-004's sky-occlusion ray treats alpha-tested foliage, fences and grates as solid
- **Severity**: MEDIUM
- **Dimension**: Ray Queries
- **Location**: `triangle.frag` `main()` (the `exteriorSkyProbe && probeShare > 0.0 && reflectionGlassRayEnabled && !helperLane && !hasAuthoredCubemap` block, calling `traceShadowBinary(..., VISIBILITY_MASK_ALL_OPAQUE)`); `include/shadow_common.glsl` `traceShadowBinary`; contrast `include/shadow_transport.glsl` `traceShadowTransmittanceDetailed`
- **Status**: NEW (introduced by 5f51748d5, RLT-IBL-004 rev 49; the #7269 follow-up did not touch it)
- **Description**: `traceShadowBinary` initialises its ray query with `gl_RayFlagsOpaqueEXT | gl_RayFlagsTerminateOnFirstHitEXT` and never inspects the hit, so every instance whose visibility layer is in `VISIBILITY_MASK_ALL_OPAQUE` (15 = architecture | static prop | dynamic actor | foliage) is a solid occluder, including cutout cards (alpha-tested leaves, fences, grates). The direct-light path does not do this: `traceShadowTransmittanceDetailed` is "an alpha-aware binary blocker" (`alphaSensitive = hitMat.alphaThreshold > 0.0 || INSTANCE_FLAG_ALPHA_BLEND`, advances past uncovered texels), and `traceWaterRay`/`traceReflection` document the same rule ("Alpha-tested leaves, grates, and other cutouts must not become solid slabs"). The sky ray replaced SSAO, whose depth buffer only contains the *alpha-passing* texels, so under a canopy or beside a fence the old form saw the real aperture and the new one sees a full quad per card.
- **Evidence**: `traceShadowBinary` body (`rayQueryInitializeEXT(rq, topLevelAS, gl_RayFlagsOpaqueEXT | gl_RayFlagsTerminateOnFirstHitEXT, mask, ...)`, returns `rayQueryGetIntersectionTypeEXT != None`); call site passes `VISIBILITY_MASK_ALL_OPAQUE`; `VISIBILITY_LAYER_FOLIAGE` = 8 is inside that mask. The PRD's own A6 contact-sky rung uses rigid casters only; RLT-CON-008's alpha-tested caster is an A5 (direct-shadow) row. The sun ray through the same canopy is dappled while the sky specular is darkened as if the canopy were solid.
- **Impact**: exterior glossy surfaces (wet/metal/rough-dielectric sky probe share) under vegetation, fences and grates lose their sky specular wherever a lobe sample crosses a card's *quad*, not its coverage. Magnitude is bounded by the probe share times `lobeWeight` (about 1.0-1.2 for roughness <= 0.5, up to ~3 at roughness 1; computed from the generated LUT), and is stochastic, so TAA smooths it into a darkened, not noisy, look. Visual only; no corruption or hang.
- **Related**: PRD `docs/prd/reference-lighting.md` RLT-IBL-004 / rev 49; RLT-CON-008; #7269 (same block, authored cubemaps).
- **Suggested Fix**: use the alpha-aware walk the direct path already has (a 2-3 layer cap is enough for a sky ray), or as a cheaper first cut drop `VISIBILITY_LAYER_FOLIAGE` from the mask and add an alpha-tested caster row to the contact-sky A6 rung so the choice is measured. Extend `environment_specular_is_the_exact_split_sum_with_probe_occlusion` to assert whichever is chosen.

### REN-D2-03: RLT-IBL-004's exterior ray is outside both the ray-quality tiers and the A13 cost gate
- **Severity**: LOW
- **Dimension**: Ray Queries / Performance coupling
- **Location**: `triangle.frag` sky-occlusion block (gate: `exteriorSkyProbe`, `probeShare`, `reflectionGlassRayEnabled`, `rtLOD < RT_LOD_REFLECT`, `DBG_DISABLE_AO`; no `rayBudget.qualityTier` term); `ray_budget.rs` `AdaptiveRayBudget::settings_for_tier`
- **Status**: NEW (the cost is disclosed in PRD rev 49: "its scenes are interiors, so the exterior ray's cost is not in it", and §6 row 12 "One more ray per exterior probe pixel"; no issue exists. `gh issue list --state all --search "sky occlusion ray exterior cost"` is empty)
- **Description**: tier 0 is documented as the watchdog-safe floor ("direct shadows but no diffuse path"), and #7076 / PAF-012 shed work by tier. The new ray fires for every non-glass exterior pixel with `rtLOD < 3` (about 1.3 BU per pixel and below, so most of the visible frame) at *every* tier, and the controller's cost model cannot shed it. The only cost evidence (A13) is on interior scenes, so the ray's cost on Whiterun-class exteriors is unmeasured, and the `floor` the controller learns now silently includes it (raising the climb target via #7076's `floor + ADDED_COST_ALLOWANCE_MS`).
- **Evidence**: `traceEnvironmentRay`-style gating only; `GpuRayBudget` has no field the block reads; PRD rev 49 text quoted above.
- **Impact**: potential frame-time regression on exteriors with no way for the adaptive budget to recover it; also feeds the heavy-scene-floor logic. No correctness impact.
- **Related**: #7076, #7221 (same "premium" accounting), PRD rev 49 A13 note.
- **Suggested Fix**: run A13-style exterior cases (Whiterun, Prospector exterior) with the ray on/off; if the cost matters, gate the ray on `rayBudget.qualityTier >= 1` (the SSAO form is already the fallback beside it).

### REN-D2-02: The environment-specular term no longer reads the material's `fresnelPower`; a dead `F` local remains
- **Severity**: LOW
- **Dimension**: Ray Queries (shading consistency)
- **Location**: `triangle.frag` `main()` environment block (`vec3 F = fresnelSchlickPower(NdotV, F0, mat.fresnelPower);` then `environmentWeight = F0 * envAB.x + envAB.y`); `include/lighting.glsl` `shadowableLightRadiance` (still uses `mat.fresnelPower`), `triangle.frag` `primaryDiffuseWeight` (still uses it)
- **Status**: NEW (introduced by 84104564e, RLT-IBL-003; owner-approved split sum, but the fresnelPower consequence is not recorded in the PRD, `grep fresnelPower docs/prd` is empty)
- **Description**: before RLT-IBL-003 the env term was `envColor * F * (1 - roughness)` with `F = fresnelSchlickPower(NdotV, F0, mat.fresnelPower)`. The split sum bakes the standard (1-VH)^5 Schlick into the LUT, so an authored `fresnel_power` (BGSM / BSLightingShaderProperty / material translate carry non-default values, e.g. 3.5, 4.5; default 5.0) now changes the light-loop specular and the diffuse weight but not the environment specular. `F` at the top of the block is dead (the compiler drops it) and reads as if it still mattered.
- **Evidence**: `fresnelPower` consumers at HEAD: `lighting.glsl` light loop, `triangle.frag` glass scalar Fresnel, eye Fresnel, `primaryDiffuseWeight`; absent from the environment `Lo +=`.
- **Impact**: for materials with non-default power the three lobes (diffuse weight `1 - F(p)`, light-loop spec F(p), env spec F(5)) stop agreeing on one Fresnel curve. Small and only off-default; also a silent change to authored-content response.
- **Related**: RLT-IBL-003; `docs/engine/nifal.md` lists `fresnel_power` as carried.
- **Suggested Fix**: owner decision: either record "authored fresnel power does not reach the environment split sum" in the PRD / nifal.md and delete the dead `F`, or fold it in (e.g. blend the LUT `B` term by the power). Measure on a non-default-power FO4 BGSM first.

### REN-D10-01: The environment term's multi-scatter compensation still reads Karis's 2014 fit, not the exact table the same term uses
- **Severity**: LOW
- **Dimension**: Disney BSDF
- **Location**: `triangle.frag` `main()` environment block (`vec2 envAB = envBRDFLut(NdotV, roughness); ... environmentWeight *= multiScatterEnergyCompensation(F0, NdotV, roughness);`); `include/pbr.glsl` `multiScatterEnergyCompensation` (its `Ess` is `envBRDFApprox`'s `ab.x + ab.y`)
- **Status**: NEW (introduced as a consistency gap by 84104564e, RLT-IBL-003; `gh issue list --state all --search "multi-scatter energy compensation"` and `"multiScatterEnergyCompensation envBRDFApprox"` return nothing)
- **Description**: RLT-IBL-003 replaced the env weight with `F0 * A + B` from the exactly integrated table (separable exact Smith G1, `scripts/gen_env_brdf_lut.py`) because the 2014 fit "measured 0.83-1.16 of the exact weights". The multiple-scatter factor `1 + F0 * (1/Ess - 1)` applied to that same weight still takes `Ess` from the fit. Fdez-Aguera / Filament require `Ess` to be the directional albedo of the SAME single-scatter lobe the weight comes from; with that, a white (F0 = 1) surface integrates to exactly 1. Here the env weight at F0 = 1 is `Ess_exact * (1 / Ess_fit)` (the table's `A + B` times the fit's compensation), i.e. `Ess_exact / Ess_fit`, which is not 1. `envAB` is already in scope, so the exact `Ess = envAB.x + envAB.y` is free at that site.
- **Evidence**: I interpolated `ENV_BRDF_LUT` (the generated `scene_buffer/env_brdf_lut.rs` table, same bilinear read as `envBRDFLut`) against the `envBRDFApprox` constants. White-furnace gain of the env term at F0 = 1, `Ess_exact / Ess_fit` (1.0 = conserving), sampled at NdotV 0.1 / 0.3 / 0.5 / 0.8 / 1.0: roughness 0.1: 1.05 flat; 0.3: 1.05 / 1.13 / 1.17 / 1.18 / 1.19; 0.5: 1.18 / 1.15 / 1.18 / 1.24 / 1.26; 0.7: 1.26 / 1.17 / 1.13 / 1.12 / 1.13; 0.9: 1.26 / 1.11 / 1.00 / 0.89 / 0.84; 1.0: 1.27 / 1.08 / 0.94 / 0.79 / 0.72. So for F0 near 1 (metals) the env specular gains energy by up to ~27 % at moderate roughness and loses ~28 % at roughness 1 head-on. Dielectrics (F0 0.04) move by under 1 %. The light loop's `specular *= multiScatterEnergyCompensation(F0, NdotV, aaRoughness)` shares the same fit but multiplies a different G (Schlick-GGX `k = (r + 1)^2 / 8`, `geometrySmith`; the PRD records that G difference as accepted, rev 47), so there the fit is not clearly wrong and I do not claim it is.
- **Impact**: conductors in exteriors (and any traced/authored-environment metal) read a roughness/angle-dependent few-to-25 % off their energy-conserving environment specular; whole-lobe magnitude, visual only. The A6/A15 conductor sweeps (0.967-0.977) were measured with this in place, so any change must be re-measured.
- **Related**: RLT-IBL-003, `DBG_DISABLE_MULTISCATTER` (RLT-REF-008), PRD `docs/prd/reference-lighting.md` T9 ("`envBRDFApprox` ... used only for multi-scatter compensation").
- **Suggested Fix**: give `multiScatterEnergyCompensation` an overload that takes `Ess` and call it with `envAB.x + envAB.y` in the environment block; leave the light-loop call on the fit until the G difference is decided. Re-run the A6 conductor rows and A15-SPEC before and after; pin the choice in `environment_specular_is_the_exact_split_sum_with_probe_occlusion`.

### REN-D1-01: an unsettled patch-BLAS stage is silently dropped at the next record instead of rolled back; nothing forbids a new post-record early exit
- **Severity**: LOW (hardening; no reachable trigger at HEAD)
- **Dimension**: AS Correctness
- **Location**: `StagedPatchContent::begin_frame` (called from `AccelerationManager::record_patch_blas_frame`, `acceleration/blas_terrain_patch.rs`); settle sites `promote_skin_frame_state` / `rollback_skin_frame_state` (`context/skinned_blas_refit.rs`); `VulkanContext::draw_frame` (`context/draw.rs`).
- **Status**: NEW (hardening beside the closed #7360; not a regression: #7360's three tail-Err sites and the success path are verified correct, see Invariants)
- **Description**: #7360 stages the prior `entry.content` at record time and settles it only in `promote_skin_frame_state` (commit) or `rollback_skin_frame_state` (restore, clears `ready`). `begin_frame` then does `self.prior.clear()` on the next record, and the unit test `a_submitted_frame_forgets_its_stage_and_a_new_record_starts_empty` pins that ("an unsettled stage is not carried into the next record"). The doc comment says such a stage "cannot be undone any more", but it could be: `begin_frame` could `rollback` instead of `clear`. The sibling fix landed the same day for the same bug class, #7361 (`terrain_tiles_upload_staged`), does exactly that: `discard_terrain_tile_upload` at the top of the next `draw_frame` re-arms the flag. So the two #7360/#7361 settle designs disagree on what an unsettled frame means.
- **Evidence**: In `draw_frame` between `record_terrain_patches` and the three tail `if let Some(e) = {end_command_buffer,reset_fences,submit}_failed { self.rollback_skin_frame_state(frame); return Err(e); }` blocks there is no `?`, `return` or `.expect` (checked by scanning that span: only the three rollback `return Err` sites and the graphics-queue `expect("graphics queue lock poisoned")`, which is a panic, not an early return). `build_and_upload_instances`, `record_geometry_pass`, `dispatch_skin_and_cluster` and the post passes all return `()`. So today every exit after the record reaches commit or rollback. `the_patch_blas_content_is_settled_with_the_skin_state_after_submit` only checks that the two hook calls exist, not that no other exit sits between record and tail.
- **Impact**: None today. A future `?` / early `return` added between `record_terrain_patches` and the tail would leave `entry.content = Some(..)` for a BUILD that never executed; the next frame plans an UPDATE refit of a never-built AS (VUID-03667 class, the skinned set's #3991), and `begin_frame` would then erase the only record of the prior value. The existing guard would stay green.
- **Related**: #7360 (closed), #7361 (closed, sibling design), #3991.
- **Suggested Fix**: Make `begin_frame` hand back an unsettled stage (restore each entry's prior content and clear `ready`) rather than clear it, or add a source-scan guard that `draw_frame_body()` has no `return`/`?` between `record_terrain_patches(` and `promote_skin_frame_state(` other than the three pinned sites. Update `a_submitted_frame_forgets_its_stage_and_a_new_record_starts_empty`, which currently asserts the drop.
- **Trigger Conditions**: a new fallible call (or early `return`) inserted after `self.record_terrain_patches(cmd, frame)` and before the three tail latches, on a frame that records a first-time patch BUILD (cell entry, camera cut).
- **Verification Path**: unit-level only; the fault-injection route in the "Needs-RenderDoc" section (force a submit failure) covers the existing three sites, not a hypothetical fourth.

### H-1 (= CON-D2-03): `dispatch_far_sun` layout transition uses `TOP_OF_PIPE` as its source stage
- **Judgement from the code**: the barrier is `src = TOP_OF_PIPE`, `srcAccess = 0`, `UNDEFINED -> GENERAL` (`image_barrier_undef_to_general`: dst access `SHADER_READ|SHADER_WRITE`), `dst = COMPUTE_SHADER|FRAGMENT_SHADER`, once per frame per FIF slot, even when `projection` is `None`. The slot's previous reader is the previous use's composite fragment sample (set 0 binding 20). The sibling per-frame discards name the previous reader's stage: `CloudShadow` and `SkyCubePipeline::record_bake` use `src = FRAGMENT_SHADER -> COMPUTE_SHADER` for the same UNDEFINED-discard shape.
