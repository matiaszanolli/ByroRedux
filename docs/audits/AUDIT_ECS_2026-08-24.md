### ECS-2026-08-24-01: two `ComponentRef<Transform>` read guards held simultaneously in `fragment.rs`, now surfaced by the new #2386 recursive-read diagnostic
- **Severity**: MEDIUM
- **Dimension**: 1 — Lock Ordering & Deadlock
- **Location**: `crates/scripting/src/fragment.rs:916-917` (`Effect::SetVehicle`), `crates/scripting/src/fragment.rs:942-946` (`Effect::TetherToHorse`)
- **Status**: NEW
- **Description**: `World::get::<T>()` returns a `ComponentRef<'_, T>` that owns its `RwLockReadGuard` for its whole lifetime (`crates/core/src/ecs/query.rs`). Both effect handlers take two such guards on `Transform` simultaneously — the textbook recursive-read pattern the just-landed `#2386` fix in `lock_tracker.rs` (this session, commit `5428e872`) added a hazard warning for, replacing the prior silent-allow behavior (pre-#2386, recursive reads were never diagnosed at all — this is a genuine new-diagnostic catch, not a regression). `condition.rs:528-537` already documents and applies the fix for the same pattern one file over.
- **Evidence** (`fragment.rs:915-918`):
  ```rust
  let relative_pose = vehicle.and_then(|vehicle| {
      let actor_transform = world.get::<Transform>(actor)?;
      let vehicle_transform = world.get::<Transform>(vehicle)?;   // guard #2 while #1 live
      if vehicle_transform.scale.abs() <= f32::EPSILON { return None; }
      ...
  ```
  `Effect::TetherToHorse` (`fragment.rs:942-946`) is the same shape with `cart`/`horse`.
- **Impact**: Two parts. (1) **Real today**: every `SetVehicle`/`TetherToHorse` fragment effect (the Skyrim cart-intro cinematic path) now emits `log::warn!("ECS recursive-read hazard: …")` on each call — not rate-limited (see ECS-2026-08-24-02), so a repeated cinematic tick floods the log. (2) **Latent, not reachable today**: `std::sync::RwLock` on Linux is write-preferring, so a recursive read can park behind a queued writer that is itself waiting on the first read guard. The mitigating fact: `quest_fragment_dispatch` and its sibling fragment systems are all registered `add_exclusive` (`boot.rs:851,895,920,932`), so no rayon worker can be parked on `Transform::write()` while these two reads straddle — the deadlock is blocked by a scheduler-registration property, not by the code. Promoting any fragment system to `add_to_with_access` (parallel) would turn this into a real hang.
- **Related**: Not a duplicate of #3130 (`PHYS-D3-2026-08-20-09`, a stale *comment* in `pull_dynamic`, different file/mechanism) or #3142 (`PERF-D7-01`, sequential per-entity re-acquire, not simultaneous hold). No existing issue covers this site.
- **Suggested Fix**: Copy out of the guards immediately (`Transform` is `Copy`), matching `condition.rs:534`'s pattern: `let actor_t = world.get::<Transform>(actor).map(|t| *t)?;` before acquiring the second. Or take one `world.query::<Transform>()` guard and `get()` both entities through it — one acquisition, strictly cheaper.

### ECS-2026-08-24-03 (INFO/LOW): `AnimatedTextureFlip::handle_for_slot` silently aliases an out-of-range index to bindless handle `0`
- **Severity**: LOW (informational — not reachable with the current single producer/consumer pairing)
- **Dimension**: 2 — Storage Correctness (component invariant)
- **Location**: `crates/core/src/ecs/components/animated.rs:206-213`
- **Status**: NEW
- **Description**: `handle_for_slot`'s `Option` return is meant to distinguish "no flipbook on this slot" from "flipbook present", but a present-yet-out-of-range `current_index` collapses to `Some(0)` (bindless slot 0 — *some other entity's texture*) instead of `None` (which callers treat as "fall back to the static `TextureHandle`").
  ```rust
  pub fn handle_for_slot(&self, slot: u32) -> Option<u32> {
      self.0.iter().find(|e| e.texture_slot == slot)
          .map(|e| e.handles.get(e.current_index).copied().unwrap_or(0))
  }
  ```
- **Impact**: Not reachable today — the attach path (`anim_convert.rs:226-236`) builds `handles` as a 1:1 map over `channel.source_paths`, and the per-frame writer (`sample_texture_flip_index`) bounds `current_index` against that same channel's `source_paths.len()` via `rem_euclid`, so `handles.len()` and the valid `current_index` range stay in lockstep as long as the entity's `TextureFlipEntry` is re-sampled against the same channel it was built from. A future clip-swap path that rebinds a *different* `NiFlipController` (more `source_paths`) onto an already-attached `TextureFlipEntry` (matched only by `texture_slot`) would silently show the wrong texture rather than falling back cleanly.
- **Related**: None — new component this session (`#2221`/`#3231` morph/flipbook work).
- **Suggested Fix**: `.and_then(|e| e.handles.get(e.current_index).copied())` — an out-of-range index then correctly reads as "no handle", triggering the caller's existing static-texture fallback.

### ECS-2026-08-24-06: cinematic unload-retention (`cinematic_retained_entities`) permanently orphans entities out of all cell ownership, leaking entities and GPU handle refcounts for the session
- **Severity**: MEDIUM
- **Dimension**: 7 — Component Lifecycles (M40 streaming orphan invariant)
- **Location**: `byroredux/src/cell_loader/unload.rs:15-45` (`cinematic_retained_entities`), `:139-152` (the `CellRoot`-strip loop inside `unload_cell_inner`, ahead of GPU-handle collection at `:154+`)
- **Status**: NEW
- **Description**: `unload_cell_inner` filters an unload's victim list against a globally-collected "cinematic retained" set (tethered carts, their horses, riders with `ActorCinematicState::vehicle`, plus the full `Children` closure of all of those), then strips `CellRoot` from **every** retained entity in the whole world — not just the ones belonging to the unloading cell. There is no re-adoption path: `CellRoot` is only ever inserted by `stamp_cell_root_range` at cell load, and `HorseTetherState` (the retention trigger) is never removed anywhere in production code (verified: every non-test call site is either the initial insert or a field-only mutation of `route_target_form_id`, never a removal). Once a cart is tethered and *any* cell anywhere unloads, that cart, its horse, its rider, and their whole render hierarchy become permanently unowned — no future unload can ever reclaim them, and their GPU handles (mesh/texture/normal-map/skin-slot/morph-slot) are excluded from every subsequent refcount decrement because the strip runs before the handle-collection pass.
- **Evidence** (`unload.rs:139-152`):
  ```rust
  let mut victims: Vec<EntityId> = world
      .try_resource_mut::<CellRootIndex>()
      .and_then(|mut idx| idx.map.remove(&cell_root))
      .unwrap_or_default();
  let retained = cinematic_retained_entities(world);   // world-global, not scoped to this cell
  victims.retain(|entity| !retained.contains(entity));
  if !retained.is_empty() {
      if let Some(mut roots) = world.query_mut::<CellRoot>() {
          for entity in retained {
              roots.remove(entity);          // no path ever re-adds this
          }
      }
  }
  ```
  Confirmed independently: `grep -rn "HorseTetherState" crates/scripting/ byroredux/` shows every non-test hit is either `HorseTetherState { ... }` construction or `tether.route_target_form_id = Some(...)` field mutation (`byroredux/src/systems/cinematic.rs:383`) — zero removal sites.
- **Impact**: Vanilla Skyrim's opening cart convoy is the canonical trigger — after the first exterior-tile unload, the cart, horse, every rider, and all their child bone/render entities become permanently resident and rendered at their last transform, across worldspace changes and interior transitions, with their GPU resources held for the process lifetime. Unbounded in duration (bounded only in count per cinematic instance). This is exactly the orphan class the skill's Dimension 7 M40 streaming invariant exists to catch.
- **Related**: None found in `/tmp/audit/issues.json`; nearest neighbors (#3163/#3165) are save-path and unrelated.
- **Suggested Fix**: Make retention explicitly reversible instead of a one-way strip — either (a) reparent retained entities onto a dedicated long-lived "cinematic root" registered in `CellRootIndex` so a tether-termination event can despawn the whole set through the normal path, or (b) keep the strip but record stripped entities in a new `RetainedCinematicEntities` resource and have the cinematic-completion path (which currently has no removal side for `HorseTetherState` at all) drain it and re-stamp `CellRoot` or despawn. At minimum, restrict the strip to `retained ∩ this_unload's_victims` so an unrelated unload elsewhere stops de-parenting live cinematics, and add a `HorseTetherState` removal path so the retention predicate can ever become false.

### ECS-2026-08-24-08: `resolve_cached_waypoints` has no navmesh-residency invalidation — a cached negative result is permanent for frozen-goal callers
- **Severity**: LOW (latent — not currently reachable through the normal streaming path; see reachability analysis)
- **Dimension**: 7 — Component Lifecycles (new-cache vs. streaming-residency)
- **Location**: `byroredux/src/systems/navmesh_path.rs:343-362`; consumers `travel.rs:229-231`, `guard.rs:187`, `escort.rs:237/276/299`, `wander.rs:286`, `patrol.rs:124`, `follow.rs:215-221`
- **Status**: NEW (adjacent to open umbrella `#2372` "EX-16: Integrate REGN, NAVM, ambient audio, and AI with exterior streaming", but not covered by it)
- **Description**: The waypoint-cache hit arm keys only on goal distance, with no notion of which `NavmeshTile` produced the path or whether that tile is still resident:
  ```rust
  match cached {
      Some(path) if path.goal.distance(goal) <= repath_threshold => {
          (path.goal, path.waypoints.clone())
      }
      _ => { /* recompute via path_from_resident_tiles */ }
  }
  ```
  Combined with the deliberate "cache the empty result too" contract and a `0.0` threshold on a frozen goal: the first tick a frozen-goal actor resolves its destination is the only tick that ever consults tile residency for that destination. If no tile localized the actor at that instant, an empty `NavPath` is cached against the frozen goal and the `0.0`-threshold comparison matches bit-identically forever — `path_from_resident_tiles` is never retried for the rest of that travel/guard leash, even after the relevant tile streams in.
- **Impact**: Verified NOT currently reachable through the normal streaming path — both loaders spawn NAVM tiles before actor/reference spawn in the same job (`cell_loader/load.rs:499` interior, `cell_loader/exterior.rs:1415` exterior), so a tile's own NAVM is always resident before its own actors exist, and cross-tile destinations can't path yet anyway (Phase 2 cross-tile search is unbuilt). It becomes reachable the moment any of: Phase 2 cross-tile search lands, NAVM tiles gain independent (partial-cell) eviction, or an actor is repositioned into an un-resident tile while holding a live frozen-goal `TravelState`/`GuardState` (e.g. a scripted `MoveTo` teleport, which reuses the frozen destination unconditionally on the next tick).
- **Related**: None; not covered by `#2372`.
- **Suggested Fix**: Add a residency epoch — a `u64` bumped in `spawn_navmesh_tiles` and `unload_cell`, stored on `NavPath`, and compared (`&& path.gen == current_gen`) in the cache-hit arm. Cheaper partial fix: only cache the *negative* result together with the generation, so an empty path is retried once residency changes.

### ECS-2026-08-24-11: `advance_time`'s `CycleType::Loop` arm latches `local_time` to NaN on unvalidated `clip.frequency`
- **Severity**: MEDIUM
- **Dimension**: 10 — Animation Runtime
- **Location**: `crates/core/src/animation/player.rs:88-119`; provenance `crates/nif/src/anim/sequence.rs:22` → `byroredux/src/anim_convert.rs:494`
- **Status**: NEW
- **Description**: `advance_time` has no finiteness guard on `delta = dt * player.speed * clip.frequency`, and `clip.frequency` is raw, unvalidated `NiControllerSequence` data (no `is_finite`/clamp anywhere between the NIF parser and `advance_time`). `CycleType::Clamp` self-heals (`f32::min` returns the non-NaN operand) and `CycleType::Reverse` early-returns via a duration guard, but `CycleType::Loop` does not: `player.local_time += delta;` followed by `local_time %= clip.duration` and a `< 0.0` repair — all of which are no-ops once `local_time` is NaN (`NaN % x == NaN`, `NaN < 0.0 == false`), so the corruption is permanent from the first bad tick onward.
- **Evidence**:
  ```rust
  CycleType::Loop => {
      player.local_time += delta;
      if clip.duration > 0.0 {
          player.local_time %= clip.duration;      // NaN % d == NaN
          if player.local_time < 0.0 {              // NaN < 0.0 == false, never repairs
              player.local_time += clip.duration;
          }
      }
  }
  ```
  Traced downstream: with `time = NaN`, `find_key_pair`'s boundary guards are both false, the binary search converges with `t = NaN`, and that NaN flows through `sample_translation`/`sample_rotation`/`sample_scale` into the bone transform, `GlobalTransform`, and the GPU instance matrices — the same NaN-into-shader class `#3194` was fixed for in `apply_speedtree_wind` this session (`billboard.rs:152`).
- **Impact**: A malformed or corrupt `NiControllerSequence.frequency` (NaN or ±inf) on any looping clip poisons that entity's pose permanently. MEDIUM rather than HIGH because the other two `CycleType` arms are unaffected and self-heal.
- **Related**: Precedent for guarding at this exact class of seam is `#3194` (SpeedTree wind NaN clamp), landed this session.
- **Suggested Fix**: `let delta = if delta.is_finite() { delta } else { 0.0 };` at the top of `advance_time`, or better, validate at the translate boundary (`anim_convert.rs:494`: `frequency: if nif.frequency.is_finite() && nif.frequency > 0.0 { nif.frequency } else { 1.0 }`), matching the project's resolve-once-at-the-boundary rule. Pin with a test asserting `local_time` stays finite after `advance_time` with a NaN-frequency clip.
