own controller chain, but the `NiPSysEmitterCtlr` usually sits at hop ≥ 2 of

**every** game measured (FO3 94.3%→70.8%, FNV 100%→50.5%, SSE 100%→31.5%).

main. The introducing session ran only the default test lane, never the
`--ignored` real-data lane the floor lives in. **Orchestrator-confirmed**: the
gate re-run on main panics (`Skyrim SE: only 63/153 emitters decoded a finite
positive birth rate (floor 50%)`, `parse_real_nifs.rs:926`).

**Delta vs FNV**: still nothing found that is unique to FO3's byte layout.
FO3 and FNV are re-confirmed to share `NPC_`/`DIAL`/`INFO` subforms (FO3 is a
strict subset of FNV's; the sole FO3-only subform — `INFO.SNDD`, 1 record —
is legacy xEdit itself strips), `CELL.XCLL` (one shared `Fallout3NV` path,
FO3 `{36,40}` = FNV `{40}` family), the WRLD/CLMT/WTHR chain, the object-LOD
scheme, and the BSA v104 reader (0 hash collisions over 1,810 folders). Every
finding below is reachable on FO3 but lives in shared code — a fix benefits
all four classic games, a regression hits them all (which is exactly what the
HIGH did).

## Dimension Findings

### HIGH

#### FO3-D2-2026-09-19-01: #4261's per-system controller scoping drops most authored emitter birth rates — #3754's per-game rate gate is RED on main (FO3 coverage 94.3% → 70.8%)
- **Dimension**: 2 — NIF Parser FO3 Block Subset (typed-emitter slice)
- **Location**: `crates/nif/src/import/walk/emitter.rs:390-405` (`find_own_emitter_ctlr_interpolator`), `:414`, `:600-606` (`extract_emitter_rate` modern tier) — introduced by `b3237e65a` (Fix #4261, 2026-09-12). Failing gate: `crates/nif/tests/parse_real_nifs.rs:926` (`real_archive_torch_meshes_surface_particle_emitters`, `--ignored` lane).
- **Status**: NEW (regression of #3754's coverage by the #4261 fix; #4261's per-instance goal was correct but the scope fix broke the lookup)
- **Description**: #4261 replaced `extract_emitter_rate`'s whole-scene first-match for `NiPSysEmitterCtlr` with a walk of the `NiParticleSystem`'s own `controller_ref` chain (`anim::walk_controller_chain`). The walk only advances through controller types `time_controller_base_of` recognizes. On real Bethesda content the emitter ctlr usually sits at **hop ≥ 2** of the system's own chain, behind sibling `NiPSys*` controllers (`NiPSysModifierActiveCtlr`, `BSPSysMultiTargetEmitterCtlr`, `NiPSysEmitterSpeedCtlr`, …) that the parser collapses into the generic `NiPSysBlock` marker (`blocks/particle.rs:164-176` — retains only `original_type` + budget, discards `NiTimeControllerBase.next_controller_ref`). At such a head, the walk's advance yields NULL and stops at hop 1; the emitter ctlr two links down is unreachable, `extract_emitter_rate` returns `None`, and the emitter falls back to the name-heuristic preset rate.
- **Evidence** (all real-data, this run):
  - Gate at HEAD `340799d66`: FNV 98/194 (50.5%), **FO3 102/144 (70.8%)**, OB 210/272 (77.2%), **SSE below the 50% floor — test FAILS** (dimension agent's `--nocapture`: 39/124; orchestrator's independent re-run panic message: 63/153 — sweep totals vary with archive discovery order, both far below floor).
  - Gate at `b3237e65a~1` (`21dcbe58d`, built out-of-tree via `git archive`): FNV 343/343, FO3 149/158 (94.3%), OB 272/272, SSE 182/182 — **passes**. Only `b3237e65a` (#4261) and `9e372f452` (#4240, forwarding-only) touched this path in between.
  - Attachment census (Fallout - Meshes.bsa): 361 `NiPSysEmitterCtlr` blocks, **100% have `base.target_ref` → a `NiParticleSystem`**; 422 systems, but only **230/422 have the ctlr at hop 1** of their own chain. The 192 missed systems' chain heads: `NiPSysModifierActiveCtlr` 114, `BSPSysMultiTargetEmitterCtlr` 45, `NiPSysEmitterSpeedCtlr` 20, others ≤ 6. Same shape on SSE (139/531 systems reachable).
- **Impact**: FO3 smoke/fire/dust emitters render at heuristic rather than authored densities (29% of FO3 emitters that previously decoded a rate lost it; FNV lost half, SSE more than two-thirds). Separately, the red gate poisons the `--ignored` real-data lane — every future run fails on SSE until fixed, masking any NEW regression the floor would catch.
- **Related**: #3754 (rate-curve mean + per-game floor — fix intact, gate doing its job), #4261 (introducing commit), #3327 (the `time_controller_base_of` stop-dead class this is a new instance of), #1402, #3286.
- **Suggested Fix**: two complementary, per-instance-safe options: (1) retain `NiTimeControllerBase` on `NiPSysBlock` (or give the sibling `*Ctlr` types that head chains real structs) and add the arms to `time_controller_base_of`, so the existing walk traverses hop ≥ 2 (the #3327 pattern); (2) fallback attribution — when the own-chain walk misses, resolve the scene's `NiPSysEmitterCtlr` blocks by `base.target_ref == this system's index` (census: 100% target the system — per-instance-exact, preserving #4261's goal, restoring pre-#4261 coverage). Either way: the #4261 fix-class must run the `--ignored` real-data lane before landing — this is the second emitter-chain regression that lane alone catches.

### LOW

#### FO3-D4-2026-09-19-01: FO3 DLC object-LOD `.high.` quad variant is shipped but never consumed (fidelity-only; no coverage hole)
- **Dimension**: 4 — FO3 Cell Loading
- **Location**: `byroredux/src/cell_loader/object_lod.rs:674-690` (`object_lod_archive_path` builds only the plain `{w}.level{L}.x{X}.y{Y}.nif` form); census comment `:626-647`
- **Status**: NEW
- **Description**: FO3's DLC mesh archives ship a second object-LOD filename variant, `<world>.level4.high.x<X>.y<Y>.nif`, beside the plain form. Raw census of the 5 DLC `*- Main.bsa` archives: 60 `.high.` quads (`dlc02anchoragebattle` 12, `dlc02chinesehq` 13, `dlc02glacier` 21, `dlc02overlook` 11, `tlandscape` 3). No code path generates or probes a `.high.` path (repo-wide grep: zero consumers). Every one of the 60 coordinates has a plain sibling, so the descent still finds a quad everywhere — detail fidelity only, no hole. Also a census gap: `object_lod.rs`'s inventory comment counts only the base BSA's 15 worldspaces, so the DLC quads and the variant are absent from the documented inventory.
- **Suggested Fix**: extend the census comment to record the DLC counts and the `.high.` variant (cheap, honest), or probe `.high.` as a preferred-then-plain fallback with a cited source for vanilla's selection rule.
- **Related**: #2086, #3321, #3502 (all closed — the scheme this rides on).

#### FO3-D3-2026-09-19-01: INFO `DATA` (dialogue Type + Flags 1) has no decode arm — dropped on 100% of FO3 INFOs; shared with FNV → routed to `/audit-esm`
- **Dimension**: 3 — ESM Record Coverage
- **Location**: `crates/plugin/src/esm/records/misc/dialogue.rs:201-289` (`parse_info` — arms for 13 subcode families, no `DATA`)
- **Status**: NEW (shared-mechanism; routed per the /audit-esm scope split — noted, not deep-audited)
- **Description**: Every FO3 INFO carries a `DATA` sub-record (measured: 22,327/22,327 FO3; 23,247/23,247 FNV) that per xEdit's FO3 definition holds at least the dialogue `Type` byte and a `Flags 1` word (goodbye / random / say-once class). `parse_info` has no arm for it, so the field is silently discarded. DIAL's own `DATA` *is* decoded (`dial_type`), which makes the INFO-side omission look like an oversight, not a policy — the module's documented deferral list (conditions/scripts/edits) doesn't mention `DATA`.
- **Impact**: latent — no dialogue runtime consumes response flags yet; when one lands it cannot tell a goodbye-flagged line from a plain one without re-parsing.
- **Suggested Fix**: add a `DATA` arm storing byte 0 as `info_type` (the same convention `DialRecord::dial_type` uses) plus the raw flags word; update the deferral list.
- **Related**: #631 (INFO stub deferrals), #3614.

## FO3-Distinctive Gaps

1. **The scripting runtime gap remains the largest FO3-specific functional
   blocker** — 1,257 SCPT records parse; FO3 authored gameplay logic still has
   no general executing runtime. The narrow Sept-2026 exception
   (`obscript_runtime.rs`, script-extender load-order idiom) still doesn't
   reach FO3: `attach_scpt_script` gives `FALLOUT3` no compiled-bytecode
   dialect (only Oblivion→Obse, FNV→Xnvse), and vanilla FO3 doesn't author
   the idiom anyway. **Positive movement since the last audit**: M47.3 now
   ticks compiled FO3 *quest* scripts game-agnostically — measured 101/192
   FO3 QUSTs carry script refs, 403/1,257 scripts have executable GameMode
   blocks, and FO3's quest-family command IDs empirically match the
   Oblivion-derived table (SetStage 0x1039 / GetStage 0x103a verified in real
   bytecode). The remaining gap (1,156 non-quest scripts, non-GameMode
   events, phase-1 command set) stays a known blocker owned by
   `/audit-scripting`. Coverage info, not a bug.
2. **Inline-shader-only material universe** — re-proven at every layer this
   run (parse, import, single boundary, GPU flag word, plus the fresh
   0-BGSM measurement). Disney-BSDF unreachable. No gap inside it.
3. **Capital Wasteland worldspace** — data-driven selection confirmed; the
   DC-street-worldspaces-vs-`Wasteland` containment overlap resolves via the
   documented, `--wrld`-overridable #444 heuristic (design trade-off, not a
   defect).
