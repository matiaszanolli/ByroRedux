## Dimension 1 — Lock Ordering & Deadlock Machinery

### ECS-D1-01: `terrain_patches::nearby_cells` takes `TerrainTileSlot` before `MeshHandle`, inverting the render collector and cell unload
- **Severity**: HIGH. It is an ECS lock-order inversion on a per-frame production path. The guards are read locks on the main thread, so it cannot deadlock today.
- **Dimension**: 1 Lock Ordering
- **Location**: `byroredux/src/terrain_patches.rs` `nearby_cells`, called from `emit_patch_draws` inside `build_render_data` (`byroredux/src/render/mod.rs`).
- **Status**: NEW. It came in with the TSD-4.1 patch host (#7152) and was reworked by #7263. No open or closed issue matches.
- **Description**: `nearby_cells` takes `(TerrainCellOrigin, TerrainTileSlot, MeshHandle)` in one tuple and holds all three. That records the edge `TerrainTileSlot → MeshHandle`. Two other paths take the opposite order:
  - The static-mesh collector holds `MeshHandle` while taking `TerrainTileSlot` (`render/static_meshes.rs` `StaticMeshQueries::new`, `let mq = world.query::<MeshHandle>()` and later `let terrain_tile_q = world.query::<TerrainTileSlot>()`).
  - `cell_loader/unload.rs` `collect_victim_gpu_handles` (`mq` then `ttq`) does the same.

  Together these close a 2-cycle in the process-wide graph. Patches are on by default, so every exterior frame records both directions once the pool meshes arrive.
- **Evidence**: `let (Some(origins), Some(tiles), Some(meshes)) = (world.query::<TerrainCellOrigin>(), world.query::<TerrainTileSlot>(), world.query::<MeshHandle>())` against `static_meshes.rs:393/454` and `unload.rs:843/848`.
- **Why the lane is green**: no test world that runs `build_render_data` has a `TerrainTileSlot` storage. `World::query` returns `None` before it arms the tracker, so no edge is recorded.
- **Impact**: any live exterior run under `BYRO_LOCK_ORDER_CHECK=1` panics in the detector. That also hides the next real cycle. Release builds are not affected.
- **Related**: #6209 (the same `collect_victim_gpu_handles` family); `dfcbcafd5`.
- **Suggested Fix**: take `MeshHandle` before `TerrainTileSlot` in `nearby_cells`, so the order is `TerrainCellOrigin, MeshHandle, TerrainTileSlot`. That is also compatible with ground cover's `TerrainCellOrigin → … → MeshHandle`. Add a fixture with all three storages that runs `nearby_cells` and the static collector under the detector.

### ECS-D1-03: Read cycle `RapierHandles → WaterContact → ActorVitals → RapierHandles`
- **Severity**: HIGH. An ECS lock-order cycle carries a HIGH floor. All three edges are read guards, but std `RwLock` prefers writers, so a read cycle can block behind a queued writer.
- **Dimension**: 1 Lock Ordering
- **Location**:
  - `crates/physics/src/water.rs` `apply_buoyancy_with_scratch`: holds the `RapierHandles` and `RigidBodyData` queries while taking `WaterContact`. The contact scan near line 704 does the same.
  - `byroredux/src/systems/water.rs` `water_damage_system`: holds `WaterContact` while taking `ActorVitals`.
  - `byroredux/src/systems/trap_hits.rs` `live_actor_bodies`: holds the `ActorVitals` query while calling `world.get::<RapierHandles>`.
- **Status**: NEW. `git blame` puts all three edges before the baseline, and they have never been reported.
- **Description**: the three systems together form a 3-cycle. The detector follows transitive reachability, so it counts. No test process runs all three with populated storages, so the bin lane stays green. A live cell with water, a trap and an actor in the water under the detector would trip it.
- **Impact**: a detector panic in a live trap or water cell. Release builds are not affected unless a writer interleaves.
- **Suggested Fix**: in `live_actor_bodies`, gather the live actors first and drop the `ActorVitals` guard before reading `RapierHandles`. That is the one-guard-at-a-time shape #5954 used. Add a fixture with all three storages under the detector. **Needs a detector run** to confirm the trip before the fix and that it is gone after.

### ECS-D1-02: `gather_export_scene` (Mitsuba export) holds storages in an order the render collector inverts
- **Severity**: MEDIUM. Lock-order inversions have a HIGH floor, but this was downgraded: it is a one-shot, opt-in (`--export-mitsuba`), main-thread dev tool that runs between frames. It cannot deadlock, and no test reaches it.
- **Dimension**: 1 Lock Ordering
- **Location**: `byroredux/src/cornell/mitsuba_export.rs` `gather_export_scene`.
- **Status**: NEW. Closed #6618 fixed the same class in `material_dump::material_rows`, not here.
- **Description**: the function holds `MaterialTextureHandles → TextureHandle → AlphaBlend → SkinnedMesh → MeshHandle → GlobalTransform → Material`, then `LightSource → GlobalTransform` and `Camera → GlobalTransform`. The render collector takes `GlobalTransform → MeshHandle → TextureHandle → …`. Several 2-cycles result, for example `GlobalTransform ↔ MeshHandle` and `MeshHandle ↔ TextureHandle`.
- **Impact**: with the detector on, the first exported frame panics and the Cornell reference workflow aborts. Nothing happens without the environment variable.
- **Suggested Fix**: read one storage at a time into owned collections, as `material_rows` does since #6618.

## Dimension 4 — Resources & World-Level State

### ECS-D4-01: `PackageDayBlocks` is keyed by `EntityId`, so a Once Per Day block is lost when streaming respawns the actor
- **Severity**: LOW
- **Dimension**: 4 Resources (resource vs component), and 7 (load/unload symmetry). The Dim 4 and Dim 7 agents reported it independently, as D4-01 and D7-02.
- **Location**: `byroredux/src/npc_spawn/package_flags.rs` `PackageDayBlocks(HashMap<(EntityId, u32), f64>)`, `once_per_day_blocked`, `note_selected`. `byroredux/src/cell_loader/stream_snapshot.rs` `ActorStreamSnapshot` does not carry the block.
- **Status**: NEW. #7252 (closed) fixed the live-load reset ordering, not the keying.
- **Description**: the block is keyed by the actor's `EntityId`. Exterior streaming despawns the actor, and on respawn it gets a fresh id, while the snapshot carries its FormID-keyed state but not the block. A Once Per Day package can then win again inside the 24 game hours, contrary to AIP-FLG-001 (`docs/prd/ai-packages-completion.md`). `NOT_SAVED_BY_DESIGN` covers save/load, not streaming. The old entry is pruned lazily, so there is no leak.
- **Impact**: Once Per Day is enforced only while the actor's entity is alive, which is a gameplay-fidelity gap.
- **Suggested Fix**: key by the actor's FormID (as `ActorRelocations` does), or carry the block in `ActorStreamSnapshot`. Add a despawn/respawn test.

The rest of Dim 4 is clean:
- Every new non-test `Component` is `SparseSetStorage`.
- The one new `OwnershipTracker` class, `texture_resident_bytes`, is `Occupancy`, as the skill allows.
- New session resources use `init_resource`.
- Only `app_events.rs` writes `DeltaTime` / `TotalTime`.

## Dimension 7 — Component Lifecycles

### ECS-D7-01: `EvaluatePackage` raised between the ambient and scene-package passes is drained unseen
- **Severity**: MEDIUM
- **Location**:
  - `byroredux/src/boot/schedule/update/quest_scene.rs`: the segment order is `package_fragments` (ambient first), `forcegreet`, `obscript_quests`, then `scene_actions`.
  - `crates/scripting/src/package.rs`: `request_package_evaluation`, and `scene_package_system`, which drains `EvaluatePackageRequest` unconditionally.
  - `byroredux/src/npc_spawn/ai_package.rs`: the ambient pass's `requested` / `release_hold` reads.
- **Status**: Existing: #7291 (SCR-D3-01, filed the same day by `/audit-scripting`). The `ReleasePackageHold` half came in with #7243 and the request half with #2652.
- **Description**:
  - `ambient_ai_package_system` collects `EvaluatePackageRequest` first in the segment.
  - Producers registered after it, but before `scene_package_system`, call `request_package_evaluation`. These are the ObScript quest lane (`obscript_actions.rs:139` `EvaluatePackage`) and the PF_ fragment effects (`fragment/effects/ai_combat.rs:184`). Their request is drained by `scene_package_system` the same frame, before ambient ever sees it.
  - The paired `ReleasePackageHold` is taken on the next ambient pass. It takes effect only if the actor happens to be due that frame (the once-per-game-minute gate).

  The comment at the registration ("ambient packages observe EvaluatePackageRequest before the SCEN package system drains") holds only for producers before ambient.
- **Impact**: a quest script's `EvaluatePackage` on an ambient actor usually neither re-evaluates the actor nor drops its Must Complete hold. That is the case #7243 meant to fix. Console `evp` and producers after `scene_package_system` work.
- **Suggested Fix**: either register ambient after the in-window producers and before `scene_package_system`, or stop `scene_package_system` draining requests that ambient owns. Then pin it with a `schedule_order` guard over every `request_package_evaluation` producer.
