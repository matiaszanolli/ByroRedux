## Findings

### NIF-AUDIT-2026-08-24-01: `NiPSys*Ctlr` family missing the `#2562`/`#2563` version-gate fix
- **Severity**: MEDIUM (escalates to HIGH on any sizeless sub-v10.1.0.104 file that actually carries one)
- **Dimension**: Stream Position Integrity / Version Gating
- **Location**: `crates/nif/src/blocks/particle.rs:938-978` (`parse_modifier_ctlr`, `parse_emitter_ctlr`, `parse_multi_target_emitter_ctlr`); dispatched from `crates/nif/src/blocks/mod.rs:1135-1169`
- **Game Affected**: any NIF below file version 10.1.0.104 (Oblivion-era NetImmerse band; FO3+ unaffected)
- **Status**: **Existing: #3174** — re-confirmed byte-identical at HEAD, still open, still unfixed
- **Description**: `#2562`/`#2563` fixed the missing `until="10.1.0.103"` `Data` ref on nine `NiSingleInterpController` subclasses, but nif.xml declares the identical field on four more types in the `NiPSys*Ctlr` family (22 dispatch names total), none of which were touched. These three parser functions open-code the inheritance chain and read the interpolator ref unconditionally with no version gate, and never read the pre-10.1.0.104 legacy `Data` ref at all.
- **Evidence**: verified live at `particle.rs:938-943` — `parse_modifier_ctlr` reads `_interpolator_ref` with no version check immediately before `read_string()` for `modifier_name`; `parse_emitter_ctlr` (line 950) already correctly gates its *visibility* interpolator on `>= V10_1_0_104` two lines below an ungated primary interpolator read — the inconsistency is visible inside one function.
- **Impact**: latent on vanilla content (0 truncations across the full corpus swept this session confirms no vanilla sub-10.1.0.104 file carries one of these 22 types), reachable on legacy NetImmerse-era mod particle content. On a sizeless file (no `block_sizes` table) the 4-byte desync cascades through every subsequent block with no recovery anchor.
- **Suggested Fix**: see #3174's filed suggestion — gate the interpolator ref on `stream.version() >= NifVersion::V10_1_0_104` (ideally by delegating to `NiSingleInterpController::parse`), add the complementary `Data` ref read for the pre-split case, extend `version.rs`'s enumerating doc comment.

### NIF-AUDIT-2026-08-24-02: `per_block_baselines` regression gate stale for 6/7 games post-RTTI-restoration
- **Severity**: MEDIUM (test-gap, not a parser defect — the underlying `#2562`/`#2563` change is a *fix*)
- **Dimension**: Block Dispatch Coverage
- **Location**: `crates/nif/tests/data/per_block_baselines/{oblivion,fallout_3,fallout_nv,skyrim_se,fallout_4,fallout_76}.tsv`
- **Status**: **Existing: #3175** — re-confirmed, and this sweep additionally verified the reclassification is exact-count-conserving on Oblivion (`3034 = 27 + 1 + 2645 + 361`) and reproduces identically (same "NiSingleInterpController PARSED shrank" signal) on all five other affected games when run live — the original filing's "on every game" claim is now empirically confirmed rather than inferred:
  - Oblivion: `3034 → 0`
  - Fallout 3: `7138 → 251`
  - Fallout NV: `11598 → 614`
  - Skyrim SE: `5640 → 54`
  - Fallout 4: `11086 → 260`
  - Fallout 76: `17439 → 246`
  (Starfield's baseline already matches — it never used the bare-`NiSingleInterpController` dispatch for these types.)
- **Description**: `#2562`/`#2563` gave nine `NiSingleInterpController` subclasses (`NiKeyframeController`, `NiTransformController`, `NiVisController`, `NiAlphaController`, …) their own dedicated block-type RTTI instead of leaving them dispatched as a bare `NiSingleInterpController`. This is the *correct* fix (restores real type-name RTTI for `anim/entry.rs`'s embedded-controller extraction), but the checked-in per-block histogram baselines were never regenerated, so the opt-in `per_block_baseline_*` test now fails on every game that ships pre-Skyrim-style keyframe/transform/vis/alpha controllers.
- **Impact**: the structural regression-guard this dimension explicitly relies on ("extend, don't reinvent") is currently non-functional for 6/7 games — a genuine future dispatch regression in this histogram class could land undetected, or (more likely in practice) simply add more false-positive noise on top of the existing one, making the signal harder to trust.
- **Suggested Fix**: `BYROREDUX_REGEN_BASELINES=1 cargo test -p byroredux-nif --release --test per_block_baselines -- --ignored` (all six games) in one commit, so the gate goes green and stays meaningful for the next drift.
