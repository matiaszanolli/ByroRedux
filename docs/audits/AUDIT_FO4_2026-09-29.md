## Executive Summary

- **Parse rate, measured this session: 235,082 / 235,082 FO4 NIFs clean (100.00%), 0 truncated,
  0 failed, across all 8 mesh-bearing archives.** This matters because b7491072f (#4622)
  introduced a new hard `UnexpectedEof` for BSTriShape payloads that overrun their block, and
  `BSMeshLODTriShape::parse_lod` (FO4-only) now hands it `block_size - 12`. No vanilla FO4
  block trips it. The figure matches ROADMAP.md:206.
- **The heaviest FO4 change in the window is M49 precombines moving onto the cell-stream worker**
  (e593770f0, 67de801f8). The worker reads, parses and CSG-decodes each `_oc.nif` off the main
  thread, and CSG reads are lock-free (1b8b21f3f). Split uploads now yield between geometry
  groups (078f650ec, `PrecombinedPlacement`). The checklist's "two routes must agree" held on
  every axis checked:
  - owner resolution: same `wctx.plugin_paths`;
  - blob routing: the shared `csg_paths_by_name_hash` / `decode_precombine_csg`;
  - cache key: already canonical, and pinned;
  - fail-closed fallback;
  - blend restore: the shared `merge_precombine_materials`.
  
  The one gap is that the shared blend restore has no test on either route (FO4-D1-01, LOW).
- **Every baseline carry-over closed.** #4428 (MEDIUM, BGSM envmap ungated) is fixed, as are
  #4654, #4836, #4941 (the specular-disabled gates) and #4636 (dead NIF texture path yields to a
  resolvable BGSM path). #4248 (CONT leveled loot), flagged at baseline as fixed-but-open, is now CLOSED.
- **FO4 corpse question (task item): FO4 does mark placed corpses with the ACHR 0x200 header bit.**
  The counts are 1,188 / 7,615 ACHRs in `Fallout4.esm` and 1,531 across the base game + Automatron +
  Far Harbor + Nuka-World. `XRGD` appears only on 0x200 refs (0 of 8,791 live ACHRs carry it). So
  #4814's decode is correct for FO4, and FNV-D2-01's Fallout-era gap does not extend to FO4. The
  authored pose half (1,418 FO4 `XRGD` corpses, plus 124 "Don't Havok Settle") is the same
  defect as SKY-D4-2026-09-29-01. It is cross-referenced with FO4 counts, not re-filed.
- **One new FO4-owned gameplay-data gap**: the sibling flag in the same header word, FO4's
  "Starts Unconscious" (0x2000), is never decoded. 191 enabled dormant robots and turrets
  (protectrons, sentry bots, Mr. Handys, bubble and tripod turrets) spawn awake (FO4-D4-01, MEDIUM).

#### FO4-D1-01: `merge_precombine_materials` (the opaque-architecture blend restore) has no test on either route; the new drain-route guard passes `mat_provider = None`, so the merge never runs in it
- **Severity**: LOW
- **Dimension**: M49 precombines
- **Location**:
  - the function: `byroredux/src/cell_loader/precombined.rs:902-926`;
  - its call sites: `precombined.rs:331` (main-thread job) and `byroredux/src/cell_loader/partial.rs:81` (stream drain);
  - the guard: `byroredux/src/cell_loader/finish_partial_tests.rs:251-291`.
- **Status**: NEW. The skill records the restore as "Unguarded", and no issue tracks it. e593770f0 added the second call site.
- **Description**: e593770f0 factored the #1619-follow-up blend restore into
  `merge_precombine_materials`. The restore keeps the BGSM's two_sided / decal / alpha_test flags
  but restores the NIF-side `has_alpha`/`src_blend_mode`/`dst_blend_mode`, because FO4 authors the
  "Standard" blend identically on lab glass and opaque Institute metal. The same commit calls the
  helper from the new streaming-drain branch of `finish_partial_import`.
  - `grep merge_precombine_materials` finds only the function and its two callers, with no test.
  - The new guard `finish_partial_import_builds_precombine_geometry_entry` calls
    `finish_partial_import(&mut world, None, key, partial, …)`, so the
    `if let Some(provider) = mat_provider` branch that applies the merge never executes in it.
- **Evidence**:
  - `finish_partial_tests.rs:274`: `finish_partial_import(&mut world, None, key, partial, &|_| false);`
  - `partial.rs:79-86`: the merge sits behind `if let Some(provider) = mat_provider`.
- **Impact**: nothing is wrong today. But if either route drifted back to a bare
  `merge_external_material` loop (the efd3c41b regression shape), every test would still pass, and
  precombined Institute / lab walls would render as `MATERIAL_KIND_GLASS` (see-through, mirror-hazy)
  on that route only. Because streamed exteriors and synchronous interiors now take different
  routes, a one-sided drift shows up only as a visual difference between load paths.
- **Related**: #1619, efd3c41b (the original regression); the skill's Dim 1 "Unguarded" note.
- **Suggested Fix**: add a unit test for the helper with an in-memory `MaterialProvider` holding a
  "Standard"-blend BGSM (function 1, src 6, dst 7, two_sided, alpha_test) and a mesh whose NIF-side
  `has_alpha = false`. Assert the blend triple is restored and the BGSM's two_sided/alpha_test
  survive. Add a provider-backed variant of the drain-route test.

### Dimension 4 — ESM architecture records + cell expansion

#### FO4-D4-01: FO4's ACHR "Starts Unconscious" header flag (0x2000) is never decoded — 191 dormant robots and turrets placed enabled in vanilla spawn awake
- **Severity**: MEDIUM
- **Dimension**: ESM architecture records + cell expansion. It is FO4 data through #4814's
  mechanism; the decode is `/audit-esm`'s and the consumer `/audit-gameplay`'s.
- **Location**:
  - `crates/plugin/src/esm/cell/walkers.rs:1190-1195`: only 0x800 and 0x200 are read from `header.flags`.
  - `crates/plugin/src/esm/cell/mod.rs` (`PlacedRef`, beside `starts_dead` at `:574`): there is no field.
  - `byroredux/src/cell_loader/references/mod.rs:748-754`: the actor-completion hook where
    `apply_starts_dead` runs has no unconscious sibling.
  - `grep -rni unconscious crates byroredux/src` is empty. The engine has no unconscious state.
- **Status**: NEW. `gh` searches for "Starts Unconscious" and "ACHR 0x2000" find nothing. #4814
  (CLOSED) decoded bit 9 only.
- **Description**: xEdit's FO4 ACHR flag list is `9 Starts Dead, 10 Persistent, 11 Initially
  Disabled, 13 Starts Unconscious, 25 No AI Acquire, 29 Don't Havok Settle`
  (`wbDefinitionsFO4.pas:4483-4490`). FO76 (`:5544`) and SF1 (`:8479`) also carry bit 13, and
  TES5's list does not. f87490826 decoded bits 11 and 9 from this header word and left bit 13
  unread.
  - The bases on the flagged refs are machines, not humans: `LvlTurretBubble` ×9,
    `DN084_LvlTurretBubbleMassFusion` ×6, `LvlProtectron` ×6, `DN083_EncTurretTripodMounted` ×6,
    `LvlMrHandy_RandomHostile` ×5, `LvlProtectronPolice` ×5, `LvlSentryBot` ×4,
    `LvlAssaultron` ×3, `DN049_LvlMrHandy_Outlet` ×3, `RR101TourBot`, and `DN035_Roboracers_*`.
  - That is the powered-down machine a terminal, pod or quest script wakes. The "dormant until
    woken" semantics is inferred from these bases plus the xEdit label. Source the runtime meaning
    (Papyrus `Actor.SetUnconscious`) before implementing (No Guessing policy).
- **Evidence**: byte census of the installed masters (`/tmp/audit/fo4/achr_bits.py`, `achr_29.py`, `achr_unc.py`):

  | Plugin | ACHR | 0x2000 | …not also 0x800 |
  |---|---|---|---|
  | Fallout4.esm | 7,615 | 79 | 77 |
  | DLCRobot.esm | 152 | 10 | 10 |
  | DLCCoast.esm | 1,124 | 6 | 6 |
  | DLCNukaWorld.esm | 1,431 | 99 | 98 |
- **Impact**: 191 dormant sentries spawn as live, AI-driven actors. Hostile variants
  (`*_Hostile`, `LvlMrHandy_RandomHostile`, raider/gunner-keyed turrets) can engage on sight through
  #4414's faction hostility, before the scripted wake-up that gates them in vanilla. Examples are
  the Mass Fusion (DN084) and Nuka-World encounter layouts and the protectron pods. This is the same
  class as #4814 (authored actor state ignored at spawn), with a narrower population. It is
  reachability-limited today, because FO4+ locomotion clips are absent (ROADMAP M42).
- **Related**: #4814 (CLOSED); #4813; #4414; FNV-2026-09-29-D2-01 and SKY-D4-2026-09-29-01 (sibling ACHR-state decodes).
- **Suggested Fix**: decode bit 13 into `PlacedRef::starts_unconscious`, gated like
  `starts_dead` (ACHR, 24-byte family). Source its runtime meaning (actor present, AI and combat
  suppressed until a `SetUnconscious(false)`-equivalent event), then consume it at the same
  actor-job completion hook as `apply_starts_dead`. Pin it with a real-data count test
  (`Fallout4.esm` = 79).
