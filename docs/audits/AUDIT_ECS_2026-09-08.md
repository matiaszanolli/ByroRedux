# Dimension 8 — Hot-Path Performance Invariants

## ECS-2026-09-08-D8-01: a clean node between two dirty entities permanently strands the subtree below the deeper one

- **Severity**: HIGH
- **Dimension**: 8 (change detection) — correctness, not perf
- **Location**: [systems.rs:225-274](crates/core/src/ecs/systems.rs#L225-L274)
  (the incremental seeding branch) and
  [systems.rs:22-41](crates/core/src/ecs/systems.rs#L22-L41)
  (`enqueue_unique_children`)
- **Status**: NEW
- **Description**: On the incremental path, each dirty entity `e` is seeded by
  composing its global from *its parent's current global* — correct only when
  no ancestor of `e` is also dirty-but-not-yet-recomposed. The code knows this
  and relies on the BFS to re-fix `e` later ("the ancestor's seeded subtree
  re-fixes `e` — order doesn't matter"). That recovery works for `e` itself,
  but **not for `e`'s children**: seeding `e` enqueues them immediately, they
  are popped and `expanded.insert`-ed while `e` still holds its wrong global,
  and when the BFS finally reaches `e` and recomposes it correctly,
  `enqueue_unique_children` sees them in `expanded` and **refuses to re-enqueue
  them**, logging `"cyclic or duplicate Children edge"` instead. The subtree
  below `e` keeps a global composed from `e`'s pre-update value.

  It does not self-heal. The next frame nothing is dirty and the state key is
  unchanged, so the fast path at
  [systems.rs:158-160](crates/core/src/ecs/systems.rs#L158-L160) returns
  immediately and the wrong value survives indefinitely.

  The existing regression test
  `dirty_descendant_is_recomposed_after_a_later_dirty_ancestor`
  ([systems.rs:844](crates/core/src/ecs/systems.rs#L844)) reads as if it covers
  this, but its fixture is a two-entity chain where the dirty descendant is a
  **leaf** — precisely the one shape that cannot exhibit the defect.
- **Evidence**: chain `A → B → C → D`, each local `+1x`; `A` and `C` moved,
  `B` and `D` untouched:

  ```
  frame1: all correct
  frame3: idx 3 got 103.0 want 112.0  <<< WRONG
  frame8 (nothing moved since): idx 3 got 103.0 want 112.0  <<< WRONG
  ```

  Trace: seed `A` → `A.global = 10`, `expanded = {A}`, enqueue `B`. Seed `C`
  → parent `B` is still stale (`2`), so `C.global = 102`; enqueue `D`. BFS pops
  `B` (→ `11`, correct) then `D` (composed from `C = 102` → `103`) then `C`
  (→ `111`, correct) — and `C`'s re-enqueue of `D` is refused because `D` is
  already in `expanded`. Reproduced identically with the entity ids inverted
  (leaf spawned first).

  The same fixture with **every** node dirty stays correct, because ascending
  `EntityId` order then happens to recompose each parent before its child —
  which is why animation-heavy frames mostly get away with it.
- **Impact**: a persistently wrong `GlobalTransform` on a whole subtree.
  `GlobalTransform` is the renderer's model matrix, the skinning palette's bone
  source, `bounds.rs`'s leaf input, and `physics_sync`'s pose source, so the
  error is visible as a mis-placed attachment and a mis-sized `WorldBound`
  (hence wrong culling) until something perturbs the hierarchy. The trigger is
  routine content, not a corner case: `animation_system` writes `Transform`
  only for the channels a clip actually carries
  ([animation.rs:706-712](byroredux/src/systems/animation.rs#L706-L712)) plus
  the accum root ([animation.rs:754-761](byroredux/src/systems/animation.rs#L754-L761)),
  so any clip that keys the accum root and a distal bone but not every node
  between them — the normal shape of a `NiControllerSequence`, which carries one
  `ControlledBlock` per *animated* node — strands whatever hangs off that distal
  bone (an equipped weapon under a hand bone is the obvious case). The bogus
  `"cyclic or duplicate Children edge"` error also mis-attributes an engine
  defect to the content, once per affected frame.
- **Related**: the `expanded` guard was added for #3700 (bounded cyclic
  traversal); this is that guard firing on a legitimate revisit.
  ECS-2026-09-08-D8-02 is the sibling defect in the same function's structural
  branch.
- **Suggested Fix**: seed only the *shallowest* dirty entities. Build an
  `FxHashSet` from `transform_dirty` and, for each `e`, climb `Parent` (under
  the existing `HierarchyTraversalGuard`) — if any ancestor is in the set, skip
  seeding `e` entirely and let the BFS from that ancestor reach it. That makes
  every subtree walk top-down exactly once, removes the stale-parent compose,
  and drops the redundant seed work as a side effect. Extend
  `dirty_descendant_is_recomposed_after_a_later_dirty_ancestor` to a
  four-deep chain with a clean node between the two dirty ones, so the fixture
  actually exercises what its name claims.

## ECS-2026-09-08-D8-02: the roots-cache key is blind to a `Parent` remove/insert pair, and the generations that would catch it are wired only to the fast path

- **Severity**: MEDIUM
- **Dimension**: 8 (change detection)
- **Location**: [systems.rs:145-168](crates/core/src/ecs/systems.rs#L145-L168)
  and [systems.rs:189-199](crates/core/src/ecs/systems.rs#L189-L199)
- **Status**: NEW
- **Description**: `topology_changed` — the flag that decides whether to rebuild
  the cached `roots` set — is keyed on
  `(Transform::len(), Parent::len(), next_entity_id())` only. `Parent`'s
  `structural_generation()` *is* read one line earlier, but it feeds
  `last_state` (the fast-path decision) and never `last_roots_key`. A frame that
  removes `Parent` from one entity and inserts `Parent` on another, with no
  spawn, leaves all three components of the key identical while genuinely
  changing the root set: the detached entity is now a root that is not in the
  stale `roots` list and has no parent to be reached from, and the newly
  attached entity is still *in* `roots`, so Phase 1b overwrites its global with
  its bare local and `expanded.insert(root)` then makes
  `enqueue_unique_children` refuse to walk it from its real parent.

  This is precisely the class of edit the `structural_gen` counters were added
  for — the code's own comment at
  [systems.rs:76-81](crates/core/src/ecs/systems.rs#L76-L81) says they "catch
  hierarchy edits (reparent / attach) that move no `Transform` and leave entity
  counts unchanged" — applied to only one of the two decisions that needs them.
- **Evidence**: root `R(+5)` with child `X(+1)`, free-standing `Y(+7)`; then
  `X` detached, `Y` attached under `R`, `X` moved to `99`:

  ```
  frame1: R=5.0 X=6.0 Y=7.0
  frame2: X=6.0 (want 99.0)  Y=7.0 (want 12.0)
  frame3: X=6.0 (want 99.0)
  ```

  Both entities are wrong and neither recovers — frame 3 takes the fast path.
  Note `X`'s `Transform` *was* marked dirty and that did not help: the
  structural branch ignores `transform_dirty` entirely.
- **Impact**: two permanently wrong `GlobalTransform`s per occurrence, same
  blast radius as D8-01. **Not reachable from any current production call
  site**: a workspace-wide search finds no `world.remove::<Parent>` outside
  `byroredux/src/systems/bounds.rs`'s own test module, and `helpers::add_child`
  only appends to `Children` — it never unlinks a previous parent. A
  despawn+spawn pairing does not net out either, because `next_entity_id()`
  advances. So this is a latent defect whose invariant is upheld by an accident
  of the current call graph rather than by the key, and the first detach path
  added (item drop, ragdoll limb release, an editor unlink) inherits it
  silently.
- **Related**: ECS-2026-09-08-D8-01 (same function, incremental branch).
- **Suggested Fix**: gate the root rebuild on `structural_changed` rather than
  `topology_changed`, i.e. fold `parent_gen`/`children_gen` into the roots key
  (`last_roots_key: Option<((usize, usize, EntityId), u64, u64)>`), or simply
  drop `topology_changed` and rebuild `roots` whenever `structural_changed`.
  `topology_changed ⇒ structural_changed` already holds, so this is strictly
  more conservative and cannot regress the fast path — a reparent-overwrite
  frame would rebuild `roots` needlessly, which is the same
  once-per-hierarchy-edit cost the branch already pays. Add a regression test
  for the remove+insert pair.

## ECS-2026-09-08-D8-03: the BFS marks every parent dirty in `GlobalTransform` just to read it

- **Severity**: LOW
- **Dimension**: 8 (hot-path)
- **Location**: [systems.rs:310-312](crates/core/src/ecs/systems.rs#L310-L312)
  and [systems.rs:236-237](crates/core/src/ecs/systems.rs#L236-L237)
- **Status**: NEW
- **Description**: `let Some(parent_global) = gq.get_mut(parent_id).map(|g| *g)`
  is a pure read — the comment says so ("the deref copies it out") — but
  `PackedStorage::get_mut` calls `mark_dirty` unconditionally
  ([packed.rs:125-131](crates/core/src/ecs/packed.rs#L125-L131)), and
  `GlobalTransform` is `TRACK_CHANGES = true`. Every BFS step therefore pushes
  its parent into `GlobalTransform`'s dirty set on top of the legitimate mark
  for the child it actually writes. The incremental seeding branch does the same
  through `gq.get_mut(parent.0).map(|g| *g)`. `QueryWrite::get` is the
  non-marking accessor and is already in the API
  ([query.rs:146-148](crates/core/src/ecs/query.rs#L146-L148)).
- **Evidence**: a 3-wide, 4-deep tree (40 entities) after one structural walk —
  `GlobalTransform` dirty entries = **119** for 40 unique entities. 40 are the
  inserts, 40 the real writes, 39 the spurious parent reads.
- **Impact**: correctness-neutral (re-folding an unmoved bound is idempotent),
  but it is ~1 extra `EntityId` push per non-root entity per walked frame,
  and `bounds.rs` then pays for it twice: a larger `sort_unstable + dedup` over
  `g_dirty` ([bounds.rs:202-204](byroredux/src/systems/bounds.rs#L202-L204)) and
  a Pass-1 `WorldBound` recompute plus a Pass-2 root climb for parents whose
  global did not change. On the incremental path — the one the whole
  change-detection design exists to keep small — a single moved leaf dirties
  its parent too, so the "touch ~1 subtree" claim is really "~1 subtree plus its
  ancestors' bounds".
- **Suggested Fix**: `gq.get(parent_id).copied()` at both sites.
  `GlobalTransform: Copy`, and the shared borrow ends before the `get_mut` write
  that follows, so it is a drop-in.

# Dimension 5b — Scheduler Access Declarations

## ECS-2026-09-08-D5-01: the declaration-completeness test covers only the two systems where declarations are *not* load-bearing

- **Severity**: LOW
- **Dimension**: 5b (test gap)
- **Location**: [boot.rs:2892-2919](byroredux/src/boot.rs#L2892-L2919)
- **Status**: NEW
- **Description**: `assert_declares_everything_it_acquires` (#3951/#3473)
  compares a system's declared `Access` against the storages and resources its
  body actually acquires. It is invoked on exactly two systems —
  `papyrus_provider_system` and `legacy_obscript_load_order_system` — both
  registered with `add_exclusive_with_access`. The test's own assertion message
  concedes the point: *"These declarations do not gate scheduling today."*
  Meanwhile the nine systems registered with `add_to_with_access` **do** gate
  scheduling: `install_runtime_registries`'s three release assertions
  ([boot.rs:2009-2030](byroredux/src/boot.rs#L2009-L2030)) are the
  construction-time deadlock proof for every same-stage parallel batch, and
  that proof is only as sound as the declarations it analyses. An
  under-declared parallel system yields `known_conflict_count() == 0` while a
  real write/write overlap sits in the batch.

  Two secondary fragilities in the same helper: `declaration()` locates the
  block with `setup.find(system)` — the *first* textual occurrence — so a `use`
  import or a prose mention of the system name earlier in `boot.rs` silently
  redirects the extraction to a wrong slice that still contains type names and
  passes vacuously (both current subjects happen to be first-mentioned at their
  registration site, so it works today by luck). And `acquired()` scans only the
  system's own body, so a dispatcher like `player_controller_system` — whose
  body acquires exactly one resource and delegates everything else to
  `fly_camera_system` / `character_controller_system` — would report a
  three-type floor failure rather than a real comparison.
- **Evidence**: applying the test's own extraction to all nine
  `add_to_with_access` registrations finds no missing declaration today
  (`player_controller_system` 1, `timer_tick_system` 2, `make_animation_system`
  0, `make_transform_propagation_system` 4, `physics_sync_system` 1,
  `camera_follow_system` 7, `reverb_zone_system` 2, `log_stats_system` 5,
  `metrics_sample_system` 8 direct acquisitions, all declared) — so there is no
  live defect, only an unguarded invariant. The three factory/dispatcher
  systems return 0–1 direct acquisitions, which is why a naive extension would
  need the delegation followed or the entry point moved.
- **Impact**: no runtime effect today. The nine parallel declarations are
  currently correct and visibly hand-maintained (`make_transform_propagation_system`
  even carries a "WRITE (was read)" note explaining that it takes a write guard
  purely to drain the dirty set). The gap is that nothing keeps them that way,
  on exactly the set where drift is unsound rather than merely undiagnostic.
- **Suggested Fix**: run `assert_declares_everything_it_acquires` over the nine
  `add_to_with_access` registrations too, anchoring `declaration()` on the
  `add_to_with_access(` / `add_exclusive_with_access(` block containing the name
  rather than the name's first occurrence, and either following one level of
  delegation or asserting against the dispatch target's body for the three
  factory/dispatcher entries.

# Verified clean

Checked against the code at `bb8ced68` and found intact — recorded so a later
audit does not re-derive them.

**Dimension 1 — lock ordering / deadlock.** Every `query` / `query_mut` /
`resource` / `resource_mut` / `get` site in `world.rs` arms a `TrackedRead` /
`TrackedWrite` and defuses it only *after* the wrapper exists (#2149), so a
panicking downcast cannot orphan a tracker row. `query_2_mut`,
`query_2_mut_mut` and `resource_2_mut` set up their tracker scopes in
TypeId-ascending order, matching acquisition order (#313), and all three
`assert_ne!` on `A == B`. Both `query_2_mut` existence checks precede either
lock, and `try_resource_2_mut` still checks both before acquiring either
(#465). Every acquisition resolves `PoisonError` through the type-named
helpers; `despawn`, `despawn_batch`, `clear_entities` and `shrink_storages`
all route through the `type_names` side-table (#466/#1836). `track_read`'s
`held_others` collect sits behind `cfg(debug_assertions) && is_enabled()`
(#3680) and runs the global check *before* the recursive-read early return
(#3696), filtering `type_id` out of the held set as documented. `track_write`
does not filter, and does not need to: both of its panic arms fire whenever a
row for `type_id` exists, and `untrack_*` cannot leave a
`read_count == 0 && !has_write` row behind. `record_and_check`'s cycle test is
a reachability search (#2675) and drops the write guard before panicking so
`GRAPH` cannot poison.

**Dimension 2 — storage.** `SparseSetStorage::remove` fixes the moved entity's
sparse pointer, takes the no-swap path for the last element, and overwrites in
place on a duplicate insert; `structural_gen` bumps on insert (including
overwrite/reparent) and on a *confirmed* remove. `PackedStorage::insert_bulk`
keeps the append + single-sort fast path (#467) and its last-writer-wins dedup
scan maintains `write <= read`, so the swapped-out stale row always lands in
the truncated tail. `remove_entities_erased` is still the in-place
read/write-cursor merge (#3689), pinned non-reallocating.
`drain_dirty_into` clears `out` and preserves `self.dirty`'s capacity (#1371);
`take_dirty` still hands the allocation away. `clear_erased` releases capacity
on both backends (#2395/#2148). `World::insert_batch` still wraps the iterator
so the per-item `debug_assert` fires. Only `Transform` and `GlobalTransform`
are `PackedStorage + TRACK_CHANGES`, and both dirty sets have exactly one
drainer — transform propagation and `bounds.rs` respectively; `bounds.rs`
drains in a scope *above* every one of its early returns, so a scene with no
`LocalBound` cannot leak the set. The other four tracked components
(`Material`, `LocalBound`, `Parent`, `Children`, `ParticleEmitter`) are
`SparseSetStorage`, which carries a counter rather than a growing `Vec`.

**Dimension 3 / 6 — query borrow safety and unsafe.** The only `unsafe` in
`crates/core/src/ecs/` is still the four cached-pointer derefs in `query.rs`,
each with a SAFETY comment tying validity to the live guard, each with the
guard field alive on the struct. `QueryWrite::new` moving the guard into the
struct does not invalidate the pointer (the `Box` lives in the lock's
`UnsafeCell`, not in the guard). `ComponentRef::new` drops the guard on the
`?` miss, and `World::get` keeps its scope armed on `None`. The `ecs-query-miri`
CI job still runs `cargo miri test -p byroredux-core --lib ecs::world::tests`
with the single documented skip. `spawn` still `checked_add`s; `despawn` still
does not reclaim ids.

**Dimension 4 — resources.** `ResourceRead`/`ResourceWrite` downcast per
`Deref` (not cached, correctly — not the #1367 hot path); `insert_resource`
and `remove_resource` both re-panic on a poisoned prior value (#1837).

**Dimension 5 / 5b — scheduler and declarations.** Zero plain
`scheduler.add_to(` in `byroredux/src/`; all nine parallel registrations use
`add_to_with_access`. `install_runtime_registries` still carries all three
**release** assertions — `undeclared_parallel_count`, `known_conflict_count`
(#1602) and `unknown_pair_count` — with the #2690 comment intact.
`all_five_stages_run_in_order` still pins `Early → Update → PostUpdate →
Physics → Late`. 42 exclusives remain undeclared by design.

**Dimension 7 — lifecycles.** `clear_ambient_behavior` tears down all seven
procedures' `Behavior`/`State` pairs plus `Seated`/`Traveled`/`Escorted` and
`NavPath` (#3255), and `reconcile_dead_actor` adds `AmbientPackageRuntime` +
`EvaluatePackageRequest` (#3708) on the death-only path. At most one behavior
lands per actor — selection is a `match` on `AmbientBehavior`, not a chain of
independent predicates. `prune_seat_reservations` still checks *both* liveness
halves (furniture live **and** claimant still `Seated` on that furniture).
`event_cleanup_system`'s Pattern-A list and the module doc's Pattern-B table
are pinned against each other by `contract_tests`. `CombatState` holds a
single-slot trace and saturating counters, not a growing log;
`PendingDeathReconciliations` is `mem::take`-drained; `MeleeState` is a
per-entity component (#3709), so despawn reclaims it.

**Dimension 10 — animation runtime.** `advance_stack` ticks both blend timers
*ahead* of the `playing` gate (#3702) and writes `weight = blend_in_target *
progress` every tick, landing exactly on target at completion (#3701).
`sample_blended_transform`'s single-layer short circuit (#3706) is genuinely
bit-identical to the two-pass walk: `total_weight == ew` makes `w = ew/ew`
exactly `1.0`, `t * 1.0 == t`, and `accumulated_weight == 0.0` takes the
`blended_rot = r` branch — and it applies the same four gates, including
`channel_has_keys` (#3471) and the NaN-safe `!(ew >= 0.001)` (#3432).
`find_key_pair` handles `key_count == 0`, the single-key case and both
out-of-range ends; `shortest_path` applies the dot-sign flip.
`write_root_motion` writes `Vec3::ZERO` unconditionally (#3707), so a
conditional drainer cannot read a stale delta. `AnimationClipRegistry` still
case-folds its path keys (#790) and `release` still strands rather than reuses
a slot, with `stub_slot_count` making it observable (#2689).

**Dimension 9 — NIFAL in the component layer.** `Material::metalness` /
`roughness` are still plain `f32`; `resolve_pbr` remains the single
fill-the-gap helper with its four idempotence/clamp pins.
