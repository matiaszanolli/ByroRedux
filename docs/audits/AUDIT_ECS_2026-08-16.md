### ECS-2026-08-16-01: `combat::disable_actor_ai` is a divergent copy of `clear_ambient_behavior` that drops the seat-reservation release
- **Severity**: MEDIUM
- **Dimension**: 7 — Component Lifecycles (P2 gameplay slice)
- **Location**: `byroredux/src/combat.rs:288-311`, against `byroredux/src/npc_spawn/ai_package.rs:326-353`
- **Status**: NEW
- **Description**: The AI-teardown helper the death path calls is a near-verbatim
  second copy of the pre-existing ambient-package teardown. Both define a private
  `remove_component::<T>` with an identical body, and both then remove the same
  sixteen behaviour components. The one thing combat's copy left behind is the
  first statement of the original: the `SeatReservations` release. Because
  `prune_seat_reservations` runs only once per `load_references`, a killed seated
  actor's `(furniture, marker index)` claim survives its own `Seated` component and
  keeps the seat unusable until the next cell-reference load.
- **Evidence**:
  `npc_spawn/ai_package.rs:332-336`
  ```rust
  fn clear_ambient_behavior(world: &World, actor: EntityId) {
      if let Some(mut reservations) = world.try_resource_mut::<SeatReservations>() {
          reservations.0.retain(|_, claimant| *claimant != actor);
      }
      remove_component::<SandboxBehavior>(world, actor);
  ```
  `combat.rs:294-296` — the same function minus the release:
  ```rust
  fn disable_actor_ai(world: &World, actor: EntityId) {
      remove_component::<SandboxBehavior>(world, actor);
      remove_component::<Seated>(world, actor);
  ```
  `cell_loader/references/mod.rs:788-808` — `prune_seat_reservations` keeps a claim
  only while the furniture is live **and** the claimant still carries a `Seated`
  naming it, but `mod.rs:366` is its sole call site, inside `load_references`.
- **Impact**: With `BYRO_SANDBOX_SIT=1`, killing a seated NPC permanently removes
  that furniture marker from the pool for the rest of the cell's lifetime — no
  other actor can claim it. Independently of that gate, the duplication is the
  real hazard: two hand-maintained sixteen-entry rosters that must grow together
  as the procedure roster grows, with no test tying them to each other.
- **Related**: `AUDIT_ECS_2026-08-10.md` ECS-2026-08-10-04 / `AUDIT_ECS_2026-08-13.md`
  ECS-2026-08-13-06 both examined `clear_ambient_behavior` for a different gap
  (un-reverted `AnimationPlayer` state) and neither noticed the new second copy.
- **Suggested Fix**: Delete `disable_actor_ai` and make `clear_ambient_behavior`
  `pub(crate)`, calling it from `combat_damage_system`'s death branch. One roster,
  one release path, and the reservation gap closes by construction.

### ECS-2026-08-16-02: Nothing checks `Dead` before re-installing an AI behavior, so a corpse can be re-animated at the next package boundary
- **Severity**: MEDIUM
- **Dimension**: 7 — Component Lifecycles (P2 gameplay slice)
- **Location**: `byroredux/src/npc_spawn/ai_package.rs:430-500`, `byroredux/src/combat.rs:215-238`
- **Status**: NEW
- **Description**: `combat_damage_system` inserts `Dead` and tears down the seven
  behavior components, but leaves `AmbientPackageRuntime` — the component that
  *drives re-selection* — on the corpse. `ambient_ai_package_system` iterates every
  `AmbientPackageRuntime` holder with no `Dead` filter, and on any tick where the
  winning `PackRecord` FormID changes it calls `behavior.insert_at_runtime(world,
  actor)`. The dead actor therefore gets a fresh `SandboxBehavior` /
  `WanderBehavior` / … at the next in-game-minute schedule boundary.
- **Evidence**: `ai_package.rs:436-444` collects runtimes with no liveness filter;
  `ai_package.rs:482-490`:
  ```rust
  for &(actor, _, behavior, changed) in &updates {
      if !changed { continue; }
      clear_ambient_behavior(world, actor);
      if let Some(behavior) = behavior {
          behavior.insert_at_runtime(world, actor);
      }
  }
  ```
  `combat.rs:294-311` removes sixteen components; `AmbientPackageRuntime` is not
  among them. A workspace grep for `Dead` consumers returns exactly three:
  `combat.rs` itself, `crates/scripting/src/scene/quest_alias.rs:490` (alias fill),
  and `crates/scripting/src/condition.rs:504` (`GetDead`). No AI system consults it.
- **Impact**: `ambient_ai_package_system` is registered unconditionally at
  `boot.rs:823` in the same `Stage::Update` exclusive lane as combat, so the
  re-install can land the same frame as the kill. The corpse only visibly walks
  when one of the seven `BYRO_*` procedure gates is set, but the component state is
  wrong in the default build too — and `WanderState`/`TravelState`/`Dead` are all in
  the M45 save registry, so the inconsistency persists across save/load.
- **Related**: ECS-2026-08-16-01 (same teardown site).
- **Suggested Fix**: Skip `Dead` actors at the top of `ambient_ai_package_system`'s
  per-actor loop, and remove `AmbientPackageRuntime` in the death teardown so the
  corpse leaves the candidate set entirely. Fixing only one of the two leaves the
  other as a latent re-entry point.

### ECS-2026-08-16-03: `sample_blended_transform` interpolates every channel twice per bone per frame
- **Severity**: MEDIUM
- **Dimension**: 10 — Animation Runtime
- **Location**: `crates/core/src/animation/stack.rs:325-357` (pass 1) and `:369-390` (pass 3)
- **Status**: NEW
- **Description**: The fused priority/weight pass calls `sample_translation`,
  `sample_rotation` and `sample_scale` for every layer × channel and then throws all
  three results away — they exist solely to evaluate `t.is_none() && r.is_none() &&
  s.is_none()`. Each of those functions returns `None` **only** when its key vector
  is empty, so the predicate is exactly three `is_empty()` checks. Pass 3 then
  re-runs the identical three samples at the identical `layer.local_time`. There is
  also no single-layer short-circuit, which the audit contract for this dimension
  explicitly calls for.
- **Evidence**: `stack.rs:337-342`
  ```rust
  let t = sample_translation(channel, layer.local_time);
  let r = sample_rotation(channel, layer.local_time);
  let s = sample_scale(channel, layer.local_time);
  if t.is_none() && r.is_none() && s.is_none() {
      continue;
  }
  ```
  `t`, `r` and `s` have no further use in the function. `stack.rs:385` re-samples:
  `let t = sample_translation(channel, layer.local_time).unwrap_or(Vec3::ZERO);`.
  The `None` conditions are `interpolation.rs:95` (`translation_keys.is_empty()`),
  `:215` (`rotation_keys.is_empty()`), `:320` (`scale_keys.is_empty()`) — the only
  `None` returns in all three functions.
- **Impact**: Doubles the interpolation cost (binary `find_key_pair` +
  hermite/TBC/slerp evaluation, three key types) on the hot path the skill names —
  once per unique channel name per stack-driven entity per frame. The live call site
  is `byroredux/src/systems/animation.rs:754`, inside the per-channel loop over
  `channel_names_scratch`, i.e. one call per bone.
- **Related**: Distinct from the two closed predecessors — *PERF-17*
  (`AUDIT_PERFORMANCE_2026-04-04.md`, per-bone `Vec` allocations, since removed) and
  *P6-05* (`AUDIT_PERFORMANCE_2026-04-13.md`, three passes, fused to two by #288).
  Neither names the redundant interpolation, and the code today allocates nothing.
- **Suggested Fix**: Replace the pass-1 sampling with
  `channel.translation_keys.is_empty() && channel.rotation_keys.is_empty() &&
  channel.scale_keys.is_empty()`, and short-circuit `stack.layers.len() == 1`
  straight into pass 3.

### ECS-2026-08-16-04: The native inventory can never equip a weapon, and `EquippedWeapon` has no runtime writer — combat's damage source is frozen at spawn
- **Severity**: MEDIUM
- **Dimension**: 7 — Component Lifecycles (P2 gameplay slice)
- **Location**: `byroredux/src/inventory.rs:106`, `:319-370`; `byroredux/src/combat.rs:269-273`
- **Status**: NEW
- **Description**: `describe_kind` returns `equip_slot_mask: None` for
  `ItemKind::Weapon` (only `ItemKind::Armor` ever produces a `Some`).
  `apply_action`'s `ToggleEquip` bails with `MutationResult::Unavailable` whenever
  the catalog entry has no mask, so a weapon row in the menu is inert. Separately,
  `EquippedWeapon` — the component `combat::attack_damage` reads to decide melee
  damage — is written at exactly two places in the workspace, both spawn-time
  (`inventory::attach_to_player` and `npc_spawn.rs:783`). Nothing mutates it
  afterwards. `EquipmentSlots` and `EquippedWeapon` are therefore two disjoint views
  of "what is equipped", and only the former is player-mutable.
- **Evidence**: `inventory.rs:106`
  ```rust
  ItemKind::Weapon { damage, .. } => ("Weapon", format!("Damage {damage}"), None),
  ```
  `inventory.rs:339-349` returns `Unavailable` on `equip_slot_mask == None`.
  `combat.rs:269-273`:
  ```rust
  fn attack_damage(world: &World, aggressor: EntityId) -> f32 {
      world
          .get::<EquippedWeapon>(aggressor)
          .map_or(UNARMED_DAMAGE, |weapon| weapon.damage.max(0.0))
  }
  ```
  Workspace grep for `EquippedWeapon` writers outside tests: `inventory.rs:249`
  (`attach_to_player`) and `npc_spawn.rs:783` (spawn tail) only.
- **Impact**: The P2 playable slice's only damage lever is decided once by
  `prefer_weapon`'s "highest base damage, lowest FormID breaks ties" heuristic at
  player spawn. Picking up or selecting a different weapon in the menu cannot change
  melee damage, and unequipping a weapon in the menu leaves `EquippedWeapon` intact
  so the player still swings for its damage. `docs/smoke-tests/p2-melee-core.sh`
  cannot see this — it asserts `damage=8.0`, the *unarmed* path.
- **Related**: `docs/engine/playable-vertical-slice.md` (corpse loot still open —
  loot will need this same write path).
- **Suggested Fix**: Give `ItemKind::Weapon` a weapon-slot mask in `describe_kind`
  and have `apply_action` reconcile `EquippedWeapon` with the weapon slot on both
  the equip and unequip branch, so `EquipmentSlots` stays the single source of truth
  and `EquippedWeapon` becomes its derived cache.

### ECS-2026-08-16-05: `combat_input_system` burns the attack edge and arms the cooldown before the `PlayerMode::Character` gate
- **Severity**: LOW
- **Dimension**: 7 — Component Lifecycles (P2 gameplay slice)
- **Location**: `byroredux/src/combat.rs:80-99`
- **Status**: NEW
- **Description**: The `CombatState` mutation block consumes `attack_pressed`,
  increments `attacks_started` and sets `cooldown_remaining = MELEE_COOLDOWN_SECONDS`
  *before* the function checks that the player is in `PlayerMode::Character`. In
  fly-cam mode the counter still climbs and the cooldown still arms, even though no
  swing, ray cast or `HitEvent` can occur.
- **Evidence**: `combat.rs:80-99`
  ```rust
  let attack_ready = if let Some(mut state) = world.try_resource_mut::<CombatState>() {
      ...
      if attack_pressed && state.cooldown_remaining <= 0.0 {
          state.cooldown_remaining = MELEE_COOLDOWN_SECONDS;
          state.attacks_started = state.attacks_started.saturating_add(1);
          true
      } else { false }
  } else { false };
  if !attack_ready
      || !world.try_resource::<PlayerMode>()
          .is_some_and(|mode| *mode == PlayerMode::Character)
  { return; }
  ```
  Note that `record_miss` is *not* called on the mode bail either, so
  `CombatState.last` keeps a stale entry while the counter moves.
- **Impact**: `attacks_started` overstates real swings after any fly-cam session,
  and returning to character mode can land on an already-armed cooldown. Cosmetic
  today, but `attacks_started` is smoke-test evidence
  (`docs/smoke-tests/p2-melee-core.sh` asserts `attacks=7 hits=7 kills=1`), so the
  counter is load-bearing for the gate's meaning.
- **Related**: ECS-2026-08-16-04 (same module's spawn-frozen state).
- **Suggested Fix**: Move the `PlayerMode` check ahead of the `CombatState` mutation
  (keep the `dt` cooldown decrement unconditional so the timer still drains), or
  record a miss on the mode bail.

### ECS-2026-08-16-06: `visit_text_key_events` silently drops every text key when one frame advances a full clip period
- **Severity**: LOW
- **Dimension**: 10 — Animation Runtime
- **Location**: `crates/core/src/animation/text_events.rs:29-68`, with `crates/core/src/animation/player.rs:97-105`
- **Status**: NEW
- **Description**: The visitor infers wrap-around purely from the sign of
  `curr_time - prev_time`. `advance_time`'s `CycleType::Loop` arm folds with
  `local_time %= clip.duration`, so an advance covering one or more whole periods can
  land with `curr_time >= prev_time` and be classified as "forward, no wrap". Every
  key outside the narrow `(prev_time, curr_time]` window is then never visited, even
  though the playhead swept past it — possibly more than once.
- **Evidence**: `text_events.rs:52-57` (the forward branch fires only
  `*t > prev_time && *t <= curr_time`) against `player.rs:97-105`:
  ```rust
  CycleType::Loop => {
      player.local_time += delta;
      if clip.duration > 0.0 {
          player.local_time %= clip.duration;
  ```
  With `duration = 0.5`, `prev_time = 0.1` and a 1.2 s hitch at `speed = 1.0`,
  `local_time` becomes `1.3 % 0.5 = 0.3`; `0.3 >= 0.1` selects the no-wrap branch and
  only keys in `(0.1, 0.3]` fire.
- **Impact**: Text keys drive footstep dispatch and, through
  `cinematic_animation_event_system` (`boot.rs:959`), Skyrim behavior/Papyrus
  completion notifications. A dropped completion during a streaming hitch can stall a
  cinematic. `animation_system` reads raw `DeltaTime` with no clamp of its own, so
  the window is a real load-time hitch rather than a synthetic one.
- **Related**: #2082 / FNV-D6-01 fixed the adjacent ping-pong misclassification in
  the same function.
- **Suggested Fix**: Have `advance_time` report how many whole periods the advance
  consumed (or pass the unwrapped `prev + delta`) and let the visitor fire every key
  once when the span covers a full period.

## Premises checked and disproved (not reported)

Recorded so a later sweep does not re-derive them.

- **`inventory.rs` as a second source of truth** — it is not.
  `InventoryCatalog` / `InventoryItemDefinition` carry only immutable record
  metadata (name, category, value, weight, details, `equip_slot_mask`), and
  `install_catalog` replaces the whole resource via `world.insert_resource`, so a
  load-order change cannot leave stale entries. Canonical state stays `Inventory` +
  `EquipmentSlots`.
- **Inventory reset on cell transition** — `attach_to_player` is called from exactly
  one place, `scene::setup_scene` (`byroredux/src/scene.rs:1291`), which itself runs
  once from `app_events.rs:156` on winit `resumed`. Door transitions keep the player
  entity, so the template never overwrites live inventory.
- **`EquipmentSlots` positional-index invalidation** — `Inventory`
  (`crates/core/src/ecs/components/inventory.rs`) exposes only `push` / `get` /
  `len` / `is_empty`; there is no removal API, so a stack can never shift out from
  under an `InventoryIndex`.
- **Scripted `HitEvent` mis-damaged by `attack_damage`** — `combat.rs` is the only
  `HitEvent` producer in the tree; the other references are the component
  definition, registration, the Late-stage drain, and a recognizer table comment.
- **Combat-local `HitEvent` cleanup** — none exists; teardown is
  `event_cleanup_system` (`crates/scripting/src/cleanup.rs:33`), by design.
- **Incomplete AI teardown roster** — `disable_actor_ai` covers all sixteen
  components of the live seven-procedure roster. (Its *gap* is the reservation
  release, ECS-2026-08-16-01, not a missing component.)
- **Stuck Attack/Block after a menu opens mid-hold** —
  `ui_input::release_world_input` (`byroredux/src/ui_input.rs:33-42`) clears both
  `keys_held` and `mouse_buttons_held` and calls `clear_debug_input`, and the
  scheduler is skipped entirely while the game menu is visible
  (`app_events.rs:619-621`).
- **`ActionState` going stale** — `refresh_action_state` is the first statement of
  `player_controller_system` (`byroredux/src/systems/character.rs:79`), ahead of
  every early-return, and runs in `Stage::Early` before all three Update exclusives.
- **Key-binding swap non-convergence on load** — `ActionBindings::rebind_key`
  displaces rather than overwrites; applying a saved permutation in registry order
  converges (traced by hand for a 2-cycle and a 3-cycle). `settings_io::decode_value`
  plus `SettingsRegistry::set` reject out-of-range numbers and unknown choices
  (`SettingsError::UnknownChoice`), so a hand-edited file cannot install a bogus key.
- **`interaction::activation_is_blocked` as a redundant re-check** — it is not:
  `collect_candidates` inserts every `DoorTeleport` holder unconditionally before the
  MG07 arm's `or_insert`, so a disabled MG07 door that is also a `DoorTeleport` needs
  the second filter.
- **#2923 `Fx*` hot-path regression in `interaction.rs`** — the `std` `HashMap` in
  `collect_candidates` is not on the skin/render path the rule scopes.
- **Undrained `RootMotionDelta`** — `animation_system` overwrites it each frame
  (`byroredux/src/systems/animation.rs:70-78`) rather than accumulating, and
  `cinematic_root_motion_system` zeroes it (`byroredux/src/systems/cinematic.rs:128`).
- **`AnimationStack` layer growth / premature layer drop** — `play` clears all
  layers when `blend_time == 0` and only arms `blend_out` on layers not already
  fading; `cleanup_finished` retains anything whose blend-out has not completed, so
  it cannot drop a contributing layer. `sample_blended_transform` allocates nothing.
