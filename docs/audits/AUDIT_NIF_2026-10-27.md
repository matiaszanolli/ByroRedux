## Findings

### LOW

#### NIF-D4-2026-10-27-01: `SkeletonBones::from_scene` is a third hand-rolled NIF world-transform composition that #6303 left behind. It drops scale and the #4549 sanitiser, uses a bare `NiNode` downcast, and caches its parse unreported
- **Severity**: LOW
- **Dimension**: Geometry Handoff
- **Game Affected**: Starfield (`bsver >= 172`, external-skeleton `BSSkin` bone-name recovery, #3549)
- **Location**: `crates/nif/src/import/mesh/skeleton.rs:76-131` (`SkeletonBones::from_scene`), `:290-295` (`resolve_external_bone_names`)
- **Status**: NEW. It follows through on #6303 (closed), which moved `extract_np_ragdoll`'s `node_world` onto `compose_transforms` + `any_ni_node`. This function has the same shape.
- **Description**: The resolver builds each joint's bind world translation by hand:
  - The parent map and the chain use only `scene.get_as::<NiNode>`.
  - Rotation × translation is folded manually.
  - There is **no scale term**: the child translation is never multiplied by the parent's scale, which `compose_transforms` does.
  - There is no `sanitize_transform_translation_and_scale`.

  The skeleton is parsed with `crate::parse_nif(&bytes).ok()?` and cached for the process. A truncated or recovered skeleton is never reported, because the `note_scene_health` path lives in the binary crate.
- **Evidence**: The probe measured the three Starfield human skeletons. `meshes\actors\human\characterassets\skeleton.nif` has 116 nodes, `_1stperson` has 112 and `human_crowd` has 90. All are plain `NiNode` and every node has scale 1.0, so vanilla output is correct today. The other remaining hand composition is `ragdoll.rs::node_world`, which already folds `compose_transforms`; a `grep` over `crates/nif/src` finds no further copies.
- **Impact**: Latent. Wrong joint positions would need a mod skeleton with a non-unit bone scale or a `BSMultiBoundNode` / `NiSwitchNode` parent. Even then the anchor solver declines rather than mis-assigns, so the worst case is the existing `Bone{i}` + bind-pose fallback.
- **Related**: #6303, #3549, #4549
- **Suggested Fix**: Build the parent map through `any_ni_node` and fold `compose_transforms`, or share one `node_world` helper with `import/collision/ragdoll.rs`.

#### NIF-D4-2026-10-27-02: `dark_role_has_one_writer_and_carries_its_census_doc` cannot fail on its doc half, because it `include_str!`s its own file and its needles match themselves
- **Severity**: LOW (test-gap)
- **Dimension**: Geometry Handoff (import types)
- **Game Affected**: none (test only; the pinned doc is Oblivion's dark-role census)
- **Location**: `crates/nif/src/import/types/material.rs:264-273` (test), with the doc at `:58-59`
- **Status**: NEW. The test has been vacuous since `0faa0b107` (#4523, 2026-09-20). #6141 (`5559074be`) moved it from `types.rs` and re-pointed the `include_str!`, keeping the defect. This is not the REN-D1-01 shape: that one is call-order, this one is self-matching needles.
- **Description**: The test asserts `types_src.contains("#4523 census, 2026-09-20") && types_src.contains("8 meshes in 6 files")`, where `types_src = include_str!("material.rs")`. That whole-file text includes the `#[cfg(test)] mod tests` holding those same literals, so each needle occurs twice. Deleting or rewording the census doc still passes. This is the #4604/#4842/#5164 class described in `_audit-common.md`. The test's second half (`legacy_properties.rs` must contain `info.dark_map = ` exactly once) is sound.
- **Evidence**: A scripted scan checked every `include_str!` + `.contains`/`.matches` pair in `crates/nif/src`. Only these two needles have a whole-file count (2) above their production-only count (1).
- **Impact**: None at runtime. The pin that should force a census re-derivation when the dark-role doc changes is not enforced.
- **Suggested Fix**: Scan `byroredux_core::source_scan::production_text(include_str!("material.rs"))`; that helper is already used in `crates/nif/src/import/{collision/mod.rs,walk/lights.rs}`.
