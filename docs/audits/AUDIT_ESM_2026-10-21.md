## Findings

### HIGH

### ESM-2026-10-21-01: Skyrim+/FO4/FO76/Starfield PSDT duration is minutes, decoded as hours, so every timed package is active around the clock
- **Severity**: HIGH
- **Dimension**: Sub-Record Byte Accounting
- **Record / Sub-record**: `PACK` / `PSDT`
- **Location**: `crates/plugin/src/esm/records/misc/pack.rs:970-1004` (PSDT arm); `pack.rs:479-495` (`PackSchedule::active_at`); pinned wrong by `parse_pack_reads_skyrim_plus_psdt_schedule_from_offset_8` (`pack.rs:~1580`)
- **Status**: NEW. Related to #2012 (closed): that fix moved the Skyrim+ duration to offset 8 but kept the hours unit.
- **Description**: xEdit defines the Skyrim+ field as `wbInteger('Duration (Hours)', itU32, wbDiv(60, 4))` (`wbDefinitionsTES5.pas:8548`, `FO4.pas:10569`, `SF1.pas:15600`). The stored integer is minutes; xEdit shows it divided by 60. The FO3/FNV/Oblivion field is plain `itU32` hours (`FNV.pas:7134`, `TES4.pas:2926`). `parse_pack` reads offset 8 on `uses_prebaked_facegen()` games and stores the raw value in `PackSchedule::duration_hours`. The Skyrim+ `Minute` byte at offset 4 is also dropped, so a start like 08:30 becomes 08:00.
- **Evidence**:
  - Skyrim.esm census: `WhiterunBraithSleep21x12` stores `hour=21, duration=720`; `SolitudeBackupFishmongerWork6x14` stores `6, 840`; `DragonBridgeClintonSleep22x10` stores `22, 600`.
  - Duration histogram over timed PSDTs: 720 ×262, 60 ×225, 120 ×218, 240 ×193, 360 ×141, 480 ×135. Every value is a multiple of 60 except 36 records.
  - In `active_at`, `end = start + duration_hours` (for example 21 + 720). With `end > 24`, the wrap arm is `h >= start || h < end - 24`, and `end - 24 ≥ 36` makes it true for every hour.
  - Skyrim.esm: 1,536 of 1,545 timed PSDTs have a raw duration ≥ 24. Fallout4.esm: 251 of 252.
- **Impact**: `select_active_package` (`byroredux/src/npc_spawn/ai_package.rs:772-800`) is not game-gated. It returns the first package in the stack whose conditions pass. On Skyrim, FO4 and Starfield every scheduled package (sleep, work, eat) is "in schedule" all the time, so an NPC is pinned to the first scheduled package in its stack around the clock. Time-of-day package switching, the core of ambient AI, does not happen on any Creation-era title. FO3/FNV/Oblivion are unaffected.
- **Related**: #2012, #6079 (Day-of-Week on the same sub-record), #3352 (zero-length windows).
- **Suggested Fix**: on the 12-byte arm, divide the raw value by 60 and keep the start minute. Store the window in minutes, or as `f32` hours, so 90-minute windows survive. Correct the #2012 test to `duration=720 → 12 h`, and add a Skyrim.esm real-data pin such as `WhiterunBraithSleep21x12` → 21:00 for 12 h.

### MEDIUM

### ESM-2026-10-21-02: FO76 NPC_ ACBS (20 bytes, FO4 layout) matches no parse arm
- **Severity**: MEDIUM
- **Dimension**: Record Schema Dispatch
- **Record / Sub-record**: `NPC_` / `ACBS`
- **Location**: `crates/plugin/src/esm/records/actor/npc.rs:793-889` (arms gated at 793, 820-822, 852, 867)
- **Status**: NEW. This is the #6120 shape, fixed only for Starfield.
- **Description**: The ACBS arms are tried in this order:

  | Arm | Matches |
  |---|---|
  | Oblivion | Oblivion only |
  | FO4 | `Fallout4 && len ≥ 20` |
  | Starfield | `Starfield && len ≥ 16` |
  | Skyrim | `Skyrim && len ≥ 24` |
  | Generic FNV | `len ≥ 24` |

  FO76's ACBS (`wbDefinitionsFO76.pas:12893-12941`) is the FO4 layout: flags u32, XP offset, level, calc min/max, disposition, template flags, bleedout override, 2 unused bytes. That is 20 bytes, which is shorter than every non-FO4/Starfield arm requires.
- **Evidence**: SeventySix.esm, 6,551 `NPC_` records, `ACBS` size histogram `{20: 6551}`. With `GameKind::Fallout76`, none of the guards above passes.
- **Impact**: Every FO76 NPC has `acbs_flags = 0`, so it is male (female-only outfit ARMAs have no mesh), not essential/protected/unique, and not auto-calc. `level` stays at its constructor default and `template_flags = 0`, so no TPLT inheritance runs and every leveled NPC shell spawns without its template's traits, inventory or model. `essential`/`protected` (#5921) are derived from the zero flags.
- **Related**: #6120 (Starfield, closed), ESM-2026-10-21-03.
- **Suggested Fix**: widen the FO4 arm to `matches!(game, Fallout4 | Fallout76) && len >= 20`, with the xEdit citation and a SeventySix-shaped fixture.

## Verified clean (no finding)

- **Starfield remap** (`reader.rs::remap_starfield`, #6118):
  - Each ordinal is counted among masters of the top byte's own kind; ordinal equal to the count means self. Unlisted masters pass through with a `warn`.
  - `build_remap_for_plugin` picks the scheme from each plugin's own `GameKind::from_header`, and it is the only production `FormIdRemap` literal.
  - All 58 installed Starfield `.esm` headers report HEDR 0.96, and TES4 flags `0x100`/`0x400`/`0x800` match `wbDefinitionsSF1.pas:9046-9053`.
  - `allocate_global_slot` caps regular slots at `0xFB` (#5988).
- **CELL override merge** (#6086): `merge_cell_override` destructures `CellData` exhaustively. Only references, landscape, navmeshes and pathgrids (now merged by FormID, like navmeshes) inherit from the base, plus the synthetic-EDID identity case.
- **Moved REFR sweep** (#6084): the sweep removes a FormID an override authors under cell X from every other cell, keyed by CELL FormID, and skips the work when `self` has no cells.
- **`locate_refr`** (#6125): a stale `refr_lookup` entry misses rather than naming another reference. `merge_from` resets both lazy indexes.
- **LTEX** (#6036, #6048):
  - `HNAM`/`MNAM` match xEdit for TES4, FO3, FNV, TES5, FO4, FO76 and SF1. The material byte is read only for Oblivion/FO3NV, and `MNAM` is remapped.
  - The TNAM→TXST join re-runs after every `merge_from`, and an ICON-authored override drops an earlier TNAM.
  - FO76 note: one SeventySix LTEX carries xEdit-"Unused" `TNAM`/`GNAM` (GNAM may name a REFR). It is folded into the grass/TXST maps and misses harmlessly.
- **WATR `SNAM`** (#6045): a remapped FormID on every game, matching xEdit (TES4/FO3/FNV `SOUN`, TES5+ `SNDR`). Oblivion.esm has 18 of 23 at 4 bytes. Starfield authors none.
- **REFR `XLMS`** (#5757): `wbArray(XLMS, LMSW FormIDs)` at `SF1.pas:8515/8994`. Starfield.esm has 689,041 REFR/ACHR `XLMS`, all with `len % 4 == 0`. No placement carries the Planet-Model component whose `XMSP`/`XLMS` are strings (`SF1.pas:6632-6634`). LMSW/MTPT fixtures are real Starfield.esm bytes.
- **`PSDT` Day-of-Week** (#6079): offset 1, `wbPackageScheduleDayOfWeekEnum` (−1 any, 0–6, 7–10 groups) matches `PackDays::from_raw` exactly.
- **WTHR** (#6037–#6042): `wbWeatherCloudTextures` uses `DNAM/CNAM/ANAM/BNAM` only under `wbIsFallout3`, and `00TX`..`O0TX` (byte − `'0'`) elsewhere. `FNAM` fog power is read only for `gmTES4R`+ (FO3/FNV 24 bytes), and Max plus height-fog only for later games, all per `wbWeatherFogDistance`.
- **`ACBS` Starfield** (#6120): 16 bytes, template flags at +14 per `SF1.pas:15012-15057`. Essential bit 1 and Protected bit 11 (#5921) match.
- **`SharedParseCache`** (#6123): keyed by ordered paths plus length and mtime. A failed parse keeps the resident index. The Oblivion exterior post-pass is idempotent, and an Oblivion index processed for an exterior is served to both kinds of session.
