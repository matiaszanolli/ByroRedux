## Dimension Pass List (verified, no finding)

### 1. Lock Ordering & Deadlock — PASS

Read `world.rs` in full (885 lines). Every acquisition site (`get`, `query`,
`query_mut`, `query_2_mut`, `query_2_mut_mut`, `resource`, `resource_mut`,
`resource_2_mut`, `try_resource`, `try_resource_mut`, `try_resource_2_mut`)
arms a `TrackedRead`/`TrackedWrite` scope before the real lock, defuses only
after the wrapper is fully constructed (the `#2149` ordering — defuse-after-
wrapper-construction, not defuse-then-construct, so a downcast panic can't
orphan a tracker row), and every guard type (`QueryRead`/`QueryWrite`/
`ComponentRef`/`ResourceRead`/`ResourceWrite`) untracks in `Drop`.

`query_2_mut` (`world.rs:475-528`), `query_2_mut_mut` (`world.rs:545-592`), and
`resource_2_mut` (`world.rs:709-766`) all branch on `id_a < id_b` and arm the
tracker scopes in that same TypeId-ascending order — the pre-#313 parameter-
order-arming bug is not present. All three plus `try_resource_2_mut` `assert_ne!`
on `A == B`. `try_resource_2_mut` (`world.rs:833-850`) does both
`contains_key` existence checks before acquiring either lock — the #465 fix is
intact.

Poison resolution: every site resolves through `storage_lock_poisoned::<T>()`
/ `storage_lock_poisoned_erased()` / `resource_lock_poisoned::<R>()`.
`despawn` (`world.rs:121-136`) and `clear_entities` (`world.rs:227-239`) both
feed the erased variant from the `type_names` side-table (#466/#1836).
`insert_resource`/`remove_resource` re-panic loud on a poisoned prior value
(#1837) rather than swallowing into `None`.

`lock_tracker.rs` (563 lines): thread-local same-thread reentrancy check is
unconditional (debug + release); the global ABBA graph is `cfg(debug_assertions)`
+ `BYRO_LOCK_ORDER_CHECK`-gated, with the held-set Vec collection itself gated
as one block (#823) so release builds skip the allocation entirely. All six
unit tests plus the combined `global_graph_detector_end_to_end` scenario pass.

### 2. Storage Correctness — PASS

`sparse_set.rs` (438 lines): swap-remove fixes `sparse[moved_entity]`; last-
element removal takes the no-swap early-return; insert into an existing
entity overwrites in place without growing `len()`. All pinned by
`swap_remove`, `remove_last`, `overwrite` tests, still passing.

`packed.rs` (740 lines): `binary_search` maintains the sorted invariant on
insert/remove; `insert_bulk` (#467) appends to the tail then does a single
`sort_by_key` + a forward-scan last-writer-wins dedup — not O(n) per-insert
shift. `drain_dirty_into` clears `out` first then appends, preserving
`self.dirty`'s capacity (#1371); `take_dirty` hands capacity away via
`mem::take`. Both documented as tolerating duplicates. `World::insert_batch`
(`world.rs:187-212`) wraps the iterator with a `debug_assert!(entity <
next_entity)` per item before delegating to `insert_bulk`.

### 3. Query Borrow Safety — PASS

`query.rs` (291 lines): `QueryRead`/`QueryWrite`/`ComponentRef` each hold their
`RwLock*Guard` for the wrapper's full lifetime and cache a raw pointer
downcast exactly once in `new()`. Every `unsafe` deref (4 total, see Dimension
6) carries a SAFETY comment tying pointer validity to the live guard.
`ComponentRef` (the #35 UAF replacement) retains the guard rather than
returning a bare pointer to storage that could be dropped. `QueryWrite`'s
`DerefMut` requires `&mut self`, so the borrow checker forbids a live `&` and
`&mut` coexisting. `query`/`query_mut` return `None` for never-created
storage without lazily creating it.

### 4. Resource Lifetimes — PASS

`resource.rs` (103 lines): `ResourceRead`/`ResourceWrite` downcast through the
guard on every `Deref`/`DerefMut` call (not cached — correctly distinct from
the #1367 hot-path caching in `query.rs`, since resources aren't accessed at
per-entity-iteration frequency). `world.rs`'s `resource()`/`resource_mut()`
panic with the type name when never inserted; `try_resource()`/
`try_resource_mut()` return `None`. `insert_resource` returns the prior value;
`remove_resource` resolves poison via `resource_lock_poisoned`.
`try_resource_2_mut` does both existence checks before acquiring either lock
(#465 — confirmed no check-then-lock-then-check regression).

### 5 & 5b. System/Scheduler Wiring + Access Declarations — PASS

`scheduler.rs`: `Stage` enum is exactly `Early=0, Update=1, PostUpdate=2,
Physics=3, Late=4` — no `ParallelUpdate`/`LateExclusive` stage exists.
`all_five_stages_run_in_order`-style tests register out of order and the
`BTreeMap<Stage,_>` still runs `Early..=Late` once.

`byroredux/src/boot.rs::build_scheduler` has exactly **10** `add_to_with_access`
calls (grep-counted, matching the skill's documented count) and **zero** plain
`scheduler.add_to(...)` calls — every parallel-stage system declares its
access; no M27 regression. `install_runtime_registries`
(`boot.rs:1091-1119`) runs the triple `debug_assert_eq!` guard
(`undeclared_parallel_count() == 0`, `known_conflict_count() == 0`,
`unknown_pair_count() == 0`) — the #1394/#1601/#1602 guard chain is intact,
not just a log line.

`access.rs` (402 lines): `AccessConflict` has exactly the three documented
variants (`None`, `Unknown{left_undeclared,right_undeclared}`,
`Conflict{pairs}`) — no `Parallel` variant. `analyze_pair` returns `Unknown`
whenever either side is `None`. Exclusive systems (`event_cleanup_system`,
`audio_system`, `spin_system`, the DLC dispatchers, etc.) are registered via
plain `add_exclusive` without access declarations, as designed — not flagged
as a conflict per the skill's explicit guidance.

Panic policy: `Scheduler::run` remains fail-fast by design (#1412) — no
`catch_unwind` present, correctly not flagged as a bug.

### 6. Unsafe Code Review — PASS

### 8. Hot-Path Performance Invariants — PASS

`lock_tracker.rs::track_read`/`track_write`: the `held_others` Vec collection
is gated inside `#[cfg(debug_assertions)]` (#823) in both functions —
confirmed release builds skip the allocation.

`crates/core/src/ecs/systems.rs::make_transform_propagation_system` (read in
full, 254 lines): the fast path keys `last_state` on
`(roots_key, parent_gen, children_gen)` where `roots_key =
(Transform::len(), Parent-len-or-0, next_entity_id())`, skips the whole walk
when `transform_dirty.is_empty() && last_state == Some(state)`, and uses
`drain_dirty_into(&mut transform_dirty)` (not `take_dirty`) to preserve scratch
capacity across frames (#1371). The incremental (non-structural-change) path
recomposes each dirty entity from its parent's *current* cached global (sound
even when an ancestor is also dirty and processed later, since the BFS queue
re-visits and overwrites the subtree once the ancestor's own recompute runs —
the double-computation is wasted work, not a correctness bug, matching the
inline comment's claim).
