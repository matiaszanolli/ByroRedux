## Findings

### ECS-SD-01: `World::init_resource` split `insert_resource`'s doc comment, and has no test
- **Severity**: LOW
- **Dimension**: 4 Resources & World-Level State (`world.rs` resource half)
- **Location**: `crates/core/src/ecs/world.rs:655-669` (the doc block and `init_resource`), `:671` (`insert_resource`)
- **Status**: NEW (searched open issues and `gh issue list --state all` for "init_resource" / "insert_resource doc": only unrelated #5802). Introduced by `d0572ed94` (Fix #5806).
- **Description**: `init_resource` was pasted between the `/// Insert a global resource ... # Panics ... (#1837)` block and `pub fn insert_resource`. Rustdoc now attaches the whole block to `init_resource` (its page reads "Insert a global resource. Returns the previous value if one existed", which is false for it) and `insert_resource` has no doc at all. Same class as the #6064 `memory_barrier` doc split fixed today.
- **Evidence**:
  ```
  /// Insert a global resource. Returns the previous value if one existed.   // 654
  /// # Panics ... (#1837). The freshly-installed replacement value ...      // 656-662
  /// #5806 — the "insert the default if absent" idiom ...                   // 663-667
  pub fn init_resource<R: Resource + Default>(&mut self) { ... }              // 668
  pub fn insert_resource<R: Resource>(...) -> Option<R> { ... }               // 677
  ```
  `rg 'init_resource' crates/core/src/ecs/world.rs` returns only the definition: no test pins the one property its 155 call sites (area: `cell_loader/created.rs:263`, `npc_spawn/seam_blend/tone.rs:68`) rely on, "an existing value, e.g. a save restore's, is left untouched". I checked that the migrated sites (`ff132d272`, `d0572ed94`, `e470f5e6d`) all previously inserted `Default::default()`, so no behaviour changed.
- **Impact**: documentation only today; the missing test means a future edit to "always insert" would silently clobber restored resources at 155 sites.
- **Suggested Fix**: move the `init_resource` doc and fn below `insert_resource`, restore the original block, and add a 6-line test (insert a non-default value, call `init_resource`, assert unchanged; call on an absent type, assert default inserted).

### ECS-SD-03: "reused entity id" comments contradict the never-recycled invariant
- **Severity**: LOW (doc rot with a dead-code hint)
- **Dimension**: 7 Component Lifecycles
- **Location**: `byroredux/src/npc_spawn/ai_package.rs:858-863` (the spawn-time `report_package_transition(world, placement_root, None, None)`), `crates/scripting/src/fragment/package.rs:181-183` (the comment on the pre-early-return `ActivePackages` write)
- **Status**: NEW (the code was added by #5864's change, `ai_package.rs` delta since the baseline)
- **Description**: both comments justify clearing `ActivePackages` for a brand-new actor because "an earlier occupant of a reused entity id left" something. `World::spawn` never recycles ids (`world.rs:140`, #372), and the live engine never lowers `next_entity` (`set_next_entity` has callers only in `crates/save/src/driver.rs` and tests; the live load path reloads the cell and applies deltas instead of calling `restore_world`). `retire_active_packages` (#5870) already removes the unloaded actors' rows, so a fresh id can never find a stale `ActivePackages` entry. The `(None, None)` call is therefore a no-op that reads as a lifecycle safeguard.
- **Impact**: none at runtime. It teaches the wrong ECS model (id reuse), the exact misconception `_audit-common`/the ECS skill tell auditors not to propagate ("Do not describe it as generational").
- **Suggested Fix**: reword both comments to name the real contract (unload retires rows via `retire_active_packages`; a restore-style `set_next_entity` rewind is test-only), or delete the spawn-time call and keep a test that a fresh actor has no row.

### ECS-SD-04: `Material::source_shader_type` is write-only
- **Severity**: LOW
- **Dimension**: 8 NIFAL Canonical Material in the Component Layer
- **Location**: `crates/core/src/ecs/components/material.rs:232-240` (field), `byroredux/src/material_translate.rs:732-734` (the only writer), `crates/save/src/snapshot.rs:558` (the bump note)
- **Status**: NEW (the commit that added it, `2266f7778` Fix #4256, is one of the three "recent" commits this suite was told to read)
- **Description**: the field's doc says "downstream consumers that need the authored provenance read this", but `rg 'source_shader_type'` finds no reader outside tests. The commit message itself says the one candidate reader (the overlay's `TextureSlotContext`, cell loader) was deliberately not retargeted because it runs on the imported tier before a canonical `Material` exists. So the canonical tier now carries a 4 B field per `Material` row that nothing consumes, and because `Material` is a registered saved column the addition bumped `FORMAT_MAJOR` 112 to 113, invalidating every existing save.
- **Verified clean in the same commit**: single-mutation-site rule holds (the field is set only in `translate_material`, before the glass classifier); `Material::default()` gives 0; the pin `source_shader_type_survives_the_glass_reassignment_of_material_kind` passes in the bin run; no `Material {` literal outside `material_translate.rs`/tests builds one without it.
- **Impact**: forced save invalidation and per-entity memory for no behaviour change. If a consumer is planned (the issue's intent), this is fine and the finding is moot; as shipped it is speculative canonical state.
- **Suggested Fix**: either land the first reader (retarget the overlay by threading the authored type through the imported tier it already reads) or note in the field doc that it is reserved and has no reader yet, so the next `FORMAT_MAJOR` bump can fold it.
