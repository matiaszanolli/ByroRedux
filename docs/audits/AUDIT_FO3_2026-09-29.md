### Dimension 2 — ESM Data Slice (Fallout3.esm)

#### FO3-D2-01: FO3 placed corpses (XRGD-posed) spawn alive — #4814's Starts-Dead decode is Skyrim/FO4-only
- **Severity**: HIGH (same impact class as #4814)
- **Dimension**: ESM Data Slice. Decode belongs to `/audit-esm`; consumption to `/audit-gameplay`.
- **Location**:
  - `crates/plugin/src/esm/cell/walkers.rs`: `starts_dead` is set only when the record is `ACHR`, the reader is `Tes5Plus` and bit `0x200` is set.
  - `crates/plugin/src/esm/reader.rs`: `FLAG_STARTS_DEAD`.
  - `crates/plugin/src/esm/cell/mod.rs`: the field doc says "FO3/FNV ship none".
- **Status**: Existing: **FNV-2026-09-29-D2-01** (`docs/audits/AUDIT_FNV_2026-09-29.md`, NEW there, no GitHub issue yet). Not re-filed. It is the FO3/FNV residual of #4814 (CLOSED). #4814 explicitly scoped FO3 and FNV out ("corpse encoding … was not established").
- **FO3 evidence (measured this run)**:
  - **Header flags.** xEdit's `wbDefinitionsFO3.pas` gives:
    - ACHR flags {10 Persistent, 11 Initially Disabled, 25 No AI Acquire};
    - ACRE the same, plus 15 Visible When Distant.
    - There is no Starts Dead bit. `Fallout3.esm` sets `0x200` on 0 of 2 154 ACHR and 0 of 3 349 ACRE. Both record types carry `wbRagdoll` (`XRGD` / `XRGB`).
  - **XRGD refs.** 498 actor refs carry `XRGD` (338 ACHR, 160 ACRE). Every payload size is a multiple of 28 bytes, i.e. a per-bone pose.
  - **Base editor ids.** 428 of the 435 refs whose base is named dead or loot-corpse carry `XRGD`. Examples:
    - dead: `DeadBrahmin` ×35, `DeadMoleRat` ×17, `FeralGhoulDEAD` ×14, `DEADGhoulWastelander*` ×24, `DeadSuperMutant1Gun*` ×15, `LDCapitolBuildingDead1` ×7;
    - loot corpses: `Loot1*` (~170).
  - **The other 70 `XRGD` refs** also read as corpses: `MS16Corpse2/4`, `OasisCorpse`, `AndaleVictim01-03`, `MS18WreckedProtectron01`, `CG04Jonas`.
  - **No reader.** `XRGD` has 0 hits in `crates/` or `byroredux/`.
- **Impact on FO3**:
  - 498 authored corpses stand up in idle poses.
  - They cannot be looted, because `is_loot_source` needs `Dead`.
  - Base AI data is Very Aggressive on 338 (253 ACHR + 85 ACRE) and Aggressive on 73. Since #4414, hostile ones can start combat on sight.
- **Caveat**: that "XRGD present" means "starts dead" is inferred from this census. The GECK wiki is Cloudflare-blocked. Confirm the semantics before implementing (No Guessing policy).
- **Suggested Fix**: see FNV-2026-09-29-D2-01. For the Fallout-era family, derive `starts_dead` from `XRGD` presence at the walker, then reuse `apply_starts_dead`. Add a real-data pin that `Fallout3.esm` yields 498 starts-dead refs.

#### FO3-D4-01: A compressed BSA entry with an empty payload is a hard extract error
- **Severity**: LOW
- **Dimension**: BSA v104 (reader discipline, owner `/audit-parsers`)
- **Location**: `crates/bsa/src/archive/extract.rs` (compressed branch of `BsaArchive::extract`); `crates/bsa/src/safety.rs:171` (`inflate_bounded_zlib`)
- **Status**: NEW. Searches for "incomplete deflate", "zero-length BSA" and "original_size 0" found no match, and `AUDIT_PARSERS_2026-09-29.md` does not mention it.
- **Description**:
  - `Fallout - Meshes.bsa : meshes\dungeons\vaultruined\placeholder.txt` has record size 4 and is archive-compressed. It holds a 4-byte original-size header of 0 and no zlib stream.
  - `extract` passes the empty slice to `inflate_bounded_zlib`. `ZlibDecoder` fails with "incomplete deflate stream". The raw-DEFLATE retry is skipped because `compressed.len() >= 2` is false.
  - A valid empty file therefore returns `Err`, while `declared_size()` on the same entry returns `Ok(0)`.
- **Evidence**: a census by Python record-header walk found every such entry is a `.txt` placeholder:
  - FO3: 1;
  - FNV: 1 (`Fallout - Misc.bsa : menus\do_not_delete.txt`);
  - Oblivion: 35 (`textures\menus*\…\*.txt` in `Oblivion - Textures - Compressed.bsa`, each confirmed `incomplete deflate stream` with `declared=Some(0)`).
- **Impact**: no content loads these files. Whole-archive consumers (corpus sweeps, extract-all tooling, an archive browser) see spurious hard errors on vanilla data, and `declared_size` and `extract` disagree.
- **Related**: #3410 (bounded inflate), #3812 (Adler-32 recovery).
- **Suggested Fix**: in the compressed branch, return `Ok(Vec::new())` when `original_size == 0` and the stream is empty. Keep rejecting a non-zero declared size with an empty stream. Pin it with a synthetic 4-byte record.
