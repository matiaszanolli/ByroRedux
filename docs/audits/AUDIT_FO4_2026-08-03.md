## Cross-Audit Context

Sibling per-game audits (FO3, FNV) run today found two genuine HIGH-severity
bugs in code paths FO4 shares: non-`T` `bhkRigidBody` colliders get
displaced (`rigid_body.rs`, shared collision path), and `env_map_scale` is
forwarded ungated (`legacy_properties.rs`, shared PBR classifier). Both are
logged under FO3's report; this audit re-examined FO4's specific exposure
to each rather than re-filing them:

- **`bhkRigidBody` displacement**: FO4 precombined architecture carries
  **no** Havok collision at all — the `_oc.nif` only has packed-combined
  geometry extra, with collision synthesized as a trimesh fallback in
  `spawn.rs` (M49 Stage A/B split, documented). The shared bug's scope does
  not extend to precombine-spawned FO4 architecture. It would only matter
  for ordinary authored-collision FO4 REFRs, unchanged from FO3's finding.
- **`env_map_scale` ungated forward**: the affected code
  (`legacy_properties.rs`) handles legacy pre-`BSLightingShaderProperty`
  shader types (`HairShaderProperty`, `VolumetricFogShaderProperty`,
  `DistantLODShaderProperty`, `BSDistantTreeShaderProperty`,
  `WaterShaderProperty`, `TallGrassShaderProperty`, `Lighting30ShaderProperty`)
  that vanilla FO4 content does not author anywhere in the game — FO4
  architecture and clutter route through `BSLightingShaderProperty`
  exclusively (confirmed independently via Dimension 1's precombine
  finding and Dimension 5's universal-BGSM-PBR-routing finding, `#1352`).
  **FO4-specific scope refinement**: the shared bug's blast radius does not
  extend to vanilla FO4 content anywhere in the game (not just precombine
  architecture, which was the narrower scope Dimension 1 alone could
  establish) — it would only bite hand-authored modded content using a
  legacy Oblivion/FO3-era shader property block.

#### FO4-D4-2026-08-03-01: Bare BSVER literal survived the #1242 rename
- **Severity**: LOW
- **Dimension**: 4 — NIF BSVER 130 / FO4 shader-band gating
- **Location**: `crates/nif/src/blocks/shader.rs:1026`
- **Status**: NEW
- **Description**: `BSLightingShaderProperty::parse_fo4` gates the FO4-DLC
  subsurface block on the bare literal range `(130..=139).contains(&bsver)`
  instead of the named constants
  `(FALLOUT4..FO4_DLC_UPPER).contains(&bsver)` used by every sibling gate
  in the same file (`:979`, `:1406`, `:1412`, `:1430-1431`). Behaviorally
  identical today (`130..=139` ≡ `130..140`), so purely a maintainability /
  rename-hygiene gap — but it is exactly the drift class `#1242` existed to
  eliminate.
- **Evidence**:
  ```rust
  // shader.rs:1026 — bare literals
  let (subsurface_rolloff, rimlight_power, backlight_power) = if (130..=139).contains(&bsver)
  // shader.rs:1412 — sibling gate, same band, named constants
  if (crate::version::bsver::FALLOUT4..crate::version::bsver::FO4_DLC_UPPER).contains(&bsver)
  ```
- **Impact**: No runtime impact at HEAD. Latent: a future correction to
  `FO4_DLC_UPPER` would update the SSR/skin-tint/`env_map_scale` gates but
  not this one, mis-reading 4-12 bytes of `BSLightingShaderProperty` on the
  newly in/out-of-band BSVERs — the same failure class as `#1223`/`#1552`.
- **Related**: `#1242` (the rename this site was missed by), `#1223`,
  `#1552`, `#1901`
- **Suggested Fix**: Replace with
  `(crate::version::bsver::FALLOUT4..crate::version::bsver::FO4_DLC_UPPER).contains(&bsver)`.
  One-line, no behavior change, existing `shader_tests/fo4.rs` band
  coverage already exercises it.

## BGSM Consumption Table

| BGSM Field | Merged via (`merge_external_material`, `byroredux/src/asset_provider/material.rs`) | Surfaced on canonical `Material` |
|---|---|---|
| Diffuse/base-color texture | `MaterialTextureSet.base_color` role | `texture_path` |
| Normal texture | `.textures.normal` role | `normal_map` |
| Smooth-spec texture | `.textures.smooth_spec` role | `gloss_map` |
| Specular color | `bgsm_metalness` (`:85-98`) — saturation for `pbr==false`, luminance for `pbr==true` | `metalness` (resolve-once, `#1476` guard intact) |
| Smoothness | `roughness_override = Some((1.0 - smoothness).clamp(0.04,1.0))`, applied once at parse | `roughness` (resolve-once; NaN backstop never fires for BGSM content) |
| Emissive color/mult | direct field copy | `emissive_color`/`emissive_mult` |
| Translucency suite (`#1147`) | gated on BGSM v>=8 | `translucency_subsurface_color`/`_transmissive_scale`/`_turbulence` via `BGSM_TRANSLUCENCY` flag |
| Model-space-normals bit | `MAT_FLAG_BGSM_MODEL_SPACE_NORMALS` | `effect_shader_flags` (OR'd in `translate_material`) |
| `leaf.pbr` flag | routes the metalness branch + unconditionally sets `is_pbr = true` for ALL resolved BGSM (`#1352`/`FO4-D7-03`) | `effect_shader_flags` → shader `MAT_FLAG_PBR_BSDF` |
| src/dst blend | `bgsm_blend_to_gamebryo` (plain `u8` cast, no swap — `#1823`/`#1651` guard intact) | Gamebryo→VK blend factors (Standard 6,7 / Additive 6,0 / Multiplicative 4,1) |

Merge signature is narrowed to `&mut ImportedMaterial` (`05d68926`) — never
touches geometry/transforms/skinning/scene ownership. Runs strictly before
`translate_material`. Template `.bgsm` inheritance is cycle-safe
(`#1148`, `DEPTH_LIMIT=16`).
