## Executive Summary

The parse and import contract itself holds. The worker (`parse_one_nif`) and the synchronous loader (`parse_and_import_nif`) now build `CachedNifImport` through one constructor (`scene_satellites` + `from_scene`, #5795). `reintern_imported_meshes` rebinds every `FixedString` an `ImportedMesh` can carry (`textures`, `material_path`; the only other `FixedString` type, `ImportedTextureEffect`, is hierarchical-only). The graph-node import uses a throwaway pool but retains only `Arc<str>`. The `PartialNifImport: Send` assertion (#1171/#5442) is in place at `streaming/mod.rs:261`. Panics in a parse task become negative registry entries (#854), and the precombine job honours them (#5522). The input budget admits against the archive-declared decoded size before extraction.

The real defect is a **capacity contract** (NIF-SD-01): the registry's fixed 2,048-entry LRU cap is far below the default-radius working set on Fallout 4, while the worker's skip filters assume every key they skipped is still resident.

## Findings

### NIF-SD-01: `NifImportRegistry`'s 2,048-entry LRU cap is below the Fallout 4 default-radius working set, so the streaming worker's "already cached" skips turn into main-thread re-parses
- **Severity**: MEDIUM
- **Dimension**: Allocation Hygiene (pre-parse / registry contract)
- **Game Affected**: Fallout 4 (and any title with a large exterior ring or heavy mod load order; FO3 peaks at 1,587 of 2,048)
- **Location**: `byroredux/src/cell_loader/nif_import_registry.rs:598-601` (cap) and `:822-905` (`insert` eviction); `byroredux/src/streaming/pre_parse.rs:637-649` and `:870` (skip filters); `byroredux/src/cell_loader/references/synth_child.rs:644-710` (inline parse on a registry miss)
- **Status**: NEW (related, all closed: #5512 salvage, #3705 clip release under LRU pressure, #1398 uncapped registry)
- **Description**: At dispatch, `step_stream` queues every missing cell of the ring at once with one shared `cached_keys` snapshot (`streaming/mod.rs:741-770`, `app_step.rs:210-224`). The worker then skips any key that is in the snapshot or in the dispatch-batch memo (`pre_parse_model_skip_reason`). The memo explicitly relies on "a memoed key is resident when a later apply needs it" (`pre_parse.rs:139-147`). Nothing protects that residency from the registry's own LRU: each `finish_partial_import` insert evicts the smallest-tick entry once `len > 2048`. When the ring's unique-key count exceeds the cap, a key parsed for an early cell is evicted before a later cell that the worker skipped it for is applied. That cell then misses at spawn and `synth_child.rs:665-696` extracts and parses the NIF inline on the main thread, the cost the worker exists to remove. The NIF was already parsed once, so the work is paid twice.
  Fallout 4 adds a second source of pressure: every `_oc.nif` precombine is keyed by a per-cell-unique path (`precombine_oc_nif_paths`) and goes through the same cache. They are never shared between cells, yet they enter the LRU as the newest entries and push the shared statics out.
- **Evidence**:
  - `census/` on `Fallout4.esm`, worldspace Commonwealth, radius 12: unique base models per 25x25 window mean 4,276, max 9,674 (centre (2,-1)); 3,587 of 4,707 centres exceed 2,048, 2,234 exceed 4,096. The window at (0,0) holds 23,644 precombine hashes (96,348 over the whole worldspace). Table above for the other titles.
  - Registry simulation (cap 2048, closest-first apply order exactly as `compute_streaming_deltas` sorts, worker batch memo, inserts at `FinishImports`, hits touched and fallback inserts committed at end of cell as `complete.rs:120-157` does): centre (0,0) gives 9,582 worker parses and **26,353 main-thread fallback parses** with base models only, **33,860** once per-cell precombine entries are included. Centre (-10,10): 9,134 / 14,999. Centre (-20,-5): 2,483 / 7,063. With cap 12,000 the same run gives 0.
  - This is a model, not an engine measurement (no engine launch). It ignores the clip-handle eviction bias, negative entries, and an already-warm registry; the `mesh.cache` console command (`evictions`) and the per-cell "NIF cache hits/misses" log line in `complete.rs:167` would confirm it on a device.
- **Impact**: On the default FO4 exterior load (boot, fast travel, door exit into the Commonwealth), a large share of the cell spawns hits inline parses on the main thread, inflating boot time and, on the steady-state path, adding frame hitches inside `ExteriorCellApplyJob`. FNV, Oblivion and Skyrim never reach the cap in vanilla, which is why the 2,048 default looked fine. `BYRO_NIF_CACHE_MAX=0` or a large value is the workaround.
- **Related**: #5512, #3705, `docs/engine/memory-budget.md` ("NIF Import Cache"), PERF-SD-02 (different cache).
- **Suggested Fix**: Do not let the LRU evict a key a queued request still depends on: pin the snapshot and memo keys until their cell applies (or fall back to having the worker re-emit a key when the registry reports it missing at apply time). Separately, keep per-cell-unique `_oc.nif` entries out of the shared 2,048-entry LRU, or size the cap from the ring (`radius_load`, game) rather than a constant.

### NIF-SD-02: Only the synchronous REFR loader looks at `NifScene::truncated`; the streaming worker and the NPC loader cache partial scenes silently
- **Severity**: LOW
- **Dimension**: Stream Position (consumer tolerance)
- **Game Affected**: all; vanilla content measures 0 truncations, so this is mod content
- **Location**: `byroredux/src/streaming/pre_parse.rs:290-296` (worker), `byroredux/src/scene/nif_loader.rs:309-319` (NPC / loose loader) versus `byroredux/src/cell_loader/references/import.rs:54-65`
- **Status**: NEW
- **Description**: `NifScene` carries `truncated`, `dropped_block_count`, `recovered_blocks` and `recovered_by_guess`, documented as "consumers that can tolerate partial geometry can ignore it" (`crates/nif/src/scene.rs`). `parse_and_import_nif` logs a warning when `truncated` is set and a second warning for a zero-contribution import. `parse_one_nif` does neither, and `parse_import_and_merge` (every NPC skeleton, body, head and armour NIF) logs only the zero-mesh case. A grep of `byroredux/src` finds `.truncated` in one place. The truncated scene is then cached as a positive entry, so there is no retry and no later signal. The scene's `root_index` heuristic may also pick a subtree when truncation hits before the root (`scene.rs` doc), so a partial skeleton can import as a smaller skeleton rather than failing.
- **Evidence**: `grep -rn "\.truncated\|recovered_blocks\|dropped_block_count" byroredux/src` returns only `references/import.rs:57` (plus unrelated `capture.truncated`). `StreamingTelemetry` has no parser-health counter.
- **Impact**: A mod NIF that truncates mid-file renders partially (exterior statics) or yields a mis-bound actor (NPC skeleton) with no log line naming the file. Observability only; nothing crashes.
- **Related**: #393, #568 (closed; the corpus-side counterparts that made truncation visible to the test gates).
- **Suggested Fix**: Route the three consumers through one helper that warns once per path on `truncated` / `recovered_blocks > 0` and counts them in the streaming telemetry.

### NIF-SD-03: FO4 precombine cache entries retain one deep copy of the decoded geometry per instance
- **Severity**: LOW
- **Dimension**: Geometry Handoff / Allocation Hygiene
- **Game Affected**: Fallout 4 (bsver 130+), shared-variant `_oc.nif`
- **Location**: `byroredux/src/cell_loader/precombined.rs:900-909` (`decoded.clone()` per instance); `byroredux/src/cell_loader/partial.rs:75-94` and `precombined.rs:1084` (`geometry_only_cached`)
- **Status**: NEW (the GPU half was fixed by #3510)
- **Description**: `build_precombine_meshes` decodes each shared object once and clones the whole `ImportedMesh` per `BSPackedGeomDataCombined` instance. #3510's `geometry_dedup` makes the upload and BLAS paths use one representative, but every clone's `positions/normals/uvs/colors/tangents/indices` vectors stay alive in `CachedNifImport.meshes` for the entry's registry lifetime.
- **Evidence**: `pcmem/` over 1,505 `_oc.nif` sampled evenly from `Fallout4 - MeshesExtra.ba2` (14,744 objects, 25,993 instances): CPU geometry with per-instance copies is 1.50x the distinct geometry. Per entry: mean 0.46 MiB, median 0.14 MiB, p90 0.96 MiB, max 46.5 MiB (estimated at 64 B/vertex + 12 B/triangle from the `ImportedMesh` field widths, not dhat-measured). Filling the 2,048-entry cache with such entries holds roughly 0.3 GiB of duplicated vertex data beyond the 0.6 GiB of distinct data.
- **Impact**: Host memory only; the entry count cap (not bytes) bounds it, and a single worst-case entry is 46 MiB.
- **Related**: #3510, NIF-SD-01 (the same entries dominate the cache on FO4).
- **Suggested Fix**: Share the decoded vertex arrays between aliases (an `Arc` inside `ImportedMesh`, or drop the alias vertex vectors once `geometry_dedup` is built) so the entry holds one copy plus N transforms.

### NIF-SD-04: `NifImportRegistry::clear()` leaks clip-registry slots, and a debug-load archive change leaves the path-keyed `SceneImportCache` stale
- **Severity**: LOW
- **Dimension**: Allocation Hygiene (cache lifecycle)
- **Game Affected**: all; debug `cell.load` across different archive sets only
- **Location**: `byroredux/src/cell_loader/nif_import_registry.rs:635-641`; `byroredux/src/debug_load.rs:318-336`; `byroredux/src/scene_import_cache.rs` (no `clear`)
- **Status**: NEW
- **Description**: `clear()` empties `clip_handles` but returns nothing, whereas every other removal path hands the freed handles back so the caller can `AnimationClipRegistry::release` them (#863). The registry's only caller is `invalidate_nif_cache_on_archive_change`, which then does not release them either. The same function clears the `NifImportRegistry` "to avoid stale cross-load model reuse" (#2078) but not `SceneImportCache`, which keys scenes by lowercased path alone (`scene/nif_loader.rs:220`) and holds every NPC skeleton/body/head/armour import. `studio_host.rs:664-666` already knows two titles ship different files under one path and qualifies its label with the game.
- **Evidence**: `NifImportRegistry::clear` body; `grep -rn "SceneImportCache" byroredux/src` shows no clear or invalidate call.
- **Impact**: After a debug load that switches archive sets (for example FNV then Skyrim in one session), NPC spawns reuse the previous game's skeleton/body scenes, and each registry clear strands the keyframe arrays of every animated cached model. Debug path only; no production caller.
- **Related**: #2078, #863, #3760.
- **Suggested Fix**: Make `clear()` return the freed handles (like `insert`) and release them in `invalidate_nif_cache_on_archive_change`, which should also reset `SceneImportCache`.

### NIF-SD-05: `pre_parse_one` runs `extract_mesh` outside every panic guard, so a reader panic discards the whole cell's payload and replays unguarded on the main thread
- **Severity**: LOW (defense-in-depth)
- **Dimension**: Allocation Hygiene / Stream Position (failure containment)
- **Game Affected**: all
- **Location**: `byroredux/src/streaming/pre_parse.rs:394-412` (extract at `:399`, outside `parse_one_nif`'s `catch_unwind` at `:285`); `:163-175` and `:240-259` (cell-level guard)
- **Status**: NEW
- **Description**: A panic inside `parse_one_nif` becomes a `None` result and then a negative registry entry (#854), and the precombine job honours that (#5522) so the panic is not replayed. The archive extraction that feeds it is not inside that guard. A panic there propagates through `in_place_scope_fifo`, is caught only by `pre_parse_cell_panic_safe`, and produces an empty `parsed` map: every sibling NIF the cell had parsed is discarded and nothing is recorded as failed. The main thread then falls back to `synth_child.rs:668`, which calls the same `extract_mesh` with no `catch_unwind`, which is the replay #5522 closed for the parse step.
- **Evidence**: control flow above. The reader returns `io::Result` by design (`extract_or_warn`), so this needs an archive-reader bug to trigger (the `/audit-parsers` territory, for example #5008); I could not construct a trigger statically.
- **Impact**: Latent. With a reader panic bug, one corrupt mesh entry becomes a process abort on the next load of its cell instead of a missing model.
- **Related**: #854, #5522, #5008.
- **Suggested Fix**: Move the `extract_mesh` call inside the per-NIF `catch_unwind` in `parse_one_nif` (or wrap it separately) so extraction failure takes the same negative-entry path.

## Considered and not filed

- **`finish_streaming_import`'s `None` arm inserts a negative entry unconditionally** while the `Some` arm early-outs on any existing entry (`streaming_helpers.rs:726-762` vs `partial.rs:46-52`). A positive entry could be overwritten by a later negative one, but that needs a non-deterministic worker/main divergence on the same bytes; I could not construct it. Noted as an asymmetry only.
- **`SceneImportCache` key** is `path.to_ascii_lowercase()` with no separator folding, unlike `canonical_model_path_key` (#3038). No evidence of mixed separators reaching the NPC loaders; not filed.
- **`SceneImportCache` FIFO half-eviction and the NPC extract-before-cache cost**: already in the perf report (PERF-SD-02 and its notes).
- **Skeleton parse failure** (`SkeletonUnit::Loaded { root: None }`) lets the actor's parts spawn without a skeleton; the finalize tails guard `skel_root.is_some()`, so this is deliberate degradation.
- **Persistent cell and PKIN/SCOL child models** are parsed by the synchronous loader, not the worker. The census found 0 PKIN refs and 0 must-expand SCOL refs in the Commonwealth ring, so there is no measurable gap in vanilla.
