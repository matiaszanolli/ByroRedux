**Scope**: `crates/nif/src/` — stream position integrity, version gating, block
dispatch coverage, geometry/import handoff, collision & shader parsing,
allocation hygiene. All 6 dimensions run (`--focus` not restricted, `--game`
not restricted). No `--corpus` override; each dimension agent used the
installed vanilla game archives listed in `_audit-common.md` where useful.

**Method**: 6 parallel `legacy-specialist` dimension agents, each reading
`_audit-common.md` / `_audit-severity.md` for shared protocol, cross-reading
`/mnt/data/src/reference/nifxml/nif.xml` field-by-field for every gate cited,
and deduping against a 72-issue GitHub snapshot (`/tmp/audit/issues.json`).
Every finding below is **NEW** — no duplicates or regressions of a closed
issue were found. One HIGH finding (PERF-D6-NEW-01) was independently
re-verified by the orchestrator against `crates/nif/src/blocks/skin.rs` and
`crates/nif/src/stream.rs` before inclusion.

### HIGH

#### PERF-D6-NEW-01 — Strip-authored skin partitions bound at 6 B/triangle against a payload that costs ~2 B/triangle
- **Dimension**: 6 — Allocation Hygiene
- **Game Affected**: Oblivion, FO3, FNV, and any LE/converted Skyrim content — every game whose `NiSkinPartition` authors faces as strips (`num_strips > 0`)
- **Location**: `crates/nif/src/blocks/skin.rs:300-319` (introduced 2026-09-03, `d49cd88b`, "Fix #3691: reserve skinning parse buffers")
- **Description**: The strip branch of `NiSkinPartition::parse` pre-sizes its de-strip output with `stream.allocate_vec_sized::<[u16; 3]>(num_triangles)?`, which bounds `num_triangles * 6` bytes against the stream's remaining bytes. But these triangles are **generated** by `strip::destrip` from u16 strip-index arrays, not read from disk — a strip of length `L` costs `2L` bytes and yields `L-2` triangles, so the true on-disk cost is ~2 B/triangle, not 6. The bound over-demands by ~3×. This is exactly the misuse `allocate_vec_sized`'s own doc-comment (`stream.rs:309-325`) warns against: a `T` decoded/widened from a narrower on-disk encoding needs `allocate_vec_min_bytes`, not `allocate_vec_sized`.
- **Evidence**: The commit's own regression test (`skin.rs:605-647`, one strip of length 4 → 2 triangles) clears the bound by exactly **one byte** (13 remaining vs 12 required). Generalized: for a single-strip partition of length `L`, the check fails whenever `3L > 13` — any strip of **5 or more indices** near the end of a file. `?` propagates the failure out of the whole `NiSkinPartition::parse`, losing the entire partition set. Independently re-verified by the orchestrator by reading `skin.rs:270-338` and `stream.rs:260-360` directly — confirmed accurate.
- **Impact**: Skinned Oblivion/FO3/FNV content (creatures, clothing, armour) can lose its skin partition entirely — same failure mode `#1549` was filed to fix. Silent: Oblivion has no `block_sizes` table, so recovery substitutes `NiUnknown` and the file still counts as "recoverable," keeping `MIN_RECOVERABLE_RATE = 1.0` green. Correlates with PERF-D6-NEW-02's measured Oblivion clean-rate drop (not proven causal — see that finding).
- **Related**: `#3691` (the reservation request), `d49cd88b` (the fix), `#2523` (the `allocate_vec_sized`/`allocate_vec_min_bytes` split this violates), `#1549` (de-strip), `#1885` (prior false-positive-direction disproof log).
- **Suggested Fix**: `stream.allocate_vec_min_bytes::<[u16; 3]>(num_triangles, 2)?` — 2 bytes is the honest per-triangle minimum. Add a regression test with a strip of length ≥ 5 that fails under the current bound.

#### NIF-2026-09-04-D1-01 — Unbounded recursion in `read_and_skip_bounding_volume`'s `UNION_BV` arm
- **Dimension**: 1 — Stream Position Integrity
- **Game Affected**: Oblivion (v3.3.0.13/v4.0.0.2 marker files shipped in vanilla `Data/`, the `#688`/`#698` family), plus any pre-Gamebryo/non-Bethesda NetImmerse content (`#2383`). Not reachable FO3 → Starfield.
- **Location**: `crates/nif/src/blocks/base.rs:307-337` (`read_and_skip_bounding_volume`), reached via `skip_bounding_volume` (`:292-304`) from `NiAVObjectData::parse` (`:125-128`)
- **Description**: The `bv_type == 4` (`UNION_BV`) arm recurses once per declared child with **no depth bound**. nif.xml marks the field `recursive="True"` — nothing in the format limits nesting, and each level costs only 8 on-disk bytes. Neither `allocate_vec`/`check_alloc` nor `MAX_SINGLE_ALLOC_BYTES` apply (nothing is allocated on this path — it only skips). A ~1 MB crafted input yields on the order of 10^5 stack frames and aborts the process on the guard page.
- **Evidence**: `for _ in 0..count { read_and_skip_bounding_volume(stream)?; }` with no depth parameter, reached unconditionally for `version() <= NifVersion::V4_2_2_0`.
- **Impact**: Process abort (SIGSEGV) on crafted/corrupt input — uncatchable, since the block loop's `Err` recovery requires the function to return. Blast radius: archive sweep harnesses, the loose-`.nif` CLI arm, and any third-party mod content on this version band.
- **Related**: `#3237` (identical class on the ESM GRUP walker, already has a 64-level cap); `#2383`; `#688`/`#698` (the marker files that put this band in the live corpus).
- **Suggested Fix**: Thread a `depth: u32` through the function and `Err(InvalidData)` past a small cap (e.g. 16), mirroring `MAX_GRUP_NESTING_DEPTH`.

#### NIF-2026-09-04-D1-02 — `NiParticlesData.Particle Radius` (and `Num Particles`) never read
- **Dimension**: 1 — Stream Position Integrity
- **Game Affected**: none of the 7 vanilla corpora; pre-Gamebryo NetImmerse/non-Bethesda/mod content (`#2383`). No-`block_sizes` band — cascades rather than reconciles.
- **Location**: `crates/nif/src/blocks/legacy_particle.rs:639-660`
- **Description**: `NiLegacyParticlesData::parse` jumps from the geometry-data base straight to `num_active`, skipping `Num Particles` (`until="4.0.0.2"`) and `Particle Radius` (`until="10.0.1.0"`). Since both dispatching object types (`NiAutoNormalParticlesData`/`NiRotatingParticlesData`) are themselves `until="V10_0_1_0"`, and this repo's own doctrine treats `until=` as inclusive (`version.rs:7-9`, `#935`), `Particle Radius` is present on **every** legal instance. 4-byte under-read always, 6 at v ≤ 4.0.0.2. Both dispatch-test fixtures omit the bytes and assert exact consumption, so the omission is pinned by its own tests.
- **Impact**: Drift with no recovery point on this band; invisible to CI because the fixtures encode the same omission.
- **Related**: `#2383`.
- **Suggested Fix**: Read `Particle Radius` unconditionally, `Num Particles` under `version <= V4_0_0_2`; extend both fixtures.

#### NIF-2026-09-04-D1-03 — `NiParticlesData.Has Sizes` read as a fixed 1-byte bool on the 32-bit-bool band
- **Dimension**: 1 — Stream Position Integrity
- **Game Affected**: same band as D1-02; no vanilla exposure.
- **Location**: `crates/nif/src/blocks/legacy_particle.rs:659`
- **Description**: nif.xml declares `Has Sizes` as the version-dependent `bool` type (32-bit ≤ 4.0.0.2, 8-bit ≥ 4.1.0.1) — exactly what `read_bool` implements. The parser calls the fixed-width `read_byte_bool` instead. `#1843` applied this exact correction to the sibling `NiGeometryData` bools but stopped at that inheritance boundary.
- **Impact**: 3-byte drift, stacks with D1-02 in the same parser (7-9 bytes combined), same CI blindness.
- **Related**: `#1843`; D1-02.
- **Suggested Fix**: `stream.read_bool()`; widen the v4.0.0.2 fixture byte to a `u32`.

#### NIF-2026-09-04-D1-04 — Unknown `BoundVolumeType` continues without consuming its body
- **Dimension**: 1 — Stream Position Integrity
- **Game Affected**: Oblivion (v3.3.0.13/v4.0.0.2) and pre-Gamebryo content — same band as D1-01.
- **Location**: `crates/nif/src/blocks/base.rs:332-335`
- **Description**: The `_ =>` arm logs "skipping" and returns `Ok(())` **without advancing the cursor**. Only `BASE_BV = 0xFFFFFFFF` is legitimately bodyless per nif.xml; every other unrecognized value means the stream has already drifted, and returning `Ok` denies the caller the `Err` that would route into `dispatch_blocks`'s recovery ladder.
- **Impact**: Silent, unbounded under-read on a no-`block_sizes` band; parse reports "clean" while the rest of the file is garbage.
- **Related**: D1-01 (same function); `#395` (the drift detector this defeats).
- **Suggested Fix**: `Ok(())` only for `0xFFFF_FFFF`; `Err(InvalidData)` otherwise.

#### NIF-D2-2026-09-04-02 — `NiTexturingProperty.Apply Mode` gates on `STRING_TABLE_THRESHOLD`, an unrelated constant with an explicit cross-file lockstep contract
- **Dimension**: 2 — Version Gating
- **Game Affected**: Oblivion (v20.0.0.x `NiTexturingProperty`) and any pre-20.1.0.2 non-Bethesda title
- **Location**: `crates/nif/src/blocks/properties.rs:283-289`; constant at `crates/nif/src/version.rs:165-174`
- **Description**: nif.xml gates `Apply Mode` `until="20.1.0.1"`. The parser expresses that as `<= STRING_TABLE_THRESHOLD` — numerically correct, but that constant's own doc declares a hard lockstep contract confined to `header.rs`/`stream.rs` ("drift here misreads every block's name"); `properties.rs` is an undeclared third party. The codebase's own precedent (`#3476`, `has_ni_sequence_prologue` vs `has_keyframe_controller_data`) is to name bit-identical-but-distinct cuts separately.
- **Impact**: Latent. If the string-table threshold is ever corrected — a one-line, explicitly-flagged-as-coordinated change — `Apply Mode` silently changes read shape by 4 bytes on every `NiTexturingProperty` in the band (30,121 Oblivion instances), which has no `block_sizes` recovery anchor below v20.2.0.5 and cascades like the v10.x truncation family.
- **Related**: `#3530`/`#3621` (the gate itself); `#3476` (naming precedent); `#2423`/TD7-001.
- **Suggested Fix**: Add `NifVersion::V20_1_0_1` and use it at this call site, leaving `STRING_TABLE_THRESHOLD` to its two declared partners.

#### NIF-D2-2026-09-04-03 — `NiMaterialProperty` reuses `FLAGS_U32_THRESHOLD` for a cut one BSVER away from what the constant is named for
- **Dimension**: 2 — Version Gating
- **Game Affected**: Fallout 3 (pre-retail dev/mod BSVERs 24-33), non-Bethesda content at `bsver == 26`
- **Location**: `crates/nif/src/blocks/properties.rs:37-63`; constant at `crates/nif/src/version.rs:432-436`
- **Description**: `FLAGS_U32_THRESHOLD = 26` is named/documented for the `NiAVObject.flags` u16→u32 widen, a cut between 26/27 (`> 26`). `NiMaterialProperty`'s `Ambient`/`Diffuse Color` use the same constant for nif.xml's `#BSVER# #LT# 26` — a cut between 25/26 — via `>= 26`. Currently correct (exact complement over integers), but violates the project's own one-constant-per-cut doctrine (`MORPH_LEGACY_CUTOFF`'s doc) and is the only `>=` consumer of a constant whose other two call sites use strict `>`.
- **Impact**: Latent; a future correction of the flags cut (e.g. renumbering to 27, a natural cleanup matching the strict-`>` sites) silently flips `NiMaterialProperty` at `bsver == 26`. FO3's own doc records dev-tool BSVERs fanning across 24-33, bracketing 26 — not purely hypothetical.
- **Related**: `#323`, `#938`, `#1331`, `#2423`/TD7-001.
- **Suggested Fix**: Add a distinct `MATERIAL_COMPACT_COLORS = 26` constant with a doc stating which side each field sits on; pin `bsver == 26` with a test on both sides.

#### NIF-D5-2026-09-04-01 — FO4+ `bhkRigidBody` reads the Skyrim CInfo body against a CInfo2014 wire layout, by the parser's own admission
- **Dimension**: 5 — Collision & Shader Block Parsing
- **Game Affected**: Fallout 4, Fallout 76, Starfield
- **Location**: `crates/nif/src/blocks/collision/rigid_body.rs:107-113`, `:173-178`
- **Description**: `BhkRigidBody::parse` has no real FO4+ CInfo prefix arm — it skips only 4 trailing bytes and reads `translation`…`quality_type` at the Skyrim field order, with in-code comments explicitly calling the FO4+ (`bhkRigidBodyCInfo2014`) layout "very different" and the path "knowingly incomplete," preserved post-`#546` to avoid a new regression.
