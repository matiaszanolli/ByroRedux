## Dimension Findings

### Dimension 2: NIF v20.2.0.7 Parser — FO3 Block Subset

#### FO3-2026-08-24-D2-01: FO3 particle-emitter decode is unverified because its own regression test structurally cannot reach FO3
- **Severity**: LOW
- **Dimension**: NIF Parser — FO3 Block Subset (Dim 2) — test-gap
- **Location**: `crates/nif/tests/parse_real_nifs.rs:311-392`
  (`real_archive_torch_meshes_surface_particle_emitters`)
- **Status**: NEW
- **Description**: The test's `games_to_try` array is
  `[Game::FalloutNV, Game::Fallout3, Game::Oblivion, Game::SkyrimSE]`. The loop body
  `return`s on the **first** game whose sampled 200 candidate NIFs yield any emitters
  (`if total_emitters > 0 { … return; }`). Both FalloutNV and Fallout3 mesh archives are
  present on this machine, and FalloutNV always yields emitters from its first 200
  fire/fx/smoke/magic/effects-folder candidates — so the loop returns before Fallout3 is
  ever tried. Confirmed live: running the test with `--nocapture` shows only
  `[Fallout New Vegas] 182 emitters across 5 meshes …` — no `[Fallout 3]` line at all, even
  though this same test has existed since #2317-era commits.
- **Evidence**:
  ```
  $ cargo test -p byroredux-nif --release --test parse_real_nifs \
        -- --ignored --nocapture real_archive_torch_meshes_surface_particle_emitters
  [Fallout New Vegas] 182 emitters across 5 meshes (sampled 200 NIFs from candidate folders)
    example: meshes\dlcanch\effects\dlcanchsnowmeshtube02.nif
    ...
  test real_archive_torch_meshes_surface_particle_emitters ... ok
  ```
  No `[Fallout 3]` line is printed; the test exits successfully having never called
  `open_mesh_archive(Game::Fallout3)`.
- **Impact**: The skill's own Dimension 2 checklist explicitly flags FO3 typed-particle
  decode (`extract_emitter_params`/`extract_emitter_rate`, feeding
  `apply_emitter_params`) as an "UNVERIFIED gap" because "the NIFAL decode doc-comments
  verify only against FNV + Oblivion." This test is the one piece of real-archive
  infrastructure that could close that gap, and its early-return-on-first-success shape
  means it never has, on any machine where FNV data ships alongside FO3 data (true of the
  dev machine and presumably CI, if game data is provisioned there at all). The code path
  itself may well be correct — FO3 shares the exact same typed-block dispatch and
  `extract_emitter_params`/`extract_emitter_rate` functions as FNV, with no FO3 gate of any
  kind — but that is an inference from shared code, not a verified fact, and the test that
  exists specifically to verify it cannot do so as written.
- **Related**: Skill text `.claude/commands/audit-fo3/SKILL.md` Dimension 2 ("FO3 is an
  UNVERIFIED gap"). Not a duplicate of any open issue (`particle`/`emitter`/`torch`/`early
  return` keyword sweep against `/tmp/audit/issues.json` found #2610 — FO4 BGEM particle
  flags, unrelated — and #2766 — a renderer dispatch-count issue, unrelated).
- **Suggested Fix**: Change the loop to try every game and accumulate results (or at minimum
  assert non-zero emitters were found for *every* game with a present archive, not just the
  first), so a future FO3-specific emitter regression can't hide behind FNV's earlier
  success. Low urgency — no evidence of an actual decode defect, only of unverified coverage.

## FNV-Shared Surface (no FO3-specific divergence found)

Confirmed at HEAD, by direct code reading and/or live test execution — these are the areas
most likely to carry an FNV-only assumption, and none did:

- **Inline shader material path** (`crates/nif/src/import/material/legacy_properties.rs`):
  `apply_pp_lighting_property` / `apply_no_lighting_property` are version- and game-agnostic;
  parallax authoring gate (#2317), env-map-scale consumption gate (#2328), fire-refraction
  promotion (#2321), and the `material_kind == 102` fullbright/no-distance-dimming gate for
  `BSShaderNoLightingProperty` are all still correct and covered by unit tests in the same file.
- **`crates/nif/src/shader_flags.rs`**: FO3/FNV `fo3nv_f1`/`fo3nv_f2` bit constants match
  nif.xml exactly (cross-checked against the module's own pinning tests, all passing); the
  documented bit-position collisions with Skyrim/FO4 (e.g. bit 22 Tree_Billboard vs Own_Emit,
  bit 21 Alpha_Decal vs Anisotropic_Lighting) are correctly isolated per-property-type.
- **Capital Wasteland worldspace selection** (`byroredux/src/cell_loader/exterior.rs`):
  `PREFERRED_WORLDSPACES = ["wastelandnv", "wasteland", "tamriel", "skyrim"]` correctly lists
  FO3's `Wasteland` EDID distinct from FNV's `WastelandNV`; `select_worldspace_key` resolves
  by grid-containment first, falls back to the preferred list only on ambiguity, and is
  deterministic under HashMap-iteration-order shuffling (pinned by
  `preferred_containing_worldspace_wins_ambiguous_grid_deterministically`, which iterates
  over all four preferred names including `"wasteland"`). No FNV-hardcoded name or origin
  found in the exterior grid path.
- **Havok collision dispatch** (`crates/nif/src/import/collision/mod.rs`): `classify_collision_block`
  / `examine_collision_kind` dispatch purely on Rust block *type* (`BhkCollisionObject` →
  `Classic`), never on BSVER — correct for FO3 (BSVER 34, classic side) by construction, no
  per-game branch needed or missing. `havok_motion_type` maps the full canonical enum
  (1-5/8→Dynamic, 6→Keyframed, 7→Static, 9→CharacterKinematic) per #1652, tested.
- **`SCHR` script flags** (`crates/plugin/src/esm/records/script.rs`): confirmed still a
  20-byte record with a `u16` flags tail read via `u16_or_default` (#1654); regression test
  `assert_eq!(rec.flags, 0x0002)` passes.
- **`BSSegmentedTriShape`** dispatch (`crates/nif/src/blocks/mod.rs:455`) routes to
  `NiTriShape::parse_segmented` with a dedicated regression test
  (`tri_shape_skin_vertex_tests.rs`). Note: issue **#3101** (OPEN) already flags that vanilla
  FO3 authors **zero** `BSSegmentedTriShape` blocks in practice, despite the skill naming it
  as an FO3 divergence surface — that is a skill-text premise correction, not a code defect;
  not re-derived here.
- **WATR `XNAM` water-hazard channel**: see *Verified Fixed Since 2026-08-20* below.
