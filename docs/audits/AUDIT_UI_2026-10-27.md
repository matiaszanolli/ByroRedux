## 3. Findings

### LOW

### UI-D4-2026-10-27-01: #5480's navigator comment says an unpatched CWS dependency reaches Ruffle compressed (it reaches it as FWS); `ui.md` still calls runtime-loaded movies un-shimmed and miscounts the UI tests
- **Severity**: LOW (doc-rot)
- **Dimension**: Resource Navigator
- **Profile**: both
- **Location**:
  - `crates/ui/src/navigator.rs:286-293` (the comment in `load_archive_resource`)
  - `docs/engine/ui.md:883-886` and `docs/engine/ui.md:753`
  - the claim being contradicted is `crates/ui/src/prepare.rs:104-132` (`normalize_scaleform_dialect_counting`)
- **Status**: NEW. The comment came in with `1ac34024f` (#5480, closed). The `ui.md` sentence predates it and was not updated by it.
- **Description**: three stale statements.
  - The #5480 comment ends: "`None` (no change) keeps the raw bytes — an unpatched CWS still reaches Ruffle compressed, as before". The commit message says the same. But the shim's own contract (#5479, `prepare.rs:78-87`) is that CWS input always comes back as `Some(file)`: one inflate, then re-emitted as FWS with a corrected length, whether or not a record was patched. `None` is returned only for conforming FWS, ZWS, foreign containers, and a CWS that fails to inflate or overruns its declared length. So every well-formed CWS dependency the navigator serves now reaches Ruffle uncompressed. `ScaleformResourceLoad::byte_len` therefore records the inflated length, not the archive entry's size.
  - `ui.md:883-886` still describes the shim as "the choke point every root and `ImportAssets` movie passes through before Ruffle sees it (a movie a running menu loads through `Loader.load` / `loadClip` reaches Ruffle un-shimmed, #5480)". Since `1ac34024f`, every body the navigator serves is shimmed, including runtime loads.
  - `ui.md:753` says "116 default tests plus 3 ignored". The measured count is 118 + 3; the two new tests are the #6225 and #5480 pins.
- **Evidence**:
  ```rust
  // prepare.rs:104-132
  let was_cws = &swf_data[0..3] == b"CWS";
  ...
  } else if !was_cws {
      return None;            // only FWS-with-no-patch returns None
  }
  if was_cws {
      file[0..3].copy_from_slice(b"FWS");   // CWS always re-emitted as FWS
      ...
  }
  Some(file)
  ```
- **Impact**: none at runtime. Handing Ruffle the FWS copy is cheaper than before, since Ruffle no longer re-inflates. But the comment misstates the decode-count property the #5479/#5967 work exists to hold. A reader trusting it would expect Ruffle to inflate every dependency, and might re-add a decode on the theory that one is already being paid. The `byte_len` meaning also changed silently. The `ui.md` sentence documents a closed bug as current behaviour.
- **Related**: #5480 and #6225 (both closed); #5479; #5967; UI-D4-2026-10-21-01.
- **Suggested Fix**:
  - Rewrite the `navigator.rs` comment to say that a CWS body always comes back inflated as FWS, so Ruffle takes the copy path, and that `None` keeps the raw bytes only for conforming FWS, ZWS and declined CWS.
  - Say on `ScaleformResourceLoad::byte_len` that it is the served length.
  - In `ui.md`, drop the "un-shimmed, #5480" parenthetical, describe the navigator fetch as shimming every served SWF, and re-measure the test count.
