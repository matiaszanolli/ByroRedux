Previous report: `docs/audits/AUDIT_FO3_2026-10-31.md`. Delta audited: 2026-10-31 to HEAD, about 287 commits across the audited paths. All five dimensions ran (1 NIF/material/collision, 2 ESM data, 3 cell loading, 4 BSA/real data, 5 animation/NPC/gameplay).

**FO3-D2-001: the FO3 dialogue "declined INFOs" pin and its census text are stale (the FNV pin is stale too)**
- **Severity**: LOW (test and doc staleness)
- **Dimension**: ESM data slice; consumer `/audit-gameplay`; owner `/audit-scripting`, FNV leg `/audit-fnv`
- **Location**: `crates/scripting/tests/condition_catalog_real_data.rs`, `fo3_dialogue_declined_by_unmodeled_conditions` (the 1202 assertion and its doc comment); the FNV leg `fnv_dialogue_declined_by_unmodeled_conditions` (613 and 69). The FO3 skill Dim 2 bullet repeats "1 202".
- **Status**: NEW
- **Description**: 1 202 was set by #6558 on 2026-11-03. `d3db6fd58` (#6545) added catalog rows for functions 110, 136, 278 and 391 and re-pinned only the FNV count (641 to 613). `b73899734` added rows for 49, 242 and 438 (CATALOG 103 to 106) and touched no test file. Those rows are not FNV-only: `condition_getter_game` maps `GameKind::Fallout3NV` to the shared Fallout family, so they fire on FO3 INFOs too.
- **Evidence** (measured, release, one named test per leg): FO3 `declined INFOs 1152 of 22327, quests 0`, assertion `left: 1152 right: 1202` fails. FNV `declined INFOs 609 of 23247, objective targets 68 of 772`, assertion `left: 609 right: 613` fails (the 69 objective-target pin is off by one as well). Oblivion's 2 639 / 450 is unchanged. Raw FO3 INFO CTDA counts for the new rows: fn 110 on 11 INFOs, 136 on 2, 391 on 15, 438 on 21, 49 on 1.
- **Impact**: a stale real-data gate hides the next real movement. About 50 FO3 INFOs (and 4 FNV) are now selectable that the pins still count as declined. No runtime defect.
- **Related**: #6460, #6558, #6545.
- **Suggested Fix**: re-pin FO3 to 1 152 and FNV to 609 / 68, and update the doc comment and the skill's "1 777 to 1 202" narrative. The pin sits behind `--ignored`, so no CI lane caught it; consider a floor with a documented tolerance instead of an exact number.

**FO3-D4-001: the skill-quoted DDS-header sweep and folder-hash census have no pinned test**
- **Severity**: LOW
- **Dimension**: BSA v104 and real-data validation
- **Location**: `crates/bsa/tests/bsa_real.rs`, `crates/bsa/src/archive/open.rs`
- **Status**: NEW
- **Description**: The skill tells the auditor to sweep `Fallout - Textures.bsa` to valid DDS headers (12 261 / 12 261) and to run the folder-hash census (0 collisions over 1 810 folders). Neither number nor any such sweep exists in `crates/bsa`. `fo3_fnv_and_skyrimse_bsa_corpus_census` pins only the archive count (16), the entry count (159 155) and that every entry extracts.
- **Evidence**: no FO3 textures DDS or folder-hash pin exists (`rg` over the crates finds none). The only DDS-header census is `crates/menuxml/tests/fo3_corpus.rs` (1 157 interface DDS). `crates/bsa/src/archive/open.rs` computes the folder hash under `#[cfg(debug_assertions)]` only and merely warns on a mismatch, so a release lane never exercises it.
- **Impact**: extraction can succeed while payloads or folder hashes are wrong, and nothing guards it. Low because extract-with-inflate plus the NIF and menuxml lanes cover most payloads.
- **Related**: #5903, #5669.
- **Suggested Fix**: add an `--ignored` `fo3_textures_bsa_dds_header_census` and a hash check that runs in release to `crates/bsa/tests/bsa_real.rs`, or mark both numbers in the skill as manual measurements.

**FO3-D5-001: the new-game chargen fallback is keyed on `GameKind::Fallout3NV`, so FO3 falls back to New Vegas's VCG00**
- **Severity**: LOW
- **Dimension**: FO3-vs-FNV discrimination; owner `/audit-scripting`
- **Location**: `byroredux/src/scene/scene_runtime.rs`, `chargen_quest_default` and its call site
- **Status**: NEW (came in with `8abbd3679`)
- **Description**: A new game reads `sCharGenQuest` from the install's `Fallout_default.ini`. When no INI can be read, it falls back to `chargen_quest_default(index.game)`, which returns `GameKind::Fallout3NV => Some(0x0010_2037)`, FNV's VCG00, for both games. `GameKind` cannot tell FO3 from FNV; `CharacterRulesProfile` is the only discriminator. The function's own comment admits it: "Fallout 3 and New Vegas share a game kind; Fallout 3's INI always sets it."
- **Evidence**: the call site does `ini.and_then(chargen_quest).unwrap_or(default_quest)` then `index.quests.get(&chargen)` and starts nothing on a miss. `Fallout3.esm` has 0 record headers with form 0x00102037. The shipped `Fallout_default.ini` sets `SCharGenQuest=0001f388` (CG00).
- **Impact**: bites only when the INI is not found next to the `--esm`'s `Data` folder (relocated or mod-manager root, name or case mismatch). An FO3 `--new-game` then silently starts no chargen quest: CG00 "Birth" never runs and the only trace is an absent log line. FNV and a vanilla FO3 install are unaffected.
- **Related**: `b972009d7`; there is still no FO3 new-game gate.
- **Suggested Fix**: take the compiled-in default from a profile row (FO3 0x0001F388, FNV 0x00102037, Oblivion 0x0002466E), or decline with a logged warning for FO3. Pin it with a test that an FO3-profile index with no INI picks CG00.

**FO3-D2-002: FO3 reach of #7329 (FormID mod index past the plugin's master list)**
- **Severity**: LOW
- **Dimension**: ESM data slice; owner `/audit-esm`
- **Location**: `FormIdRemap::remap` in `crates/plugin/src/esm/reader.rs`; LMC fold provenance
- **Status**: Existing: #7329 (measured on FNV only; this is the FO3 leg)
- **Description**: three of the five FO3 DLCs carry boilerplate records whose FormID mod index is past their master list: Anchorage (INFO `02000800`, QUST `02000801`), ThePitt (INFO `02000800`), Zeta (INFO `02000800`, QUST `02000801`), plus `Fallout3.esm` REFR `013C8D6D` (the #1308 pass-through). BrokenSteel and PointLookout have none.
- **Evidence**: in each DLC the stray ids fill the DLC's own `0x800` / `0x801` gap, and the INFO's `QSTI` points at its sibling `02000801`. That pattern reads as "self" (stale creator-quest scaffolding), which supports #7329's clamp-to-self option; no external source is cited, so the question stays open. In the order Fallout3, Anchorage, ThePitt, BrokenSteel, PointLookout, Zeta the pass-through lands in slot 2 (ThePitt), so Anchorage's QUST, Zeta's QUST and ThePitt's own NPC_ `01000801` share one global FormID: a bogus three-plugin carrier chain in `FoldProvenance` and a bogus conflict-report row.
- **Impact**: about 6 boilerplate records; the creator quests have DATA flags 0, so they are not start-enabled. No gameplay effect found; conflict report and provenance are wrong for those forms.
- **Suggested Fix**: whatever #7329 decides; add the FO3 five-DLC set to its oracle. Publish as a comment on #7329, not a new issue.

## FNV-Shared Surface

- **NIF / material**: FO3's flag vocabulary (`fo3nv_f1` / `fo3nv_f2`) matches nif.xml bit by bit; the legacy import paths read only those constants; decal bits are honoured on both legacy properties; `BSShaderNoLightingProperty` maps to `MATERIAL_KIND_NO_LIGHTING` (102); two-sided comes from `NiStencilProperty`; `BSSegmentedTriShape` feeds the plain `NiTriShape` arm. All verified. The env-mask classifier change (`2ed1d91ce`) has unmeasured FO3 reach, tracked by #6816 (add FO3 to its census checklist at publish).
- **Collision**: `CollisionAuthoring::Classic`, `walk_through_by_authoring`, BOX_INERTIA to Dynamic, every dispatched bhk shape has a resolve arm (test passes). The #6560 FO3 pin is present.
- **BSA v104**: no game conditional in the v104 path; embedded names are a version rule; codec is a version rule; the empty compressed placeholder is pinned for 103/104/105. `970d6bb3f` (#7100) moved ESM record inflation onto the shared `inflate_bounded_zlib`; a real `Fallout3.esm` parse after that change is unmeasured (the plugin `--ignored` tests were not run).
- **Cell loading**: no hardcoded worldspace names in `crates/plugin/src/esm/cell/wrld.rs`; every `GameKind` use on the load path is asset-family classification; legacy object LOD, LOD-inheriting children and "Use Land Data" children all still resolve through their single resolvers.
- **Gameplay**: sneak, VATS, doors, packages, fn 586 and consumable gating are all profile-keyed or have no `GameKind` split between FO3 and FNV.
