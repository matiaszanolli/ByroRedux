## Summary

This is a mature, heavily self-documented subsystem. Every invariant the skill
calls out as "already fixed" or "already correct" was independently re-verified
against the live code and found to hold: TypeId-sorted multi-lock acquisition
with matching tracker-scope order (`world.rs` `query_2_mut`/`query_2_mut_mut`/
`resource_2_mut`/`try_resource_2_mut`), the #1367 cached-pointer soundness in
`query.rs` (all four unsafe blocks carry a correct SAFETY comment tied to the
live guard), `SparseSetStorage`/`PackedStorage` swap-remove and bulk-insert
invariants, the three release assertions in `boot/registries.rs`
(`undeclared_parallel_count`/`known_conflict_count`/`unknown_pair_count` all
zero, confirmed by a passing `build_scheduler_reports_zero_access_conflicts`
test), the complete seven-procedure AI-behavior teardown list in
`clear_ambient_behavior`, and the `Material::resolve_pbr` plain-`f32`
NaN-sentinel contract.

The highest-churn code in this scope — `make_transform_propagation_system`
(three real bugs fixed there in the three days before this audit: #4060,
#4061, #4062) — was traced by hand through both the structural and
incremental code paths, including the interaction between the new
dirty-ancestor climb and the shared BFS drain. No residual defect was found;
the fixes compose correctly with each other (verified the seed-skip case,
the multi-level-dirty-chain case, and the traversal-guard-exhaustion fallback
case by hand-tracing, not just reading the commit message). The
`clippy::neg_cmp_op_on_partial_ord` rewrites from the same-day #4090 cleanup
(`!(x >= y)` → `x.is_nan() || x < y}` in `animation/player.rs` and
`animation/stack.rs`) were checked for De Morgan/NaN equivalence by hand and
are correct.

Net result: **1 finding**, LOW severity, about the audit tooling itself
rather than the ECS code.

## Findings

### ECS-2026-09-11-01: Stale `byroredux/src/boot.rs` path references in this skill's own Dimension 5b
- **Severity**: LOW
- **Dimension**: 5b (Scheduler Access Declarations) / audit infrastructure
- **Location**: `.claude/commands/audit-ecs/SKILL.md:154-155`
- **Status**: NEW
- **Description**: Dimension 5b instructs the auditor to enumerate live
  `add_to_with_access` declarations and verify no plain `add_to` calls survive
  via `rg -n '^\s*scheduler\.add_to_with_access\(' byroredux/src/boot.rs`
  and `rg -n '^\s*scheduler\.add_to\(' byroredux/src/boot.rs`. `byroredux/src/boot.rs`
  does not exist — the scheduler build moved to `byroredux/src/boot/schedule/mod.rs`
  plus per-stage siblings (`early.rs`, `update.rs`, `post_update.rs`, `physics.rs`,
  `late.rs`) at some point before this session; `.claude/commands/_audit-validate.sh`
  already lists this exact basename as an advisory (non-fatal) miss at
  `audit-ecs/SKILL.md:305`, alongside the same stale basename in four other
  skill files (`audit-fnv`, `audit-save`, `audit-scripting`, `audit-tech-debt`)
  and several `docs/engine/*.md` references — so this is a pre-existing,
  tooling-flagged (advisory, not fatal) condition rather than something newly
  introduced by this session's work, and not unique to `audit-ecs`.
- **Evidence**: `ls byroredux/src/boot.rs` → "No such file or directory";
  `find . -name boot.rs -not -path './target/*'` → no results anywhere in the
  tree. The correct paths for the same check are
  `rg -n '^\s*scheduler\.add_to\(' byroredux/src/boot/schedule/*.rs` (confirmed
  empty — zero plain `add_to` calls survive, so the underlying invariant this
  dimension protects still holds) and the three release assertions actually
  live in `byroredux/src/boot/registries.rs` (which line 150 and line 188 of
  the same skill file already point at correctly — only the two `rg` commands
  in lines 154-155 are stale).
- **Impact**: None on runtime behavior. A future auditor who runs the given
  `rg` command literally gets an empty/error result and could misread that as
  "confirmed zero plain `add_to` calls" for the wrong reason (file doesn't
  exist) rather than actually checking the real files. Purely a
  audit-tooling-accuracy issue.
- **Related**: Same basename is stale in `audit-fnv/SKILL.md:188`,
  `audit-save/SKILL.md:86`, `audit-scripting/SKILL.md:1517`,
  `audit-tech-debt/SKILL.md:221,224`, and multiple `docs/engine/*.md` files —
  a single sweep across all of them would be more efficient than fixing this
  one site in isolation.
- **Suggested Fix**: Update the two `rg` targets in Dimension 5b from
  `byroredux/src/boot.rs` to `byroredux/src/boot/schedule/*.rs`.

## Dimensions Verified With No Findings

For completeness, everything checked and confirmed correct (not re-litigated
in prose above):

- **Dim 1 (Lock Ordering)**: every `query`/`query_mut`/`resource`/`resource_mut`
  site arms a tracker scope before the real lock and defuses only after
  acquisition; `query_2_mut`/`query_2_mut_mut`/`resource_2_mut` all sort by
  `TypeId` for both the tracker scopes and the real locks, in the same order;
  `assert_ne!` guards same-type double-lock in all three + `try_resource_2_mut`;
  `try_resource_2_mut` checks both keys' existence before touching either lock
  (#465); poison resolution (`storage_lock_poisoned`/`_erased`/`resource_lock_poisoned`)
  covers every lock site; `lock_tracker.rs`'s `#3680` gating (`is_enabled()`
  before the `held_others` collect) is intact in both `track_read`/`track_write`.
- **Dim 2 (Storage Correctness)**: `SparseSetStorage::remove` fixes
  `sparse[moved_entity]` and takes the no-swap path for the last element;
  `PackedStorage::insert`/`remove` maintain sort order via `binary_search`;
  `insert_bulk` is append+single-sort+dedup (last-writer-wins, matches serial
  semantics); `TRACK_CHANGES` dirty-set/`structural_gen` machinery is const-
  folded away for non-tracked components; `drain_dirty_into` preserves
  capacity vs. `take_dirty`'s zero-cap regrow; `insert_batch`'s wrapped
  iterator still fires the `entity < next_entity` debug_assert per item.
- **Dim 3 (Query Borrow Safety)**: all four #1367 cached-pointer unsafe blocks
  in `query.rs` (`QueryRead::storage`, `QueryWrite::storage`/`storage_mut`,
  `ComponentRef::Deref`) carry correct SAFETY comments; `ComponentRef` retains
  its guard (sound replacement for the old #35 pattern); `QueryWrite`'s
  `Deref`/`DerefMut` route through the borrow-checker-enforced `&self`/`&mut self`

- **Dim 4 (Resource Lifetimes)**: `ResourceRead`/`ResourceWrite` downcast on
  every `Deref` (not cached, as documented — this is not the #1367 hot path);
  `resource_2_mut` and `try_resource_2_mut` mirror the query-side TypeId-sort +
  both-checks-before-either-lock pattern exactly.
