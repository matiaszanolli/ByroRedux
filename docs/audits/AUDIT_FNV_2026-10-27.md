## Findings

### HIGH

#### FNV-2026-10-27-02: FNV light-beam and glow VFX STATs get solid synthesized trimesh colliders, because the 10-26 VFX-sheet gate recognises only Skyrim+ `BSEffectShaderProperty`
- **Severity**: HIGH. Static evidence only, not reproduced in a running engine. The same mechanism wedged the character capsule at Riverwood, per `1efe39722`.
- **Dimension**: 1 (cell spawn), FNV data through the PHYSAL missing-collision fallback. **Owner of the mechanism**: `/audit-physics`, plus the `/audit-nifal` boundary.
- **Location**: `byroredux/src/cell_loader/spawn.rs:76-90` (`render_geometry_can_collide`), `:92-111` (`missing_collision_fallback`: any `RenderLayer::Architecture` base whose NIF has no bhk → `ArchitectureTriMesh`); `byroredux/src/cell_loader/spawn/mesh_instance.rs:1526-1539` (`spawn_trimesh_collider_ghost`); `crates/plugin/src/record.rs:304-341` (STAT → Architecture).
- **Status**: NEW. `1efe39722` (2026-10-26, "VFX effect-shader sheets no longer synthesize solid colliders") fixed the Skyrim dialect only.
- **Description**: The predicate excludes decals, alpha-tested meshes, fire-refraction and `effect_shader.is_some()`. FO3/FNV author their VFX sheets as `BSShaderNoLightingProperty` plus a blended `NiAlphaProperty`. They carry no `effect_shader` and no alpha test, so they pass the predicate. These are god-ray light beams, industrial light rays, glow fills, dust shafts and bright spots. A STAT base sends them through the fallback, which builds a Fixed trimesh from the render geometry.
- **Evidence**: census over `FalloutNV.esm` STAT `MODL` × `Fallout - Meshes.bsa` / `Update.bsa` block types (`/tmp/audit/fnv/probe/vfx2.py`): **98 non-marker STAT bases, 6,763 REFRs (6,726 under `meshes\effects\`)** have no `bhk*` block, an `NiAlphaProperty`, and only `BSShaderNoLightingProperty`. The largest are `FXGlowSimpFillRndFltHalf` ×866, `FXLightBeamBrt04` ×557, `FXBrightSpotFlat` ×556, `FXLightBeamW01Dim` ×540, `FXLightBeamW03` ×415, `IndFXLightRays01` ×298 and `FXLightBeamSuperWide01` ×277. Six of these were sampled with `dump_alpha` / `material_dump`. Each has `blend=true test=false`, decal 0 and material kind 102 (`MATERIAL_KIND_NO_LIGHTING`), so `render_geometry_can_collide` returns `true`.
- **Impact**: Light shafts in FNV interiors and lit exteriors become solid. They block the player capsule, NPC KCC walks and dropped bodies, and they intercept physics probes. This is FNV's version of the Riverwood rapids wall, spread over thousands of placements. FO3 shares the same dialect but was not measured.
- **Suggested Fix**: Key the gate on a canonical "VFX / does not collide" signal set at the NIFAL boundary, not on one game's shader block. For example, exclude `MATERIAL_KIND_NO_LIGHTING` (or blended + no-depth-write unlit). Then add an FNV real-data pin that the census bases synthesize no collider.

### MEDIUM

#### FNV-2026-10-27-01: #6251 residual. 406 FNV INFOs, 4 whole quests (157 INFOs) and 22 objective targets are still declined only by CTDA functions the ObScript VM already answers
- **Severity**: HIGH. Raised from MEDIUM during suite reconciliation: the FO3 leg, measured in AUDIT_FO3_2026-10-27 as a dup of this finding, is far larger. With no `catalog.rs` row for `IsInList` (372) or `GetTalkedToPC` (50), the quest-condition gate fails closed on **21 FO3 quests, 5,377 of 22,327 INFOs (24%)**. These include DialogueMegaton 746, ConvUnderworld 516, ConvMegaton 448, MS16 447, DialogueRepublicDave 404, Followers 395 and DialogueCitadel 380. Another 522 INFOs carry these functions in their own conditions. Same class as #6251.
- **Dimension**: 5 (dialogue and quests through the M47.1 condition gates). **Owner of the mechanism**: `/audit-scripting` (catalog), `/audit-gameplay` Dim 2.
- **Location**: `crates/scripting/src/condition/catalog.rs` (`ROWS` and `FOREIGN_INDICES`: 365 is the Oblivion-only `GetPlayerInSEWorld` row, foreign on FO3/FNV, where 365 is `IsChild`). The existing getters are:
  - `crates/scripting/src/obscript_more/tail.rs:325` / `:809` (`is_child`, `0x116d`);
  - `crates/scripting/src/obscript_more.rs:292` / `:548` (`get_talked_to_pc`, `0x1032`);
  - `cmd_1174` (`IsInList`, `0x1174`);
  - `CMD_GET_HAS_NOTE` `0x117e`, `CMD_GET_LOCKED` `0x1005`, `CMD_GET_CURRENT_TIME` `0x1012`, `CMD_GET_IN_SAME_CELL` `0x1020`, `CMD_GET_BASE_AV` `0x1115`, `CMD_GET_DESTRUCTION_STAGE` `0x11d7`;
  - `get_map_marker_visible` `0x11ec`, `get_hit_location` `0x1187`, `cmd_1120` (`GetFriendHit`), `get_current_ai_package` `0x106e`.
- **Status**: NEW. This is a residual of #6251 (closed by `f57c75616`, which catalogued 10 getters and named only 427 and 372 as follow-ups; 427 has since landed). The IsChild and GetTalkedToPC getters predate that fix (`6e9d55aa9`, 10-18).
- **Description**: The fail-closed gates decline any condition whose function `is_modeled` rejects. The VM answers these functions as script getters (command id `0x1000 + index`), but the catalog has no row for them. The gates therefore cannot read state the engine already keeps.
- **Evidence** (`/tmp/audit/fnv/probe/ctda2.py`, catalog indices from `catalog.rs` minus FNV-foreign): 984 of 23,247 INFOs are still declined (5,968 at 10-21). Of those, **406 are declined only by VM-implemented functions**: 365 ×140, 50 ×71, 382 ×39, 372 ×32, 5 ×24, 18 ×18, 32 ×15, 277 ×15 and smaller. Quest-level gates decline 4 quests whole: **`GenericAdultCombat`** (71 INFOs, `IsChild`), **`GenericKids`** (69, `IsChild`), **`Followers`** (14, `IsInList`) and `DialogueCrimeKarma` (3, `GetTalkedToPC`). 22 `QSTA` targets are declined only by VM getters: 471 ×9, 6 ×4, 492 ×3 and others. The largest remaining non-VM blocker is `GetScriptVariable` 53 (333 INFOs).
- **Impact**: Every adult's generic combat barks and every child's generic lines are unselectable on FNV, and so are the `Followers` lines. Some objective markers never highlight. Nothing crashes.
- **Suggested Fix**: As in #6251, give each function one implementation: add catalog rows (the 365 row is a game-variant pair) that call the existing getter bodies. Add a real-data floor on the number of declined FNV INFOs and quests.
