### MEDIUM

#### UI-D5-2026-08-30-04 — one unresolvable `ImportAssets` URL in the root movie is a hard menu-load failure, while the identical failure on a *nested* import and at fetch time is deliberately degraded

**Dimension**: Resource Navigator · **Profile**: both (archive route)

`import_asset_paths_from_tags` (`crates/ui/src/navigator.rs:517-533`) ends in
`.collect()` into a `Result<Vec<String>, String>`, so **a single**
`ImportAssets` entry whose URL fails to `join` or fails
`archive_path_from_url` aborts the whole list:

```rust
tags.iter()
    .filter_map(|tag| match tag {
        Tag::ImportAssets { url, .. } => Some(url.to_string_lossy(swf::UTF_8)),
        _ => None,
    })
    .map(|relative| {
        movie_url.join(&relative.replace('\\', "/"))
            .map_err(|error| format!("invalid ImportAssets URL {relative:?} in {movie_url}: {error}"))
            .and_then(|url| archive_path_from_url(&url))
    })
    .collect()
```

On the archive route that `Err` is returned by `prepare_movie`
(`prepare.rs:91`), mapped to `anyhow!` in `SwfPlayer::from_resource_provider`
(`player.rs:224-225`), and logged by `scene.rs:1580-1584` as
`Failed to load archive menu …` — **no menu at all**.

The same two failures are non-fatal everywhere else in this module:

- **At fetch time**, `ScaleformNavigator::fetch` routes both a `resolve_url`
  error and an `archive_path_from_url` error through `self.degraded(...)`
  (`navigator.rs:340-356`), recording the message and substituting a valid
  empty movie so Ruffle's `awaiting_import` flag clears.
- **One level down**, `load_archive_resource` calls the *same*
  `import_asset_paths` on a fetched child's tags and maps its `Err` to
  `record_degraded` (`navigator.rs:280-283`) — non-fatal.

So the identical error is fatal at depth 0 and recoverable at depth ≥ 1, and
`from_resource_provider`'s own comment states the policy the root scan
violates:

> "#2720 — a dependency that fails to fetch is recorded, not fatal: the root
> movie loaded, and a menu missing an imported font is worth more than no menu."

**Reachable input**: the concrete trigger is an `ImportAssets` URL that is
absolute with a non-`file` scheme — `movie_url.join("http://host/x.swf")`
succeeds, then `archive_path_from_url` rejects the scheme
(`navigator.rs:465-470`). `ImportAssets` URLs are chosen by untrusted movie
content, and R4's stated premise is preserving third-party SWF mod
compatibility, so this is not a purely hypothetical shape. I could not sweep
vanilla content for such a URL (no FO4/Skyrim corpus on this machine), which is
why this is MEDIUM and not HIGH.

**Fix shape**: mirror the depth-≥1 policy — partition rather than
short-circuit. Keep the resolvable paths and push each unresolvable one into
`NavigatorState.errors` so it surfaces through `resource_errors()`. The set's
**only** consumer is the `is_import_asset` test at `navigator.rs:270`, which
decides whether `prepare_import_asset_swf`'s frame-boundary workaround applies
to a fetched resource; an entry that can never resolve to an archive path can
never be fetched from the archive either, so dropping it from the set costs
nothing.

Structurally this is the same asymmetry as **#3428** (fatal lifecycle-class
scan vs non-fatal inventory scan over the same ABC tags) — worth fixing in one
change.

### LOW

#### UI-D1-2026-08-30-01 — #2968 is closed, but the live `--menu` route still inflates the movie three times and extracts the archive entry twice; `prepare.rs`'s own doc claims two

**Dimension**: Profile & VM Selection · **Profile**: both (archive route)

`crates/ui/src/prepare.rs:16-17` states the post-fix cost as "**two inflates**
rather than four, and one tag walk rather than two". That is true *of the
crate*. It is not true of the only production caller.

`byroredux/src/scene.rs:1530-1539`:

```rust
Ok(archive) => match archive.extract(menu_path) {                  // archive extract #1
    Ok(root_bytes) => match ScaleformProfile::detect(&root_bytes) {  // whole-stream inflate #1
        Ok(profile) => {
            let (w, h) = ctx.swapchain_extent();
            let mut ui = UiManager::new(w, h);
            match ui.load_swf_from_resource_provider(Arc::new(archive), menu_path, menu_path, profile) {
```

`root_bytes` is used for **nothing but** `detect`.
`SwfPlayer::from_resource_provider` (`player.rs:210-214`) then calls
`provider.load(movie_path)`, which is `Archive::load` → `contains` + `extract`
(`byroredux/src/asset_provider/archive.rs:75-83`) — a **second full
decompression of the same archive entry** — hands the result to
`prepare_movie`, which inflates it again (#2), before `SwfMovie::from_data`
inflates a third time.

So the archive route costs **2 archive extractions + 3 SWF inflates + 1 tag
walk** per menu open, synchronously on the winit main-loop thread, on FO4's
multi-megabyte `hudmenu.swf` / `pipboymenu.swf`. #2968 removed two of the five
inflates the 08-27 audit counted; the two outside the crate boundary survived
because the fix was scoped to `SwfPlayer`'s constructors — the commit body says
so explicitly ("removing that would change the public loader signature and is
left alone").

The `profile` argument scene.rs computes is not a cross-check either: it is the
same function on the same bytes, so `prepare_movie`'s mismatch guard is
tautologically satisfied on this route and can never fire.

**Fix shape**: `prepare_movie` already detects the profile unconditionally.
Either widen `UiManager::load_swf_from_resource_provider` to take
`Option<ScaleformProfile>` and pass `None` from `scene.rs`, or return the
detected profile from it so scene.rs's `ui.menu: loaded … profile={:?}` line
(which `m48-menu-load.sh` greps and must keep) retains its value without the
pre-extract. Deleting scene.rs's `extract` + `detect` pair removes one archive
decompression and one whole-stream inflate.

**Impact**: load-time only, so LOW. Filed because the module that exists to
hold this property documents a number the shipping route does not meet — the
exact drift class #2968 was opened for.

#### UI-D2-2026-08-30-02 — the #2969 drop-counter latch is not reset on menu swap, so a new menu's first N drops are silent when the previous menu dropped N

**Dimension**: Host Bridge Transport · **Profile**: both

`byroredux/src/app_frame.rs:277-291` latches the reading in
`self.ui_dropped_host_calls`, which lives on `App` and is never reset.
`host_call_gap` (`main.rs:141-143`,
`reported.checked_sub(latched).filter(|l| *l > 0)`) deliberately treats a
*decrease* as a menu swap and reports nothing — correct, that is what stops
`checked_sub` wrapping. But the latch is then overwritten with the new, smaller
value, and no code path zeroes it at `install_player` time.

The correct case:

| frame | menu | `dropped_calls()` | latch before | warned? |
|---|---|---|---|---|
| n | A | 1000 | 900 | yes, "lost 100" |
| n+1 | A | 1000 | 1000 | no |
| n+2 | B (fresh bridge) | 0 | 1000 | no — reset, latch ← 0 |

The lossy case is a swap landing on a frame where the new bridge has *already*
evicted:

| frame | menu | `dropped_calls()` | latch before | warned? |
|---|---|---|---|---|
| n | A | 1000 | 1000 | no |
| n+1 | B (fresh bridge, dropped 999 during load/first tick) | 999 | 1000 | **no** — 999 < 1000 reads as a reset |
| n+2 | B | 1000 | 999 | yes, "lost 1" |

Menu B's first 999 lost calls are reported as one. The latch cannot distinguish
"same bridge, impossible decrease" from "different bridge, smaller count",
because it latches a number and not the identity of the bridge that produced
it.

**Fix shape**: `app_frame.rs` already holds `ui.menu_name` in the same block
and already keys `ui_reported_host_methods` by it. Latch the pair
`(menu_name, dropped)` — or zero `self.ui_dropped_host_calls` whenever
`ui.menu_name` differs from the name seen last frame — so the swap case becomes
an explicit reset rather than an inferred one. `host_call_gap`'s decrease guard
then stays as the belt-and-braces it was meant to be.

**Impact**: diagnostic-only today (nothing routes host calls into game state
yet), and it needs a menu that overflows the 1024-entry bound at all, which no
measured vanilla menu does — `docs/engine/ui.md`:601-610 records at most one
host call across 600 ticked frames for every corpus menu tested. LOW. Filed
because this is the exact channel #2969 exists to provide, the fix is three
lines against data already in scope, and the failure is silent: it costs
nothing observable until the drain starts routing calls into quest / inventory
/ player state, at which point it is a lost state transition with no signal.

#### UI-D4-2026-08-30-03 — the FO4 catalog's `Command`/`Request` kind is partly heuristic-derived and partly evidence-derived, and the array records which is which nowhere

**Dimension**: Catalog Fidelity & Drift · **Profile**: `Fallout4Avm2`

`docs/engine/ui.md`:441-451 states the provenance plainly: of the 269 entries,
138 came from the F4CF reconstruction plus installed-ABC inventory, and the
**131 added by the #2966 311-movie sweep have their `kind` "inferred from name
prefix (`Get*`/`Is*`/`Should*`/`Can*`/`get*`)"**. The array itself carries no
marker distinguishing the two provenances, and the doc does not list which 131.

The heuristic's boundary is demonstrably imprecise. All 33 `Request` entries
match the prefix set — i.e. **no entry was ever promoted to `Request` on
evidence that contradicted the prefix rule** — while the `Command` side needed
at least two hand-overrides (`Cancel`, `CancelPlayback`, both matching `^Can`)
and still holds 16 names carrying query-shaped verbs the prefix set does not
cover:

```
AreModsLoaded                CheckHardcoreModeFastTravel   CheckRequirements
DoQuicksave                  ValidateHackingWord           requestCredits
RequestAudioOptions          RequestDisplayOptions         RequestGameplayOptions
RequestHelpText              RequestHelpTitle              RequestInputMappings
RequestInstalledContentText  RequestInstalledContentTitle
RequestRefreshInstallProgress                              requestLoadingText
```

I am **not** claiming these are misclassified. Several — the `Request*` family
in particular — are very plausibly correct, because Bethesda settings menus use
a request→native→push-back pattern rather than a return value, and I have no
F4CF checkout or installed FO4 corpus on this machine to decide it. *That* is
the finding: the catalog gives a maintainer no way to tell a `Command` that was
**measured** from one a prefix rule **guessed**, so all 236 have to be
re-derived from scratch before a handler can be trusted against any of them.

**Why LOW rather than the "hanging callback" this skill's checklist warns
about**: that failure mode is Skyrim's. On FO4 there is no callback protocol —
the injected forwarder does `ExternalInterface.call(...)` through
`Function.apply` and returns synchronously, and `record_call` returns
`ExternalValue::Null` for both `Queued` and `MissingResponse`
(`host.rs:483-487`). `request_id` is always `None` on the AVM2 normalization
path (`host.rs:532-547`), so `GameDelegateResponse` is unreachable for this
profile. The kind therefore decides **only** whether a method lands in
`unanswered_methods()` and which dispatch label it logs — no menu hangs either
way. What it costs is the completeness of the to-do list the handler work will
be driven from.

**Fix shape**: mark the 131 sweep-derived entries (the #2966 measurement
presumably still has the list) with a third field or a delimited comment block,
so `unanswered_methods()` consumers know the classification's confidence.
Alternatively fold this into **#3103**, which already asks for a corpus
measurement of the sibling Skyrim catalog.

  `#[cfg(test)]`-only. Detection is still movie evidence only —
  `header.is_action_script_3()` — with no `--game`, archive-name or path
  inference anywhere in `crates/ui/src` or `byroredux/src`. Forced-profile
  mismatch is now rejected **earlier** than before, inside `prepare_movie`
  before the tag parse, injection and import scan
  (`a_profile_mismatch_is_rejected_before_any_further_decode`).
  `external_interface_id` still has exactly one consumer
  (`BridgeProvider::get_id`), so there is no registration-vs-filter mismatch
  surface. `SwfMovie::from_data` failure is `?`-propagated in all three
  constructors.
- **Dimension 2** — eviction is `VecDeque::pop_front` in a `while len >= cap`
  loop with `dropped_calls += 1` per eviction; `overflow_warned` latches once
  per bridge. `MissingResponse` and `Unknown` remain distinct dispatches
  feeding distinct sets. Re-entrancy is safe: the response handler is cloned
  out from under a *temporary* borrow (`host.rs:392-398`) and invoked with no
  borrow held, and `call_method`'s re-entrant `respond` runs after `record_call`
  has fully returned. `Rc`/`RefCell` makes `!Send` compiler-enforced, and no
  `impl Resource for UiManager` exists in the tree. `ScaleformValue` ↔
  `ExternalValue` is total in both directions — seven variants each, one arm
  per variant, no catch-all, no panic path. Every sibling bounded channel
  (`callbacks`, `known_methods`, `unknown_methods`, `unanswered_methods`,
  `resource_errors`, `resource_loads`, `import_asset_paths`) logs once at the
  point it trips.
- **Dimension 3** — the #2968 refactor is mechanical and equivalent. The
  `Option` return never loses the patched movie
  (`patched.unwrap_or_else(|| swf_data.to_vec())`); moving the `ImportAssets`
  scan from the patched bytes to the unpatched tag list is safe because
  injection only assigns and inserts `DoAbc`/`DoAbc2` tags; injection failure
  was already fatal pre-#2968, so #3428 was not widened. Both idempotency
  guards live (outer `ADAPTER_NAME` tag scan, `patch_root_constructor`'s own
  `INSTALL_HELPER` scan), both pinned by default tests. Constant-pool
  discipline holds — every index derives from its own push, `Index::new(0)` is
  only the ABC "any" sentinel, and the four conditional destroy strings are
  referenced solely through the `Option` tuple, so a movie without the trait
  cannot reference a slot that was never pushed. Forwarder ↔ method pairing is
  structurally unrepresentable-wrong (one loop variable feeds all three pool
  entries; installer consumes the two vectors with `zip`). `BGSCodeObj.X` → `X`
  normalization is one shared helper.
- **Dimension 4** — counts re-derived and matching; sort order correct for the
  `binary_search_by`; `find` is case-**sensitive** and must be (the FO4 array
  deliberately carries `CloseMenu`/`closeMenu`, `PlaySound`/`playSound`,
  `GetButtonFromUserEvent`/`getButtonFromUserEvent`), so there is exactly one
  normalization point because there is none. **This skill's own Dim 4 text
  ("documented as case-preserving with case-insensitive lookup") is the drift,
  not the code** — the 08-27 audit filed the same correction and the skill text
  is unchanged. The `unknown_methods()` path is live, keyed `(menu_name,
  method)`, capped, and the de-dup set is never cleared.
- **Dimension 5 (trust boundary)** — **a menu cannot reach the filesystem or
  the network.** `archive_movie_url` rejects `..` in the movie path;
  `resolve_url` is `movie_url.join(...)` so traversal normalises away;
  `archive_path_from_url` refuses non-`file` schemes and
  `ParentDir`/`Prefix` components. A fully-resolved `file:///etc/passwd`
  becomes the archive key `etc\passwd` and is looked up only through
  `ScaleformResourceProvider::load` (`contains` + `extract` against the archive
  file table). `navigate_to_url` is a `log::debug!` no-op; `connect_socket`
  answers `ConnectionState::Failed` immediately; `fetch` refuses anything but
  GET. **The loose-file `--swf` route is sealed too** — it passes no navigator,
  and `PlayerBuilder`'s default at pinned rev `0dde9813` is
  `NullNavigatorBackend` (`core/src/player.rs:2969`). Bounds are all in place
  (512 import paths, 64 recorded loads deduped with `hit_count`, 64 recorded
  errors), and the raw `NavigatorState.loads`/`errors` are `mem::take`n every
  tick so they hold at most one tick's fetches. The executor pump is driven
  from the same place the player ticks. Misses leave a trace — every failure
  routes through `record_degraded`, which records *and* substitutes a valid
  empty movie so Ruffle's `awaiting_import` clears.
- **Dimension 6** — one shared process-wide Ruffle wgpu device (#2733), not one
  per menu; creation failure non-fatal and **not** cached (`get_or_try_init`,
  pinned by a GPU-free test). `render()`'s three failure paths all leave
  `dirty` set and return `None`; the first render is always handed over.
  Stride is tight-packed on both sides by construction — `capture_frame` →
  `into_raw` → length-checked → `copy_from_slice`, and `update_rgba` is always
  called with the menu's own dimensions. **A row-pitch shear would not be
  visible to `cargo test`**; this is verified by construction, not by a test.
  The `pending_destroy` ring is bounded to `MAX_FRAMES_IN_FLIGHT`. The overlay
  is sized at **output** resolution (`swapchain_extent()`, explicitly distinct
  from `render_extent()`), so under an FSR preset it is no longer drawn into a
  smaller attachment and upscaled. **Nothing in `crates/ui` is `unsafe`.**
- **Dimension 7** — `crates/ui` has no `winit` dependency at all, so a leak is
  a compile error. F3 is consumed at `app_events.rs:281`, ahead of every gate;
  `is_debug_overlay_key` additionally keeps F3 key-up and auto-repeat out of a
  focused menu. `cache_window_state` runs ahead of every early return (#2973
  intact). A menu-open frame cannot leak an `InputAction` edge:
  `release_world_input` clears both held sets and the injected-key resources,
  `refresh_action_state` then derives `pressed = 0`, and **no production code
  reads `was_released`** (every call site is a test). `about_to_wait`
  re-enforces the release every frame. Each winit event is translated exactly
  once; wheel deltas keep their units; dropping the horizontal wheel axis is
  correct because `ruffle_core`'s `MouseWheelDelta` is single-axis. Cursor →
  texture scaling is the exact inverse of the overlay stretch and survives a
  window resize. A hidden or absent menu costs nothing (both `tick` and
  `render` early-out on `!visible`; the whole block is inside
  `if let Some(ref mut ui)`).

### Ordering fact for `/audit-concurrency` Dim 6

`App::drop` (`byroredux/src/main.rs`) drops `VulkanContext` first, so the
Ruffle wgpu device drops **after** the engine's Vulkan context — the opposite
of this skill's Dim 6 checklist premise. Still harmless, for the same reasons
the 08-27 audit gave: the Ruffle device is a separate `VkInstance`/`VkDevice`
from `create_wgpu_instance`, the UI texture lives in `VulkanContext`'s own
registry and dies with it, and `SwfPlayer::drop`'s
`call_internal_interface(DESTROY_CALLBACK)` touches no engine GPU object. The
checklist wording predates the #2733 shared-descriptor singleton and should be
reworded — flagged for the second cycle running.

## 5. Pending-Row readiness

- **Host-method handlers** — the mechanism remains sound and self-retiring
  (`register_method` / `set_response*` remove from `unknown_methods` and
  `unanswered_methods`), and observability improved this cycle: `dropped_calls()`
  now has a live engine consumer (#2969). What is still invisible to the
  engine is everything hanging off `SwfPlayer` rather than the bridge —
  `host_object_state()`, `preload_stalled()`, `resource_loads()`,
  `resource_errors()` — because `UiManager` exposes no accessor for its
  `player` field (#3427, sharpened above). `unknown_methods()` /
  `unanswered_methods()` are reachable through `host_bridge()` but still have
  no caller.
- **Menu stack / focus policy** — `UiManager::set_input_focus` has **no
  producer of `false` anywhere in the tree**; the only calls are
  `install_player`'s own `false`-then-`true` pair. So the two-state focus
  contract has exactly one reachable state today: once `--menu`/`--swf`
  installs a player the menu holds focus for the process lifetime, and
  `App::capture_world_input` correctly defers to it rather than fighting it.
  The carrier is in good shape — `set_input_focus` forwards
  `FocusGained`/`FocusLost` to Ruffle exactly once per transition, refuses
  focus without a visible player, and reports whether the effective state
  changed. A stack will additionally need a producer of
  `set_input_focus(false)` and a re-registration of `ui_texture_handle` on
  swap (the engine holds one handle, registered once in `scene.rs`).
- **Papyrus ↔ UI bridge** — unchanged; `invoke_callback` still has no non-test
  caller.
- **Font fidelity** — **unblocked this cycle.** #3426 removed the reason no
  font work was measurable: menu pixels no longer pass through ACES, height
  fog, bloom, TAA and FSR before reaching the swapchain. This row is now
  actionable.
- **Resize** — still fixed-at-load by decision (#2723). Worth noting the
  *input* half is already correct (`cursor_to_ui` compensates exactly), so a
  resize fix is confined to rebuilding the `SwfPlayer` renderer and
  re-registering the texture.
