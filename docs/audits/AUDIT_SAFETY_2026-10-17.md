## Findings

### SAFE-VOL-2026-10-17-01: the finite-fp16 guard (#4782) is not carried through the integration store
- **Severity**: LOW. Defence-in-depth gap. Reachability depends on emitted radiance above the fp16 ceiling, and no current content was measured to reach it.
- **Dimension**: GPU-fed data / non-finite handling (Dim 7).
- **Location**:
  - `crates/renderer/shaders/volumetrics_integrate.comp:79-100` (`inscatter_total += inscatter * trans_cumulative * sourceIntegral;` then `imageStore(integrated, …, vec4(inscatter_total, trans_cumulative))`).
  - Upstream guard: `volumetrics_inject.comp:3290` (history scrub) and `:3345-3353` (clamp `rgb`/`a` to `6.0e4`, zero if non-finite).
  - CPU boundary: `byroredux/src/render/fog_volumes.rs:285-290` (`sanitize_emission` is finite + `max(0.0)` only, no ceiling).
- **Description**: The `integrated` image is RGBA16F (finite ceiling 65504). The inject pass clamps every stored lane to `6.0e4`, but the integration pass accumulates up to `froxel_z_slices` (≤ 256, default 64) slabs in fp32 and converts to half on `imageStore` with no clamp. A column whose source radiance (`inscatter * sourceIntegral`, which is the medium's source-function radiance) exceeds 65504 therefore stores `+Inf`. `composite.frag` has no `isnan`/`isinf` guard (grep: none) and computes `scene * vol.a + vol.rgb`. The #4782 comment itself notes that "composite/bloom reach the screen with no guard either", so one Inf froxel column becomes a bloom-spread white or NaN smear. Unlike the inject history, the integrated volume is not fed back, so the damage lasts one frame per occurrence. The `6.0e4` inject clamp does not bound the integral: with a small extinction the per-slab factor `sourceIntegral` is about `dt` (tens to hundreds of world units).
- **Disproof attempted**: In the physical regime `inscatter ≈ sigma * L` and `sourceIntegral ≈ 1/sigma`, so the integral is bounded by about `L`, the source radiance. An overflow therefore needs authored `L_e` or sun radiance above 65504, which no vanilla-derived value reaches (not measured on device). The CPU side only floors emission and applies no upper bound, so an absurd-but-finite authored/ECS value would pass `sanitize_emission`. That is why this is LOW and not MEDIUM.
- **Suggested fix**: Apply the same two-line `isnan/isinf → 0` plus `clamp(…, 0, 6.0e4)` to `vec4(inscatter_total, trans_cumulative)` before the integrate store, and optionally cap `sanitize_emission` at a documented radiance ceiling. This needs a `.spv` rebuild (plain `glslangValidator -V`); the reflection tests then pin the result.

### SAFE-VOL-2026-10-17-02: `fog_cluster_dirty_range` is committed after the fallible uploads it describes
- **Severity**: LOW (latent). The trigger is a driver-reported failure in `vkFlushMappedMemoryRanges` (non-coherent memory only) or a missing/unmapped allocation, which no normal run produces. No out-of-bounds access results (all stale offsets/counts were produced by an earlier valid build, so the shader's reads stay inside the index buffer); the effect is wrong local-fog references.
- **Dimension**: GPU-lifetime / state commit (Dims 3 and 5 adjacent). Same class as #5772 and the concurrency sibling's latch (state advanced before the GPU work it vouches for is confirmed).
- **Location**: `crates/renderer/src/vulkan/volumetrics.rs:886-902`.
- **Description**: The frame-slot's GPU-side `entries` array only holds non-zero counts inside `fog_cluster_dirty_range[frame]`. Each frame rewrites `union(current range, previous dirty range)`. The new range is stored at `:901`, after `write_mapped_at(...)?` (`:891`) and the index `write_mapped(...)?`. If the entries write copies bytes into the mapped slice and then the flush (or the following index write) returns `Err`, `dispatch` returns early, the frame is treated as skipped, and the range is not updated. The slot's mapped memory now holds the failed frame's counts for `(lo_f, hi_f)`, a range that appears in neither the stale dirty range nor, necessarily, the next frame's range. Those clusters keep non-zero `count` until some later frame touches them, and the shader then dereferences index slots that were never written for them.
- **Disproof attempted**: On HOST_COHERENT memory `flush_range` returns `Ok` before any fallible call, and the only other `Err` sources (`Buffer has no allocation` / `Buffer not mapped`) are permanent and fail before the copy. So the stale-range window needs a non-coherent memory type and a flush failure. It is real but not reachable without fault injection.
- **Suggested fix**: Store `fog_cluster_dirty_range[frame] = union(old, new)` (or `(0, FOG_VOLUME_CLUSTER_COUNT)`) before the first fallible write and narrow it only after both writes succeed.

## Sibling-reported items: safety angle only (not re-filed)

- **REN-VOL-L-01 (`new_inner` §7 `integration_param_buffers` local filled before being tracked in `partial`)**: confirmed at `init.rs:720-739`. Release builds free it through the `GpuBuffer::Drop` safety net (warn, no leak, no UAF since nothing references it yet); debug builds hit `debug_assert!(false, "GpuBuffer leaked into Drop")` (`buffer.rs:1721-1727`) and panic instead of returning `Err`. Added scope: the same disposition is repeated by the two callers, `context/init.rs:1100-1108` (`pipe.destroy(...)` on `initialize_layouts` failure) and `context/resize.rs:965` (`new_volumetrics.destroy(...)`), whose comments assert "no in-flight users". ## Verified intact (regression guards and the focus-list items)

1. **67476a5d7 / #5772 (partial-init cleanup)**: `GpuCombustionLightMoment` and occupancy buffers are pushed into `partial.combustion_light_moment_buffers` / `combustion_occupancy_buffers` at `init.rs:459` and `:491`, before their `fill(0)` and `flush_if_needed`. `destroy` drains every one of those vectors, so each `try_or_cleanup!` exit frees exactly what exists. The other per-slot buffers (`param_buffers`, `fog_volume_buffers`, `fog_cluster_buffers`, `fog_cluster_index_buffers`) are `push(try_or_cleanup!(create…))`, so no fallible step sits between creation and tracking. Volumes, samplers, descriptor layouts/pools/sets, pipelines and layouts are assigned to `partial` immediately after creation. No double-free: `GpuBuffer::destroy` takes the allocation once, nulls the handle and clears the allocator Arc; `GpuImage::destroy` is guarded the same way; `destroy` null-checks every raw handle and nulls it afterwards.
2. **Destroy order**: images (view, image, slab) → buffers → integration pipeline/layout/pool/set-layout → injection pipeline/layout/pool/set-layout → samplers. Children before parents, descriptor consumers (`composite`) are destroyed earlier in `teardown.rs:205-219`, and `GpuBuffer::destroy` releases the allocator Arc before `VulkanContext::drop`'s `Arc::try_unwrap`. The resize path (`recreate_bloom_and_volumetrics`) destroys the old pass only after the device-idle wait and returns `Err` on failed rebuild, which both callers treat as fatal (`event_loop.exit()`).
3. **Panics in the create path**: `validate_set_layout(...).expect(...)` (`init.rs:520`, `:754`) fires after resources exist; a panic there skips `partial.destroy`. Only the safety-net `Drop`s run (raw `vk::Sampler`/pipeline handles leak). This is a build-time drift guard and a deliberate create-path panic, not a finding.
4. **Mapped-pointer writes vs sizes**: `VolumetricsParams` 336 B (2 mat4 + 13 vec4), `GpuFogVolumeUpload` 16 + 512 × 96 = 49168 B, entries 4096 × 16 B, indices 4096 × (64 + 128) × 4 B = 3 MiB, occupancy 4096 × 4 B, moments 256 × 32 B. Each `create_host_visible`/`create_host_readback` size is `size_of` the exact host type, and descriptor `range` equals the same expression. `write_mapped_prefix` is capped by `fog_volume_upload_bytes` (clamped to `MAX_GPU_FOG_VOLUMES`); `write_mapped_at` is `checked_add` + `get_mut` bounded; the moment drain `ensure!`s `bytes.len() >= stride * 256` before slicing. `repr(C)`/`NoUninit`: every SAFETY claim is true (vec4-shaped homogeneous arrays, no padding; `GpuFogVolumeUpload` has a 16 B header and a 96 B-stride array). GLSL std140/std430 twins are pinned by the reflection tests above; the lights/cluster SSBO prefix (`previousLightToCurrent[MAX_LIGHTS + 1u]`) is pinned by `gpu_instance_layout_tests.rs`.
5. **Fog-cluster CPU build**: `indices[(offset + count)]` stays below `FOG_VOLUME_INDEX_COUNT` because density count ≤ 64 and portal count ≤ 128 per cluster (checked before every push) and `next` is the exact sum; `cluster as u16` / `volume as u16` are covered by the two `const _: () = assert!` guards (`volumetrics.rs:202-209`). Non-finite camera/far/extent inputs produce `NaN as usize == 0`-style saturating casts, never a panic (`f32::max` discards NaN, `clamp` is only called with finite bounds).
6. **Integer casts / size arithmetic**: `froxel_extent` uses `div_ceil` on a divisor validated to `2..=32` (CLI path validates, `VolumetricsPipeline::new` validates twice, including after `fit_froxel_divisor_to_device`); `screen_scaled_reservation_bytes` widens to `u64` and saturates; the boot log multiplies in `u64`. `froxel_extent` is `pub` and would panic on divisor 0, but the only unvalidated entry (`recompute_blas_budget` at `context/init.rs:1123`) is fed a CLI-validated config. Hardening note only.
7. **GPU/host synchronisation**: HOST→COMPUTE `memory_barrier` precedes the inject dispatch; per-slot history READ→WRITE / previous WRITE→READ image barriers cover all five history fields; inject→integrate and integrate→composite barriers carry `TRANSFER` in the source scope (#3647); COMPUTE→HOST `SHADER_WRITE→HOST_READ` publishes the moment atomics before the host `invalidate_if_needed` drain, which `fill(0)`s and flushes before the next submit. The occupancy mask's host rewrite rests on the documented all-slots fence wait (rider 15), unchanged. `PipelineStageFlags::NONE` is legal because `synchronization2` is a required device feature (`device.rs:227`).
8. **Moment buffer memory-type angle** (asked by the performance audit): `GpuToCpu` may resolve to non-coherent memory; the code handles that (flush after the host zero, invalidate before the host read, explicit COMPUTE→HOST barrier). A non-coherent flush widens outward to `nonCoherentAtomSize` and could in principle publish stale cache lines over a neighbouring sub-allocation the GPU is writing; here every neighbour is idle at flush time (all-slots fence wait precedes the drain), so no hazard. No separate safety finding on PERF-VOL-01. The `u32` atomics cannot wrap in practice (per-invocation contribution clamped to 65535, 256 bins of 8 m cubes).
9. **Shader-side memory safety (GPU-fed data)**: `rigidBoundaryNormal` (`volumetrics_inject.comp:1910-1980`) bounds-checks the instance index against `boundaryInstances.length()`, `indexOffset`, `primitiveIndex` against the remaining index count, local indices against `vertexCount` and the vertex-buffer capacity before every `boundaryVertexData[...]` read; the custom-index lookup at `:335` is likewise length-checked. Descriptor bindings 2-5/19-21 are rewritten every dispatched frame, and the `tlas_written`/`lights_written`/`boundary_geometry_written` latches reset in `dispatch`.
10. **Non-finite handling (#4782)**: inject history is scrubbed (`:3290`), every store is zeroed-if-non-finite and clamped to the fp16 range (`:3345-3353`), `quantizeCombustionMoment` rejects non-finite, `sanitizedChemistry/Dynamics/Optical` scrub the transported fields, and the CPU boundary sanitises volume centres, extents, rotations (`fog_volumes.rs:136-149`), emission, fog tint (`normalize_fog_tint`/`pack_fog_tint`) and simulation time (`dispatch` falls back to the last finite time). Pinned by `v_buffer_history_rejects_non_finite_and_the_store_clamps_to_fp16`. See SAFE-VOL-01 for the one remaining gap (integration store).
11. **Record vs submit latches inside volumetrics**: `history_valid`, `transport_fields.submitted()` and `last_simulation_time_seconds` are promoted only from `mark_frame_completed` (called after a successful submit, `draw.rs:663-665`). `combustion_moment_dirty` is conservative (set at record, cleared only by a drain that actually zeroes, `latched_drain` #4535). The `volumetrics_cleared_on_skip` latch in `post_passes.rs` is the concurrency audit's item and is not re-reported here.
