## Findings

### FNV-2026-08-30-D1-01 (MEDIUM) — REGN `RDSB` / `RDSI` are **MSET** FormIDs on FNV, but the ambient dispatcher resolves them through the SOUN map, so region ambient audio is a guaranteed no-op on the reference title

**Labels**: `bug`, `medium`, `game:fnv`, `legacy-compat`, `esm-plugin`, `audio`

**Location**:
- `byroredux/src/components.rs:538-544` — `RegionAmbientRes { music_form, incidental_form }`
- `byroredux/src/asset_provider/audio.rs:159-190` — `dispatch_region_ambient_music`
- `byroredux/src/asset_provider/audio.rs:31` — `resolve_sound_path(sounds: &HashMap<u32, SounRecord>, form_id)`
- `crates/plugin/src/esm/records/misc/world.rs:719-724` — the `RegionDataPayload::Sound` doc

**Premise the code carries.** `RegionAmbientRes`'s doc reads *"`RDMD` (Oblivion) /
`RDMO` (Skyrim) / **`RDSB` (FNV)** — the winning entry's background-music/ambient-bed
FormID"*, and `world.rs:723` calls `RDSI` the *"incidental **sound** form (FNV)"*.
`dispatch_region_ambient_music` acts on that premise: it takes `music_form` straight to
`resolve_sound_path`, which is a lookup into the parsed **`SounRecord`** map, and uses
the returned `FNAM` path as the archive key.

**Measured.** Across all 276 REGN records in `FalloutNV.esm`, 10 carry `RDSB` and 11
carry `RDSI`, for 55 FormID references in total. Their target record types:

| Sub-record | Target type | Count |
|---|---|---:|
| `RDSB` | **MSET** (Media Set) | 44 |
| `RDSI` | **MSET** | 10 |
| `RDSI` | unresolved (other master / DLC) | 1 |
| either | **SOUN** | **0** |

Sampled EDIDs of the targets: `musSetBTTLRuralGood3Perc`, `musSetBTTLCityGood1Perc`,
`musSetINCDesert`, `musSetINCHostile`, `musSetINCMountain` — Media Sets, each carrying
the `NAM1`/`NAM2`/`ANAM`…`INAM` track-slot bank, not a `FNAM` file path.
`FalloutNV.esm` holds 140 MSET records; the engine parses none of them.

The confirming detail is what *is* SOUN-typed: the **`RDSD` ambient-loop list**, which
the same `RegionDataPayload::Sound` arm parses into `sounds: Vec<RegionSound>` and which
`RegionAmbientRes` deliberately does **not** surface (its doc explains why — the
`chance_raw` fixed-point scale is unverified, correctly invoking the no-guessing
policy). Measured: **1039 of 1081 `RDSD` entry targets are SOUN records.** So the
engine consumes the sub-record that is MSET-typed and skips the one that is SOUN-typed.

**Impact.** On FNV, `resolve_sound_path` misses on 100 % of `music_form` values, so
`archive_path` is always `None`, `stop_region_ambient_music` runs unconditionally, and
region ambient music can never play — *independently* of which archives are opened.
It fails silently by design: the `provider_present` split at `audio.rs:177-182` warns
only when an archive was supplied but lacked the file, so the FNV path emits nothing at
all. Not a crash, not a regression, and audio-only — hence MEDIUM, not HIGH. But it
means a shipped, documented feature is structurally dead on the project's reference
title, and it invalidates the premise the code and two doc sites assert.

**Cross-audit note.** `docs/audits/AUDIT_AUDIO_2026-08-30.md:291` restates the same
"`RDSB` (FNV) → sound FormID" premise while filing AUD-2026-08-30-D4-01 about the
dispatched track's loop/re-trigger behaviour. That finding is about a code path that
cannot execute on FNV. This one should be resolved first.

**Recommendation.** Either (a) decode MSET and route FNV's `RDSB`/`RDSI` through it, or
(b) if that is out of scope, correct both doc sites to say `RDSB`/`RDSI` are **MSET**
FormIDs on FNV and make the FNV arm log once at `info` that region ambient is
unsupported pending an MSET runtime — silence that looks like success is the worst of
the three states. Do not "fix" it by pointing the lookup at `RDSD` without first
settling `chance_raw`'s scale; that would be exactly the guess the existing doc refuses.

### FNV-2026-08-30-D8-01 (MEDIUM) — `--game fnv` supplies no `--sounds-bsa`, so footsteps, water splash and region ambient all have zero asset source on the reference title, while `--game skyrim_se` supplies two archives

**Labels**: `bug`, `medium`, `game:fnv`, `audio`, `tooling`

**Location**:
- `assets/debug_profiles.toml:42-61` — `[profiles.fnv]`
- `byroredux/src/boot.rs:1727-1730` — `default_sounds_bsas` → `--sounds-bsa` expansion
- `byroredux/src/asset_provider/texture.rs:100-110` (`try_load_default_footstep`), `:149-155` (`try_load_default_water_splash`)
- `byroredux/src/asset_provider/audio.rs:177-182` (`dispatch_region_ambient_music`)

**Description.** The shipped FNV profile declares:

```toml
[profiles.fnv]
default_bsas = ["Fallout - Meshes.bsa"]
default_textures_bsas = ["Fallout - Textures.bsa"]
default_materials_bsas = []
# default_scripts_bsas and default_sounds_bsas absent
```

`expand_game_profile_args` emits one `--sounds-bsa` per `default_sounds_bsas` entry, so
`--game fnv` emits **none**. All three consumers of that flag then early-return
silently: `try_load_default_footstep` (`let Some(path) = path else { return }`),
`try_load_default_water_splash` (same shape), and
`dispatch_region_ambient_music`'s `Some(p) if !p.is_empty()` guard, whose own comment
calls the no-archive case a *"silent no-op, the common case"*.

By contrast `[profiles.skyrim_se]` declares
`default_sounds_bsas = ["Skyrim - Sounds.bsa", "Skyrim - Voices_en0.bsa"]` and
`default_scripts_bsas = ["Skyrim - Misc.bsa"]`. FNV — the title whose compat bar is the
highest — is the one running dark.

**Measured — the assets are all there.**

- `Fallout - Sound.bsa` exists in the vanilla `Data/` with **6465 entries**.
- `try_load_default_footstep`'s hardcoded canonical path
  `sound\fx\fst\dirt\walk\left\fst_dirt_walk_01.wav` is **present in
  `Fallout - Sound.bsa`**, byte-for-byte the string the loader asks for.
- The water-splash candidates are present too (`sound\fx\phy\water\splash_{l,m,h}\*.wav`,
  `sound\fx\phy\water\human\npc_human_splash_0{1,2,3}.wav`).
- **2700 of 3189 FNV `SOUN.FNAM` paths (84.7 %) resolve inside `Fallout - Sound.bsa`** —
  1127 as exact files and 1573 more as random-pick directory prefixes with at least one
  matching entry. Only 489 do not resolve there.

So a single archive name closes all of it. The omission is not a design decision that
was weighed: the profile parser's **own unit test** (`game_profiles.rs:328-352`) uses an
FNV fixture that declares `default_sounds_bsas = ["Fallout - Sound.bsa"]` and asserts it
round-trips — the intended shape is written down beside the code, just not in the
shipped file.

**Impact.** Three shipped M44 subsystems (footstep audio, water-splash acoustics, REGN
ambient) produce nothing on `--game fnv`, which `ROADMAP.md` and this skill both name as
the *preferred* CWD-immune invocation for ad-hoc runs and audits. Nothing warns. Any
audit or manual check of FNV audio through the recommended launch path measures silence
and cannot distinguish "not implemented" from "no archive". Note FNV-2026-08-30-D1-01
independently kills the REGN half, so fixing this profile alone restores footsteps and
splash but not region ambient.

**Recommendation.** Add `default_sounds_bsas = ["Fallout - Sound.bsa"]` to
`[profiles.fnv]` (and evaluate `Fallout - Voices1.bsa` separately — 105 517 entries, and
no dialogue consumer exists yet). Consider the same audit for `[profiles.fo3]` and
`[profiles.oblivion]`, which are shaped identically; scoping that is out of this
dimension's remit.

### FNV-2026-08-30-D8-02 (LOW) — `--game fnv` omits `Update.bsa`, so 21 base-game `FalloutNV.esm` MODL paths resolve to no mesh

**Labels**: `bug`, `low`, `game:fnv`, `tooling`

**Location**: `assets/debug_profiles.toml:47` — `default_bsas = ["Fallout - Meshes.bsa"]`

**Description.** FNV's `Update.bsa` (86 entries, 55 of them NIFs) is the base game's own
patch archive and loads at higher priority than `Fallout - Meshes.bsa` in the retail
engine. The profile does not list it, and `Update.bsa` is not a `<stem>N.bsa` sibling of
anything, so the auto-load rule in `asset_provider/archive.rs` does not pick it up
either.

**Measured.** Resolved the first `MODL` of every `STAT`/`DOOR`/`CONT`/`ACTI`/`FURN`/
`MSTT`/`WEAP`/`ARMO`/`MISC`/`TERM`/`LIGH`/`TREE`/`GRAS`/`SCOL` record in
`FalloutNV.esm` (11 994 paths) against the archive index:

| Outcome | Count |
|---|---:|
| in `Fallout - Meshes.bsa` | 11 953 |
| **only in `Update.bsa`** | **21** |
| only in a DLC archive | 1 |
| in no FNV BSA (loose / pre-order pack) | 19 |

The 21 include the NCR guard towers (`meshes\architecture\ncr\nvguardtower01a.nif`,
`…01b`, `…01c`) — visible exterior architecture, not debug props.

**Impact.** Small and bounded (21 of 11 994 base records, 0.18 %), and it degrades to a
missing mesh rather than a failure. Filed LOW for completeness of the profile, and
because `Update.bsa` also carries 6 `wastelandnv` object-LOD block quads that the #3321
LOD ring would otherwise resolve.

**Recommendation.** `default_bsas = ["Fallout - Meshes.bsa", "Update.bsa"]`, ordered so
the patch archive wins.

### FNV-2026-08-30-D2-01 (LOW) — the `/audit-fnv` Dimension-2 checklist sends auditors after `bhkMultiSphereShape` / `bhkConvexListShape` collision shapes, which FNV ships zero of

**Labels**: `documentation`, `low`, `game:fnv`, `nifal`, `doc-rot`

**Location**: `.claude/commands/audit-fnv/SKILL.md`, Dimension 2 — *"Collision-shape
no-drop guard (`9c6096aa`) … Any FNV mesh with a multi-sphere / convex-list Havok shape
must surface a `CollisionShape`."*

**Description.** The `resolve_shape` arms exist and are correct
(`crates/nif/src/import/collision/shape.rs:110` for `BhkMultiSphereShape` → Compound of
`Ball` children, `:235` for `BhkConvexListShape` → `ConvexHull`) and both are covered by
synthetic-fixture tests at `:1185`, `:1302`, `:1319`. But **neither block type appears
anywhere in FNV's shipped content**: the 150-type `fallout_nv.tsv` per-block baseline
over all 20 746 meshes has no `bhkMultiSphereShape` and no `bhkConvexListShape` row.
The FNV shape universe (all 11 mesh archives) is `bhkMoppBvTreeShape` 9947 /
`bhkPackedNiTriStripsShape` 9914 / `bhkConvexVerticesShape` 2793 / `bhkBoxShape` 1498 /
`bhkCapsuleShape` 1363 / `bhkListShape` 162 / `bhkConvexTransformShape` 109 /
`bhkSphereShape` 38.

**Impact.** Doc-only, and exactly the same shape as last cycle's
FNV-2026-08-27-D1-02 (the `_far.nif` bullet, #3539's sibling): the checklist directs
effort at a probe that can only ever confirm a no-op, which costs audit time and
manufactures false confidence when it "passes".

**Recommendation.** Re-scope the bullet to a title that authors those shapes, or annotate
it as a construction-only guard with the FNV zero-count pinned inline, the way the
`_far.nif` / `distantlod\` census pin now is.

## Stale candidates dropped (5)

1. **`NifVariant::detect`'s ambiguous-tuple WARN fires on FNV's own archive**, and the
   comment beside it attributes the sample to FO3 (both games ship a
   `Fallout - Meshes.bsa`). Dropped after grepping every `NifVariant` consumer: the only
   non-test reader is `havok_scale_for`, which maps Oblivion / Fallout3 / FalloutNV all
   to 7.0. `ambiguous_v20_0_0_4_misroute_is_unobservable_via_havok_scale` already pins
   that. #1219 is correctly CLOSED.
2. **Two FNV skeletons come out as 5 disconnected components with zero dropped
   constraints** (`clutter\skeleton\skeleton{male,female}50scasual.nif`). Looked like a
   silent articulation loss. Dropped after extracting the file and running
   `nif_stats --all` on it: the source authors **16 rigid bodies and only 11
   constraints** (9 LimitedHinge + 2 Ragdoll), so 5 components is the arithmetic
   minimum and the authored topology of a pre-dismembered corpse prop. The importer
   surfaced everything present.
3. **`.high.` object-LOD block variants unhandled** — FNV ships 25
   (`<world>.level4.high.x*.y*.nif`) that `object_lod_archive_path` never generates.
   Dropped: all 25 have a plain counterpart at the same `(level, qx, qy)`, so this costs
   detail on 25 quads and can never leave a hole.
4. **The Fallout-legacy LOD ladder requests levels 4/8/16/32 while FNV ships blocks at
   level 4 only.** Dropped: `select_lod_quads`' `available` predicate subdivides any
   node the archive lacks down to the finest level, and the probe is memoised per
   `(level, qx, qy)` (#3385), so the mismatch is absorbed by design.
5. **LVLI expansion discards the LVLO `count` field** (1359 of 13 319 FNV entries carry
   count > 1). Dropped: `expand_leveled_form_id` is documented equip-only, its callers
   supply their own count from the CNTO entry, and `expand_leveled_any` is already the
   named seam for a future loot consumer (#3341).
