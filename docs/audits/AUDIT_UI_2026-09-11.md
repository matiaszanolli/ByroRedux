## 2. Findings

### LOW

#### UI-D4-2026-09-11-01 — the `/audit-ui` SKILL.md checklist still asserts a case-insensitive catalog lookup that neither the code nor `docs/engine/ui.md` has ever claimed

- **Severity**: LOW
- **Dimension**: Catalog Fidelity & Drift
- **Profile**: n/a
- **Location**: `.claude/commands/audit-ui/SKILL.md` (Dimension 4 checklist,
  the `find` case-normalization bullet)
- **Status**: NEW — carries forward a defect first reported against the wrong
  file two days ago, and **fixed in this session**

**Description.** The checklist read: *"the catalog is documented as
case-preserving with case-insensitive lookup. Verify exactly one
normalization point."* `ScaleformHostCatalog::find`
(`crates/ui/src/catalog.rs:132-137`) is a plain case-sensitive
`binary_search_by(|m| m.name.cmp(name))`; no normalization point exists
anywhere in `crates/ui` (`host.rs` has zero
`to_lowercase`/`to_uppercase`/`eq_ignore_ascii_case` occurrences). Neither
`docs/engine/ui.md` nor the catalog source has ever claimed case-insensitivity
— the doc states the opposite: case is preserved deliberately "because FO4
contains forms such as `CloseMenu`, `closeMenu`, `PlaySound`, and `playSound`."

**What's new here versus the 2026-09-09 report.** That report's §7 flagged
this exact wrong sentence — but filed it as drift in `docs/engine/ui.md`,
which never actually carried the claim (confirmed independently this cycle:
`ui.md` has no such line either then or now). The real defect was always the
SKILL.md checklist item itself, which was never touched. `git log -p
b3db49fa` — the same-day "Update SKILL documentation across multiple audit
commands" commit — shows `audit-ui/SKILL.md` was edited today, but not this
block: a doc-sync pass explicitly aimed at this file walked past the exact
line the prior audit had already named.

**Evidence.**
- `crates/ui/src/catalog.rs:132-137` — `find`'s literal case-sensitive body.
- `docs/engine/ui.md:500-501` — states the opposite (case preserved by
  design, with the `CloseMenu`/`closeMenu` example).
- `docs/audits/AUDIT_UI_2026-09-09.md:313-316` — the same drift, reported two
  days ago, against the wrong file.

**Impact.** Audit-process friction only — no runtime effect. An auditor
following the checklist literally would hunt for a normalization point that
was never built, or risk misreporting the documented case-sensitive contract
as a bug. Worth naming as a pattern: a `Fix.` note in an audit report does not
by itself propagate to the skill file whose checklist generated the finding —
this is the second time the identical sentence was examined and found wrong
without the source of the sentence being corrected.

**Suggested Fix.** Applied this session: reworded the Dimension 4 checklist
item in `.claude/commands/audit-ui/SKILL.md` to state the case-sensitive
contract directly and point at the actual prerequisite —
`binary_search_by`'s sortedness requirement, pinned by
`*_catalog_is_sorted_and_unique` — instead of asking future auditors to
verify a normalization point that doesn't exist.

## 5. Cross-audit pointer — GPU teardown ordering (recorded here, owned by `/audit-concurrency` Dim 6)

Dimension 6 traced the concrete teardown mechanism rather than only asserting
the fact:

`App`'s field declaration order (`byroredux/src/main.rs:385-390`) places
`renderer: Option<VulkanContext>` before `ui_manager: Option<UiManager>`, but
this is moot because `App` overrides plain field-drop order with an explicit
`impl Drop for App` (`main.rs:652-683`) whose body calls
`self.renderer.take()` **synchronously inside `App::drop()`**, tearing down
`VulkanContext` and its `ash` allocator *before* control returns to Rust's
automatic post-body field sweep that drops `ui_manager` (and, inside it,
`SwfPlayer`'s Ruffle wgpu device). The `WindowEvent::CloseRequested` path
(`shutdown()`, `app_events.rs:40-72`) does the identical thing explicitly,
again without touching `self.ui_manager`.

**Net fact, on every exit path checked (normal `CloseRequested`, and
drop-without-`shutdown()` such as a panic unwind or `--bench-frames`'s
natural exit): the Vulkan `ash` device/allocator tears down *before*
`SwfPlayer`'s separate Ruffle/wgpu device.** This is the opposite of this
skill's own checklist phrasing ("`SwfPlayer` ... must drop before the Vulkan
context tears down its allocator"). Whether this ordering is actually safe —
because the two devices are independent `ash`/`wgpu` `VkDevice`/`VkInstance`
objects — or a hazard at the ICD/driver level is the `/audit-concurrency`
Dimension 6 question; not adjudicated here, per this skill's own dedup rule
(GPU teardown ordering belongs to that audit). Report the fact once, here,
with this pointer, so that audit does not need to re-derive the mechanism.

## 7. Pending-Row readiness

Unchanged from the 2026-09-09 report's own §6 — re-verified rather than
assumed stale:

1. **Menu swap would make two dormant issues live**, still true today because
   no runtime menu-swap path exists (`scene.rs`'s one-shot `--menu`/`--swf`
   startup route remains the only caller of `load_swf*`, confirmed by grep
   this cycle):
   - `host_call_gap_for_menu` keys its latch on **menu name**; a same-name
     reload would start a fresh bridge counting from 0 against an old
     latch total. Needs a bridge identity/generation counter when the
     menu-stack work lands.
   - This is now **less** of a device-multiplication risk than previously
     stated: `SwfPlayer`'s wgpu device is a process-wide singleton (#2733),
     so a runtime swap will drop the old `SwfPlayer` and reuse the cached
     device, not allocate a new one per menu open. The 2026-09-09 report's
     framing of this half was already stale when written; corrected in §4
     above.
2. **The navigator's trust boundary rests on every provider being
   archive-backed.** `../` and UNC-style escapes are neutralized only because
   the resolved string is a BSA/BA2 hashmap key. A filesystem-backed
   `ScaleformResourceProvider` (the natural way to support loose/modded menu
   files) would make the escape real and need the traversal check moved to
   act on the resolved *string*, not just the URL's parsed components.
3. **`set_mouse_in_stage`'s focus-vs-visibility coupling** (§4, "latent
   coupling") only matters once a visible-but-unfocused HUD layer exists.

None of the above are findings; they are invariants this audit pinned as
still-true prerequisites for work that hasn't landed yet.
