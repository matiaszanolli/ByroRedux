### The headline change: `--menu` / `--menu-archive` is now a real engine route

`byroredux/src/scene.rs`'s `archive_menu_args` (new, explicitly commented
`#3147`) parses `--menu <archive-relative.swf> --menu-archive <BSA-or-BA2>`
and drives `Archive::open` → `archive.extract` → `ScaleformProfile::detect`
→ `UiManager::load_swf_from_resource_provider`, registering the UI texture
exactly as the `--swf` loose-file path does. This was the 08-20 HIGH
finding (#3147: "the shipped binary cannot open any vanilla Bethesda
menu"). It is fixed: `load_swf_from_resource_provider` now has a real,
non-test caller, reachable from the CLI.

One consequence promotes an existing LOW finding's practical weight: with
the archive route reachable, **#2968's four-decompress startup cost is no
longer dead-code-adjacent** — it now runs on every `--menu` launch. Still
LOW per this repo's severity rubric (load-time only, no correctness
impact), but no longer "on the unreached path" as the 08-20 report
correctly qualified it.

- **Dimension**: Resource Navigator / Engine Wiring

  `byroredux/src/scene.rs`:1509-1529 (`archive_menu_route_tests`, the only

  `archive.extract` → `ScaleformProfile::detect` →
  `load_swf_from_resource_provider` → `register_rgba`) requires a real GPU

  `--bench-hold` → `byro-dbg`-attach pattern from
  `docs/smoke-tests/README.md`), there is no smoke-test script for
  `--menu`. `docs/engine/ui.md`:39 lists the route under Status with no

- **Evidence**: `grep -rn "\-\-menu\b" docs/smoke-tests/` → no matches;
  `ls docs/smoke-tests/` → only `m41-equip.sh` + `README.md`.
- **Impact**: The #3147 fix is real and correctly wired by static reading
  (traced above), but "the shipped binary cannot open any vanilla
  Bethesda menu" (the HIGH severity #3147 carried) converts to "unverified
  whether the shipped binary can open one," which is a materially
  different and lower-severity claim precisely because #2968's
  redundant-decompress path and the whole `ScaleformNavigatorRuntime`
  preload loop are exercised for the first time by a real caller today. A
  smoke test is the only way to close that gap the way `m41-equip.sh`
  closed it for NPC outfit equip.
- **Related**: #3147 (the fix this verifies is unverified), #2968
  (promoted by the same fix, see §1).
- **Suggested Fix**: Add `docs/smoke-tests/m48-menu-load.sh` following the
  `--bench-hold` pattern: launch with `--menu interface\hudmenu.swf
  --menu-archive "Fallout4 - Interface.ba2" --bench-hold`, attach
  `byro-dbg`, and assert the UI texture handle is populated / the menu
  reached frame 1 (mirroring what the ignored corpus tests already check
  headlessly, but through the real CLI entry point).
