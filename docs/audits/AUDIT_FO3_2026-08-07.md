#### FO3-D2-05: `extract_emitter_rate` only downcasts `interpolator_ref` as `NiFloatInterpolator` — drops the authored rate on 78% of real FO3 particle effects, which target `NiBlendFloatInterpolator`
- **Severity**: MEDIUM
- **Location**: `crates/nif/src/import/walk/mod.rs:842-865` (`extract_emitter_rate`, "Modern" branch)
- **Status**: NEW
- **Description**: The modern-path branch downcasts `NiPSysEmitterCtlr.interpolator_ref`
  only as `NiFloatInterpolator` and returns `None` on failure, never handling
  the `NiBlendFloatInterpolator` wrapper (`blocks/interpolator.rs:1052`, a
  weighted array of sub-interpolators via `InterpBlendItem`).
- **Evidence** (real `Fallout - Meshes.bsa`, 10,989 NIFs): of 361
  `NiPSysEmitterCtlr.interpolator_ref` targets, **283 (78%) are
  `NiBlendFloatInterpolator`** and only 78 are the handled `NiFloatInterpolator`.
  Affected files include `fxharoldfire.nif`, `fxpulseexplosion01.nif`,
  `fxplasmacritburst.nif`, `explosionbigfiry.nif`, `fxravenrockexplosion01.nif`,
  `fxdrippingwater01.nif`, `fxdrippingblood03.nif`, `fxgorepophead01.nif` —
  most of FO3's fire/explosion/dust/blood/gore VFX library.
- **Impact**: Visual-only regression — affected emitters silently fall back to
  the heuristic preset spawn rate instead of the artist-authored birth-rate
  curve. No parse failure, no crash, no data loss. `emitter_params`
  (speed/radius/life-span/color) and GrowFade `base_scale` both decode
  correctly for the same blocks — only the birth-rate path is affected. This
  is the SKILL's flagged "unverified gap" for FO3, now confirmed as a real,
  broad-blast-radius bug rather than a documentation gap.
- **Related**: Upstream of #1364/#1402/#1771 (the `sane()`-filter follow-up on
  the *handled* `NiFloatInterpolator` path — this bug is on the interpolator-
  *type* dispatch, not the value-sanity gate). No existing open issue matches.
- **Suggested Fix**: In the "Modern" branch, on `NiFloatInterpolator` downcast
  failure, try `NiBlendFloatInterpolator`: walk `base.items`, resolve the
  highest-weight (or first) `InterpBlendItem.interpolator_ref` as
  `NiFloatInterpolator`, apply the same keyed-data → constant-value → `sane()`
  chain. Add a fixture-based regression test sibling to
  `import/walk/tests.rs:798-861`.

**Checklist items verified clean**: `BSShaderPPLightingProperty`/
`BSShaderNoLightingProperty` field completeness against nif.xml (the one gap,
`falloff_start_angle` absent-case default, is already tracked as open #2331 LOW,
unreachable on retail bsver-34 content). `BSSegmentedTriShape` vertex-index

#### FO3-D4-NEW-01: `NifImportRegistry::insert` drops freed animation-clip handles in the precombined-mesh commit path
- **Severity**: MEDIUM
- **Location**: `byroredux/src/cell_loader/precombined.rs:313-316`
- **Status**: NEW — **same underlying defect as PERF-D3-NEW-01 in
  `docs/audits/AUDIT_PERFORMANCE_2026-08-07.md`** (identical file:line;
  compiled the same day by an independent audit sweep). Cross-referenced
  here, not double-filed as a separate issue.
- **Description**: `NifImportRegistry::insert` returns `Vec<u32>` — the
  `AnimationClipRegistry` handles of any entries the 2048-cap LRU sweep
  evicted as a side effect of this insert — annotated
  `#[must_use = "evicted clip handles must be released ... see #863"]`. The
  precombined-mesh commit path binds the return to `_freed` and discards it,
  unlike its two sibling call sites (`references/mod.rs`, `partial.rs`) which
  correctly forward evicted handles to `AnimationClipRegistry::release`.
  Binding to a *named* `_freed` (not bare `_`) satisfies both the `must_use`
  and `unused_variables` lints, so the compiler gives no warning — this is
  the exact silent-drop shape #863's original bug had before the `Vec<u32>`
  contract was added.
- **Impact**: Slow CPU-RAM leak (not VRAM), gated on (a) FO4 precombined-mesh
  content loading (M49), (b) the `NifImportRegistry` LRU cache being at cap,
  (c) the evicted victim owning a registered clip handle. **Not directly
  FO3-triggerable** — `precombined_mesh_hashes` is always empty for FO3 — but
  the call site lives inside the shared `NifImportRegistry` cache FO3 also
  depends on, so it's reported here per the cache-lifecycle checklist item;
  the actual exposure is FO4-side (see the performance audit for that framing).
- **Suggested Fix**: Mirror `partial.rs`'s pattern — capture the returned
  `Vec<u32>` as `freed` (not `_freed`) and forward each handle to
  `AnimationClipRegistry::release`.

**Non-finding worth tracking**: the new quest-alias landing (`a844c26b`) will

stat-miss/marker REFRs now spawn one lightweight logical entity each) — does
not affect the 929 parse-side baseline, but relevant if an entity-count
baseline gets captured later.

code path, with no FO3-only structural gap found:

- **NIF parser**: identical v20.2.0.7/BSVER-34 block set and dispatch table;
  the one real gap found this cycle (FO3-D2-05, `NiBlendFloatInterpolator`

  FNV's.

  design — zero `GameKind::Fallout3`-specific branches exist anywhere in the

  `BSLightingShaderProperty`, no BGSM ever reachable), identical NIFAL

  both games).
- **Collision**: identical classic `bhk*CollisionObject` → `BhkRigidBody`
  chain and motion-type mapping; the havok_filter drop (FO3-D5-NEW-01) is
  shared code, exposed by FO3's `FOL_NONCOLLIDABLE` authoring.
- **Cell loading**: identical interior/exterior/streaming code, identical
  `CachedNifImport`/`NifImportRegistry` LRU cache (whose lifecycle bug,
  FO3-D4-NEW-01, is shared with FO4 and only latently reachable on FO3),
  identical WTHR→CLMT resolution.

The REFR XATO/XTNM/XTXR override path (#1887) remains the clearest example of

FO3 content simply never authors it, so there is nothing to regress.

## FO3-Distinctive Gaps

1. **Obscript scripting runtime** — 1,257 SCPT records parse; the bytecode
   disassembler that would make them executable does not exist yet (M47.2's
   Papyrus-only progress does not touch this format). FO3's (and FNV's, and
   Oblivion's) largest functional gap for quest/world interactivity —
   tracked as a known blocker, not a bug.
2. **Inline-shader-only material universe** — Disney-BSDF/BGSM paths
   confirmed provably unreachable (zero BGSM authoring anywhere in FO3
   content).
3. **Capital Wasteland worldspace** — confirmed distinct WRLD form ID with
   generic (non-hardcoded) worldspace selection; no FNV-specific name/coord
   found in the cell loader.
4. **FaceGen** — runtime-recipe model (`headhuman.egm/.egt/.tri`), shared with
   Oblivion/FNV and distinct from Skyrim+/FO4's prebaked-mesh model; confirmed
   byte-identical to the already-tested FNV fixture. Test-coverage gap only
   (#2335): the fixture test doesn't independently exercise the FO3 data path.
